# EDF6VehicleCrew：NPC 开载具 / 开直升机，玩家随时顶替

EDFModLoader 插件，只支持 EDF.dll TimeDateStamp `0x678CCB46`（当前 Steam 版）。版本不符或代码签名对不上时，
插件只写一行 `REFUSED` 日志后自行退出，不改动游戏的任何内容。

## 仓库里的两个插件

| 插件 | 目录 | 做什么 |
|---|---|---|
| `EDF6VehicleCrew` | `src/` | NPC 开载具 / 开直升机，玩家随时顶替（本文下面全部内容） |
| `EDF6AutoTurret` | `autoturret/` | 防空车（KG6 克卜勒系）改高射炮并自瞄、玻尔斯对地自瞄；泰坦和带炮手座坦克的两门副炮自瞄，炮手座没人时自动开火（算驾驶员的）；关卡里 NPC 开的防空车换成 mod 版防空车，NPC 泰坦补上副炮，关卡里的坦克开炮时有和玩家版一样的车体后坐力。说明见 [autoturret/README.zh-CN.md](autoturret/README.zh-CN.md) |

**发布包（安装器）两个插件都装**：`EDF6VehicleCrew安装器.exe` 里打包了 `EDF6VehicleCrew.dll` / `.ini` 和 `EDF6AutoTurret.dll` / `.ini`，
选 1 时连同 `EDF6AutoTurret` 的武器 / 载具数据一起装好，选 2 卸载时一起去掉，选 5 检查（见「安装 / 卸载」）。
空袭兵呼叫的地面载具、自行榴弹炮、喀秋莎、关卡里的防空车、测试场停放的防空车和坦克副炮都要 `EDF6AutoTurret` 才会自瞄，
所以它算在全军出击里，不需要另外安装。0.8.0 及以前的安装器只装 `EDF6VehicleCrew`，`EDF6AutoTurret` 停留在玩家自己装过的旧版本；用新安装器选 1 即可换成同版本。

两个插件在代码上各自独立（缺哪个都不影响另一个加载），开发时也可以只装一个。根目录 `build.cmd` 一次构建两个，DLL 和 ini 都输出到 `build/Mods/Plugins/`（构建产物，不进仓库）。
单独使用 `EDF6AutoTurret` 时，它的武器 / 载具数据用下面的命令由你自己的游戏数据生成（安装器调用的是同一份 `build.py`，同一份清单）：

```
python autoturret\tools\build.py install      （游戏关闭时；--mods DIR 指定 Mods 目录）
python autoturret\tools\build.py uninstall    （按安装清单恢复，别的 MOD 的文件不动）
```

它写 `Mods/WEAPON/`（防空车、玻尔斯的呼叫和炮）、`Mods/OBJECT/`（关卡防空车 `V603_FLAK_*`、NPC 泰坦 `VEHICLE404_BIGTANK_AI` 和其它关卡坦克，见 `autoturret/tools/npc_recoil.py`）以及 `WEAPONTEXT` 里这几辆车的说明行，只改自己的行；
做了什么记在 `Mods/.edf6at_data.json`（含备份），卸载照它恢复。这些数据不依赖插件也能用：插件被停用或删掉时，这些炮照原版方式开火，只是没有自瞄和近炸引信。

## 功能

1. **NPC 自动上车**：己方空载具空置 `CrewDelayMs`（默认 3 秒）后，会来一名 NPC 驾驶。用的是任务脚本让 NPC 坦克队出动的同一个原生调用
   `Vehicle_RideAi`（VehicleBase 第 50 槽）。只给玩家同队、离玩家 `CrewRange` 米以内的载具派人。
   - 直升机例外：玩家还没坐过的直升机不派 NPC，停在原地等你（NPC 一上直升机就起飞，你就上不去了；测试场停放的直升机原来开局 9 秒就全飞走）。你开过、下机离开的直升机照常派 NPC 跟随你；空袭兵呼叫来的直升机本来就带 NPC，不受影响；
   - 武装装甲车格雷普斯（`Vehicle_Car`）原版有坦克同款驾驶 AI，只是它的找座位函数和别的车不同，以前一直没被登记、从没派过人；现在会派（同一类的轻卡、拖车头没有武器，不派）；
   - 深渊爬行者（`Vehicle502_GroundRobo`）原版完全没有驾驶 AI，NPC 坐上去由插件来开（`src/ground.cpp`，逆向见 `docs/ground-ai-re.md`）：没敌人时跟随玩家、停在 `GroundFollow` 米处；`GroundRange` 米内有敌人就转身、逼近到射程的七成、机炮和左右臂炮各自对准了才开火，弹道上有玩家不开火；离玩家不超过 `GroundLeash` 米。**爬在墙上 / 天花板上也照样开**（`src/crawl_logic.h`，2026-10-06 用户：「蜘蛛车爬墙上指挥不动了」）：目标按三维方向投影到它自己贴着的那个面上走，转向绕它自己的「上」方向量；目标点离开这面墙时：在墙面朝向的一侧（墙外）先沿墙往下爬回地面再走，在墙背后（隔着楼）就往上翻过墙顶，不会在墙脚上上下下来回跑；趴在天花板上、目标就在正下方时原地不动；在地面上「到了」仍按水平距离判（玩家开直升机在头顶时不会在下面绕圈），在墙上 / 天花板上按三维距离判。离线检查 `build\crawl_check.exe`（CTest `crawl_check`）。`GroundPilot=0` 关闭。
2. **玩家顶替 NPC**：原版不允许玩家坐已有人的座位。插件放开了这一限制，所以 NPC 坐着的载具也会照常出现上车提示，按上车键就能坐进去：
   - 被顶下的 NPC 优先挪到空的副座/炮手位；
   - 没有空位时它下车（NPC 会直接消失，这是原版对 AI 乘员下车的处理）；
   - 玩家下车后，过 `CrewDelayMs` 又会有 NPC 来开这台车。
3. **NPC 开直升机**：游戏本身没有直升机驾驶 AI（静态分析结论见 `docs/heli-input-re.md`），NPC 坐上直升机后由插件来飞：
   - **跟随**：保持在玩家旁 `HeliFollow` 米、头顶 `HeliHeight` 米处；
   - **护卫**：`HeliRange` 米内有敌人时，飞到玩家与敌人之间，机头对准敌人，开机枪、发导弹。不会隔着玩家开火。机枪固定朝机头方向、悬停时机头是平的，所以交战时它会压低到目标斜上方约 8 度（至少高出目标 8 米），只在机头（含俯仰）偏离目标 `HeliFireCone` 度以内、且目标在射程内时开火（506 的机枪子弹只飞 160 米）。导弹位挂的是无导引的烧夷武器时（空袭兵叫来的 N9 エウロス·ブレイズ / バルチャーＺＡ / ＺＡＭ 的连装烧夷炮、エウロス ナンバー６ 的烧夷弹投射荚舱），按这发弹自己的弹道（弹速、下坠、继承的载机速度）解算，把机头摆到让炮口打出的弧线正好落到目标届时位置的方向；只有从炮口按它此刻的朝向打出去的弧线离目标不超过这把武器自身散布本来就会偏出的距离（至少 3 米）、且这个散布不超过 12 米（连装烧夷炮约 120 米内）时才开火，机身倾斜让炮口偏离解算方向时就不开火；荚舱则在飞临目标、算得正好落到目标上时投下。它同样受 `HeliMissile` / `HeliMissileMs` 控制，落点离玩家 15 米内不开火；
   - **盘旋 / 降落**：附近没有敌人时，玩家站着或只在小范围内走动（最近 10 秒的活动跨度不到约 70 米、或来回折返），它沿一个罩住玩家活动范围、外扩 `HeliFollow` 米的椭圆一直朝同一方向绕飞，不会跟着玩家的每次转身掉头；玩家持续朝一个方向走远时才转为在侧翼护航跟随。默认从不自己降落。把 `HeliLandMs` 设成毫秒数可打开降落：玩家原地站这么久、且周围 `HeliRange` 米内同样这么久没有敌人时，降落在玩家身边约 20 米处；玩家在 25 米内时不起飞，方便走过去顶掉 NPC、自己开；有敌人靠近立刻起飞；
   - **炮艇模式**：玩家坐在直升机副座、由 NPC 驾驶时，它不再跟随玩家（玩家就在机上），改为以直升机自己为中心，打 `HeliRange` 米内的敌人（同样是扫射航线）；附近没有敌人时原地悬停。
   - 只接管本插件派了 NPC 的直升机。任务脚本里的直升机（演出机、运输机）不受影响。
   - 插件为 NPC 调过的速度 / 转向参数只在 NPC 驾驶时生效：玩家顶下 NPC 自己开、或座位空了，立刻换回这架直升机原版的参数（以前会一直留着 NPC 的调校；日志 `HELI ... its own params back`）。
   - **鼠标瞄准飞行**（`src/heliaim.h`，ini `HeliMouseAim`，默认 1，0 = 原版操作；2026-10-05 起取代之前的 `HeliMousePitch` 鼠标俯仰杆，旧 ini 里的这一项不再读取、日志会说明）：键鼠开原版直升机（风神 506、Nereid 409、布鲁特 410、602 等）以及插件的旋翼机（空中航母、自爆 / 人偶无人机）时，按战争雷霆「教官」/ 战地的方式飞：
     - **鼠标**移动一个以地面为参照的瞄准点（和战斗机的鼠标瞄准点同一套：左右 = 方位，上下 = 高低角，最多 ±75°，速度跟 `PlayerJetMouseSpeed`，方向跟 `PlayerJetInvertPitch`；屏幕上画同样的青色方框，瞄准点不会跑出屏幕：推到屏幕边时只挡住出界的那个方向，另一个方向照常动），机头自己转向瞄准点的方位：按与瞄准点的夹角要一个转向速度（每度约 2°/s，最多到这架的最大转向速度），推着鼠标不停时机头以接近最大转向速度追着转；键鼠鼠标瞄准飞行时，最大转向速度至少提到 `HeliYawRate`（默认 50°/s，与 NPC 飞行员同一项；原版风神只有 23.5°/s），下机或改用手柄后恢复原值（2026-10-06 用户：「鼠标动了基本上没变化，没跟随鼠标走」——日志里玩家的风神只转 5–17°/s：屏幕把瞄准点限制在机头前约 30° 内，旧的转向律又按转向速度本身阻尼，一半指令被抵消。离线检查 `heli_aim_check` 的「mouse swept right 4 s」：现在 48.5°/s，旧律 19.2°/s）；
     - **瞄准点的高低角就是飞的方向**：往上 = 爬升，往下 = 下降，前进越快爬升 / 下降越快（航迹沿着瞄准线）；悬停时抬高瞄准点只是缓慢上升（约 2 m/s × sin 高低角）；瞄准点在水平 ±3° 内 = 保持高度；
     - **W / S** 调前进速度的设定值：按住 W 约 3 秒从 0 加到满速，松开后**保持在那个速度**（不回弹）；S 减速，一次按住最多减到 0（悬停）就停住，松开再按 S 才开始倒飞（最多满速的 30%）；
     - **A / D** 按住时左右平移（满速的 60%），松开停止平移；**空格**上升、**Ctrl**（减速键 `PlayerJetBrakeKey`）下降，按住时以最大爬升率升降，松开后保持当时的高度；直升机 HUD 最下方一行写着这些键（在地面上是「按住空格起飞」）；
     - **全部松开**：保持高度、机身回平，按设定的速度飞；设定为 0 时停住悬停（原版直升机配合下面的悬停辅助约 1 秒停稳）；
     - 原版直升机：插件在原版输入之后（同一帧物理之前）把设定换算成原版直升机自己的操纵量——前进量（同时决定机头下压角度和前进速度）、横移量、偏航量和油门（旋翼转速），用的就是 NPC 飞行员那一套控制律（`heli.cpp` 的 `Steer` 与玩家共用 `heliaim.h` 里的 `StockStick` / `StockThrottle` / `StockYaw`）；在地面上不碰水平操纵和油门（按空格起飞，同原版），离地 1.5 秒内不给水平操纵、这期间按着 W 也不累计速度设定（不会离地就往前冲，也不会 1.5 秒一到猛地一窜）。「在地面上」和 NPC 飞行员的判法相同：机体接触标志加上机身下 4 米内有地形或建筑（停在楼顶算着地）；压在敌人、载具或别的直升机上不算，所以低飞擦过它们不会清零速度设定、交回原版油门。偏航按这架直升机自己最大偏航角速度（`veh+0x1634`）的正负给（原版都是正的）；原版直升机旋翼转速变化很慢（加速约每帧缺口的 0.1%、减速 0.07%），所以松开空格后的停升、按 Ctrl 后开始下降都要几秒，这是原版直升机自己的特性；
     - 插件的旋翼机：同样的设定交给它自己的旋翼飞行（`jet_flight.cpp` 的 Hover），最高速度和爬升率按机种；
     - 只对键鼠生效，手柄仍是原版 / 原来的摇杆操作。离线检查：`cmake --build build --target heli_aim_check` 再运行 `build\heli_aim_check.exe`，按文档里原版直升机的飞行规律模拟一遍，确认「鼠标上 = 爬升、W = 前进、鼠标右 = 右转（最大偏航角速度为负的机体也一样）、D = 右移、空格 = 上升、Ctrl = 下降、S 停在 0、起飞时按着 W 不攒速度」这些方向；
   - **直升机 HUD**（`src/hud.cpp` `HeliHud`，ini `HeliFlightHud`，默认 1；0 = 原版直升机仍用旧的起飞面板、旋翼机仍用战斗机座舱）：玩家驾驶原版直升机或插件的旋翼机时显示，绿色、用游戏自己的 HUD 绘制：
     - 飞行仪表：地平线和俯仰梯、顶部航向带、左边速度框（km/h，下面是 W / S 设定的速度，SET HOVER = 悬停）、右边高度框（离地米数，下面是爬升率 VS）；前进时显示速度矢量，**悬停时改为漂移指示**：屏幕中下方一个圆圈，箭头指向机身正在漂移的方向（上 = 沿机头，右 = 向右），圆圈边 = 5 m/s，更快时箭头变琥珀色；
     - 悬停辅助：慢于 8 m/s 或离地 30 米以下时显示漂移指示；离地 30 米以下高度框右边出现一条 0–30 米的离地高度条（每 5 米一格，三角标当前高度，10 米以下下降快于 4 m/s 时变琥珀色）；
     - 武器瞄准：原版直升机用上面的机炮瞄准具（`PlayerHeliGunSight`）；插件旋翼机用战斗机的瞄准具、锁定框和投弹点；左下方是战斗机同款的雷达告警圆盘（`PlayerJetThreatHud`，见下文「座舱告警」）；鼠标瞄准飞行时画青色瞄准点方框，旁边标 **FLY**（这是飞行方向，不是武器落点；只看 `HeliMouseAim`：`HeliFlightHud=0` 时也画）；
     - 原来屏幕下方的面板去掉，只留两行：速度设定和 ALT HOLD（正在保持高度）一行，旋翼机的挂载在它下面画成一排**挂载图标**（见下文「挂载」）；在地面上它上方是起飞提示（旋翼转速占离地所需的百分比，够了闪 LIFT OK；离地所需转速按这架的升力算，风神 / Nereid / 布鲁特约 0.42、602 约 0.21——以前把升力读错了单位，风神不显示、602 一直是 1%，602 的鼠标飞行还会以满油门一路爬升）；告警（导弹、锁定、近地、离地 10 米内下降快于 4 m/s 的 SINK RATE）改由下文的「座舱告警」显示和发声；
   - **玩家开原版直升机的悬停辅助**（ini `PlayerHeliStopSec`，默认 1 秒，0 = 原版手感）：原版直升机松开摇杆后要约 13 秒水平速度才衰减下来，会一直往前滑、停不住；
     玩家自己坐在驾驶座时，插件把这架直升机的速度参数改成约 1 秒停稳（推杆加速也同样变快），最高速度不变（风神约 23 m/s 仍是 23 m/s）。
     从满速松杆，1 秒后剩约 8 m/s（原版 21 m/s），约 3 秒内基本悬停（原版约 40 秒）。用的是游戏自己的速度参数，不直接改机体速度；下机后恢复原版参数。日志 `HELI ... player assist`。
   - **玩家开原版直升机的机炮瞄准具**（`src/helisight.cpp`，ini `PlayerHeliGunSight`，默认 1，0 = 原版红线）：玩家自己驾驶或坐炮位的原版直升机（风神 506、Nereid 409、布鲁特 410 的门炮、602 等），
     原版那条从炮口伸出的红色瞄准线换成和玩家战机同款的绿色瞄准具：炮口指向的小十字（门炮跟着炮塔转），加一个弹着圈——按这门炮自己的弹速、下坠（重力系数 × 世界重力）、
     寿命和继承载机速度的比例（原版直升机炮都是 0），逐帧模拟现在打出的一发，画在它第一次碰到地面 / 建筑的地方，右边标距离（米）；寿命内打不到地面时（例如平飞向远处），
     弹着圈画在炮弹寿命结束的位置并变暗，这时的距离就是这门炮的射程（风神的机炮只有约 160 m，布鲁特门炮约 720 m）。原版没有红线的炮（409 的炮塔机炮）也画（取座位里最快的那门炮，弹着圈跟着炮塔转）；
     原版机炮不锁定目标，所以没有提前量。
     原版直升机没有「当前选中的武器」：主射击键打机炮，副射击键打导弹 / 火箭（`docs/heli-input-re.md` §2b），所以瞄准具同时画两样，形状各不相同：
     **导弹**（风神 506、602 的追踪导弹）——锁定中是收缩的黄色方框、锁定后是红色菱形（读武器自己的锁定列表，和玩家战机挂载的锁定框同一套），下方标 `MSL 距离`；没锁定时在导弹指向处画一个暗色圆环，下方标 `MSL 锁定距离`（500 m）；

14. **炮塔镜头 / 观察键 / 高视角**（`src/turretcam.cpp`、`src/highcam.cpp`，ini `DecoupledTurretCam` / `TurretCamRate` / `FreeLookKey` / `FreeLookButton` / `HighCam*`，逆向与设计 `docs/camera-re.md`）：

   - **炮管稳定器**（`src/stab.cpp`、`src/stab.h`，ini `GunStabilizer`，默认 1；设计与各车理由 `docs/camera-re.md` §7；2026-10-06 用户：「应该有稳定器的载具应该加一个炮管稳定器」）：车身颠簸、俯仰、侧倾、转弯时，炮管守住它在**世界里**瞄着的方向，像现代坦克的双向（高低 + 方向）稳定器。玩家、NPC、EDF6AutoTurret 给的转向照常转炮，稳定器只额外抵消车身的转动：

15. **载具撞击伤害**（`src/vehicleram.cpp`、`src/vehicleram.h`，ini `VehicleRam` / `VehicleRamDamage`，逆向与设计 `docs/vehicle-ram-re.md`；2026-10-06 用户：「载具增加碰撞伤害，和飞机一样，要看质量和速度的关系。这里的速度指的是子部件，比如脚踩」）：有人驾驶（玩家或 NPC）的地面载具用车体或部件撞到敌人时，敌人受到和飞机撞击同一公式的伤害：
   - **伤害** = ½ · 部件带的质量 · 部件撞上去的速度² ÷ 287 kJ × 本车强度倍率（最大耐久 ÷ 车体文件的耐久，随难度 / 呼叫等级放大）× `VehicleRamDamage`（默认 20，0 关闭；1 = 和飞机完全同一标准）。
   - **速度是撞上去的那个部件自己的速度**（按部件每帧的实际位移算），只算朝着敌人的那一部分：坦克、Grape / 卡车、摩托、Maser、深渊爬行者是车头（倒车时是车尾）；Begaruta / Nix / Proteus 等机甲是两只脚——脚往下踩到敌人身上按踩下去的速度算，从旁边擦过不算，冲刺时脚往前撞也算；巴尔加是两只脚和两只拳头。
   - **质量**：坦克、车、摩托用游戏自己算好的车体总质量（例：Blacker 17 吨、E551 24.6 吨、Titan 227.5 吨、摩托 0.2 吨、轻卡 2.4 吨），读不到时用这类车原版文件的质量；机甲文件里没有质量，按体型估：Begaruta / Nix 30 吨、Proteus 150 吨、巴尔加 2000 吨、深渊爬行者 10 吨。车头 / 车尾带整车质量，一只脚带一半（腿加上压下来的半个车身），巴尔加的一只拳头带十分之一。
   - **爆炸范围 = 撞上去的部件的大小**（车头取车宽的一半、脚取脚掌、拳头取拳头），用安装器生成的撞击装药里最接近的一个（2 / 4 / 8 / 12 / 16 / 32 / 64 米）；伤害只按上面的公式算，不随范围变。
   - 同一辆车对同一个敌人 1 秒内只算一次；接近速度不到 2 m/s（推着走）或伤害不到 1 点不算。不伤友军（装药的阵营是本车的），本车自己撞东西掉的耐久照原版。空车（没人开）滑过去不算。
   - **按真实动能，数值偏小**（倍率 1、最低难度）：Blacker 20 km/h 撞巨蚁约 0.9 点（不到 1 点不算）、60 km/h 约 8 点；Titan 30 km/h 约 28 点；摩托 100 km/h 约 0.3 点；Nix 一脚（每秒 4 米踩下）约 0.4 点、冲刺时脚每秒 20 米撞上约 10 点；Proteus 一脚约 3 点；巴尔加一脚（每秒 6～12 米）约 60～250 点、一拳（每秒 15 米）约 80 点；对比：战斗机空挂 100 m/s 约 280 点。所以默认倍率是 20（上面的数都乘 20：Blacker 60 km/h 约 160 点、Nix 冲刺一脚约 200 点、巴尔加一脚 1200～5000 点）。`tools/vehicle_ram_check.cpp` 离线算出这些数并核对部件和接触判定。

     - **选择（框选）**：**Ctrl + 左键拖动**拉出一个矩形框（拖动时画出半透明青框），松开后选中框内所有可指挥的单位；**Ctrl + Shift + 拖动**是加选。**左键单击**（按下到松开几乎没动）单位 = 只选它；**Shift + 单击**单位 = 加选，再点一次已选中的 = 取消它；**单击空地** = 取消全部选择（Shift + 单击空地不变）。点和框都按单位图标在屏幕上的位置（地面单位在图钉顶上，飞机就在它本身）判。**Tab / Shift+Tab** 仍可一个一个轮流选（最后一项 **ALL** = 全部），选中单个时地图移到它身上。
       - **为什么框选要按 Ctrl**：地图原来的鼠标用法是左键拖动平移（抓着地面拖）、右键拖动转向 / 俯仰、滚轮缩放，左右键拖动都被占了。按用户要求不能抢掉它们，所以框选用 Ctrl 修饰（Ctrl 在地图打开期间没有别的用途，游戏和插件的按键此时都被保持住）；不带 Ctrl 的左键拖动照旧平移，只有「按下到松开几乎没动」的左键才算单击，所以平移不会误选。
     - **下令**（作用于当前选中的所有单位）：**G** 前往**指针处**驻守（飞过去 / 开过去，在那里巡逻、攻击附近的敌人）；**V** 回到你身边跟随；**X** 解除命令，恢复原来的任务（呼叫来的回到原来的守点或跟随，派 NPC 的直升机 / 爬行者回到跟随你）。**多个单位驻守同一点时按队形散开**：第一个站在目标点上，其余按 30 米间距一圈一圈排开（第一圈 6 个、第二圈 12 个……），每个位置各自落到地面上，不会挤在一个点；**直升机例外**：开着守点盘旋（`HeliGuardRadius` > 0）时它们共用目标点上的同一个盘旋圈，原版逻辑已经把同一守点的几架在圈上均匀错开，再给它们不同圆心反而让圈互相交叠（`HeliGuardRadius=0` 悬停时照样按队形散开）。
     - **手柄**（没有指针）：**X** 一个一个轮流选（最后一项 ALL），**Y** 驻守屏幕正中准星处，**RB** 跟随，**LB** 解除。
     - **地图上显示**：拖动中的选择框；每个可指挥的单位外面套一个青色圈，**选中的套白色角框**（只选中一个时上方写名字：`HELI 506`、`JET fighter`、`CRAWLER`……）；驻守命令画一条从单位到它的队形位置的青线、那里一个青色小圈；跟随命令在单位下方标 `FOLLOW`。按键说明上方多一条带：**选中数量**（`SELECTED 3 / 7`、`SELECTED ALL 7`、`SELECTED 1 / 7: HELI 506`）和按键；下令后底部上方显示结果约 3 秒（如 `GUARD (60, 420): 2 UNITS`），没选中单位时提示 `SELECT UNITS FIRST`。
     - **怎么实现**：不另写 AI，命令只改各单位「围着哪里干活」的那一个点，飞行、选目标、开火全部照旧——直升机：和空袭兵的「守点」呼叫一样把守点换成目标点（绕点盘旋 `HeliGuardRadius`、打附近的敌人），解除时把原来的守点 / 跟随放回去；战机 / 航母：巡逻和找目标的锚点换成目标点（跟随 = 锚点换成你）；深渊爬行者：原来跟随的「领队点」换成目标点（停在 `GroundFollow` 米外，`GroundLeash` 米内交战）。指针下的地面点用 HUD 上一帧画地图用的视图投影矩阵反算出指针处的射线，再打地图射线求交（打不到时取与焦点所在水平面的交点）。
     - **洞穴 / 室内地图**（`src/map_floor.h`，2026-10-06 用户：「3d地图要对洞穴图适配一下」）：洞顶的三角面只画朝洞内的一面，从地图上方看过去看到的是洞底，但碰撞是两面都挡，之前指针射线停在洞顶背面、驻守点落在洞顶上，队形位置和地图焦点也用「从天上往下第一个命中」，同样落到洞顶。现在射线会穿过**背对它的命中面**（洞顶从上面看到的背面）继续找第一个地板；队形位置、焦点、单位下方的地面取「这个位置上所有地板里离它自己高度最近的那层」，多层洞穴里各层各算各的；队形位置还要求地板上方有 2.5 米空间（落在楼的投影里时放在楼顶，不放进楼体里面的地面）。命中法线是三角面自己的法线还是「朝向射线」的法线，在地图打开时用玩家脚下的地板从上、从下各打一次判定（日志 `MAP ray normals: ...`；判成「三角面自己的」就定下来，判成「朝向射线」每秒再判一次，薄板底面也会读成这样）；判不出或是「朝向射线」时，指针仍取第一个命中（旧行为），地面高度仍按离自身高度最近的那层取。
     - **联机：只在单机（含本地分屏）可用**。插件的 NPC AI 在每台机器上各算各的（呼叫来的飞机没有网络身份，`docs/online-re.md` §1–3），命令也不同步，在联机里下令只会改本机那份副本，所以联机时按键无效，底部写 `NPC COMMANDS: OFFLINE ONLY`。
     - **离线检查**：`cmake --build build --target map_cmd_check` 再运行 `build\map_cmd_check.exe`（准星射线在各高度 / 俯角下落在焦点、投影到屏幕的地面点能被指针射线找回、框选 / Shift 加选 / 单击单选 / Shift 单击切换 / 单击空地取消、Tab 循环与 ALL、单位消失后从选择里去掉、每个按键对应的命令或拒绝原因、队形每两个位置至少相隔 30 米、洞穴里指针穿过洞顶落到洞底、多层洞穴取各自那层的地板、法线朝向的判定；CTest 也跑它）；`build\hud_view.exe` 的 `map_mid` / `map_low` 里画着拖动中的选择框、两台选中并按队形驻守的爬行者、驻守同一点的直升机和跟随的战机（`map_high_pad` 是手柄版：准星、无指针）。**待游戏内确认**（`Debug=1` 日志 `MAPCMD` / `HELI ... map command` / `JET ... map command` / `GROUND ... map command`）：指针随鼠标移动的方向和速度（用的是平移拖动同一份鼠标位移）；Ctrl、Shift、Tab、G、V、X 在原版游戏里没有别的用途（地图打开时人物输入本来就被保持）；单位确实飞到 / 开到目标点。
   - 离线检查：`cmake --build build --target map_cam_check` 再运行 `build\map_cam_check.exe`（镜头位置、拖动时地面跟着鼠标走、缩放上下限、网格覆盖整个画面）；`build\hud_view.exe` + `python tools\hud_view.py` 画出三张地图叠加层（含图钉和几百个小型敌人的点）的布局图（`map_mid` / `map_high_pad` / `map_low`）；`map_cam_check` 也核对图钉的杆在 200 米到 3 公里高时屏幕上一样长。
   - **待游戏内确认**（`Debug=1` 时日志 `MAP` 行）：镜头确实换成地图机位（`MAP open`；若画面没变，说明你此刻用的不是玩家镜头 `CharacterGhostCamera`）；鼠标拖动的方向（日志 `MAP mouse delta`；反了就是游戏鼠标位移的正负与推断相反）；任务目标点是否就是游戏里的 `DestinationMarker`（`MAP marker ...`）；手柄 Back 键在游戏里是否另有用途（有就改 `MapButton`）；驾驶摩托 / 汽车时个别车型自己直接读手柄的按键（例如鸣笛）不在保持范围内。

9. **星导者生物（敌人）**（`src/primer.cpp`，设计与依据见 `docs/primer-plan.md`，ini `Primer` / `PrimerHpScale` / `PrimerFire` / `CentipedeLinkMax` / `CentipedeLinkRange`）：两种新的**敌方**生物，都是插件驾驶的 506 机体（同战斗机），只是队伍设为敌方、外形是插件自己生成的模型（安装器生成，用原版星导者模型的材质与贴图）：

## 安装 / 卸载

**玩家：解压即用，不需要 Python。** 前提是游戏目录已装好 EDFModLoader。

1. 退出游戏，解压发布包 `EDF6VehicleCrew-<版本>.zip`，双击 `EDF6VehicleCrew安装器.exe`，输入 1。
   它自动在 Steam 库里找游戏目录（也可以把 exe 放进游戏目录再运行；都找不到会让你粘贴路径），然后：
   先用你本机的 `Root.cpk`（只读，不修改）在内存里生成战机 / 直升机 / 无人机 / 潜水母舰和呼叫武器，并检查武器表；
   全部成功才开始写：生成的模型（每个文件原子替换）→ 武器表和武器说明（整体写入，见上）→ `EDF6AutoTurret` 的武器 / 载具数据
   （`autoturret/tools/build.py`：防空车、玻尔斯、关卡防空车、NPC 泰坦副炮和它们的说明行，记在 `Mods/.edf6at_data.json`，替换别的 MOD 的文件前先问、同意后备份）
   → 最后才换两个插件的 DLL（`EDF6VehicleCrew.dll`、`EDF6AutoTurret.dll`）。
   已有的 `EDF6VehicleCrew.ini` / `EDF6AutoTurret.ini` 不覆盖：你的设置和注释原样保留，只在原有 `[VehicleCrew]` / `[AutoTurret]` 节末尾补进新版本新增的设置（带默认值和说明）。节名不区分大小写，与游戏内插件一致；例如 `[vehiclecrew]` 也会保留并补齐，`StockHeliStores` 同样按此读取。
   这些资源不能预先打包：它们由游戏本体文件派生，武器表又是各 MOD 共用的，只能在你机器上现场生成。
   生成的文件由 `Mods/.edf6vc_files.json` 登记归属（安装器、测试场等谁在用），卸载只删没人再用的文件。
2. 卸载：运行安装器输入 2。选 1 连呼叫武器、生成的模型和 `EDF6AutoTurret` 的数据一起删（武器行变成「已卸载」占位行，存档装备着也不会崩溃；
   `EDF6AutoTurret` 替换过的文件和说明行按清单恢复）；选 2 只删两个插件，武器照原版 KM6 轰炸机呼叫、防空车的炮照原版开火，不影响游玩。
   两种都会删掉两个插件的 DLL、ini 和日志（含轮换出的 `.log.1`）。
3. 游戏运行中安装、卸载会拒绝执行（游戏占着插件 DLL），不会替你关游戏。输入 5 检查安装状态：两个插件是不是本安装包的版本、ini 缺不缺新设置、
   `EDF6AutoTurret` 数据、呼叫武器和生成的文件是否完整；它只读，游戏开着也能查。
4. 原版直升机的挂载（`StockHeliStores`，见功能 13）是选装的：在 ini 里改成 1 后运行安装器选「安装」才生成，改回 0 再运行就删掉。
5. 升级：退出游戏后直接运行新版安装器选「安装」即可，旧版装的武器行原位更新、新行追加在表尾；新版本新增的模型（例如炮舰机 `EDF6VC_JET_GUNSHIP.SGO` 及其炮手座、撞击装药 `EDF6VC_IMPACT_*.SGO`（2 / 4 / 12 米三个是载具撞击伤害一起加的）、炮舰机的机炮炮弹 `EDF6VC_GUNSHIP_CANNON.SGO`、EMC 蓄力光束的 `EDF6VC_EMC_*.SGO`）要这样重新安装后才有。

更新会按资源组校验并复用已有模型和地图，不再每次全量生成和重写。首次使用支持增量更新的安装器仍需生成一次；
之后只有生成器及其依赖、游戏原始资源包、外部模型发生变化，或已装资源缺失 / 内容被修改时，才重建对应组。
单独更新 DLL 不会让资源缓存失效。武器表、可选的原版直升机挂载和测试场关卡仍走原有检查 / 安装流程，以保留与其它 MOD 的兼容处理。
每组显示「生成」或「复用」及耗时，大地图另显示碰撞、远景、解压和地形处理阶段。地图来源是只读的 `Chunk02.cpk`。
缓存清单是 `Mods/.edf6vc_builds.json`，只记录生成依据与输出摘要，不额外复制模型或地图；删除清单可强制下次重建。
资源成功写入后即保存缓存；后续关卡安装失败时，重试仍能复用已完成的资源。资源生成或写入失败则不记录为成功。
生成依据使用构建时打包的 Python 源码依赖指纹、CPK 路径 / 大小 / 修改与创建时间，以及外部模型、材质和贴图的内容摘要；
输出每次按 SHA-256 与归属清单校验。CPK 不做全盘哈希，手工修改资源包并刻意保留全部时间戳后需删除缓存清单。

**开发者**：`build.cmd` 构建到 `build/Mods/Plugins/`（DLL 和 ini 都在那里，ini 由 CMake 自动复制）。
`python tools/build_release.py` 用 PyInstaller 打出 `release/EDF6VehicleCrew-<版本>.zip`（安装器 exe 内含 `tools/installer.py` `PLUGINS` 列出的每个插件的 DLL 与 ini，
即 `EDF6VehicleCrew` 和 `EDF6AutoTurret`；`tools/selftest.py` 的 `pack_ships_every_plugin` 检查 CMake 构建的每个插件都在这个清单里）；
版本号只有一处：`CMakeLists.txt` 的 `project(VERSION)`（DLL 自报的版本也来自它）。CI 每次推送都打同样的安装器包，
推 `vX.Y.Z` 标签时要求它与 `project(VERSION)` 一致。不打包时也可直接 `python tools/installer.py install`（从 `build/` 取 DLL，没构建会提示先运行 `build.cmd`）。
`python tools/selftest.py` 是安装链的自测（CI 里跑）；改了 `tools/calls.py` 后运行 `python tools/gen_calls.py` 重新生成 `src/calls.inc` 并一起提交。

- 与 `EDF6AutoTurret` 共存：两边都 hook 了坦克的第 55 槽，本插件会串在它后面，也就是先执行它、再执行本插件，所以加载顺序无所谓。
- 炮塔的锁定框和预瞄圈（ini `TurretAimHud=1`）：坐在 EDF6AutoTurret 瞄准的炮位上（克卜勒、玻尔斯、自行榴弹炮的炮塔，泰坦和游骑兵坦克的炮手座 / 驾驶座）时，本插件画出它的锁定（黄色收缩方框、红色菱形，和战斗机一样）、预瞄圈模式下的绿色预瞄圈和炮口指向的白色十字、距离和飞行时间，屏幕下方两行写**自动瞄准是开还是关**和按键：绿色 `AUTO-AIM ON` = 自瞄开着（炮塔自己瞄），橙色 `AUTO-AIM OFF (LEAD CIRCLE)` = 自瞄关了、改用预瞄圈（炮塔归你）；下一行是切换键（键鼠默认 **Z**，ini `AimModeKey`；手柄默认不绑定，要在 `EDF6AutoTurret.ini` 设 `AimModeButton`，没设时这一行会提示）和锁定键（Q / 手柄 X）。按切换键的那一刻，屏幕中上方会出现约 1.5 秒的大字横幅 `AUTO-AIM ON` 或 `AUTO-AIM OFF - LEAD CIRCLE`。只有坐在 EDF6AutoTurret 管的炮位上才有这两行（其它载具没有自动瞄准可切换）（用法见 [autoturret/README.zh-CN.md](autoturret/README.zh-CN.md)「玩家的炮塔」）。反过来，本插件把镜头视线和地图射线提供给它，它的「锁定离屏幕中心最近、看得见的敌人」靠这两样。两个插件互相按导出函数名查找（`common/edf/aimlink.h`），缺哪个都不影响另一个。

## 原版问题修正：分裂导弹撞上大目标前不分裂

血腥风暴（Blood Storm 及 M2 / M3 / M4 / MV）这类分裂导弹（弹类 `MissileBullet02`），原版按「到锁定点的距离 < 70 米（初代 50 米）、
且偏离机头 < 0.75 弧度」决定分裂。锁定点是目标唯一的中心骨骼，所以遇到 DLC 的卵这种半径超过这个距离的目标，导弹在分裂前就撞上表面爆炸了，
子导弹一发都没放出来。开启 ini `SplitMissileSurface=1`（默认）后，插件沿视线朝锁定点打一条只看得见这个目标的射线，
把「距离」换成到目标表面的距离交给原版判定（角度判定、按时间分裂的地狱风暴都不变）。普通大小的目标提前约一个目标半径分裂（几米，一两帧）。
联机时分裂由每台机器各自计算，所有玩家设成一样最好。逆向依据见 `docs/split-missile-re.md`（只做了静态分析和离线模拟，未进游戏实测）。

## 原版追踪弹：比例导引、准星锁定、Tempest 电视制导

2026-10-06 用户：「把所有的引导改成咱们做的比例导引」「NPC 的武器的导引也要换」「原版的锁定改成和飞机一样的锁定」「暴风雨飞弹支持电视制导」。
逆向依据 `docs/guidance-re.md`、`docs/lockon-re.md`、`docs/tvguide-re.md`（静态分析 + 离线模拟 `tests/pn_test.cpp`，**未进游戏实测**）。

- **比例导引**（`src/guidance.cpp`，ini `StockMissilePN=1`，导引常数 `StockMissileNav=3`）：所有原版追踪弹（`MissileBullet01` 各种导弹、
  空袭兵呼叫的巡航导弹，`MissileBullet02` 血腥风暴，`HomingLaserBullet01` 翼装兵的追踪激光），**不论谁发射**（玩家、NPC 队友、敌人），都从原版的纯追踪改成比例导引：
  算提前量飞向拦截点，不再在目标身边绕圈。强度照原版：每发弹每帧能转多少、推力多大、什么时候开始追（导引延迟）都是它自己武器的数值，只是换了用法；
  插件自家导弹仍用各自型号的过载和导引常数。锁定目标的速度由锁定点逐帧差分得出；被诱饵弹骗走、来袭导弹告警与插件导弹同一套。
  离线对比（同样的转弯能力）：横穿目标 PN 202 帧命中、纯追踪 233 帧；近距离擦过的目标 PN 130 帧命中、纯追踪绕到 1400 帧。

  先锁**离屏幕中心最近**的目标（和战斗机一样），多重锁定武器先锁不同目标、再重复锁同一个；锁定时间、锁定距离和锥角、保持时间、最多锁几个都照原版武器自己的数值（插件载具照插件的数值）。
  NPC 的武器锁定顺序不变（它们没有准星）。原版 HUD 照常画原版武器的锁定框。步兵还没有「切换锁定目标」键（战斗机的 Q / X 照旧）。
- **Tempest 电视制导**（`src/tvguide.cpp`，ini `TempestTv=1`，鼠标灵敏度 `TempestTvMouseSpeed=1.0`，加速倍数 `TempestTvBoost=3`）：**单机**空袭兵的 Tempest A1 / A2 / A3 / AT / ATS 巡航导弹出弹后，

- **联机**：每台机器各自计算每发导弹的飞行。房间里所有人要装同一版本、同一设置，否则各人看到的轨迹和命中会不同；**电视制导在联机时不接管**，各端继续使用原版 / PN 激光制导；尚未实现同步的鼠标转向和加速不会只作用于本机副本。

## 已知问题（原版自带，与本 MOD 无关）

不装本 MOD 的原版游戏也会出现下面两种现象，报告问题前请先对照：

- **电脑配置不够导致卡顿**：原版本身就会出现。敌人和载具多的关卡掉帧更明显，降低画质或分辨率能缓解。
- **文字显示成别的字（乱码）**：例如兵种名「剑兵」显示成「水兵」，存档界面的「Epic Games」少了几个字母、
  其余文字也变成不相干的字。这是字的显示被换成了别的字，文本本身没坏。本 MOD 只改写它所加载具的武器说明行，
  不改兵种名、菜单、存档界面，也不改字体。

### 自动实测（run_test.py）

一条命令：启动游戏 → 认画面走菜单（标题、存档、模式这些绿色菜单一路回车；作战指令总部 → 出击 → 任务列表按到顶再往下数到测试场那一项，
核对任务说明文字的参考图后才确认）→ 选上次的难度 → 进关后按脚本操作、截图 → 退出游戏 → 汇总插件日志。

```
python testrange/run_test.py --heli --act "wait:3 key:z:300 wait:60 shot:t60"
```

- `--heli`：空袭兵、载具格 N9 风神直升机、开局补满、不放脚本载具（`--enemies` 再加敌人波次）。`--plan 文件` 用启动器存的方案。

## 喀秋莎火箭炮车

空降兵可以请求一辆喀秋莎（武器 `EDF6VC_CALL_KATYUSHA`，请求方式和档位都参照 Naegling，由运输机空投）。
- **外形**：照现实中的 BM-13 喀秋莎做：三轴军用卡车（原版 V607 的卡车，去掉机器人；Root.cpk 里其它卡车——皮卡 V610/V611、轻卡 V512、牵引车头 V513——要么太短、要么两轴、要么是民用车头没有车斗，都不如它像），车斗后部的转台上架着一组 **8 根工字形导轨**（每根 4.65 米、间距 0.30 米），每根导轨上下各挂一枚 M-13 火箭弹（共 **16 枚**，直径 132 毫米、长 1.41 米、尾部四片翼，装在导轨后端），导轨架在横梁和两根纵梁上，后端绕转轴俯仰，发射架抬起时前高后低。导轨、横梁、火箭弹都是安装器用原版 Naegling 发射架的材质和贴图现场生成的（`pylib/katyusha_model.py` `launcher_parts`，`pylib/procmesh.py`），模型从你本机的 Root.cpk 现场拼出（`tools/make_katyusha.py`）。武器的 10 个炮口挪到了导轨的前端、正对火箭弹的轴线（8 根导轨的上排 + 最外侧两根的下排；`katyusha_model.MUZZLES`，写进武器 SGO 的 MAB 定位点），火箭弹从导轨前端飞出；生成时会在模型里重新找出 8 根工字形导轨、16 枚火箭弹，并核对每个炮口都在某根导轨的前端、某枚火箭弹的轴线上（`katyusha_model.check_launcher`），以及发射架从 0° 抬到 80° 始终高出车斗底板（`launcher_clearance`）。
- **液压杆**：发射架下面的液压杆做成了伸缩式：缸筒装在转台上，活塞杆的末端连在发射架上，发射架从 0° 抬到 80° 时活塞杆从缸筒里伸出约 0.28 米，两头始终连着。原版 Naegling 的液压杆是一整根、跟着发射架的仰角一起转，只配得上它的 50°：抬过约 52° 杆头就从发射架里露出来，80° 时离开发射架 1.3 米（这就是之前看到的「液压杆不够长、和顶部分开」）。模型把活塞杆拆到一根自己的骨骼上（`edf6vc_ram_rod`），由 EDF6VehicleCrew 每帧把缸筒和活塞杆对准彼此的转轴（`src/katyusha.cpp`）；生成模型时按 0°～80° 每 5° 检查一遍：活塞杆始终插在缸筒里、杆头始终在发射架里（`katyusha_model.check_ram`）。
- **操作**：和 Naegling 相同。车辆类沿用 Naegling 的，所以是坦克式转向，左右轮差速，可以原地转弯，前轮不打方向。
- **武器**：无制导火箭弹（外形是原版歌利亚 / 格兰特火箭筒的细长尾翼火箭弹 `bullet_rocket.rab`，按 M-13 的 1.41 米长缩放（`AmmoSize` 1.34，碰撞球仍是原来的 1.5），拖着 2 秒长的尾烟），走抛物线，一轮齐射 40 发、散布覆盖一片区域，装填 10 秒。火箭弹出膛 120 m/s（`AmmoSpeed` 2.0 米/帧；档位只放大伤害和耐久，不改弹速），寿命 25 秒，散布锥半角 0.02 弧度（45° 时落点散开约 ±28 米，80° 时约 ±38 米）。
- **高抛弹道**：发射架最高能抬到 80°（Naegling 原版只到 50°）。在平地上（游戏实测重力 14.7 m/s²，`pylib/ballistics.py`）：最远射程 978 米（仰角 45°，飞行 11.5 秒）；高抛弹道（仰角 45°～80°）覆盖 335 米到 978 米，80° 时飞行 16.1 秒。比 335 米更近的目标只能放低发射架平射。
- **瞄准**：和其它载具一样，用镜头瞄准：把屏幕中心对准地面上要打的地方，发射架会自己抬到让火箭弹落在那里的仰角（优先高抛弹道；目标近到高抛要超过 80° 时用低伸弹道；超出最远射程时抬到 45° 打最远），镜头不跟着抬，始终看着你瞄的地方（开着战争雷霆式镜头时，转台也是先转镜头、转台再跟过去，见「功能」12）。发射架按原版炮塔的速度（约每秒 1.1 弧度，63°）转过去，落点以黄色十字为准。屏幕中心看着天空、找不到地面时，发射架就停在你镜头的方向（和原版 Naegling 一样，抬镜头就抬发射架）。这由 EDF6VehicleCrew 做（`src/launcher.cpp` 算仰角，`src/katyusha.cpp` 只改发射架骨骼的姿态，不改座位的瞄准轴，所以不会动镜头），不需要 EDF6AutoTurret。
- **镜头**：车辆视角比原版 Naegling 高：镜头在车后上方（原点上方 8.5 米、后方 15 米），往前下方约 12° 看，能看到发射架和前方约 25 米外的地面（原版是 4 米高平视）。由安装器写进 `EDF6VC_KATYUSHA.SGO` 的 `game_object_camera_setting`（`tools/make_katyusha.py` `CAMERA`；两个向量的含义见 `docs/camera-re.md`），由炮塔镜头摆放（「功能」12；逆向确认开车时游戏自己不读这组参数，而是挂在发射架骨骼上的原版镜头点，所以 `DecoupledTurretCam=0` 时仍是原版 Naegling 的视角）。
- **高视角**：开着喀秋莎时按 **C**（手柄按下右摇杆 R3；ini `HighCamKey` / `HighCamButton`）在车辆视角和高视角之间切换：高视角的镜头在车后上方（默认原点上方 45 米、后方 35 米，ini `HighCamHeight` / `HighCamBack`），看着地面上的瞄准点，看得到火箭弹落在哪一片（黄色十字和散布圈）；屏幕中心对准的地面就是目标，发射架照样自动抬到对应仰角。高视角里鼠标左右转方向、上下把瞄准点推远拉近（每帧满输入 3 米 + 距离的 1.2%，10～1500 米），瞄远处时镜头自动升高，视线始终至少 25° 朝下，不会越过地平线；开 / 关高视角时屏幕中心和炮塔都留在原来瞄的那一点上。（关掉战争雷霆式镜头 `DecoupledTurretCam=0` 时，高视角仍按 ini `HighCamPitch` 的俯角跟着瞄准轴摆。）屏幕下方显示 `HIGH CAM [C]`（开着高视角时绿色 `HIGH CAM ON [C]`）。下车、车被打爆、ini 里关掉 `HighCam` 或插件、换任务时自动换回车辆视角；同一个任务里再坐上一辆有高视角的车会沿用你上次的选择。由 EDF6VehicleCrew 做（`src/highcam.cpp` 管开关，`src/turretcam.cpp` 摆镜头）：改的是游戏镜头每帧取的两个目标点，切换时镜头平滑移过去，镜头碰到建筑也照常被推近。（2026-10-05 的版本改的是载具的 `game_object_camera_setting`，开车时游戏根本不读它，所以那时按 C 没有效果；`docs/camera-re.md` §3b。）
- **落点显示**：你坐上喀秋莎时，屏幕上的黄色十字是此刻发射的火箭弹会落在哪里（和战斗机炸弹的 CCIP 一样），周围一圈黄点是一轮齐射的散布范围，十字下面写着水平距离、飞行时间和发射架仰角（`ELEV`）。它从发射架自己的炮口、沿发射轨方向、按武器实际的弹速和重力系数、像游戏一样逐帧推进弹道，并沿弹道每 0.25 秒打一条地图射线找落地点（地形和建筑，水面不算）；火箭弹在寿命内落不了地时不显示。由 EDF6VehicleCrew 画（`src/launcher.cpp`），不装 EDF6AutoTurret 也有。
- **自瞄**：只给 NPC 开的喀秋莎（需要 EDF6AutoTurret，本仓库 `autoturret/`）：它把发射架转向地面目标，走**高抛弹道**（两个解里仰角大于 45° 的那个；目标近到高抛解超过 80° 时才退回低伸解）。你自己开的喀秋莎它不碰：原版的开车镜头挂在发射架的骨骼上（逆向确认，`docs/camera-re.md` §3b），自瞄转瞄准轴就等于替你转镜头（以前把发射架抬到 75°～79° 时镜头一直看天，就是这个原因），所以现在由你用镜头选目标，发射架自己抬到高抛仰角（见上面的「瞄准」）。
- **高视角待游戏内确认**（只做了静态逆向，`docs/camera-re.md` §6）：按 C 后镜头升高（`Debug=1` 时日志 `HIGHCAM v=… on by the key`、`TURRETCAM v=…: camera taken (… high)`），镜头随鼠标转动时高视角的表现，黄色十字仍在屏幕中心瞄的地方附近，下车后视角恢复（日志 `HIGHCAM v=… off (…)`、`TURRETCAM v=…: released (the player got out)`）。
- **已离线核对 / 待游戏内确认**：液压杆在 0°～80° 的姿态、仰角解算（`tools/selftest.py` `lofted_arc_solver`、`katyusha_pose_agrees`）都离线核对过；游戏里还要看：镜头确实只跟瞄准轴、不跟发射架骨骼（`Debug=1` 时日志 `LOFT` 行的 `camera` 应接近 `stock(axis)`，而不是 `bone`），火箭弹沿抬起后的发射架飞出、黄色十字落在屏幕中心瞄的地方附近，液压杆在画面里连着；新的 BM-13 导轨：火箭弹从导轨前端（而不是原来箱子的正面）飞出，尾焰在导轨后端；发射架的碰撞体仍是原版 Naegling 发射箱的（模型外形换了，碰撞没改）。

## 自行榴弹炮

空降兵可以请求一辆自行榴弹炮（武器 `EDF6VC_CALL_ARTILLERY`，请求方式和档位都参照 Kepler）。
- **外形**：双管坦克模型（`models/twin_tank/twin_tank.obj` 和炮塔贴图 `fortressx_02df.dds`：E551 的车体、履带和车灯，上面一座双管炮塔），套在 Kepler 的骨架上，所以两门炮的俯仰和后坐、履带和负重轮都照 Kepler 原版的方式动。**炮塔固定朝前、不能转**（用户 2026-10-06 的要求）：瞄准时炮只上下抬，左右靠转车身；镜头仍可自由转动（看哪里由你，炮口没对准时屏幕上有白色小方框），高视角照旧。安装器读取发布包里的 `models` 文件夹（和 exe 放在一起解压；开发者：环境变量 `EDF6VC_MODELS` 或仓库里的 `models/`），再用你本机的 Root.cpk 现场生成模型（`tools/make_artillery.py`、`pylib/artillery_model.py`，通用的 OBJ 导入在 `pylib/obj_model.py`）：
  - **底盘（车体、履带、车灯）直接用原版 E551**：模型里这几部分本来就是 E551 的三角形，顶点一一重合，所以生成时不再用 OBJ 里的副本重建，而是从你本机 Root.cpk 的 `OBJECT/V505_TANK.MRAB` 取原版网格（每个顶点原样拷贝，只把骨骼编号换成 Kepler 的）、原版材质（着色器、参数不变）和原版贴图（颜色、法线、粗糙度/金属度/遮蔽贴图，档案成员原样拷贝），外观和原版 E551 一样。模型自带的底盘贴图（`npc_tank.png`、`Vehicle504_tankdf02/03.dds`）不再使用，也不放进档案（以前履带用的 `Vehicle504_tankdf02.dds` 几乎全黑，履带因此发黑）；
  - 履带材质用的是 E551 的履带材质（和 Kepler 同一个履带着色器，带 `scroll_texture` 参数），只是改名为 Kepler 的 `v603_kyata_L / _R`：Kepler 的 SGO 按这两个名字滚动履带贴图，滚动参数（`tank_caterpillar_animation_info`）和 E551 自己的一样；生成时检查 SGO 要滚动的每个材质和参数模型里都有；
  - 模型车体原本缺了一个面（OBJ 里少了 E551 车体的 5 个三角形，在车顶右侧两处：炮塔环正前方的一条斜面和炮塔旁车顶右边缘的一条倒角）。现在底盘取的是「三个角都落在模型底盘顶点上的所有 E551 三角形」，这 5 个三角形自然包含在内，不再需要单独补面（生成时核对正好多出这 5 个，模型变了会提示）；
  - 只有炮塔保留模型自带的贴图 `fortressx_02df.dds`（法线用平面法线、参数贴图用一张纯色图）；
  - 炮塔里两根炮管各从粗的炮尾套筒和细的身管交界处切开：套筒随俯仰转动，身管开炮时后坐、缩进套筒；俯仰轴在炮管穿出炮塔前脸的位置（炮塔前脸上有给炮管留的开口，−5°…60° 时炮管不碰炮塔和车体），炮弹从炮口发射；
  - E551 每侧 7 个负重轮，Kepler 只有 6 个：前 6 个按 Kepler 的悬挂和转动，第 7 个（最后一个）固定在车体上，不转；前导轮、主动轮照常转动；
  - 没有 `models/twin_tank` 时安装器提示一句，自行榴弹炮先用 Kepler 原版外形（武器照旧）。
- **武器**：两门炮同时开火，每次曲射两发大口径高爆弹，爆炸半径 25 m；每 5 秒一轮。炮弹和抛出的弹壳都按炮口内径（0.35 m）放大：炮弹约 0.32 m 粗、0.7 m 长（`AmmoSize` 5.0，碰撞球仍是原来的 1.2 m），弹壳约 0.32 m 粗、0.93 m 长（`ShellCase_CustomParameter` 的 `scale` 4.5，原版只有大型炮用过 2.0）。
- **镜头**：车辆视角比原版 Kepler 高：镜头在原点上方 9 米、后方 18 米，往前下方约 12° 看，前方约 26 米外的地面在画面中心（原版是 4 米高平视）。写在 `EDF6VC_ARTILLERY.SGO`（`tools/make_artillery.py` `CAMERA`），由炮塔镜头摆放（「功能」12；`DecoupledTurretCam=0` 时是原版 Kepler 的视角）。
- **高视角**：和喀秋莎一样，按 **C**（手柄 R3）切换高视角（见「喀秋莎火箭炮车」）。插件按武器认间接射击的车：座位 0 的武器带插件的对地 / 高抛标记、且弹药寿命不少于 10 秒的载具都算，所以喀秋莎和自行榴弹炮都有，EDF6AutoTurret 改过的 Bohr 榴弹（寿命不到 2 秒）不算；大车另有（`HighCamClass`，见「功能」12）。
- **自瞄**：需要 EDF6AutoTurret，自动瞄准地面目标并按弹道算好仰角（低伸弹道；喀秋莎走高抛弹道）。
- **修复：模型全黑**。以前生成的档案里贴图都排在模型后面，游戏加载模型时还没读到贴图，所有贴图槽都是空的，整辆车是黑的；现在贴图按原版顺序排在模型前面，生成时自检这一点（静态逆向依据见 `docs/mdb-format.md`；还没有在游戏里看过修复后的效果）。（当时模型自带的履带贴图 `Vehicle504_tankdf02.dds` 本身几乎全黑，平均亮度约 3/255；现在底盘改用原版 E551 贴图，见上。）
- **改动：炮塔固定**（2026-10-06，用户：「双管战车的炮塔应该不能转」）。`EDF6VC_ARTILLERY.SGO` 的炮塔约束（`car_base_constraint_data` 的 `cannon_main`）加上 0°～0° 的限位：这条约束同时是炮塔铰链和驾驶座偏航轴的上下限来源（原版 Kepler 是不限位的整圈），所以玩家的鼠标、炮塔镜头、EDF6AutoTurret 和原版 AI 都转不动它；稳定器本来就不管间接射击的炮。NPC 开的自行榴弹炮因此只能打车头方向附近的目标。炮塔镜头对这种「不能转、但是间接射击」的炮照样接管（`src/turretcam.cpp`），镜头和高视角不变。
- **修复：炮弹和弹壳的出口**（2026-10-06，用户：「炮管装反了」）。Kepler 的炮把炮弹出口写在炮自己的数据里：从炮管骨骼往前 2.894 米（Kepler 的骨骼在身管根部，往前 2.9 米正好是炮口），抛弹壳的位置在骨骼后方 1.451 米（耳轴处）。双管坦克的炮管骨骼在炮口平面上，照搬原版的结果是：炮弹在炮口前方 2.9 米的空中出现，弹壳从炮管中段（炮塔外面）抛出来。现在 `EDF6VC_HOWITZER_L/R.SGO` 按模型改写这两点：炮弹从炮口出，弹壳从耳轴（炮塔前脸）前 5 cm、炮管上方抛出；生成时核对。模型本身的炮管朝向是对的（炮口朝车头 +Z，炮管从炮塔前脸往前伸 4.0 米，粗的套筒在后、炮口在前）。如果你说的「装反」是别的样子（例如炮塔前后长反了），请截图说明。
- **修复：炮塔转不动**（2026-10-06）。Kepler 的炮塔、两门炮和每个轮子在游戏里是物理刚体，用铰链 / 悬挂连在车体上，炮塔画在哪、怎么转都跟着这些刚体走。以前模型把炮塔、炮管和轮子的骨骼挪到了双管坦克的位置，物理部分（`Ragdoll_v603_flak.shkt`）却还是 Kepler 原版的：炮塔的铰链在炮塔中心前方 0.67 m，炮的铰链在耳轴后方 1 m，炮塔因此被卡住。现在安装器同时生成 `EDF6VC_ARTILLERY_RAGDOLL.SHKT`：每个刚体移到对应骨骼的位置，铰链跟着移动（`pylib/ragdoll_fit.py`，生成时核对物理骨架与模型骨架逐项一致；原版各载具本来就一致）。顺带：轮子和履带也画回到 E551 的轮位上；负重轮的物理位置随之前移约 0.3 m、低 2.7 cm，车身离地会差 2～3 cm。逆向和推断见 `docs/artillery-re.md`（「炮塔卡死」的具体机制是推断，待游戏内确认）。
- **已离线核对 / 待游戏内确认**：物理骨架（刚体、铰链、绑定）与模型骨架一致（`ragdoll_fit.problems`）；模型的蒙皮（炮塔外壳只蒙在 `cannon_main`，炮管只蒙在两门炮的骨骼上）、骨骼（逆绑定）、贴图成员（顺序、lod 布局）、底盘材质和贴图成员与原版 E551 逐字节一致（材质除名字外全部相同；档案里没有用不到的成员）、履带滚动用到的材质名和参数、炮管俯仰净空都在生成时自检（`python pylib/artillery_model.py <输出目录>` 还会导出一份 OBJ 和每根骨骼的包围盒）；游戏里还要看：炮塔是否随镜头 / 摇杆转动、两门炮是否正常俯仰，车体和炮塔是否显示出贴图颜色（底盘应和原版 E551 一个样子）、履带是否滚动、车轮 / 履带骨骼挪到 E551 的位置后悬挂和履带滚动是否正常、炮口火焰和炮弹是否从炮口出来、弹壳放大后（`scale` 对 `Weapon_VehicleShoot` 是否生效、它的物理形状是否随之放大）会不会穿地。

## 钻头战车

空降兵可以请求一辆钻头战车（武器 `EDF6VC_CALL_DRILL`，请求方式和档位都参照 Blacker（ブラッカー）E 系列）。逆向笔记见 `docs/drill-re.md`。
- **外形**：《地球防卫军：铁雨》的钻头战车（Tank_C），车头上方装着巨大的钻头。安装器用你提供的模型（`drill_tank/drill_tank.obj` 和
  `Tank_C_BC.png`）加上你本机 Root.cpk 里 Blacker 的骨架现场拼出模型（`tools/make_drill.py`、`pylib/drill_model.py`）。
  - 模型按 0.8 倍缩放：车身约 6.0 米长、3.8 米宽、4.6 米高，和 Blacker 的车身与碰撞体大小相当；钻头约 3.8 米长，伸在车头前方。
  - 履带和底盘那一部分的贴图模型里没有带，用深钢灰色代替；履带不会滚动（原版 Blacker 的履带滚动贴图不适用于这个模型）。
  - 模型找不到时（`EDF6VC_MODELS` 环境变量指定的目录、`D:\APP\edf6-models`、或安装器旁的 `models` 文件夹里都没有
    `drill_tank/drill_tank.obj`），安装器照常完成，只是这把请求先叫来一辆普通的 Blacker，并打印一行说明；放好模型后重新安装即可。
- **操作**：和 Blacker 相同（车辆类沿用 Blacker 的，履带式，原地转向）。**按住射击键钻头加速旋转，松开逐渐停下**：
  从静止到最高转速约 1.8 秒（`DrillSpinUpSec`），从最高转速停下约 2.5 秒（`DrillSpinDownSec`）。屏幕下方显示转速和热量
  （`DRILL xxx RPM  HEAT xx%`，左边转速条：加速/减速时琥珀色，满转速时绿色；右边热量条：黄 → 70% 以上琥珀 → 90% 以上红；钻到东西时显示 DRILLING）。
  - 钻头看上去的转动：钻头外形每 1/16 圈重复一次（螺旋刃），300 转/分在 60 帧下每帧转 30°，比一个重复还多，看上去只是在闪、
    甚至像没转。所以画面上的转动每帧最多转 9°（一个重复的 0.4），按转速比例加快；伤害、HUD 读数仍按真实转速。
  - 钻头挂在 Blacker 原有的骨骼 `catapi_body`（原履带骨架的根，这辆车没有履带物体，它空着）上转动，而不是一根新加的骨骼：
    2026-10-05 19:56 的试玩里新骨骼的矩阵每帧都跟着转，画面上的钻头却一动不动——游戏画出来的姿态只覆盖这辆车动画骨架
    （`v505_tank.cas`）里有名字的骨骼，新骨骼一直按初始姿态画（详见 `docs/drill-re.md` §5.4；未实机验证）。
  - **修复：钻头埋在车体里、不转**（2026-10-06，0.8.0 试玩「钻头的模型依旧有问题」）。Blacker 的物理绑定（SGO 里 `ragdoll`
    的第二项）把 `catapi_body` 绑在车体刚体上（偏移 0.881 米高），游戏每帧按刚体直接写它的世界矩阵。钻头挂到这根骨骼上以后，
    画出来的钻头被拉到车体原点上方 0.88 米：整根钻头落在车体里面（前后 0～3.8 米、离地 −0.1～1.9 米，本来在车头前 4.2～8.0 米、
    离地 2.4～4.3 米），插件写的旋转也被覆盖。现在钻头战车的 SGO 去掉这一条绑定（其余 43 条照旧），这根骨骼按插件写的局部矩阵
    跟着车体走、转动；生成时用物理绑定核对每根骨骼都画在它的初始位置（`docs/drill-re.md` §5.6；未实机验证）。
- **热量 / 过热**：钻头转动时升温，转速越高升得越快，钻到东西时再快一半；停转（或转得慢）时降温。最高转速空转约 12 秒
  （`DrillHeatSec`）从冷到满，钻东西时约 8 秒；停转约 8 秒（`DrillCoolSec`）从满冷到 0。热量到 100% 即**过热**：
  钻头被强制停转、不造成伤害也不破坏建筑，HUD 变红并显示 OVERHEAT；冷却到 30%（`DrillResumeHeat`）后才能再按射击键转动。
- **镜头**：车身 4.6 米高，钻头在车头前方 3.4 米高处。镜头的注视中心放在离地 7.5 米（车身高的 1.6 倍；原版坦克是 1.2～1.5 倍，
  例如 Blacker 2.6 米高、注视中心 4 米），镜头参数 `(0, 7.5, 0) / (0, 12.5, -17)`。第二组数是「镜头位置」（逆向确认，`docs/camera-re.md` §1）：
  镜头离地 12.5 米、车后 17 米，下俯约 16°；由炮塔镜头摆放（「功能」12，开车时游戏自己不读这组参数）。
  两种读法下整辆车、整根钻头（视线越过车头上沿至少 0.5 米）和钻头前方的地面都在画面里。（之前是 `(0, 5.7, 0) / (0, 10.5, -17)`，太低。）
- **钻头是近战武器**：不发射任何炮弹。原来的坦克炮换成了不开火的「钻头」，射击键由插件接管，所以玩家驾驶时坦克炮绝不会开火。
- **伤害**：钻进车头前方「钻头区」的敌人每 0.2 秒受到一次伤害。钻头区是车头前方的一个箱子：左右与车身同宽（各 1.9 米），
  从地面一直到钻头顶（离地约 4.6 米），从车头（车辆中心前 3 米）到钻头尖前 1 米（前 9 米）；敌人按身体算——从它的位置（脚下）
  到锁定点这一段，再各方向加 1 米——只要身体碰到这个箱子就算接触。（2026-10-05 19:56 的试玩里，按「钻头轴线周围 3.5 米」算，
  开着钻头撞进蚁群也一次都没碰到：钻头轴线离地 3.4 米，地面敌人的锁定点只有 1 米高，离轴线 5.5 米以上。）
  每秒伤害 = `DrillDamage` × 当前转速 / 最高转速（转速低于最高转速的 15% 时不造成伤害）。伤害算你的（这辆车的），**不伤友军**：
  用的是游戏自己的伤害结算，只伤敌方阵营。
- **钻开建筑和岩石**：钻头区里碰到地图物体时，每 0.2 秒对接触点造成一次破坏，
  每秒从建筑 / 岩石的耐久里扣掉 `DrillBreak` × 当前转速 / 最高转速。用的是游戏自己的「破坏建筑」结算（和爆炸毁掉建筑是同一条路），
  所以能钻倒的就是爆炸能炸倒的东西：普通建筑耐久几百到一千多，岩石（如平原地图的大石块）耐久只有 1，一碰就碎。
  每次破坏在接触点有一个半径 4 米的小爆炸效果，范围内的敌人也会受伤。
  - 地图用 6 条探测线：从车体内部（车辆中心）往前打到前 9 米，中间 4 条离地 1.2 / 2.3 / 3.4（钻头轴线）/ 4.2 米，两侧各 1 条
    （左右 1.3 米、离地 2.3 米），取最近的命中。从车体内部开始探测，所以车头顶着墙、钻头已经插进墙里时也算接触。
  - 离地 1.2 米以下不探测：再低的线遇到前方的上坡就会「碰到」地面。比 1.2 米更矮的石块由车身去撞。
- **NPC 驾驶**：NPC 不会按射击键；NPC 开的钻头战车在钻头碰到敌人或建筑时自动转起来，同样会过热、过热后停转到冷却为止。
- **限制**：伤害和破坏不随请求档位、难度变化（是 ini 里的固定值，可自己调）；敌人的身体按「脚下到锁定点再加 1 米」估算，
  身体特别宽的巨大敌人在侧面贴着钻头区时可能不算接触；车身两侧的敌人（不在车头前方）不受钻头伤害；
  需要 EDF6VehicleCrew 插件（没有插件时钻头不转，射击键什么也不发射）；联机时钻头的伤害只在开车的那台电脑上结算。

## EMC 蓄力光束

空降兵请求的 EMC（EMC / EMCS / EMCX，`V510_MASER`，原版武器「原子光線砲」）原版是按住射击键连射 1000 发、每发 5 点伤害、
细水长流打 16 秒多。插件把它改成「蓄力 → 一道粗光束」（`src/emc.cpp`、`src/emc_plan.h`，ini `EmcBeam` 等，默认开；
逆向与设计 `docs/emc-re.md`；2026-10-06 用户要求）：
- **操作**：玩家坐 EMC 驾驶座，**按住射击键蓄力**（默认 3 秒，`EmcChargeSec`）：炮口亮起一道细光，越蓄越粗，同时响起游戏自带的
  充能音（翼装兵武器充能的循环音），音调随蓄力升高。**蓄满自动发射**；蓄到一半松开就不发射，蓄力很快退掉（退得比蓄得快一倍）。
  射完要**松开射击键再按**才开始下一次蓄力，两发之间至少隔 2 秒（原版两次连射之间的间隔）。
- **一发 = 原版一次连射**：一道粗光束持续 `EmcBeamSec` 秒（默认 2.5），消耗 1000 发弹药，伤害就是这 1000 发的总伤害
  （武器的单发伤害 × 游戏给这把武器的伤害倍率 × 1000，运行时从武器本身读取；按原版数值约为 EMC 6500、EMCS 37500、EMCX 62500，即 5 × 请求倍率 1.3 / 7.5 / 12.5 × 1000），
  一个弹匣（7000 发）照样是 7 发、总伤害和原版一样。光束**贯穿**：沿线的每个敌人都吃满这份伤害（原版那 1000 发
  只会打在挡在最前面的那个身上）。光束跟着炮管走，射击期间可以转炮塔扫过去。射程同原版（600 米）。
- **沿途建筑一起摧毁**：光束照射期间，每 0.1 秒给光束线上的每栋建筑一个「破坏装药」（半径 12 米，游戏自己的炸毁建筑结算），
  每秒从每栋扣掉 `EmcBreak` 耐久（默认 20000，普通建筑和高楼一下就倒）；光束一路穿过沿线的建筑，不是一栋一栋啃。
- **终点大爆炸**：光束结束时，在它照到的地面（或最后一栋建筑）上爆出一个半径 `EmcBlastRadius` 米（默认 300）的爆炸，
  伤害是光束伤害的 `EmcBlastShare` 倍（默认 1 倍）；范围内的建筑同样受到这份伤害。光束射向天空、600 米内什么也没照到时不爆炸。
- **不伤友军**：光束、破坏装药、爆炸都由这辆 EMC 发出，按游戏自己的阵营判断只伤敌方，击杀算你的；玩家和 NPC 队友、
  友军载具在爆炸范围里也不受伤害（是否会被爆炸冲击推倒未实机确认）。
- **地形不能被摧毁**：EDF6 的地形（山、地面）是地图里预先烘焙好的静态碰撞和渲染网格，游戏里没有任何改变地形的机制
  （逆向见 `docs/emc-re.md` §4），所以「一炮毁掉一座山」做不到：光束照到山体 / 地面就停在那里，在那里爆炸。
- **HUD**：原版载具 HUD（`StockVehicleHud=1`）的武器行下面多一行和一条进度条：`EMC READY x5  HOLD FIRE`（绿，还能打几发）、
  `EMC CHARGE 62%`（琥珀，蓄力条）、`EMC BEAM 1.4s`（白，光束剩余时间）、`EMC REARM`、`EMC EMPTY`（红）。
- **需要**：安装器生成的 4 个文件 `EDF6VC_EMC_BEAM / _SIGHT / _BREAK / _BLAST.SGO`（`tools/make_emc.py`，由本机 Root.cpk 派生）；
  没有这些文件、`EmcBeam=0`、或直升机模块没启用（`HELI profile=0`，光束借用喷气机模块的炮弹发射）时，EMC 是原版连射。
  NPC 开的 EMC 不变（它的 AI 自己扣扳机，仍是原版连射）。联机时光束和爆炸只在开车的那台电脑上结算。
- **待游戏内确认**（只做了静态逆向和离线验算 `tools/emc_check.cpp`）：光束外观（粗细、颜色）、穿透是否每发都打到沿线每个敌人、
  伤害是否再乘难度系数、建筑倒塌后碰撞是否立刻消失、300 米爆炸的特效和性能；`Debug=1` 时日志 `EMC v=… fired: …`（伤害预算）、
  每秒一行 `EMC v=… beam: … building(s) on its line …`、结束时 `EMC v=… beam over: … blast …`。

## 尼克斯（Nix）上下半身分离

空降兵的战斗框架尼克斯（`Vehicle612_nix`，`V612_NIX*.SGO`）改成机甲战士式操作（ini `NixTorsoTwist`，默认 1，0 = 原版）。逆向笔记见 `docs/nix-re.md`。
- **操作**：W/S 前进后退，A/D 原地转下半身（腿）——这两样原版就是这样（原版尼克斯没有横移）。上半身（连同镜头和双臂的瞄准）只跟鼠标转：
  原版上半身的朝向是「相对腿」的角度，A/D 一转腿，上半身、准星和镜头跟着一起甩；现在腿转多少，插件每帧就把上半身相对腿的角度
  反向补回多少，上半身在世界里的朝向保持不动，只有鼠标能转它。手柄同理：左摇杆管腿，右摇杆管上半身。
- **扭转极限**：上半身相对腿能扭多少沿用原版的限制（尼克斯的瞄准轴自己的上下限，SGO 的 `begaruta_pilot_class` 里是 ±70°；
  轴没有上下限时用 ±120°）。腿继续转、上半身扭到极限时，上半身停在极限、跟着腿一起转；鼠标往极限外推也只是停在极限，
  **不会**反过来带着腿转——要转身就按 A/D。
- **只管玩家自己开的尼克斯**：NPC 开的（它的瞄准是自己的闭环）、联机里别人开的不变；其它载具（包括同一家族的贝加尔塔）不变。
- **给别的功能的数据**：插件每帧公开玩家这台尼克斯的腿朝向、上半身朝向、扭转角和上下限、上半身的瞄准方向（`src/nix.h`
  `PlayerNixTorso`），载具 HUD 的扭转指示和载具镜头用它。
- **待游戏内确认**（只做了静态逆向和离线验算 `tools/nix_twist_check.cpp`）：`Debug=1` 时上车日志
  `NIX v=… the player drives it; torso held in the world, twist … stops …` 给出实际的扭转极限；之后每秒一行
  `NIX v=…: heading H (matrix M) torso T twist W … camera-torso D deg`：H 与 M 应相同（车身矩阵确由这个朝向建出），
  按 A/D 转腿时 T 应保持不变、W 反向变化，D 应接近 0 且不随转腿变化（镜头跟着上半身的瞄准）。若转腿时 T 反而变化两倍，
  说明瞄准轴的转向符号与腿相反（`docs/nix-re.md` §3 的推断不成立）。

## 边三轮摩托

游骑兵（Ranger）可以请求一辆边三轮摩托（武器 `EDF6VC_CALL_SIDECAR`，放在游骑兵的载具槽，请求方式和档位参照フリージャー
（Freed）摩托：模板是フリージャー１）。逆向笔记见 `docs/sidecar-re.md`。
- **外形**：原版フリージャー摩托，右侧加一个船形边斗（参照二战军用边三轮宝马 R75 / 乌拉尔）：尖头圆尾的车斗（长 2.1、宽 0.92 米，
  底离地 0.20 米），侧板内倾、圆底、带胶条的座舱口沿，车头盖板（拱形甲板）和一块钢制前挡板，座舱尾部一条长凳带靠背；两根支撑臂把
  车斗连到车架，边车轮（复制摩托自己的前轮）装在车斗外侧的短轴上，上面一块挡泥板。全部用程序网格生成、贴摩托自己的材质
  （深蓝涂装、蓝灰钢、黑色橡胶各取摩托贴图里一块均匀的颜色），来自你自己的 Root.cpk（安装器只读它），不需要额外模型和贴图。
  射手站在座舱里、脚踩车斗地板（离地 0.30 米），两侧口沿到他的胯部（地板以上 0.88 米），前挡板到胸口。
  碰撞体：摩托的碰撞体（ragdoll `RAGDOLL_V503_BIKE.SHKT`）里后座顶盖那一块凸包被移到车斗下面，铺满车斗的平面轮廓，从车斗底
  （0.20 米）到地板（0.30 米），顶面就是射手站的地板；车斗侧板只画出来、没有碰撞（一个凸包做不出空心的斗，侧板夹住人物胶囊会卡住，
  射手由插件保持在座舱里）。摩托的质量和重心不变。
- **两个人**：驾驶员和原版摩托一样开车、用车上的两挺机枪射击。**边车上的人用自己的武器**：他不是坐在载具座位里，而是站在边车上，
  插件每帧把他保持在车斗里（移动摇杆被拿掉），所以瞄准、射击、换弹、换武器全都和平时步行一样（兵种的特殊动作见「限制」）。
  - 为什么不是座位：游戏里任何载具座位上的人都处在「乘坐」状态，进入时自己的武器被隐藏并禁用，射击、换弹、换武器的按键也都被
    这个状态挡掉（NPC 在座位上同样不开枪）。这是人物的状态，不是座位的类型决定的，原版没有一种座位能保留自己的武器。
- **上下车**：走到边车旁按上车键坐进边车（站得离驾驶座更近就照常开车；驾驶座有别的玩家时上车键直接进边车）。
  在边车里再按一次上车键从边车外侧下车；跳起来也会离开边车。
- **NPC 射手**（`SidecarNpcGunner`，默认开）：你开车、边车空着时，`SidecarNpcRange`（默认 25 米）内最近的 NPC 队友会跳进边车，
  用他自己的武器向敌人射击；你离开驾驶座时他也下车。
- **你坐边车、没人开车时**：插件替你开（不派 NPC 司机）：推左摇杆，车朝你镜头看的方向开（偏得多时减速转弯），松开就不再加油门。
  方向的正负按实际转向自动学习；油门如果推了 2.5 秒还走不动，会改用另一个踏板值（会记一行日志）。
- **不会翻**：三轮车不能像两轮摩托那样压弯。插件接管摩托车身每一帧的角速度里的「侧倾」分量，换成回到水平的转速
  （开着的时候不压弯，停着也不会倒），俯仰和转向不变。这一项在游戏启动时装上，`Sidecar=0` 要重启游戏才完全关闭。
- **限制（需要实机确认）**：边车射手是「站着的步兵」，翼装兵起飞、剑兵冲刺、游骑兵翻滚这类会让人离开边车的动作，离开超过 3 米
  （或跳起）就算下车；被炸倒（布娃娃）时会掉出边车。射手站在车斗里时，插件用步行控制器自己的单步速度带着他跟车，偏离站立点
  0.25 米以上才把他放回去（偏离多少记在 Debug 日志的 `SIDECAR` 行）。车斗侧板没有碰撞：跳起离开边车后可以直接从侧面出去。你坐边车时插件开车用的是摩托的驾驶输入块
  （油门、转向），没有人坐在驾驶座时游戏是否照这个块开车没有实测过；若完全开不动，日志会写明。联机：只在本机保持本机的射手。

## 普罗透斯（Proteus）

空降兵的大型步行机甲普罗透斯（`VehicleBigBegaruta`：`V614_PROTEUS_MK2*`、`VEHICLE407_BIGBEGARUTA*`）重构成「行走时是快速转移的指挥平台，
架设后变成能保护周围友军的火力据点」（`src/proteus.cpp`、规则 `src/proteus_logic.h`，ini `ProteusRework` 和其它 `Proteus*`，默认开；
逆向笔记 `docs/proteus-re.md`；2026-10-06 用户需求）。只在**你坐在里面**时生效，你下车后它恢复原版的全部数值。

- **两个座位**（`ProteusTwoSeats`）：驾驶员（0 号座）和炮手（1 号座）。炮手的两门炮一起转、一起开火（右炮跟着左炮的角度，
  左炮开火时右炮同时开火）。原版的右炮座和导弹座关闭：谁都坐不进去，原版派进去的 NPC 炮手被请下车；导弹发射架改成驾驶员的导弹齐射
  （只在齐射用得了时：本关预载了炮舰机的炮弹、导弹座也关着；否则导弹发射架照原版能用，每帧重新判断）。
  （以前插件从没给普罗透斯接上每帧入口，所以它也没有载具 HUD、换座位、NPC 驾驶；现在都有了。）
- **自动配 NPC**（`AutoCrew`）：和直升机同一规则——任务里停着、**你还没坐过**的普罗透斯，插件不派 NPC 进去（否则原版会坐满四个座位把它开走，
  你就上不去了）；你坐过、下车之后，它照常配 NPC 驾驶（原版 RideAi，四个座位都坐 NPC）。
- **按键**（驾驶员；键盘 / 手柄，ini 可改）：切换行走 / 架设 **T** / **RB**（`ProteusModeKey` / `ProteusModeButton`）；
  护盾开关 **B** / **LB**（`ProteusShieldKey` / `ProteusShieldButton`）；标记目标 **Q** / **X**（`ProteusMarkKey` / `ProteusMarkButton`：
  屏幕中心 8° 内最近的敌人，再按一次同一个目标就取消）；导弹齐射 **鼠标右键** / **LT**（`ProteusSalvoKey`）；
  架设时驾驶员的机炮 **鼠标左键** / **RT**。手柄键位选的是驾驶员原本空着的键：A、B、L3 是原版的跳跃（`docs/proteus-re.md` §3），Y 留给上下车，L3 / R3 另有观察键 / 高视角。
- **行走模式**：移速和起步加速 ×1.6、转向 ×1.3（`ProteusWalkSpeed` / `ProteusWalkTurn`），能迈上去的台阶从约 1.2 米提高到
  2.6 米（`ProteusStepHeight`；同时能走的最陡坡从 40° 变成约 61°），靠高腿跨地形、抢位置。
  - **正面护盾**（护盾键开关）：车头左右各 60°（`ProteusShieldArc`）内打来的伤害全挡（`ProteusShieldBlock`），打开时移速和转向
    减半（`ProteusShieldSlow`），没有热量，用来转移途中保命。
  - **护盾打开时己方 NPC 和自动炮塔优先攻击**：解读为「指挥平台」——友军优先打**普罗透斯附近（`ProteusPriorityRadius`，100 米内）
    或正在攻击它的敌人**：己方 NPC 士兵挑目标时（原版按距离挑最近的）这些敌人的距离按 `ProteusPriority`（0.3）打折；
    EDF6AutoTurret 的自动炮塔（防空车、Titan 和坦克的副炮）挑新目标时同样打折（两个插件通过 `common/edf/aimlink.h` 的 `PriorityZoneV1` 互相告知）。
    没有做成「嘲讽」（让敌人都打普罗透斯），因为那和「保命」相反（逆向见 `docs/proteus-re.md` §7，嘲讽也能做：敌人的目标权重 +0x47C）。
  - 炮：射速 ×0.7、散布 ×1.8（`ProteusWalkGunRate` / `ProteusWalkGunSpread`）；导弹发射架让给齐射（齐射用不了时照旧，见上）。
- **架设模式**：按切换键后 1.5 秒硬直（`ProteusDeploySec`；收起同样 `ProteusStowSec`），期间不能走、不能转、不能跳；
  架好后不能走（是固定炮台），可以原地慢慢转身（`ProteusDeployTurn`）去面对威胁。镜头升高 12 米（`ProteusViewLift`），视野变大。
  - **力场**（半径 60 米，`ProteusFieldRadius`；地面上的青色虚线圈）：覆盖范围内的友军士兵和载具受到的伤害 −30%（`ProteusFieldDefense`），
    士兵造成的伤害 +20%（`ProteusFieldAttack`），武器射速 ×1.2（`ProteusFieldFireRate`），翼装兵每秒多恢复 5% 能量（`ProteusFieldEnergy`），
    空袭兵的支援武器每秒多充 25 点（`ProteusFieldPower`）。普罗透斯自己不在力场里（它有自己的护盾）。
  - **自身护盾**：容量为最大耐久的 30%（`ProteusBarrier`），先替车体挨打，4 秒没挨打后（`ProteusBarrierDelaySec`）40 秒从空回满（`ProteusBarrierRegenSec`）。
  - **单向盾**（护盾键开关，面朝车头 ±60°）：挡住覆盖角度内的伤害，有热量：开着时热量只随时间涨，12 秒过热（`ProteusHeatSec`），
    过热后盾降下，冷却到 30%（`ProteusResumeHeat`）后自动重新升起（只要开关还开着），关掉时冷却（`ProteusCoolSec`）。
  - **炮**：射速 ×1.8、散布 ×0.35（`ProteusDeployGunRate` / `ProteusDeployGunSpread`）——炮手席在架设模式射速大幅提高。
    原版炮弹 200 发、不装填，射速变快后打完得更快。
  - **驾驶员机炮**（`ProteusDriverGun`）：主射击键开火，每秒 4 发（`ProteusGunRate`）炮舰机的 40 毫米高爆弹（每发 45 伤害，`ProteusGunDamage`，基础档，按档位放大），从背上发射架的位置打向屏幕中心；
    标记的目标在屏幕中心附近时自动算提前量（可以当防空炮打飞行目标）。
  - **导弹齐射**：标记目标后按齐射键，12 发（`ProteusSalvoCount`）炮舰机的火箭弹从背上依次射出，按抛物线落向目标（按目标移动算提前量，
    落点在目标周围 6 米内散开），每发 150 伤害（`ProteusSalvoDamage`，基础档，按档位放大）；打完冷却 30 秒（`ProteusSalvoCooldownSec`）；标记最远 1500 米（`ProteusSalvoRange`）。
- **HUD**（原版载具 HUD 的左下块里）：姿态（硬直时琥珀色进度条）、护盾状态（架设时下面是热量条，过热闪红）、自身护盾条、
  力场半径和覆盖的友军数、齐射状态（冷却秒数 / 待标记 / READY）和标记距离；车体圆环外侧的青色弧是正在立着的护盾的方向；
  被标记的目标上有红色菱形和距离。离线排版检查：`tools/hud_view`（`stock_proteus_*`）。
- **离线检查**：`cmake --build build --target proteus_check && build\proteus_check.exe`：两套参数下逐帧验证硬直时长、硬直中不接受切换、
  热量按时间过热 / 冷却 / 自动重新升起、自身护盾吸收与恢复、齐射冷却、护盾覆盖角度和台阶高度换算。
- **做不到的、近似的地方**（`docs/proteus-re.md` §8）：
  - 「架好后机身升到最高」：普罗透斯的身高是走路动画和出生时建好的物理胶囊决定的，类里没有能调身高的参数，所以做的是镜头升高 12 米、
    往后拉开（视野变大），机体本身不变高。
  - 驾驶席的「机枪 / 防空炮塔」：原版驾驶席没有武器，也无法在运行时给座位加武器，所以用插件发射炮舰机的机炮弹实现（伤害、
    击杀、阵营都算普罗透斯的）；导弹齐射同理用炮舰机的火箭弹（无制导，按抛物线和提前量打标记的位置），不是原版的追踪导弹。
  - 机炮和齐射需要本关预载这些弹药（任务开始时自动预载，需要喷气机功能可用：`JetPilot` 那套的签名对得上）；没有时 HUD 显示 SALVO OFFLINE。
- **待游戏内确认**：`Debug=1` 时日志 `PROTEUS` 行：上车 `reworked (... walk / turn / jump / step normal ...)` 给出原版数值；
  每 2 秒一行姿态、护盾、热量、自身护盾、齐射、力场友军数和这 2 秒里挡掉 / 自身护盾吸收 / 打到车体的伤害，以及腿的数值。
  要看的：行走变快、能迈上更高的台阶；架设时立刻停住；炮手开火时两门炮都开火；护盾方向打来的伤害被挡（`blocked` 增加）；
  力场里的队友受伤变少；驾驶员机炮和齐射能打出来；镜头在架设后升高。联机：只在本机生效（数值在本机改，别人的机器上不变）。

## 登车狙击枪

游击兵（Ranger）的狙击枪「登车狙击枪」（武器 `EDF6VC_CALL_BOARDING_GUN`，`src/boarding.cpp`）：原版 ＫＦＦ５０ＬＳ 的复制品，自带激光瞄准器和 5.5 倍狙击镜，射程拉长到 1500 米。
- **用法**：瞄准己方载具开枪。子弹真正命中载具时不造成伤害，下一帧尝试坐进那台载具（优先驾驶座，驾驶座坐不了时按座位顺序换下一个）。碰撞检测保持原版；擦过载具包围盒或被墙挡住不会触发登车。
  NPC 正在驾驶的载具照「玩家顶替 NPC」处理：NPC 挪到空副座，没有空位时下车。对敌人照常造成伤害。
- **哪些载具**：插件能派 NPC 的那 23 类载具（坦克、装甲车、直升机、机甲、玩家战斗机等），只限玩家同队、友军（2 队）和无主（5 队）的；
  插件自己飞的 NPC 战斗机、潜水母舰不行（它们的驾驶员从不被顶替）；敌方载具照原版吃子弹。友军（2 队）载具在上车前先放进无主队，
  上车后由原版上车流程给它玩家的队伍；没坐上就还给它原来的队伍。
- **怎么做到的**：子弹的命中候选收集（`addBody`，`docs/bullet-pass-re.md`）里认出这把枪的子弹——它的 `AmmoColor` 的 alpha 是 `1 + 7301` 个最小单位
  （位模式 `0x3F801C85`，与 1.0 差约 0.0009，看不出来；原版 1564 把武器的 alpha 只有 0.05–1.0 六种取值，不会撞上），
  这个颜色原样拷进子弹参数，不随星级、开火修正缩放；子弹的所有者就是开枪的士兵。下一帧在游戏线程里替玩家按一次原版上车键：
  只在按键这一瞬间把玩家位置放到该座位的上车点上（原版上车判定按这个距离算），并让第 49 槽 FindSeat 只认这一台载具；坐上了就留在原版放的位置，没坐上就把位置放回去。
- 关闭：ini `BoardingGun=0`（子弹就照普通狙击枪打中载具）。不装插件时它就是一把普通的 ＫＦＦ５０ＬＳ。日志 `BOARDING`。
- 安装器每次读档把它设为已拥有（同呼叫武器），出击前在游击兵的狙击枪栏里选它。**未实机验证**（静态逆向，见上面的证据链）。
