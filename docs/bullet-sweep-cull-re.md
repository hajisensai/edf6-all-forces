# 子弹 step-3 形状投射按包围盒剔除部件（SweepCull）逆向笔记

对应代码：`src/bullet_sweep_cull.cpp` / `src/bullet_sweep_cull_logic.h`，ini `SweepCull`（默认 1，每次投射都经 `Cfg()` 读取，支持热重载）。
只支持 Steam 版 `EDF.dll`（TimeDateStamp `0x678CCB46`）。以下 RVA 都是 EDF.dll 的地址。

## 背景

bench:4000 时原版 pre_update 每步约 72 ms，大部分花在子弹扫掠上。下面这几条已经证伪，不再做：同组去重、在源头按层或阵营剔除、缩小扫掠盒。

## 调用路径

- 批处理 step `0x237CF0`：
  - `0x237D15` 设 `r15 = *(image+0x20B2958) + 0x10`（xgs System 的 world）。
  - `0x238286..0x2382E2` 逐个遍历子弹 `[rdi+8]`。当 `core+0x8C1` 置位且 `core+0x8E0 > 0` 时，在 `0x2382B6` 调用 `0x231720(core, cmd = [rdi+0x60] + i*0xB0)`。这里是该函数唯一的调用点，原始字节 `E8 65 94 FF FF`。
  - 之后调用 `0x11A8E40(r15, cmds, n)`，即批量形状投射。
- 候选列表 `core+0x8D8`（id 数组）/ `core+0x8E0`（个数）每步都是新建的：
  - step 1 `0x233BD0` 在 `0x233C39` 对每颗子弹无条件清 `0x8C1`。
  - `0x2359C0` 先清 `8C1` / `8E0`，再写 `8A0` 起点、`8B0` 终点、`8C0`，置 `8C1 = 1`，重新填 `8D8`（层过滤已在这里做完）。
- `0x231720`（构建 step-3 命令）：
  - 先调 collector 的 reset（`[core+0x990]` vt+0x10）。
  - 如果 `!(AF4 & 0x1000) && 8E0 != 0`：
    - `core+0 != core+0xBE0`（半径变了）时重建球形 shape。
    - 填命令：`8A0 → cmd+0x80`，`8B0 → +0x90`，过滤 `894 → +0xA0`，最多命中数 `0x32 → +0xA4`，shape `core+0x18 → +0x40`，collector `→ +0x10`。
    - 调 `0x11AA620(cmd, W, ids = 8D8, n = 8E0)`，返回 1。
  - 否则返回 0。
- `0x11AA620`：把 `(*(W+0x58)+0x20)->vt[0x80](store, id)` 取到的 body 指针按顺序追加到 `cmd+0x30` 的 hkArray 里（`+0x30` data、`+0x38` count、`+0x3C` capacity，掩码 `0x3FFFFFFF`）。
- `0x11A8A90`（逐 body 的窄相）：
  - 可选的过滤是 `cmd+0x20`，即 world 接口 slot 0x10 的组碰撞过滤器，调它的 slot 0x30，无状态。
  - shape 取 `[body+0x78]`，变换就是 body 本身。
  - 没有 AABB 预检，各 body 之间互相独立。投射消耗就在这里。
- 命中读取在 `0x2321F8`：
  - collector 是 `[core+0x990]`，vt slot 3（+0x18）返回命中数组，`collector+0xC` 是命中数。
  - 每条命中占 0x70 字节，`+0x48` 是 body id，`+0x20` 是 fraction。
- 包围盒：`0x11B15E0` 返回 `[slot0x80(id)]+0x78`，即窄相用的那个 shape。calcAabb 是 `*(image+0x20F1930) + shape[0x18]*0x100 + 0x18`，调用形式 `(shape, body, out[8])`，和 `body_box.cpp` 用法一致。

## `AF4 & 0x1000`（爆炸弹）

这一位只在子弹初始化时写入（`0x231D69..0x231D80`，来源是 param 的 `+0x8C` 字节），或随整个 dword 拷贝写入（ctor `0x230173`、`0x2A2FBB`），批处理期间不变。

置位的子弹不做形状投射：`0x2321B0` 的爆炸（约 `0x232491` / `0x2324DF`）通过 `0x542860` 直接用 `8D8` 列表做点查询。这类子弹必须原样跳过，否则会少炸部件。

## 做法

在 `0x2382B6` 的调用点包一层，只在消费侧裁剪。没有采用方案 A 在 `0x109F6F` 展开处剔除，原因有两个：

- 消费侧的几何就是 step 3 实际投射的几何（`8A0 → 8B0`，半径 `BE0`），层过滤也已经做过。
- `8D8` 除了 `0x231720` / `0x11AA620` 和爆炸路径之外没有别的读者。

代价是展开、追加列表的开销省不下来，只省窄相。

`n ≥ 2` 时，用 calcAabb 求每个 body 的世界盒，向外扩 `r + 0.1`。线段 `8A0 → 8B0` 碰不到扩大后的盒子的 body 就剔除（double 精度的 slab 测试；某一轴退化时检查起点坐标是否在 slab 内）。规则如下：

- 至少保留一个 body，保持原有顺序，原地写回 `8D8` / `8E0`，然后调用原版 `0x231720`。
- 以下情况一律原样交给原版，不剔除：
  - 取不到 store 或 AABB 表；
  - 爆炸弹；
  - `n < 2`；
  - 半径不是有限的非负数；
  - 取不到某个 body 的 shape 或 calcAabb，或得到的盒子不合法（这种 body 保留）。

## 等价性论证

1. 裁剪后的列表是原列表的有序子集，`0x11AA620` 按同样顺序追加。
2. 被剔除的 body，它的 calcAabb 盒子（和窄相用的是同一个 shape、同一个变换）到线段的距离大于 `r + 0.1`。半径为 r 的球扫过这条线段碰不到它，不可能产生命中。
3. 窄相逐 body 独立，过滤器无状态，所以剩下的 body 命中不变。命中数组的顺序由窄相按 fraction 收集，不依赖被剔除的 body。这一条是推测，由游戏内的 shadow 对比核验。
4. 列表不会变空，原版的 `8E0 != 0` 分支照常走。
5. `8D8` 每步重建，裁剪结果不会泄漏到下一步。

## 校验与观测

- 安装前对以下范围做 FNV-1a 指纹检查（值见 `kFingerprints`），并检查调用点字节：
  - `0x231720..0x231839`
  - `0x11AA620..0x11AA64C`
  - `0x11A8A90..0x11A8E37`
  - `0x11A8E40..0x11A9261`
  - `0x2359C0..0x235AD5`
  - `0x238286..0x2382E2`
  - `0x237D12..0x237D24`
  - `0x233C39..0x233C47`
  - `0x2321F8..0x232240`

  任何一项不符就写一行 `SWEEPCULL REFUSED`，什么都不装。
- `PerfProbe` 打开时，每 5 s 输出一行 `PERF SWEEPCULL`：投射次数、候选部件数、剔除数及比例、原样放行数、裁剪耗时、shadow 次数和不一致次数。
- `Debug=1` 时，每 256 次有剔除的投射做一次 shadow 对比：用完整列表和裁剪列表各跑一次 `0x231720` + `0x11A8E40(W, cmd, 1)`，比较 collector 的命中字节。不一致时写 `SWEEPCULL MISMATCH`（最多 32 行），并把本次恢复成完整列表。

## 离线测试（`tests/bullet_sweep_cull_test.cpp`，ctest `bullet_sweep_cull`）

- 几何：40 万组随机线段、盒子、半径（含零长度、轴对齐、万米坐标），对照黄金分割搜索求出的精确距离。距离 ≤ r + 0.1 的盒子全部保留。
- Cut：保持顺序，全部拒绝时保留第一个。
- 私有 `DONT_RESOLVE_DLL_REFERENCES` 映射：
  - 安装成功，说明全部指纹匹配；调用点已被重定向。
  - 伪造 System、store、AABB 表、collector，跑 3000 组随机群。
  - 原版 `0x231720` 吃完整列表，`0x2382B6` 的挂钩目标吃同一列表，比较两者：
    - 返回值相同，命令其余字节相同，collector reset 各一次；
    - 挂钩命令的 body 是原版的有序子序列，只少了精确距离 > r 的 body。
  - 爆炸弹、单个 body、`SweepCull=0` 三种情况与原版完全相同。
- 变异检查：把扩张量改成 `r - 1` 后测试变红。

做不到的部分：真实窄相 `0x11A8E40` 无法离线逐位比对，它要 Havok 的 TLS 内存路由和栈分配器、任务队列和真实 hknp shape。命中等价只能靠游戏内 `Debug=1` 的 shadow 对比来证明。
