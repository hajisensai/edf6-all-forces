# 玩家镜头：`game_object_camera_setting`、座位镜头与炮塔镜头（静态逆向，2026-10-05 / 10-06）

EDF.dll TimeDateStamp 0x678CCB46，地址都是 RVA。H = 静态确认，L = 推断、未在游戏里看过。
用到它的地方：`src/turretcam.cpp`（炮塔镜头、观察键、高视角的摆放）、`src/turretcam.h`（摆放和炮塔指令的数学，
`tools/turret_cam_check.cpp` 离线核对）、`src/highcam.cpp`（高视角开关）、`tools/make_katyusha.py` / `tools/make_artillery.py` /
`tools/make_drill.py` 的 `CAMERA`、`pylib/vcobjects.py camera_view`。

## 1. 结论（给改镜头的人）

- **坐在载具里时，镜头不读载具的 `game_object_camera_setting`**（H，§3b）：玩家镜头的目标始终是玩家自己（人物），坐车时它走
  状态 2，按**座位的 MAB 镜头定位点**摆放（坦克：眼睛挂在炮管骨骼 `cannon` 上，注视点挂在炮塔骨骼 `cannon_main` 上）。镜头随炮塔转，
  是因为这两个点长在炮塔上。2026-10-05 的 `highcam.cpp` 改的是载具 `+0x170/+0x180`，坐车时从没被读过（高视角其实没有效果）；
  `make_katyusha.py` 等写进 SGO 的 `CAMERA` 也一样没有作用到开车视角上。现在两者都由 `turretcam.cpp` 用上（§5）。
- `game_object_camera_setting` = `[向量0, 向量1, (不读), 系数]`（H）：向量 0 = 注视点，向量 1 = 镜头（眼睛）位置，都是物体坐标系里的点
  （x 右、y 上、z 前），向量 1 不是相对向量 0 的偏移；第 4 项是镜头位置的缓动系数。它只在镜头目标是这个物体本身时（状态 1）起作用。
- 要改坐车时的镜头，改的是状态 2 每帧取的两个目标点（§3b 的 `0xFC01B`），游戏照常做缓动、碰撞（`0xF6760`）和朝向。

## 2. 解析：`0x54DDF0`（GameObject 公共，H）

唯一读 `game_object_camera_setting` 字符串（`0x17CDBB8`）的函数。物体 = rcx：

| 写入 | 内容 |
|---|---|
| `+0x170` | 第 0 项（向量，读成 xyzw；默认 (0,0,0,1)，常量 `0x1765B30`） |
| `+0x180` | 第 1 项 |
| `+0x190` | 默认 1.0；列表多于 3 项时取第 3 项（`0x54E227..0x54E2A1`） |
| `+0x194`、`+0x1B0`、`+0x224` | 清 0 |
| `+0x1A0`、`+0x1C0` | (0,0,0,1)；`+0x1D0` = 1.0，`+0x1D4` = 0；`+0x1E0..+0x21F` = 单位矩阵 |

- 若第 0 项本身又是列表（类型 3），按 `+0x220`（玩家的镜头距离选项序号）取其中一组：人物用这个。
- 调用者：GameObject 构造 `0x545670`（所有物体创建时解析一次），以及各兵种的类。载具类没有再写 `+0x170 / +0x180`（H）。

## 3. 镜头：`CharacterGhostCamera`（vtable `0x1768C10`，H）

- 构造 `0xF4860`：目标物体弱引用在 `+0x350/+0x358`，`+0x360` = `dynamic_cast<SoldierBase*>(目标)`。**目标只在构造时设置**
  （H：扫描全部 `+0x350/+0x358/+0x360` 写入，`0xF4860` 之外只有另外两个镜头类 `0xFE210`、`0x1051F0`），所以玩家镜头的目标
  一直是玩家的人物，上车不会换成载具。
- 第 4 槽 `0xF86A0`（每帧）：复制目标的世界矩阵 `obj+0x60..+0x9F` → `cam+0x370`；复制目标的 `+0x170` 起一整块（`+0x224` 为 1 时
  `+0x230` 起的另一块）到 `cam+0x3B0..`；`+0x1D4` > 0 时坐标系向 `+0x1E0` 的矩阵按此比例混合（`0xF87EB..0xF888F`，四元数插值）；
  然后调当前状态（`cam+0xB58`）。
- 状态 1 `0xFAF20`：第三人称（目标的 `+0x170/+0x180`，见 §1）。坐标系 = 目标的世界矩阵（`0x511C0` 只是正交化），`cam+0x3F0`
  为 1 时旋转换成 `cam+0x400/+0x404` 两个角度（`0x4CD10`）。目标（人物）的 `+0x1550` 有效（在车上）就切到状态 2。

## 3b. 坐车时的镜头：状态 2 `0xFB9F0`（H）

- 座位 = 人物 `+0x1540`（座位结构 0x340 字节，`+0xC8/+0xD8` 是它的武器表，和 `src/layout.h` 一致）。下车（`+0x1550` 失效）回状态 1。
- 座位的镜头字段由座位构造 `0x62B430` 填（`vehicle_riding_position` 的第 3 项是 MAB 定位点名，例如 `カメラ１`；`0x6BADD0` 查定位点
  和父骨骼；定位点记录 `+0x1C` 是它自己的一小段 SGO）：

  | 座位 | 内容 |
  |---|---|
  | `+0x200` | `Type`（定位点 SGO；没有时 0） |
  | `+0x208` / `+0x210` | 眼睛的定位点记录 / 父骨骼 |
  | `+0x218` / `+0x220` | `LookTarget` 指向的注视定位点 / 父骨骼 |
  | `+0x228` | `Param` 节点：[眼睛缓动, 注视点缓动]，进入状态 2 时拷到 `cam+0x650/+0x654` |
  | `+0x230` | `XAngleAdjust`（默认 1.0；小于 1 时眼睛按父骨骼俯仰的这个比例重算，`0xFBCB1..0xFC00F`） |

- `0x6BB5A0`（点 → 矩阵）：定位点记录 `+8` 的类型决定局部矩阵（0/1 只有平移，2 再加 `+0x14` 的三个角度），乘以父骨骼的世界矩阵
  （骨骼记录 `+0xB0..+0xEF`，平移 `+0xE0`）；返回的矩阵第 4 行就是点的世界坐标。
- 每帧（`edx` = 1）按 `Type`：
  - **1**：眼睛目标 = `0x6BB5A0(seat+0x208)`（`XAngleAdjust` < 1 时重算），放在 `rbp+0x30`；注视目标 = `0x6BB5A0(seat+0x218)`
    （**调用点 `0xFC01B`**：`lea rcx,[rbx+18h]; lea rdx,[rbp-40h]`，结果在 `rbp-0x10`，镜头在 rsi）；然后 `cam+0x630`（眼睛）、
    `cam+0x640`（注视点）按 `+0x650/+0x654` 缓动过去，`0xF6760` 做地图碰撞，镜头矩阵从眼睛看向注视点。
  - **0**：人物自己的视角（`human+0x1240` 两个角）乘以眼睛定位点的矩阵（大型机器人 Balam 的座位没有 `Type`，走这里）。
  - 其它值：不写镜头。
- 原版各车（`animation_model[2]` 的 MAB，`カメラ１` / `カメラ１注目`；坐标是父骨骼坐标系里的偏移）：

  | 车 | 眼睛 | 注视点 | Param / XAngleAdjust |
  |---|---|---|---|
  | Blacker（403） | `cannon` (0, 1.65, −7.05) | `cannon_main` (0, 1.55, 0.3) | 0.05 / 0.9 |
  | Titan（404） | `cannon_aim` (0, 6.3, −40.45) | `cannon_main` (0, 2.7, 1.25) | 0.025 / 0.5 |
  | Naegling（402，喀秋莎沿用） | `Rocketcannon_main` (0, 3.45, −9.52) | `Rocketcannon_base` (0, 1.85, 2.08) | 0.025 / 1.0 |
  | Kepler（603，自行榴弹炮沿用） | `cannon_l` (−0.75, 3, −10) | `cannon_l` (−0.75, 1.5, 0) | 0.12 / 0.9 |
  | E551（505，钻头战车沿用） | `cannon` (0, 2, −10) | `cannon_main` (0, 0.5, 0.3) | 0.12 / 0.65 |
  | Begaruta / Nix | `aim_center` (0, 4.21, −12.74) | `aim_center` (0, 2, 0) | 0.1 / — |
  | Proteus / 大 Begaruta | `neck` (0, 5, −23) | `neck` (0, −0.65, 5.95) | 0.01 / — |

  眼睛挂在**俯仰**骨骼上（Blacker 的 `cannon`、Naegling 的 `Rocketcannon_main`）：炮管抬起时眼睛跟着往下沉到车后，视野被车挡住，
  这就是用户说的「视野全被载具挡住」。（喀秋莎：`katyusha.cpp` 抬的就是 `Rocketcannon_main` 这根骨骼，原版镜头因此会跟着
  抬起的发射架看天——这与 `katyusha.cpp` 当初「镜头只跟瞄准轴」的推断相反；开着炮塔镜头时镜头不再读骨骼，两者都无所谓了。）

## 4. 座位的瞄准与输入（H）

- 座位的瞄准 `seat+0xE0` 是 `VehicleWeaponAimAddSe`（vtable `0x17D8A90`；基类 `VehicleWeaponAim` `0x17D8A68`）。每帧第 2 槽
  `0x5FCD80` 收到这一座位的输入（两个 -1..1 的值：偏航、俯仰；`0x5FBDA0` 对两根轴各调一次 `0x5FBC00`）。
- 轴（`+0x10`，步长 0x40）：`{min, max, angle, rate(rad/帧), …}`；参数 `+0x90` = `{刹车, 加速, 最高速度(rad/帧)}`（`0x5FBC00`）：
  归一化速度 v 朝输入缓动——同向（或速度不到「刹车」且有输入）按「加速」，否则按「刹车」，没有输入且 |v| 低于「刹车」× 0.4 时停下；
  角度 += v × 最高速度，到头停住（满 2π 时绕回）。所以输入限制在 -1..1 时，炮塔永远不会比原版转得快、加速得快（`turretcam.h`
  `NextRate` / `AxisStep` 原样复刻）。偏航角 = `atan2(局部 x, 局部 z)`（EDF6AutoTurret 同一约定；局部 x 是车身矩阵第 0 行，车头朝 +Z
  时它是 +X，也就是车的左边：偏航角增大 = 向左），俯仰角向上为负。
- 骑手的输入（`0x56DBC0`，人物写到 `seat+0x2D0`；`0x572DF0` 已按设置反转）：手柄 = 右摇杆；鼠标 = 位移 / 24，坐车时经累加器
  `human+0x15B0` 每帧最多送出 ±1、余量留到下一帧（最多攒 26）。各车类的第 55 槽把它以 **(−x, y)** 交给瞄准
  （Naegling `0x5FD948`、Kepler `0x6214D8`、E551 `0x61AD38`、`0x6207F8`、Maser `0x61DE58`：写到车的 `+0x2AA0`，第 4 槽再交给瞄准）。
- 车辆参数（L）：`vehicle_setup[1]` 的 6 个数各车不同（Blacker 0.15, 14, 0.015, 0.537, 0.035, 1.2），疑似包括轴的最高速度与缓动，
  没有追到写入 `+0x90` 的代码；插件每帧读活的 `+0x90`，不依赖这一点。

## 5. 炮塔镜头的设计（`turretcam.cpp`，2026-10-06）

目标：像《战争雷霆》——鼠标先转镜头，炮塔按自己的原版转速跟过去；观察键只转镜头；镜头放在不被车身挡住的地方；高视角推广到
所有该有的车。

- **接管点**：`0xFC01B` 的调用改道到一个小跳板（`mov r8, rsi`：把镜头传成第 3 个参数），先照常取原版注视点，插件接管时再把
  注视目标（`rbp-0x10`）、眼睛目标（`rbp+0x30` = 同一帧缓冲 +0x70）和已缓动的 `cam+0x630/+0x640` 都写成插件的点：游戏的缓动成了空操作，
  碰撞、朝向、画面中心的射线照旧（`CameraRay`、落点显示都按画出来的镜头算）。签名 `0xFC013` 起 39 字节（含 `cam+0x630/0x650/0x640`
  的偏移），不符就整个功能不装。
- **哪些车**：玩家坐 0 号座位，座位镜头 `Type` = 1，座位有武器，偏航轴能转超过 10°（炮塔）；直升机和插件的喷气机除外。
  Balam（Type 0）不在内。
- **镜头方向**：插件自己的航向 + 仰角，以世界为准（车身转弯不带着镜头转）。瞄准的第 2 槽钩子（vtable 槽位替换，链在别的插件之上）
  每帧按骑手自己的摇杆（`seat+0x2D0`，按 (−x, y) 换成瞄准的方向：偏航输入为正 = 向左）以 `TurretCamRate`（默认 90°/秒，且不慢于
  该车炮塔自己的最高速度）转镜头，再把**炮塔指令**交给原版的轴。炮塔归谁由两个插件明说（`common/edf/aimlink.h` V2，2026-10-06
  用户拍板「自瞄改了，不需要抢」）：本插件导出 `CameraTurretV2`（这个座位的镜头是分离的，炮塔跟视线走），EDF6AutoTurret 据此只在
  自瞄模式 + 玩家锁定时转这门炮、也不把右摇杆当拖炮；它这一帧写了这个座位的转向输入就由 `SteersV2` 说出，镜头这一帧把炮塔让给它
  （镜头照样是玩家的，日志 `TURRETCAM the aim's input is another hand's`）。对方是旧版（没有 V2 导出）时退回旧的猜法：瞄准收到的
  输入和骑手摇杆差超过 0.02 就算别人的（`turretcam.h Foreign`）。旧猜法的毛病：自瞄贴近目标时的小修正会被当成玩家的、被镜头抢回，
  来回抢。
  - 目标点：画面中心的射线打到的第一个地形 / 建筑点（3000 米内），没有就沿射线 800 米处。
  - 想要的轴角：从炮口（`MeanMuzzle`）到目标点，在车身坐标系里；只有目标点是**真的打到了地图**、且不在 EDF6AutoTurret 的预瞄圈模式
    时，炮弹会下坠的炮才用低伸弹道（`edf::BallisticArc`）；预瞄圈模式（圈已经解过弹道，炮膛线要穿过圈心）和视线什么都没打到
    （800 米处是编出来的点）时用炮膛直线（`turretcam.h BallisticAim`），否则会把下坠补两次、打高。喀秋莎的高抛仍由
    `launcher.cpp` / `katyusha.cpp` 抬发射架（这里给直线）。俯仰夹在轴的限位内，满圈的偏航走近路。
  - 指令（`turretcam.h AxisCommand`）：在 -1..1 里挑一个输入，使「这一帧用它、之后回到跟上目标转速的输入」时炮塔正好停在目标上
    （原版的轴同号缓动、无输入刹车，所以按输入的正负分两段各二分求解，再和「不给输入」「跟速输入」比，越过目标算双倍）。
    远处就是满输入（原版最高速度），近处滑行到位、不来回摆；目标在动（镜头在转）时把它每帧的变化作为前馈。
    离线核对（`tools/turret_cam_check.cpp`）：刹车 0.015～1.2、加速 0.015～1、最高 0.3～3 rad/s、误差 1°～170° 的 900 组阶跃，
    最大过冲 0.68°（只有最高 3 rad/s 那几组，不到四分之一帧的转动），都在「最高速度所需时间 + 缓动」内稳定到 0.2° 以内；满圈走近路；
    超出限位停在限位；镜头以 40°/秒扫动时稳态滞后 0.67°（一帧）。
- **观察键**（`FreeLookKey` 默认鼠标中键，`FreeLookButton` 默认 L3）：按住时镜头照样转，炮塔守住按下时的目标点（分离模式）或
  原地不动（`DecoupledTurretCam=0` 时，此时插件临时接管镜头）；松开后镜头每帧转回 25%，回到按下时的方向（不分离时回到原版镜头
  的方向再交还）。
- **镜头摆放（不被车身挡住）**：镜头绕一个点 O、隔一段距离、从后面看过 O（`turretcam.h Rig / Place`）。两种候选，取**更远**的：
  - A：原版定位点本身（距离 = 眼睛到注视点，O 在炮塔转轴上、注视点的高度）；
  - B：载具的 `game_object_camera_setting`（设计者给第三人称写的框图，各车按大小不同：Blacker 4/15.5，Titan 8/25.5，喀秋莎 8.5/15
    看向前方 4 米，自行榴弹炮 9/18，钻头战车 12.5/17），O 是它的注视点、随镜头航向绕车身原点转。
  - 眼睛**不低于**该候选自己设计的高度（A：炮管放平时的眼睛高度；B：向量 1 的高度）：往上看时只是镜头仰起，眼睛不沉到车后，
    往下看时眼睛绕 O 升高。这就是「不被车身挡住」的保证；地图碰撞仍是游戏的。
  - 结果：Blacker、E551、Kepler、喀秋莎、自行榴弹炮、钻头战车用 B（比原版远一倍左右、高出车顶），Titan、Proteus、Begaruta、Nix 用 A。
- **高视角**（`highcam.cpp` 只管开关）：在当前候选上换成 `turretcam.h High`——在 `HighCamHeight` 米高、`HighCamBack` 米后、
  往下 `HighCamPitch` 度看的那个位置（O 在 Height − Back·tan 处，半径 Back / cos），大车按候选半径 / 20（至少 1）放大；
  分离时镜头俯仰再加上（高视角的俯角 − 候选的俯角），不分离时 = 瞄准轴俯仰 + 高视角俯角。`HighCamClass`：1 间接射击的车
  （喀秋莎、自行榴弹炮），2 再加大车（候选半径 ≥ 17 米：Titan、钻头战车、Proteus、大型机甲……；默认），3 所有炮塔车。
- **过渡**：接管时从镜头当前的眼睛 / 注视点、用 15 帧缓入；候选和高视角之间每帧 12% 地缓动；交还时 15 帧缓出到原版的目标
  （原版注视点不缓动，直接交还会跳）。
- **HUD**：`PlayerTurretCam` 给出瞄准点、炮管此刻在该距离上的弹着位置（下坠的炮按弹道）、炮口与方向、是否对准（两轴误差 < 0.5°）；
  `hud.cpp` 只画一个小方框（炮还没转到位时）和观察时的青色十字，其余留给载具 HUD。
- **与躯干独立的机体兼容**：只用座位的瞄准轴（相对车身）和车身矩阵；腿与躯干分开转的 Nix 仍是「车身 = 下身、瞄准 = 躯干」。
  镜头在转 Nix 的躯干时（`TurretCamSteers`），`nix.cpp` 的扭腰补偿让开：镜头的指令是对世界上一点求的轴角、已经扣掉了腿的转动，
  补偿再扣一次躯干会被甩过头（`tools/nix_twist_check.cpp`：腿 12°/秒转动时镜头单独 0.2°、两者都补 1.3°）。
- **重新接管**：每次接管（换车、换座位后回到 0 号座）都有新的编号（`Shared::take`），镜头侧见到编号变了就从原版镜头重新 15 帧缓入
  （离开座位时镜头钩子不再被调用，它看不到玩家走了）。
- **座位瞄准第 2 槽已被别的插件改过**：不接管炮塔，但镜头摆放和高视角照装（以前整个功能放弃）。

## 6. 没有静态确认、需要在游戏里看的（L）

1. 各车类确实每帧都经第 2 槽把骑手的输入交给座位瞄准（Naegling、Kepler 已有静态证据：`0x5FD948`、`0x621872`）；没经过的车类
   插件不接管视角（日志 `TURRETCAM` 行的 `aim` 时间不新），只剩高视角。
2. 输入与轴的方向：偏航输入为正 = 轴向车身 +x（左），俯仰为正 = 向下（按 EDF6AutoTurret 的瞄准约定和各车类的 (−x, y) 推断）。
   若镜头左右 / 上下反了，`TURRETCAM` 行的 `view` 航向与 `yaw` 轴角会朝不一致的方向变化（航向向右增大，轴角向左增大）。
   Blacker / Titan（403 / 404 的第 55 槽不读 `seat+0x2D0`）、机甲这几类若输入另有换算，日志会出现 `another hand's`，这时炮塔照原版跟着摇杆转。
3. `Debug=1` 的日志：上车 `TURRETCAM v=…: a turret the player drives`、接管 `camera taken (view, rig authored r=… )`，
   每秒一行 `view=(航向,仰角) yaw=… pitch=…（轴角）free= high= on= aim=`；高视角开关 `HIGHCAM v=… on by the key`。
