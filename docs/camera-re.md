# 玩家镜头与 `game_object_camera_setting`（静态逆向，2026-10-05）

EDF.dll TimeDateStamp 0x678CCB46，地址都是 RVA。H = 静态确认，L = 推断、未在游戏里看过。
用到它的地方：`src/highcam.cpp`（火炮高视角）、`tools/make_katyusha.py` / `tools/make_artillery.py` / `tools/make_drill.py`
的 `CAMERA`（载具自己的镜头）、`pylib/vcobjects.py camera_view`。

## 1. 结论（给改镜头的人）

- `game_object_camera_setting` = `[向量0, 向量1, (不读), 系数]`（H）：
  - **向量 0 = 注视点**，**向量 1 = 镜头（眼睛）位置**，两者都是**载具坐标系里的点**（米；x 左右、y 上、z 前，原点是物体
    自己的原点）。向量 1 **不是**相对向量 0 的偏移：镜头 = 坐标系矩阵 × 向量 1（带平移，w = 1），注视方向 = 向量 0 − 向量 1
    在同一坐标系里（`0xFB02D..0xFB0E6`、`0xFB520..0xFB683`）。
  - 第 3 项（原版都是整数 1）解析时不读；**第 4 项（原版 0.1）是镜头位置的缓动系数**：每帧镜头 += (目标位置 − 镜头) × 系数
    （`0xFB0AE..0xFB0E6`；0.1 ≈ 半秒内跟上）。
- 镜头的碰撞（H）：先从坐标系原点上方 1 m 到注视点打一条射线，再从注视点到镜头位置打一条（`0xF6590`，`0xFB859..0xFB8FB`）。
  所以**注视点要放在不会埋进地面 / 墙里的地方**（例如车头上方），否则镜头会一直被拉近。
- 运行时改：镜头每帧从目标物体身上把这一块复制过去（见 §3），所以**直接写物体的 +0x170 / +0x180 就会在下一帧生效**，游戏照常做缓动和碰撞
  （`src/highcam.cpp` 就是这样做的）。

## 2. 解析：`0x54DDF0`（GameObject 公共，H）

唯一读 `game_object_camera_setting` 字符串（`0x17CDBB8`）的函数。物体 = rcx：

| 写入 | 内容 |
|---|---|
| `+0x170` | 第 0 项（向量，读成 xyzw；默认 (0,0,0,1)，常量 `0x1765B30`） |
| `+0x180` | 第 1 项 |
| `+0x190` | 默认 1.0；列表多于 3 项时取第 3 项（`0x54E227..0x54E2A1`） |
| `+0x194`、`+0x1B0`、`+0x224` | 清 0 |
| `+0x1A0`、`+0x1C0` | (0,0,0,1)；`+0x1D0` = 1.0，`+0x1D4` = 0；`+0x1E0..+0x21F` = 单位矩阵 |

- 若第 0 项本身又是列表（类型 3），按 `+0x220`（玩家的镜头距离选项序号，`0x572E5C..0x572E89` 在它变化时重新解析）取其中一组：
  人物用这个，载具的 SGO 是一组平铺的值（L：没有逐个核对所有载具）。
- 调用者：GameObject 构造 `0x545670`（所有物体创建时解析一次），以及各兵种的类（`0x563DC0` Engineer、`0x572DF0` HumanBase 第 4 槽……）。
  **载具类（`0x5E0000..0x700000`）没有再调用它，也没有写 `+0x170 / +0x180` 的代码**（H，扫描全部 `[reg+0x170/0x180]` 写入）：
  插件写进去的值不会被游戏每帧覆盖。

## 3. 镜头：`CharacterGhostCamera`（vtable `0x1768C10`，H）

- 构造 `0xF4860`：目标物体弱引用在 `+0x350/+0x358`，`+0x360` = `dynamic_cast<SoldierBase*>(目标)`（`0xF4F5D`，类型描述
  `0x2006400` GameObjectBase → `0x2006428` SoldierBase；目标是载具时为空）。
- 第 4 槽 `0xF86A0`（每帧）：锁定目标；复制目标的世界矩阵 `obj+0x60..+0x9F` → `cam+0x370`；
  `obj+0x224` 为 0 时复制 `obj+0x170` 起的一整块（否则复制 `obj+0x230` 起的另一块；置 `+0x224` 的是人物类 `0x550C30/0x563DC0/0x5790E9/0x579776` 和几个 `0x7F7EC0..0x8F91A0` 的非载具函数，载具类里没有）：

  | 物体 | 镜头 | 用途 |
  |---|---|---|
  | `+0x170` | `+0x3B0` | 注视点（向量 0） |
  | `+0x180` | `+0x3C0` | 镜头位置（向量 1） |
  | `+0x190` | `+0x3D0` | 位置缓动系数 |
  | `+0x194` / `+0x1A0` | `+0x3D4` / `+0x3E0` | 为 1 时坐标系的平移换成这个世界坐标点 |
  | `+0x1B0` / `+0x1C0` | `+0x3F0` / `+0x400` | 为 1 时坐标系的旋转由这两个角度（偏航、俯仰）构成（`0x4CD10`） |
  | `+0x1D0` | `+0x410` | 缩放：视角 = 常数 / 它（`0xF8906`） |
  | `+0x1D4` / `+0x1E0` | `+0x414` / `+0x420` | 坐标系向这个矩阵按此比例混合（`0xF87EB..0xF888F`） |

- 状态机（`cam+0xB58`）：
  - 状态 1 `0xFAF20`：上面的第三人称计算（§1）。若 `+0x360`（人物）的 `+0x1550`（所乘载具）有效，切到状态 2。
  - 状态 2 `0xFB9F0`：人物坐在座位上时，按座位 `+0x200` 的方式用座位自己的镜头来源（`+0x208` 眼睛、`+0x218` 注视点，
    `0x6BB5A0` 由骨骼 + 偏移算出；方式 0 = 骨骼上的第一人称、1 = 骨骼第三人称），**不读** `+0x3B0/+0x3C0`。

## 4. 没有静态确认、需要在游戏里看的（L）

1. **开车时镜头的目标是不是载具**：若是（推断：`+0x360` 只在目标是人物时非空，状态 2 只服务于人物），载具 SGO 的
   `game_object_camera_setting` 决定开车视角，插件写 `+0x170/+0x180` 有效；若开车时目标仍是人物（走状态 2 的座位镜头），则两者都无效。
   原版各载具的值互不相同（Blacker (0,4,0)/(0,4,-15.5)，Titan (0,8,0)/(0,8,-25.5)，502 (0,5,0)/(0,7,-10)），
   与各自车体大小相符，支持「载具镜头用它」。
2. **镜头怎么跟着鼠标转**：载具类没有写 `+0x1B0/+0x1C0/+0x1D4/+0x1E0`（扫描未找到），而状态 1 的坐标系只来自这几项和物体矩阵；
   载具镜头能独立于车身转动，说明这一路还有没找到的写入者（可能经由别的指针）。若坐标系包含瞄准的俯仰，镜头位置会绕原点转（越往下看镜头越高）。
3. 判断方法：`Debug=1` 开喀秋莎 / 自行榴弹炮，日志每秒一行
   `HIGHCAM v=… stock|high: camera eye in the vehicle's frame (x,y,z), D m from the block's eye; look (…) pitch …`
   和一行 `HIGHCAM v=… stock|high: look (…) eye (…) ease … alt … angleFrame … (…) zoom … blend …`。
   - D 接近 0（缓动跟上、没被碰撞拉近时）= 镜头位置就是坐标系 × 向量 1，且坐标系就是车身矩阵；
   - 切换高视角（`HIGHCAM v=… on`）后 eye 的 y 变成约 45 = 插件写入生效；不变 = §4.1 的推断不成立；
   - D 随鼠标俯仰明显变化 = 坐标系含瞄准的旋转（eye 绕原点转），`angleFrame` / `blend` 若非 0 即那一路的来源。
