# Clickable mounted weapons (2026-10-08)

The map UI consumes `PlayerSelectablePayload(PayloadReadout*)`, a render-thread-safe copy accessor. It holds `choiceLock` shared while copying the complete immutable readout and checking wall-time freshness; it never reads game objects, `PlayerHuman`, configuration or the game clock. The game thread publishes the final selected readout and request-admission metadata together under the exclusive lock, and clears both together on invalidation. Both stock seats and plugin-aircraft pilot stores use `selectionToken`, `seat` and the drawn entry index; only entries marked `selectable` should be interactive. `RequestPayloadSelection(token,seat,index)` queues a bounded, last-valid request under an SRW lock. It does not dereference game pointers or write fire state. A successful return means queued, not already applied.

On the game thread, the context validates the current human and vehicle weak identities, seat identity, list ordering, holder and control identity, weapon/spec identity and ammunition availability. The token remains stable for an unchanged context, rotates on identity/topology/availability changes, and is never recycled by mission resets. Both publication and requests have a 200 ms wall-time freshness bound. Native reloadable stock weapons remain selectable while reloading; permanently exhausted choices do not. Aircraft selection follows its existing loaded-store policy.

Stock selectable entries exactly match its R/LB cycle: the native weapon on that control plus installed additional stores. Titan's independent primary cannon is read-only; its secondary and real additional stores are clickable. A single-control vehicle can select its native primary back from an added store. Selection updates preview/fire routing without raising a trigger; RT/LT edge precedence remains unchanged.

Plugin aircraft update the persistent `PJet::store` used by `Stores`. A real holder, non-null weapon, canonical matching `StoreSpec` and positive native ammo are required. Null-weapon actions such as bomb-bay, drones and gunship special fire are displayed read-only rather than represented as ordinary mounted weapons. Gunner seats cannot change the pilot's stores. A UI selection or map-held frame cannot call `TriggerStore`/`FireSpecial` from the normal stores step.

`PumpPayloadUi(human)` is the explicit game-thread entry for the M map, called after map command processing while the map holds input. It validates the real riding weak reference and updates only selection/readout state. Stock vehicles use the payload step; aircraft use `PumpAircraftPayloadUi`, which never runs flight, target acquisition, flares or firing. The aircraft pump also clears a stale secondary-fire byte and drains the physical R/LB edge, preventing map close from replaying a held switch. No guarantee about vehicle input frequency while the native map no-pad branch is needed.

Validation includes the real production payload selection/queue paths and the separate production playerjet Stores/pump bridge, plus existing stock sight/runtime and playerjet recovery regressions. Tests use bounded stand-in native memory and input edges, not an actual game or two-machine session. HUD hit rectangles, map event routing and pointer-capture tests are owned by the integration changes.

Snapshot concurrency regression: 5,000 production payload publications with a changing holder identity and correlated token/ammunition fields race a real Windows SRW reader thread. Every read must be one complete generation; poisoned native-context and main-thread invalidation cases ensure no render-time game-object validation returns.
