# 载具机组来源与初始化顺序

生成来源按原生意图区分，不能用“所有地图车空着”或“所有地图车都补人”代替：

- 普通玩家召唤、地图 `CreateVehicle2`：原生空车。仅观察、设置路线、应用 mission_setup 都不构成机组请求。
- 原任务 `CreateFriend` / `RideAi`：保留原生 AI 意图，初始化完成后创建真实机组。
- EDF5 旧 BVM 直接创建的 Dummy / 原生 Dummy 快照：实际存在的原生乘员同样构成迁移意图，即使没经过 slot 50。
- 执行空袭任务的机体不是交付给玩家的空车，必须由空袭派遣流程配置实际驾驶员并等网络事务激活与实际登车。

只读 native/Root 核对：`633280` 只应用设置与空投状态 `E30=2`，不生成乘员；EDF5 BVM 的 `219720`、`2269B0` 直接创建 Dummy 并 SeatRide，现有每帧乘员扫描必须保留。M003 AI 卡车使用 `CreateFriend`，M045 轨道炮、M092 EMC、M112 对空坦克使用 `CreateVehicle2`；测试场也根据 `npc` 在这两种原生入口之间选择。

此前 `RideHook` 在记录意图前调用 `PrepareNpcVehicle`；适配器尚未就绪时，一次性的原生 AI 请求会丢失。现在先保存对象身份及请求来源，待 native adapter 就绪后执行一次初始化；真正的原生 setup 故障仍停止，并保留可诊断的意图，不做每帧异常重试。新的明确脚本请求可以重新初始化。

生产 fixture 覆盖无 AI 不派人、原生 AI 延迟就绪、原生 setup 故障不循环重试、显式新请求、EDF5 BVM/Dummy 扫描及重复帧去重。未运行游戏或双机验收。
