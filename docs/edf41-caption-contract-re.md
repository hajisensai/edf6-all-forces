# EDF4.1 语音字幕 key 后缀契约（2026-10-19）

用户截图中的「＊＊不明な再生キー＊＊」是语音字幕查表失败的原生文案，与同一截图里的 NPC 举枪姿势是两个独立问题。没有运行或控制用户游戏，也没有取得该截图时的具体缺失 key 日志；下面修复的是从原生代码和实际源语音列表复现出的确定缺口。

## 根因

`tools/edf41_sounds.py::cut_key` 原先在 cue 名字中找到第一个 `_E` 或 `_S` 就截断。安装器据此给五种语言的 `EDF6_VOICETABLE` 添加字幕行。

受支持的 `EDF.dll`（TimeDateStamp `0x678CCB46`）的 `0x7B17F0` 并非这个契约：

- `0x7B1900..0x7B1952` 取 `key.length - suffix.length`，仅比较最后可能的匹配位置。
- 静态初始化 `0x7B2066..0x7B20AA` 建立 `_E`、`_S` 两个后缀，按这个顺序检查。
- 命中后 `0x7B19F5..0x7B1A1E` 将长度减去后缀长度，补 NUL，直接离开循环。一次只移除一个末尾后缀。
- `0x7B1AD8` 将所得完整 key 交给 `0x55A30` 查字幕行；缺行走原生未知 key 提示。

例如 `A_E_S` 的 key 是 `A_E`，`A_S_E` 的 key 是 `A_S`。中间的 `_E` 不移除。

实际 EDF4.1 日语及英语源列表都包含 `E115_001_E_B`，源字幕插件也提供这个完整名字对应的原文。旧安装器错误地生成 `E115_001`，原生却查 `E115_001_E_B`。两种语音列表共有 24,906 个不同 cue；该错误影响这个 cue 的两种语音记录。

## 修复与安装

`cut_key` 改为只移除一次末尾 `_E` / `_S`，保留其余字符。已有 EDF6 字幕行仍逐行保留；新增行的 `name` / `caption` 命名结构和作者字幕内容仍沿原始资料生成。无线电开关提示音仍使用引擎正式的 `***no_subtitle***` 标记。

字幕组版本从 3 升至 4，下一次运行安装器会重建字幕组；无需重新转换约 1.6 GB 的语音波形。不修改未知 key 的原生处理，也没有通过过滤黑条隐藏缺失数据。

## 验证

`tests/edf41_caption_contract_test.py` 4 项通过：末尾/中间/重复/大小写边界，源字幕保留，受支持原生 DLL 的实际指令和后缀常量，以及完整 JA/EN cue 集在五语字幕表的覆盖。原版字幕表每个已有行均与源行相同，实际 `E115_001_E_B` 得到作者提供的字幕。

现有安装链的 `edf41_sounds_captions_synthetic`、`edf41_sounds_install` 两项通过，包含缓存、归属、更新与卸载闭环。截图的具体触发关卡和 key 仍需在游戏中验收；没有将这项资料修复表述为对所有未知字幕提示的实机证明。
