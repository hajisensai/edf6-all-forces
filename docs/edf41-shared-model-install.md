# EDF4.1 共享车模安装归属

## 2026-10-15：坦克任务被误排除

`da35c411` 分享包安装后，`OBJECT/VEHICLE301_TANK_AI.SGO` 因共享的
`OBJECT/V505_TANKEDF4.MRAB` 被判定为其它 MOD 文件而跳过。磁盘文件与发布资源的
SHA-256 一致，`.edf6vc_calls.json` 也记录了相同哈希；问题是呼叫武器的事务记录了
车模，却只把载具请求的依赖登记进 `.edf6vc_files.json`，漏记了移植车模的写入者。

任务包预检早于呼叫武器写入，`edf41_objects.unavailable` 只查统一归属账本，因此
新安装与旧版升级都会把自己的车模当成外部冲突。放行同名文件不足以修复：还要处理
共享文件的引用与卸载，否则撤回一个组件时会删掉另一个组件仍使用的模型。

## 修复契约

- 呼叫武器事务提交后，以实际磁盘哈希核对其清单，使用 `Ledger.record` 登记移植资源。
  该接口不重复写文件；哈希不符拒绝登记，并保留其它组件的引用。
- 旧版预检可使用武器清单作为归属证明，但仅限移植登记表列出的资源，且清单、磁盘和
  EDF4.1 预期哈希一致。不凭文件名、单纯的存在或仅与发布包相同就接管。
- EDF4.1 安装同一车模前补齐旧版写入者，随后登记自己的引用。重复安装保留双方引用。
- 呼叫武器卸载或修复时，另一组件仍引用的资源保持原样；最后一个组件移除时才释放。
  若首次安装前已有同名文件，将原始备份与恢复哈希交给归属账本保管，即使武器修复清除
  自身备份，最后一个组件仍能恢复原文件；恢复前校验备份和当前文件，避免覆盖外部编辑。
  武器表行号、存档占位行和事务回滚逻辑不变。

## 验证范围

`tools/selftest.py` 覆盖新安装、缺少旧版归属记录的升级、重复安装、无归属证明、外部
修改、两种卸载顺序、武器修复及原文件恢复；`ledger_committed_writer` 核对登记不重写文件且拒绝
错误哈希。

本机只读对比新旧 `unavailable` 与真实 `plan41`，新增可安装任务 13 个：

- 本篇：M190、M515、M106、M117、M113、M131、M120、M119、M501、M133。
- 任务包２：M990、M506、MP501。

这是安装计划的资源检查，未写入本机游戏，也未证明这些关卡可在实机或双机中通关。
涉及 UfoMother301、UfoMother401 及其 DLC 变体、UfoRobo401 的 29 个任务仍因原生移植
未完成而排除；它们的实现不属于本次安装归属修复，不通过假资源或关闭缺失校验放行。
