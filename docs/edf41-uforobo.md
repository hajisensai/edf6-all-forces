# UfoRobo（EDF4.1「アルゴ」/ 巨神船）原生类移植

2026-10-15。4.1 的 `OBJECT/UFOROBO401.SGO`：出生是飞行舰，脚本一句 `ObjectAction 0` 变形落地成巨型步行机器人。EDF6 没有能承担它的类
（飞的只会飞、走的只会走，而且脚本在变形前后对**同一个句柄**登记耐久事件，换对象不行），所以插件注册自己的类 `UfoRobo`。
解锁的关：本篇 **M007**（巨神船）、**M411**（アルゴ01，开局就是机器人）、任务包 1 **M415**（三艘，只飞不变）、**M416**、任务包 2 **M010**。

逆向出处：`jobs/14618f05/tmp/rerobo/SPEC.md`（4.1，EDF41.exe RVA）、`tmp/re6/PRIMITIVES.md` 与 `tmp/re301/SPEC2.md`（EDF6，EDF.dll
TimeDateStamp 0x678CCB46）。可信度：**H** 反汇编读到，**M** 推出，**U** 未核。

## 1. 4.1 的行为（规格摘要，全部 H，细节见 SPEC.md §3）

- **身体状态机 12 态**（4.1 `+0x15B0`）：S0 飞行待机 / S1 小炮齐射 / S2 中炮 / S3 巴斯特炮（蓄力 300 帧、每 31 帧一发、持续 600 帧）/
  **S4 变形（此态不受伤）** / S5 下落（切机器人形态）/ S6 着地 / S7 机器人主态（选步伐、转身、攻击）/ S8 一段步伐或转身 / S9 攻击 /
  S10 死亡（8–15 秒）/ S11 残骸（10 秒后删除）。
- **AI 6 态**：A1 飞行——在目标 300–500 m 外、上方 250 m 盘旋并面向目标（偏航每帧至多 0.01 rad，速度命令 ≤ 90），之后直飞一段，
  另有横移；身体在 S0 时三个计时器：小炮 180–720 帧（0–500 m）、中炮 300/s–480/s（150–800 m）、巴斯特 1800/s–3600/s（0–1000 m），
  距离不在区间内不倒数。A3 机器人——普通模式先只转身、再前进（2/3）或后退（1/3）；接近模式按半径进退；转身按目标方位 36°/72°/126°
  选 45/90/180 度转身动画；攻击计时器 600/s–1800/s 到期 → A5 按 `robo_attack_table` 的距离 / 角度窗口等概率选一项。
- **运动**：飞行时速度每帧向命令插值 0.25 %、横滚 = clamp(−30·偏航速率, ±0.9425) 每帧趋近 10 %；机器人靠**动画根运动**，按步伐开始时
  的朝向旋转，地面射线贴地，离地则每帧 −0.008 的下落加速。
- **四组炮**（各自 G0 待机 / G1 蓄力 / G2 射击）：小（膝，BeamBullet01，速度 2、寿命 180、伤害 0.5·s、瞄准上限 0.5、散布
  max(0.05, 0.25/s)、每 6 帧一轮持续 300 帧、蓄力 180）、中（肩，RocketBullet01，伤害 30·s、爆炸 9+s、每 3 帧、1 轮、蓄力
  max(20, 180·(1+0.1(s−1)))）、大（手，RocketBullet01，速度 10、伤害 40·s、爆炸 40）、歼灭（手，速度 0.1、寿命 6000、伤害 80·s、
  爆炸 100）。机器人化后膝炮 900–1200 帧、肩炮 300–480 帧自动开火。`s = level/10`。
- **MAB 事件**：每一步脚落地都是范围伤害（`攻撃判定` 伤害 20、着地 30、劈砍 / 践踏 40，× s）；`砲撃開始 / 砲撃終了` 是手炮光束攻击，
  `ジェノサイド砲発射` 是歼灭炮；其余是音效。
- **ObjectAction**（4.1 消息 0x80000009 → EDF6 **0x1000000D**）：0 = 存活则变形；1 = 立即机器人形态 + 播 `stand` + 接近模式；
  2 = 只置接近模式。

## 2. EDF6 实现

### 2.1 数据（`tools/make_edf41_objects.py` 的 `ROBO_*` / `robo_fix`）
- 新 ROOT `UFOROBO401.SGO`（`ROOTS` 记 2 关：M007、M411；DLC 的三关名字是同一个本篇文件），**没有 Alias**：类名保持 `UfoRobo`，
  4.1 的键全部保留（插件读）。`NATIVE_FIXES` 现在对没有 Alias 的原生根也跑（在 check_materials / check_sounds 之前）。
- CAS：`main` 补 `default`（EventAnimationObject 的构造播它）= `ship`；会移动的 18 个状态（走 / 横移 / 转身）的根骨 `globalSRT`
  轨道删掉（`cas_pose.strip_bone`），否则模型会自己再走一遍。
- `edf41_robo_motion`：这 18 个状态的根运动，每个关键帧 `(x, z, yaw)`（相对起点，`cas_pose.root_motion` 从 CANM 读）：
  `walk_f_nl` 前进 50、`walk_f_lr` 100、`walk_b_*` 后退、`side_step_l` +80 x、`turn_l45/90/180` +45°/90°/180°（180 度转身同时前进
  150）。插件按 4.1 的做法：位置 = 起点 + 起点朝向 × 曲线，偏航 = 起点偏航 + 曲线。
- `edf41_robo_events`：每个 CAS 状态、每段剪辑的 MAB 事件 `[时间, 种类, 文本, a, b, c]`（`mab_legacy.mab_event_params` 读事件的内嵌
  SGO 参数；`attack_fire_genocide` 状态依次播两段剪辑，`cas_graft.state_clips` 给出顺序）。
- `edf41_se`：`se41_table(games, ('ロボ',))` 的 4.1 SEPRESET 项（只留本对象真的会播的 39 个；`ロボ３６０停止` 的 cue EDF6 的库里没有，
  也没人播）。**原因**：EDF6 带着 `TIKYUU4_EN_UFOROBO.ACB`（全部 `en_Robo_*` cue），但它的 SEPRESET 一个 4.1 名字都没有，所以插件按
  cue 名播（`edf41c::PlaySe`）；`check_sounds` 对 `edf41_se` 里的名字改查「cue 在对象加载的库里」。
- `material_animation`：4.1 的两块裸 MTAB（灯光）改成 `[[块 0, 0], [块 1, 2]]`（`ROBO_MATERIAL_PAIRS`，即 4.1 0x273FB2 / 0x274046 给
  0x32F9E0 的槽号；裸块是 EDF6 材质代码会崩的形式）。check_materials 照常查（两块动画的材质都在模型里）。EventAnimationObject 的构造
  不读这个键，插件自己交给 EDF6 的材质动画播放器（2.2）。
- `CLASS_NAMES['UfoRobo']`：插件播的状态与用的定位点必须在文件里。

### 2.2 插件（`src/edf41robo.cpp`）
- 对象由 **EventAnimationObject** 的构造（0x5B5FB0，0xC90）造，克隆虚表（槽 0 / 5 / 9 自己的，**槽 6 OnLevel** 也换）。
  - 构造后清 `+0x380 bit0`（EAO 构造置的「不掉血」，H）。
  - 槽 6：脚本 CreateEnemy 设等级（SetLevel 0x54E740）时调一次；EAO 原本 `return true` 不按等级缩放耐久，这里用 UfoCarrier508 的
    公式（0x4F6D00：`0xD7720(base × 等级/10)`，H）写最大 / 当前耐久，之后脚本的 3019 百分比照常生效（M416 的 80 %）。
  - 队伍：CreateEnemy 给 SetTeam(1, true)（H），所以它是敌人、会被计数、会成为友军 NPC 的目标。
  - **锁定点**：EAO 不登记锁定点（H），插件用 `AddLockTarget 0x547A50(obj)` 加一个，每帧把位置（`+0x10`）写成 MAB 定位点 `ロックオン`
    的位置。**`ロックオン` 在 MAB 的定位点表 1（锁定表）里**，不在表 0：`FindLocator 0x6BADD0(model, out, 表号, 名字)` 的第三个参数就是
    表号，UfoCarrier508 的锁定点组件 0x6C74E0 读的正是表 1（MAB+8+[+0x14]）。第一版按表 0 找、找不到，锁定点一直停在出生点（ds4_M007：
    整关都在 103 250 −361）；现在按表 1 找（找不到时退回骨骼 `hara1` 的原点），锁定点跟着胸口走（rf1_M007：出生 73 247 −347，之后
    85 430 −699 而对象在 92 433 −732；机器人 rf2_M411：177 214 −210 而对象脚下在 190 37 −212）。DevShoot 与玩家的锁定武器都瞄它。
- 每帧：AI → 身体状态机 → 运动 → 四组炮 → 写 `+0x60` 矩阵 →（机器人形态）脚 IK 目标 → 原 Update（模型 / 骨骼跟随矩阵）→ 读 CAS 时钟
  触发 MAB 事件 → 瞄准骨 → 灯光动画一步 → 锁定点。
- **MAB 事件**：插件自己比较主播放器的剪辑时间（`+0xE8`，与 MAB 事件时间同单位，巨龙模块实机验证过），越过即触发；同一状态时间回退
  = 下一段剪辑。`se`：按 `edf41_se` 播 cue。EDF6 的 MAB 事件回调登记（0x116BE30，唯一的调用者 0x502006）要的是一个带虚表、引用计数的
  函数对象（shared_ptr 形式）加 std::wstring 事件名，插件造不出与游戏同一个分配器的这种对象；比较时钟按同一份事件时间触发，帧数相同，
  所以不换。
- **`攻撃判定` = EDF6 自己的范围伤害**（4.1 0x277790 → 0x28B930）：
  - 先从定位点上方 50 m 向下 50 m 打地图射线（4.1 0x277A83），**打不到地面就什么都不发生**（0x277A8C），打到了一切都在地面那点；
  - 半径 = scale × 定位点自己的尺寸：MAB 第 0 类记录 `+0x10` 的浮点（脚 `足歩行衝撃` 20、手 `手攻撃範囲` 50；4.1 0x277B48 乘的就是它；
    第一版用定位点矩阵的行长 = 1，圆只有 1–3 m）；伤害 = damage × s；
  - 震屏（0x2E9B30）+ 尘土（ExplosionWind 0x2E4D90，scale × 尺寸 × 0.7）；
  - 伤害：`ApplyAreaDamage 0x542670(GDI*, bool* 命中, 命中集合 = 空, 跳过 = 自己)`。GDI 照 DragonSmall（0x32DBED，常驻 +0xA30）与
    UfoCarrier508 死亡（0x4F9C85..0x4F9DAA，栈上）的做法填：+0x10/+0x18 自己的弱引用、+0x24 队伍、+0x30 中心、+0x40 冲量 (0,0,0,1)、
    +0x50 伤害、+0x58 半径、+0x60 标志 2（爆炸性：被踩的士兵倒地）、+0x64 = 0.5、+0x68 = 1.0、子命中向量空。函数自己做 AABB 查询、按
    GDI+0x24 的队伍过滤（只打敌对的：玩家、EDF NPC、他们的载具；本队的 UFO 不打）、给每个对象发一份伤害消息（0x543920）；命中集合
    传空是允许的（0x5439CF 判空）。什么都不画，和 4.1 一样。旧的手雷替身（`edf41c::Blast`）不再用。
- **炮**：炮口 = MAB 定位点（`robo_*_muzzle_setting`），方向 = 炮口 +Z 转向目标、至多转瞄准上限，再在散布锥内随机；子弹用
  `edf41c::FireSe`（= Fire，外加子弹 InitParam `+0x100` 的 SePreset：**命中音** `ロボビーム着弾小 / 中 / 大`，4.1 0x275730 给每组子弹
  参数的 `+0xB0` 填的就是它们；EDF6 InitParam 的构造 0x1001D0 在 +0x100 初始化这个 SePreset，插件按 `edf41_se` 的 cue 填）。
  - **瞄准骨**（4.1 0x27AC20 / 0x27BB70，只有膝 / 肩两组）：目标从瞄准骨的位置、在炮口定位点的坐标系（只按动画、不含本文件转的角）
    里看，得 pitch = −atan2(y, |xz|)、yaw = atan2(x, z)（0x51B490）；角度每帧走差值的 5 %、一步至多 0.01 rad；没有目标 / S3 巴斯特
    （+0x15F4 bit3）/ 死后回 0。写法：原 Update 之后 CAS 已经把这一帧的骨骼局部矩阵（骨骼记录 +0x70）写好，插件把它换成
    Rx(pitch)·Ry(yaw)·局部（4.1 是 0xE5810 乘在骨骼 +0x60 上）；下一帧 0x1100010 用它算世界矩阵，炮口跟着转。CAS 没重写时（矩阵还是
    插件上次写的）用上次记下的动画局部，避免累乘。`muzzle_small_l` 挂在 `small_gun_r` 上而它的瞄准骨是 `small_gun_l`（4.1 数据如此，照搬）。
  - **蓄力特效** `UfoRoboCanonChargeEffect`：EDF6 保留了这个类（构造 0x306B60，0x590），但**没有工厂名**（EDF.dll 里没有这个字符串），
    所以和 4.1 一样直接调它的创建函数 0x84A60(管理器, 出参弱引用, 矩阵, 参数)；参数 = InitParamBase（虚表 0x1762068，0x30）+ 4.1 模板
    的数（4.1 模板 +0x28..+0x48 → +0x30..+0x50，颜色 4.1 +0x50/+0x60/+0x70 → +0x60/+0x70/+0x80；对照 4.1 构造 0x1C51C0 与 EDF6
    0x306B60 读参数的顺序得出）。每组的模板照 4.1 0x2744B0 / 0x277C10：小 (1, 10, π/4, 20, 1, 0.05, 15, 3, 5) 色 (1.8, 0.8, 1.2)、
    中 (1.5, 30, π/4, 60, 1, 0.075, 15, 4, 6) 色 (1, 1.5, 1.8)、大 (3, 50, π/4, 80, 3, 0.1, 30, 7, 10) 色 (1, 1, 1.8)、手炮光束
    (3, 70, π/4, 90, 3, 0.2, 55, 7, 10) 色 (2, 2, 3.6)、歼灭 (8, 80, 0.967, 100, 3.5, 0.2, 50, 10, 13) 色 (1, 2, 1)。进 G1 时每个炮口
    一个，G1 里每帧 `0x307C40(特效, 炮口矩阵, dt)`（= 4.1 0x1C6280；EDF6 这个类的槽 5 是空的，粒子靠这一步走），离开 G1 删掉。
  - **炮口火光没做**：4.1 每发造一个 ParticleObject（贴图 ParticleAlpha_6.dds，寿命 组+0x3F0 = 10 / 35 / 60 帧，颜色 = 模板颜色，大小 =
    蓄力特效最后的强度，内含 PointLight；EDF41 0x27C3F7..0x27C5A7 → 0xC5BB0）。EDF6 有这个类（创建 0x844C0，构造 0x301110，参数虚表
    0x17620E8、0x1D0、析构 0x8FDF0），参数块大体同形（+0x1A0..+0x1B8 的指针字段一致），但贴图引用的位置与类型不同（4.1 +0x150 是带虚表的
    贴图持有对象；EDF6 的析构释放 +0x158，EffectGenUtil::Explosion 0x2E650C 用 0x8F000 装一个手工拼的引用），没把握照抄（填错是游戏里
    崩溃），留着。
- **目标**：GameObjectBase 自己的目标（0x30C0F0，每 60 帧换最近的敌对对象，瞄准其锁定点），没有时用玩家。
- **受击 / 死亡**（4.1 槽 11 0x275A30 = EDF6 **槽 18 OnDamaged(对象, GDI)**，ApplyDamage 0x5485F9 扣血之后调，EAO 原本是空的 0x54A280）：
  - 伤害消息 0xF0000000 在 S4 直接吞掉（= 4.1 槽 10）。
  - 活着：每次命中在对象处播 se_table[1]「ロボ被弾」；子弹命中（GDI +0x58 半径 0）在第一个子命中点放火花 —— EDF6 的 `MetalHit`
    （EffectGenUtil 0x2E8F20，子弹打金属用的那个；4.1 是 0x1B6AE0，尺寸 = (0.5 + 0.45 (1/s − 1)) × 伤害，EDF6 子弹给 MetalHit 的尺寸
    是 1–20 这个量级，所以夹到 [1, 20]，M）；飞行形态的移动刚体（4.1 +0x1D08）挨推：爆炸 ((r − 5) × 0.5 + 5) × 0.1 背离爆心，子弹 =

  - 死亡（第一次耐久 ≤ 0）：随机一个子命中点放爆炸（0x2E5ED0，尺寸 3，沿该点法线）；**ragdoll 接管**：先把全部刚体放回 ragdoll 碰撞层 6

    子弹 / 射线碰的层），地面挡不住 —— 第一次实机死亡整只掉穿地图；4.1 自己死亡时也是先把每个刚体的过滤改成层 6，0x275B30），再
    `0x6E40B0(ragdoll)`（全部刚体模式 4 = 动态，约束打开；ShootingTarget 死亡 0x5CB297 在同一布局上就是这么做的），并照 ShootingTarget

  - S10（8 + 7·rand 秒）：对象停在死的位置（骨骼归 ragdoll），灯光动画放第二段（4.1 0x278DEB）。S11：在 ragdoll 第 0 个刚体处

### 2.4 联机
没有移植 4.1 的同步（`+0x24F0..`）。每台机器各自跑这个类（脚本在每台机器上造它的话），位置 / 开火不同步；不会因此崩（没有任何只在
主机才有的指针）。**未在联机下跑过。**

### 2.5 规格更正
- M415 / M010 的 `CreateEnemy(…, 0.75, …)` 的第三个参数**不是尺寸**，是等级倍率（EDF6 原生 2000 `0x2154C0` 的 xmm3 level，
  PRIMITIVES §3/§10）：它们的 s 小 25 %（耐久、伤害、计时器都跟着变），模型大小不变。插件仍从创建矩阵的行长读缩放（= 1）。
