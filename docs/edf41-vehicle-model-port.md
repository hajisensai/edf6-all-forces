# EDF4.1 载具原模型移植核对

2026-10-19，针对「4.1 的坦克模型没有导入，V301 没有导；检查类似遗漏」的反馈。

## 根因与当前覆盖

原呼叫登记把 V301 的普通版和五款涂装全部指向 `v505_tank.sgo`；任务中的 V301 AI 坦克还套用 EDF5 重制模型。406 贝加尔塔和 302 直升机也分别指向 504、506 的重制载具。只替换 `animation_model` 会混用不同骨架、动画绝对位置、物理绑定或武器槽。

| 原载具 | 新覆盖 | 行为合同 | 保留的原资源 |
| --- | --- | --- | --- |
| V301 坦克 | 普通、五款宣传涂装、AI，共 7 个对象 | EDF6 `Vehicle505_Tank`，7 对轮；仅移植并重定向炮管后坐动画 | 原 MDB/DDS、18 个刚体的 SHKT、源座位/瞄点/炮口 MAB |
| 302 直升机 | 1 个对象、6 个对应机载武器别名 | EDF6 `Vehicle506_Helicopter`；原飞行配装加 EDF6 燃油两字段 | 原 MDB/DDS、原 CAS 绝对姿态、SHKT、武器挂点/炮口 |
| 406 贝加尔塔 | 普通/红/金/绿，共 4 个对象；16 种原武器 | EDF6 仍注册的 `VehicleBegaruta`；保留原 6 挂点；补足脚节点与 EDF6 驾驶员元数据 | 原机体、CAS、28 刚体 SHKT、私有目录中的原武器模型/动画 |
| 408 边三轮 | 1 个对象、独立炮手机枪、5 条请求 | `Vehicle_Car` 真三轮底盘 + 专属 seat1 原生 Aim / Pose 路由 | 原 MDB/DDS、8 代理 SHKT、双向绑定、单骨双轴枪、双座与炮口 |

合计 13 个真实模型对象、64 个模型 / 配置 Mods 文件，另有 13 个独立默认摆放 SGO（包括已移植的巴拉姆），共 77 个资源已实际解包核验 SHA256。45 条已有载具呼叫现在指向对应原载具。模型、声音等公用资源按现有归属登记安装；没有写游戏目录。

## 合同修复

- V301 的 CarBase 轮、物理体、约束、接触过滤、履带材质表都来自实际源骨骼与材质。原模型没有 505 的天线、挡泥板和 H/I 轮，不再保留这些悬空引用。原碰撞形状、质量和绑定保留，炮管后坐有唯一动画写者。
- 505 的 CAS 存储绝对局部位置，直接套用会把 301 的炮管从源 `z=0.723746` 拉回 `z=0.958056`。新 CAS 只保留 `cannon_slide`，把默认和开火轨迹重定向到源绑定位置，并保留后坐幅度。
- 302 的源呼叫是三列，EDF6 版本增加燃油块和燃油武器。旧的布局相等检查会整份回退到 506 配装。现在保留源装甲、七项飞行参数和原炮口别名，仅从模板补燃油字段。
- 406 直接使用原六挂点类；呼叫第 5 列的六武器槽保持原样。不会再扩成 504 的八槽或因布局不同回退到 504 武器。
- 406 在 EDF6 中缺失的音效 preset 只替换为已验证同一原 bank、同一 cue 的 504 命名；45 个 MAB 音效事件保留原时间与定位点。全部特殊载具的类音效表和 MAB 事件都会校验 preset 存在，且 cue 位于该载具实际加载或常驻的 bank；注册名存在而 bank 未加载也会被拒绝。16 种原武器补齐 HUD 名称。
- 4.1 的 `_light.rab` 是源安装也不存在的可选次模型；不把它视为可用模型或作为缺失资源补造。实际主模型独立保留。

EDF6 的 ragdoll loader 已内置旧 `hkpPhysicsData` 到 `hknpPhysicsSceneData` 的迁移，并保留刚体名称，见 `src/legacymap.cpp` 开头及对应 native RVA。这里通过该正常加载路径使用源 SHKT。

## M 直接摆放与呼叫原型分离

直接摆放的 native `ApplyMissionSetup` 读取 `mission_setup`。原呼叫用 V301/302/406 SGO 只具有 `vehicle_setup`，不能直接拿来创建任务载具。生成器现为这 11 个非 AI 对象生成私有 `OBJECT/EDF41_RANGE_<原对象名>.SGO`，只将最终 `vehicle_setup` 复制为 `mission_setup`，保留原字段。非 AI 巴拉姆现有 `mission_setup` 的武器列为空，因此也生成私有版本，默认包含两门巴拉姆炮。408 同样保留独立调用与摆放路径，合计 13 个私有 SGO，不为摆放副本复制模型或纹理。

本次私有副本生成不修改原调用 / AI SGO；此前 14 个加新增 408 共 15 个原型保持独立，AI 保留原任务调校。登记行的 `spawn_object` 指向私有文件，`files` 同时登记私有文件；地图和测试场沿稳定 ID 选取私有路径。私有版本保留原血量、完整武器调校，302 包含燃油字段及第四燃油槽，406 保留六挂点。

`test_edf41_vehicle_spawn_data.py` 5 项与 `test_edf41_vehicle_spawn.py` 3 项通过；真实游戏只读 `debug_spawn_resource_audit.py` 通过 297 项检查，零缺失资源。验证涵盖 classic SGO / DSGO 的源呼叫字节不变、最终默认字段一致、AI 设置独立及实际资源引用闭包。

## 验证与实机验收边界

`tests/test_edf41tank.py`、`tests/test_edf41heli.py`、`tests/test_edf41mech.py`、`tests/test_edf41_vehicle_calls.py`、`tests/test_edf41_vehicle_sounds.py` 加上 `tests/test_edf41bike.py` 共 36 项通过。覆盖打包资源的实际解包、源 DDS/骨骼/物理字节比对、绑定位置和旋转、302 的 CAS 高度与武器炮口、缺失节点/CAS 控制、错误刚体旋转和错误挂点的失败注入。另已用本机原游戏数据转换全部 45 条受影响呼叫，确认行内 `weapon` 快照与当前转换一致，其 SGO/RAB/CAS/SHKT 引用均能由原游戏或新登记闭包提供，77 个资源的实际解包 SHA-256 与登记一致。

这些证据来自离线数据与 native 代码核对；还需要实际任务验收上车、移动、炮塔/旋翼、开火、卸载与联机表现。

408 已进一步沿真实 CarBase / seat1 Aim 合同适配，见 `pylib/edf41bike.py` 与 `src/edf41bike.cpp`：保留原 8 代理、3 真实轮、双座与独立车载机枪，不复用装饰第三轮 / 自由站立射手。数据测试 `tests/test_edf41bike.py` 7 项通过；四职业拟合座位的骨盆最大残差 7.32 cm，姿态与实际驾驶 / 炮手表现仍待实机验收。当前真实模型总计 13 个源对象、64 个原模型配置资源；另有 13 个私有默认摆放 SGO，45 条相关请求。

## 2026-10-25 实机：406 跳跃崩溃（「维加泰跳跃会炸游戏」）

- 复现（本机，main 471bfc5 + #weaponrec 修复，`drive.py` 后台）：测试场 `DebugSpawn` 召唤 `VEHICLE406_BEGARUTA`，游骑兵上车，按一次跳跃即崩：`C0000005 at EDF.dll+0x64833E, writing 0x3EC`，栈 `0x64833E <- 0x638D22 <- 0x6443CA`（`EDF6.exe.89740.plugin.dmp`）。
- 根因：406 保留 EDF6 仍注册的 `VehicleBegaruta` 与 4.1 的 `begaruta_boost` 键，载具设定把它交给旧喷口解析 `0x636DCE -> 0x640340`（`begaruta_boost6` 走 `0x63DEC0`，`begaruta_boost5` 走 `0x63CEC0`）。喷口组 `vehicle+0x1BB0` 有四个槽（`+0x20 + i*0xA0`，喷焰发射器在 `+0x50`）；EDF6 自己的两种解析按骨骼一槽一个填满四槽（504 / 608 / 612 全用 boost5 / boost6），旧解析只循环两次（`0x640CB3 cmp rsi,2`），槽 2、3 的发射器留空。更新里两处循环不检查就写每个槽的发射器：状态步 `0x6482A0`（起跳 / 推进开始时由 `0x638CE7 / 0x638D1D` 调用，写 `+0x3EC` 强度与 `+0x3F0`）、推进停止 `0x638EF0`（写 `+0x3EC`）。崩溃转储里槽 0、1 有发射器，槽 2、3 为 null。原版数据从不走旧键，所以这条路径在原版从未运行过。
- 修复（`src/edf41mech_boost.cpp` / `.h`）：给这两处循环补上旧解析的约定——没建成的槽不是喷口，跳过对其发射器的写入。两段循环体各换成跳到近址桩，桩里执行原样指令、只把发射器写入放在 null 判断之后，再跳回循环步进；建成的槽（所有 EDF6 原版对象的每个槽）执行与原版逐字节相同的指令。406 仍按 4.1 的两组喷口显示。
- 检查：`tests/edf41mech_boost_test.cpp`（ctest `edf41mech_boost`，真实执行两个桩：空槽不写不崩、建成槽写入值与原版相同；变异：去掉 null 判断即访问违规）、`tests/edf41mech_boost_native_audit.py`（ctest `edf41mech_boost_native`：三条解析的键与调用、旧解析两槽、两处循环四槽、本类代码中再无其它写发射器的指令）。
- 实机（同一租约，修复后 DLL `8130a582…`，日志 `EDF41MECH boost: ... on`）：同样召唤 406、上车，起跳 / 空格 / 前推加推进共 8 轮，未崩，机体移动约 250 m（日志 `VEH ... Begaruta ... seats=[P] pos=(-407,6,-51)`）。原版 504 的跳跃本次未实机回归（其四槽全建成，走的仍是原版指令，单测覆盖）。
