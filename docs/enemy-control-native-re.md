# 敌方单位原生玩家输入契约

支持版本：Steam `EDF.dll`，TimeDateStamp `0x678CCB46`。本文据本机文件只读反汇编；不代表实机或双机验收。

## 共享入口

许多敌人已含原生玩家控制路径。它们共同使用 `GameObjectBase+0x340` 控制器指针、`+0x354` 玩家标志。`enemy_control_native.cpp` 只在真实输入虚槽调用期间借入一块合成控制器，`__finally` 恢复原指针和标志。对象身份由 `+0x30` 弱引用控制块核对。退出时仅释放原生输入命令，保留物理速度、状态机和动画。合成控制器驻留在稳定的 `NativeLease.pad` 中；页不可写、身份暂时不可读时保留恢复基线并报告失败。已死亡或标为删除但仍有强引用、身份仍匹配的对象，也必须归还借用的控制器字段；仅在强引用归零或对象地址已复用时遗忘。

运行层按对象复制完整主虚表（保留 RTTI），包装输入阶段和 AI 槽 7。控制期间跳过原 AI 决策，保留槽 4/5 中的移动、武器、CAS/MAB 事件。不能调用 `0x118A3E0 / 0x118A4B0` 反复移出、加入 AI 表：重新开启 bit 3 会再次运行虚槽 6，重建动作状态机。

## 控制器布局

四轴浮点值在 `+0x0C / +0x24 / +0x3C / +0x54`。按键记录自 `+0x70` 起，步长 `0x18`，每条 `+0` 为 held 字节、`+1` 为 pressed 字节。Humanoid 的 `0x470EB0` 是 `movzx ecx, byte ptr [rax+0x70]`，不是读取 float。飞行器另外读取 `+0xCC / +0xE4` 的升降模拟量；小乌贼通过第 6/7 按键的 held 控制升降。

`UfoSmall507` 的第 1/2 按键（pressed `+0x89 / +0xA1`）修改模型缩放，属于原生调试功能，不能作为战斗技能开放。`DropBoat512` 第 0 按键只启动原生舱门/降落转换，不提供移动轴。

原生技能有上下文。例如蚂蚁抓住目标时，主攻击转入 `capture_throw / capture_throw_over`，副攻击转入 `capture_bite / capture_impact / capture_swing`。应保留这条完整状态机；直接播放一个 CAS 状态既不等于完整技能，也可能越过具体变体的武器初始化条件。

## 释放输入

`Neutralize` 清除每个家族真实输入分支写入的命令字段。例如 InsectBase 的 `+0xFC0 / +0xFD0 / +0xFE0 / +0xFF0..3`、Walking 的 `+0x1290 / +0x12A0 / +0x12C0`、Humanoid 的 `+0x11D0 / +0x11E0 / +0x11F0..5`。Merman 动作号恢复 `-1`，Monster 的动作选择恢复原生默认 `0xFFFFFFFF / 0x8FFFFFFF`。这避免退出后仍持有射击或行走意图。

## 离线证据

- `tests/enemy_control_native_audit.py`：逐项检查实际 PE 中的 RTTI、主虚表长度、输入/AI 虚槽、28 个原生代码指纹、原生按键读取指令和继承调用链。
- `tests/enemy_control_native_fixture.cpp`：执行生产适配函数，覆盖合成输入、临时字段恢复、异常路径、弱身份以及退出意图释放。它使用私有合成内存和回调，不执行真实游戏对象。

## 随机数和网络协议

同一技能边沿同步两个真实 64 位游标：`+0x3E8` 是对象动作随机数，`+0x490` 是 SGO 范围/分布参数随机数。两者均由原生 LCG `state = state * 0x5D588B656C078965 + 0x269EC3` 推进。`0x6CDE00` 接受第二参数 `uint64_t*`；例如 `0x35A790` 把 `self+0x490` 传给它。持续按住和空闲帧不重置随机状态。Berserker 的原生攻击 tag 10 也写出 `+0x3E8`。这是原生数据契约证据，不等于实机双机一致性验收。

`NetworkObject` 的运动接口有两种真实形态。蚂蚁等的第 5/6 槽是具体 writer/reader，第 7 槽仅计数；另一些家族的第 5/6 槽通过 `0x125A70 / 0x125180` 转发第 7/8 槽。不能统一假设第 7/8 槽或任何非空函数就已同步根位置。联机准入由独立的 native pose 审计决定。

## 相机语义到原生移动、瞄准

输入协议保留相机绝对偏航/仰角。每个原生帧再按真实目标角反算 pad，避免把一次鼠标位移放入 30 Hz 最近值通道后丢失。Walking 使用目标角 `+0x1450/+0x1454` 与原生每帧步长 `+0xF9C`；Humanoid 使用 `+0x10D0/+0x10D4`、步长 `1/30`。原生俯仰为向下正，故取相机仰角的负值。其余族的控制目标、禁转条件与参数读取由 `enemy_control_native_look_extra.cpp` 的逐族代码和真实指纹固定；不直接写物体矩阵。

昆虫必须读 cling **目标四元数 `+0xE30`**，不能用另行平滑的绘制姿态；丝网蜘蛛用 `+0xE10`。昆虫转向还按原生 `+0x1070` 的惯性递推反算。盾兵通过原生 MAB 左/右转动作，保留 `.3/.1` 启动/保持阈值，不承诺它具备任意角连续转向。合法零转速和原生禁转状态输出零转向，保留相机与技能。

移动同样以真正被原生消费者读取的基准反投影：Walking 当前角 `+0x1444`、Humanoid 当前角 `+0x10E4`，而不是各自的目标角；TimeShip 移动用 `+0xFB0` 四元数，瞄准用另一目标四元数 `+0xFC0`。UFO507/515 的原生移动消费者明确直接读取 actor 的 `+0x60/+0x70/+0x80` 三轴，只有这两族按这些轴转换。**Deiroi 是例外：`+0xF10` 是世界方向，不能按身体 `+0xF44` 再旋转。** 壁面昆虫的移动留在原生切平面，相机朝向退化为法线时保留原生前向。

瞄准转换只解决控制器姿态。原生武器仍可能读取旧 AI 对象，例如 Large 的 `0x34E470`；受控武器由另一个类型明确的瞄准层提供同源 aim point。不能通过假造 GameObject 或把任意旧目标当相机目标绕过。

## 插件自身包装与恢复编排

`RegisterControlledAiExtension` 只接受目录内准确的原生 vtable/AI RVA，由注册者证明当前全局槽是自身已知包装。受控期间只运行其明确维护部分，既不重新运行原 AI，也不宽泛接受外部钩。可选 `onSeed` 同步移植技能自身的随机数状态。

`NativeLease.restoreGate` 是待恢复原生事务的前置闸门。网络姿态层在任何回滚 journal/写入之前设置它；只要闸门失败，`NativeRestore` 保留租约及弱引用基线，不得发送恢复完成确认。这样输入层不依赖网络模块，也不会越过未完成的物理回滚。
