# 2026-10-09 新功能：断剑式运输、直升机机降、运输机空降

分支 `feat/fb1009b-transport`，基于整合分支 `fix/fb1009b-rts`（已含地图指挥组、空中组、支援入场组）。
**本文所有内容只做了离线验证（编译、离线 check、运行时替身测试），没有进游戏实测。**

用户原话：

- 「飞机和直升机应该也有运输机。卡车之类的运输载具改成断剑那种操作方式」
- 「飞机就空降，飞翼的话可以直接飞下来不用降落伞」

用户确认的方案：机降呼叫 + 可指挥运输机；小队绑定载具，远距离自动接送。

## 1. 设计

### 数据结构与生命周期（`src/transport.cpp`）

| 数据 | 拥有者 | 生命周期 |
|---|---|---|
| 配对 `Pair{小队队长 ObjRef, 载具 ObjRef}`（32 条） | `transport.cpp` | 地图「上车」成功（`npcai.cpp` 命令处理）/「有人」运兵车·轻卡到达 / 直升机机降时建立；载具或小队消失、`WITHDRAW`、并入别的小队时删除；队长阵亡由 `npcai.cpp Succeed` 调 `TransportSucceed` 换成新队长；新关卡 `ResetTransports` 清空 |
| 行程 `Trip`（8 条，**按载具**，每条最多 4 个乘员小队，各带下车后要执行的命令） | `transport.cpp` | 一辆载具同一时间只跑一个行程；收集阶段（pickup / boarding）别的配对小队可以加入同一行程（一个 12 人大队 = 3 个小队同乘一架直升机） |
| 伞降 `Drop` 与伞兵 `Jumper` | `transport.cpp` | 运输机注册后到投完；每个伞兵到落地 / 死亡 / 180 秒 |

只在小队 AI 的权威端（单机 / 房主）运行；每帧由 `map.cpp` 在 `SupportDispatchTick` 之后调用 `TransportTick`。

### 行程（纯逻辑 `src/transport_logic.h`）

`pickup → boarding → moving → (landing) → unloading → 结束`：

- **pickup**：有驾驶员时载具开 / 飞到小队旁边（直升机落在小队身边 25 米处），**无人驾驶的空车则小队走过去**（上车时驾驶座优先，所以小队自己会有人开车）。
- **boarding**：小队原地守住（不再被移动命令带走），每 2 秒重新分配一次座位（`NpcSquadBoardVehicle`，没有地图 BOARD 的 150 米限制）。25 秒内有人上车就出发，剩下的人步行。
- **moving**：地面载具按 `GroundNavigate` 的滚动路线（每段 120 米）走，路线点作为 `NpcPrepareVehicleRoutePost` 的岗位，跟支援车辆入场用的是同一套；直升机用 `HeliFerry` 飞过去。下车点在目的地前 40 米（直升机 60 米）。
- **landing**（只有直升机）：降落在下车点上，着地后才下人。
- **unloading**：`NpcSquadDismount`（原生 SeatKick）。全员下车后把原命令交还给小队（攻击移动 / 移动 / 守点），载具原地待命，直升机改为守下车点。
- 异常处理：载具消失、没人驾驶且还在移动、各阶段超时，都结束行程，小队步行执行原命令；静止时会先让小队下车。

### 命令接入（不另写一套驾驶）

- `npcai.cpp NpcSquadCommandForRequester`：
  - 点位命令先问 `TransportOrder`。由运输接手时，命令被接受，小队自己的命令暂时不改。
  - `withdraw` 交给 `TransportWithdraw`。
  - 其他命令调 `TransportCancel`，把小队移出当前行程。
- `mapcmd.cpp`：
  - `Takes`：已配对的乘车小队接受点位命令和 `withdraw`。
  - `Give`：对载着配对小队的载具下点位命令，转成小队自己的运输行程；小队若也被选中，就不重复下令。
  - 框选去重规则沿用地图指挥组：乘车小队不被框选，由载具代表。
- 新命令 `Order::withdraw`，追加在枚举末尾，线上值 11。命令协议升到 v4，旧版对端拒收，不会误执行。新增拒绝原因 `noTransport`。
- 命令卡新增「载具撤离」按钮。地图上在步行小队和它的载具之间画细线，行程中亮显。

### 撤离（复用支援组的 `Retire`）

`support_dispatch.cpp SupportWithdrawVehicle`：

- **直升机**：`HeliStartLeaving`；飞远后由 `Retire` 先删机组再删机体。`Retire` 改为只删**仍在机上**的机组：机降的乘客也挂在这架直升机下（role 相同），下机后在地面作战的小队不能被删。
- **运输机**：`JetWithdrawNow`。
- **地面支援车辆**：沿地面路线开回自己的入场点（`WithdrawGround`）；到达后删车上自己的机组，座位空了再删车。没人驾驶时就地删除。
- 非支援载具不能撤离（返回 `noTransport`）。载具在行进中、小队还在车上时拒绝；静止时先让小队下车。

### 支援栏新增四项（追加在 catalog 末尾，旧序号、ini 键、线上值都不变）

| 键 | 名称 | 内容 |
|---|---|---|
| `SQUAD_HELI` / `PLATOON_HELI` | 直升机机降·小队（4人）/ 大队（12人） | 运输直升机从场外空中入场（沿用空中支援的 `BoardAirborne`），驾驶员和 4 / 12 名士兵在机内生成并当场入座；`Assign` 时编成小队（每 4 人一个队长），用 `TransportDeliver` 交给运输模块：飞到目标前 60 米降落、下机守点，直升机留场作它们的载具（`HeliKeep`：燃料或弹药用尽不自行离场，只在重伤时离场） |
| `SQUAD_AIRDROP` / `PLATOON_AIRDROP` | 运输机空降·小队 / 大队 | 运输机空中入场，`JetFerry`：不攻击任何目标，直飞目标点，离目标 150 米高。进入 400 米范围后乘客每 0.35 秒跳一人（`NpcMoveSeat` 原生下车）。翼人不开伞自己飞下来，其他兵种张开降落伞（与玩家弹射同一个伞面物体 `ChuteCanopyMake`，下落限速 6 m/s，水平速度逐渐衰减）。落地后守目标点；投完后运输机离场，由 `Retire` 删除 |

「有人」的运兵车 / 轻卡（坦克除外）到达目的地后，乘客座上的士兵编成一个小队，与车配对并下车守点；驾驶员留在车上待命。这就是用户说的「卡车改成断剑那种」。

联机：
- 新增支援能力位 `kCapTransports`，线格式仍是 v2。只有房间里全员都具备时，房主才规划这四项；否则拒绝并在 HUD 说明需要全员更新。
- 远端小队（另一台机器的权威）的配对状态在那台机器上，本机地图上不显示它的「载具撤离」，乘车的远端小队也不接点位命令。这是已知限制。

## 2. 逆向 / 资源证据

只读 Root.cpk（`tools/make_jets.py` 的 `vc.Game`），原版座位：

| SGO | 座位 | 说明 |
|---|---|---|
| `VEHICLE410_HELI`（Brute） | 3 | 驾驶（掩码 9）+ 左右门炮手（掩码 15，`410_HELI_GUNNER_L/R`，按键行 6），**三个座位共用同一组上车口 / 座位定位点** |
| `V506_HELI` / `VEHICLE409_HELI` | 1 | 只有驾驶 |
| `V507_RESCUETANK_AI`（运兵车） | 5 | 驾驶 + 4 个 `507_RESCUE_SHEET1..4`（掩码 143） |
| `V512_KEITRUCK_BGP`（轻卡） | 5 | 驾驶 + 4 个 `512_KEITRUCK_SHEET1..4`（掩码 15） |
| 实机日志 `VEH ... seats=[...]` | 410=3、506=1/2、409=1 | 与上表一致 |

原版没有能载一个小队的直升机或固定翼。做法与炮舰机加炮手座位（`with_gunner_seat`）相同：复制机体已有座位的定位点，套用 410 门炮手的姿势和按键行，掩码 15，乘客座上不挂武器。

- `EDF6VC_HELI_TRANSPORT.SGO`：410 + 10 个乘客座 = 13 座，可载 12 人（门炮手座上的人会操作门炮）。
- `EDF6VC_JET_TRANSPORT.SGO`：bomber401 打击机 + 12 个乘客座 = 13 座。mark 7001，所以插件按打击机来飞它，再用 `ferry` 标志关掉索敌。

`check_passenger_seats` 生成时会校验：座位数、乘客座的掩码 / 姿势 / 按键行、定位点来自原版座位、乘客座上没挂武器。

固定翼不降落载人：用户要的是空降，伞降也不需要跑道（参见支援组「空中支援不需要真起飞」）。

## 4. 未在游戏里验证（如实）

1. **新 SGO 的座位在游戏里的表现**：
   - 乘客座都复用原版那一组定位点，乘客模型会重叠在门口 / 驾驶舱位置。
   - 13 座的 410 和 bomber401 能否正常生成、上下人，都没有验证。
   - 如果原生 RideVehicle 拒绝复用定位点的座位，机降和空降会在生成时回滚，日志里会有 `crew seated in aircraft` 不足。
2. 直升机按 ferry 降落时，是否会落在建筑或斜坡上；`kFerryLandNear` 80 米开始下降是否合适。
3. 运输机 150 米高的空降：伞兵从机舱下车时，原生下车会把人放在哪里、给什么速度；伞面是否正确跟随 NPC。
4. 地面载具的滚动路线在城市里走得怎样（与支援入场同一套规划器，但段长 120 米）。
5. 门炮手座上的小队成员会不会开火（NPC 炮手逻辑本来就处理 410 门炮）。
6. 联机：没有做双机测试。远端小队的配对状态只在权威端。
7. 撤离只对本机生成的支援载具有效；任务关卡里原有的载具只能配对、不能撤离。
