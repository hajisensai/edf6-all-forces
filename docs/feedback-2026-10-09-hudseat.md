## 1. 「上了载具以后，可以把原版的左上角的血条hud隐藏吧，我们已经有自制的hud了」

**原因**：不是缺陷，是此前有意保留。左上角是 `HUiHudPowerGuage`（玩家护甲 + 载具耐久同一个布局），`docs/hud-re.md` §9.3（旧版）
因为「只藏载具条会连护甲一起动」而不改，`main:src/stockgauge.cpp` 只处理武器栏。

**为什么不复用 M 地图那套**：地图用的是镜头 `+0x200` 整体开关（`map_stock_hud.h`），会把雷达、武器栏、准星一起藏掉，坐车时不能用。
复用的是同一套**记录**（`maphud::Record` / `maphud::Step`：按住期间是这个字节的唯一所有者、放开时写回按住前的值、换关后旧记录不盲写），
被按住的字节换成护甲仪表布局根节点的显示标记。

**逆向（静态，H 除注明外）**：vtable `0x17FCC98`（构造 `0x825250` 的 `0x825290`），第 1 槽更新 `0x827010`；
HUiHud 基类 `0x816080` 按名字 `Guage_Root` 取根节点存进对象 `+0x788`（控制块 `+0x790`），构造在 `0x825438` 调它；
节点 `+0x1F8` 是显示标记（节点构造 `0x7E999C` 置 1，原版武器栏布局 `0x832348` 写 0 藏面板）。全 .text 扫 `+0x1F8` 写入，
护甲仪表自身代码和基类更新都不写它。根节点为 0 时整棵子树不画：由武器栏面板（含子文字）的行为类推，**M**。

**修法**：
- `src/stockgauge.cpp:186` `ArmorHook`：串在护甲仪表第 1 槽之后（与武器栏同样的 vtable 槽串接，`InstallArmorGauge` `:233`，
  7 处签名任一不符只关这一项）；覆盖判据与武器栏完全同一个（`SetStockGaugeCover` 发布的所乘载具 + 仪表拥有者 `RideOf`，
  `HideStockGauges` 与 `Enabled`）。
- `src/stock_armor_hud.h`：每块仪表一条 `maphud::Record`，`Slot` 选槽（自己的 → 空闲 → 最老一关的旧记录），`Step` 调 `maphud::Step`。
- 生命周期：上车隐藏；换座（仍在车上、仍覆盖）保持；下车、载具被毁（玩家离车）、换到插件 HUD 不覆盖的载具、插件 HUD 画不出文字、
  `HideStockGauges=0`、`Enabled=0` 都在下一次更新写回；换关 `ResetStockGauges` 推进代数，旧仪表不再被写，同地址的新仪表写回显示值。
- 坐车期间玩家自己的护甲数字也随之不显示（一个布局，无法只藏载具部分）；README 已注明。

**测试**：`tools/armor_hud_check.cpp`（18 条）：上车 / 换座 / 下车 / 原本就是 0 的标记保持 0 / 按住期间被写 1 / 换关异地址不碰 /
换关同地址恢复 / 双人分屏各自 / 旧记录让位。

**未实机验证**：整块是否真的消失（根节点标记对子树生效是 M）、下车恢复、与地图 `+0x200` 叠加、双人分屏。

## 2. 「切换载具席位的时候，旧席位会显示有人，切换不回去」

**日志证据**：
- `00:03:28.933 SEAT … moved seat 0 -> 1`，42 ms 后 `00:03:28.975 … moved seat 1 -> 0`：一次按 F 换了两次（弹回原座）。
  同一帧 `GUNNER … trigger 0.00 (pad) …`：键盘玩家的新座位读成「手柄」。
- `11:25:48.007 moved seat 0 -> 1` 后 32 ms `seat 1 refused (taken …)`；`10:57:40.575 moved 0 -> 1` 后 28 ms `seat 1 refused`：
  数字键换完下一两帧又被当成一次按下，`number == at` 被拒，座位行变琥珀色「坐席 2 有人」——用户看到的「显示有人」。
- `10:57:40.575 the driver seat empty: an NPC driver seated`：离开驾驶座后 `SeatPilot` 派了 NPC 司机进去，之后 F 只找**空**座，
  驾驶座永远轮不到——「切换不回去」。

**根因**：
- `main:src/seatswitch.cpp:256-262`：按键的「上一帧按住」状态是透过当前座位的输入模式字节 `+0x2B0` 读的
  （`keys ? KeyDown : 座位按键字`，数字键 `down=keys && …`）。玩家没坐过的座位 `+0x2B0` / `+0x2E8` 是旧值
  （座位构造 `0x6291B0` 不初始化 `+0x2B0`），玩家自己的写入（HumanBase 第 4 槽 `0x572DF0`）在本帧载具输入之后。
  换座后一帧 `keys` 为假，按住状态被清成松开，下一帧仍按着的键被当成新的一次按下。
- `main:src/seatswitch.cpp:212`：下一座键只接受 `SeatHolder::empty`。

占用表本身没有问题：`0x634940` 清座位（`+0x260/+0x268`，以及载具 `+0x628` 的位，推测是占用 / 同步位）在换座第一步就做了，旧座位不会残留玩家；
联机广播（消息 6）未改。

**修法**（`src/seat_switch_logic.h`，`src/seatswitch.cpp`）：
- 换座读出旧座位的玩家输入模式与按键字（`seatswitch.cpp:171`，在离座清零之前），`Take` 写进新座位（`:154`，`CarryRiderInput`）：
  这正是玩家下一步自己会写的值，新座位从换座那一帧起就按玩家的输入读。
- 按键的按住状态跟着物理按键本身（`seatsw::Press`，每帧都更新；键盘和手柄按钮各一份，`:261` 起），座位的输入模式只决定用哪一份，
  模式字节翻一帧也不会再造出第二次按下。
- 下一座键按顺序轮到每个能坐的座位（`seatsw::Wanted`：空座或可对调的 NPC，`MayTake` 原样），和数字键一致。

**测试**：`tools/seat_switch_check.cpp`（12 条）：按住跨过换座只算一次、旧读法会算两次（复现日志）、松开再按算第二次；
输入模式 / 按键字带到新座位且不写别处；Titan 三座轮转（司机 NPC → 炮手 → 空座 → 回驾驶座对调）；跳过别的玩家；数字键边界。

**未实机验证**：手柄 B 换座、联机（`SeatSwitchOnline=1`）其它机器上的座位显示、炮舰机两座。

## 3. 「这个俯瞰视角有问题，计算明显不对，稍微远就跳到了指数级别的距离」

**日志证据**（11:25，Titan，`b89d26a`）：`pitch=0.4`（炮口下俯 0.4°）`range=122`，`pitch=3.0` `range=66`，
`pitch=-2.1`（上仰 2.1°）`range=2409`，之后一直 2409——镜头跳到 2.4 km 外。

**根因**：`main:src/turretcam.cpp:186-190` `ShotFocus`：没有落地时直接用 `RoundLands` 返回的「寿命末端 / 搜索球面」点（空中），
`ImpactPlace` 再把镜头放在它上方 45 m、后方 35 m（大车按比例放大）。平射炮略微上仰，炮弹寿命在空中耗尽，观察点 = 2.4 km 外、
几十到几百米高的空中点；离线复现：同一参数的平射炮旧观察点最高到 2380 m 高，榴弹炮 1843 m。另一处：搜索范围是 3 km 的三维球面，
按 15 帧一段检查，炮弹在高处穿出球面时观察距离会按段跳动（离线扫描抓到榴弹炮约 45 m 的不连续）。

**修法**：
- `src/turretcam.h:111` `tcam::HighFocus`：落地且水平距离 ≤ 上限 → 真实落点；否则 → 炮弹终点（或落点）方向上、水平距离
  `min(终点水平距离, 上限)` 处的**地面**（`src/turretcam.cpp:190` `ShotFocus` 竖直向下打地图射线求地面高度，没有就用车体高度）。
  上限 `kSightFar` = 3 km；无法预测的导弹沿炮口方向、上限 `kAimFar` 800 m。不在空中、不超过炮弹自身射程。
- 落地搜索放到 `kFocusSearch` = 6 km（上限的两倍），炮弹穿出搜索球面时水平距离已经超过上限，观察距离停在上限而不是随高度回退。
- 平地上观察距离对仰角连续，升到最远射角后只降（单峰）。平射炮接近水平时真实落点按「炮口高度 ÷ tan(俯角)」增长，
  这一段仍然灵敏（离线：0.01° 一步最多变 56 m），这是落点本身的几何，不是计算错误；现在被炮弹射程和 3 km 封顶，且停在地面上。

**测试**：`tools/turret_cam_check.cpp` 新增 `HighFocusSweep`：喀秋莎 / 榴弹炮 / 平射炮从 −30° 扫到 85°（0.01° 一步），
用生产的 `rounds::FirstHit` + `tcam::HighFocus` + 竖直找地面，检查：始终在地面、不超过射程和 3 km、单峰、步长缩到 1/4 时最大变化
至少减半（真跳变不会随步长缩小）；并检查旧观察点对平射炮在空中 100 m 以上（复现日志）。
`tools/turret_cam_runtime_check.cpp` 里两条钉住旧行为（「没有落地保留空中寿命末端」「导弹沿炮口 500 m 以上」）改为新契约。

**未实机验证**：真实地形上的观察手感；Titan 等平射炮近水平那一段仍然灵敏，是否还需要另行处理（例如 `HighCamClass=1` 只给间接火力车）
需要用户试过再定。
