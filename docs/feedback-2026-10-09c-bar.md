用户原话：「支援栏是断剑那种，先点载具，然后选里面的人并且可以点多次，直到座位满」「上车声是原版的上载具声音」。

## 1. 断剑式编组

### 数据

- 编组 = `support_call.h SupportLoadout`：按座位顺序的兵种列表，第 i 名在 `i % 4 == 0` 时是其小队的队长（与所有步兵计划同一规则），所以每 4 人一支独立小队。
- 兵种表 `SupportWeapon` 在 5 种游骑兵之后追加 9 种 Root.cpk 现成的 NPC 模板（只读核对，`tests/support_soldier_native_audit.py` 39 项通过）：
  - 翼人 `N606_AIPALEWING_{LANCE,LR,MS,IZN,TB}[_LEADER]`，类 `PaleWing`，`EDF6_wingDiver.cas`；
  - 重装 `N607_AIHEAVYARMOR_{SC,SMC,SP,SSG}[_LEADER]`，类 `HeavyArmor`，`EDF6HeavyArmor.cas`；
  - Root.cpk 没有空袭兵的 AI 模板（`N60*` 共 56 个文件，只读列举），所以不提供。
  - 座位兵种掩码（只读 SGO）：运兵车乘客座 143、轻卡 15、运输直升机 / 运输机乘客座 15，四个兵种都能坐。
  - ini 的武器项仍只认 5 种游骑兵（`kSupportRangerWeaponCount`，安装器菜单与 `support_config_ini_test.py` 不变）。
- 可编组的支援与座位（`SupportCallSeats`）：步兵小队 / 大队 12，运输直升机 / 运输机 12，有人的运兵车 / 轻卡 4（原版 5 座去掉驾驶座）；坦克、空车交付、空中打击 0（照旧直接呼叫）。
- 初始编组（`SupportCallPreset`）= 不编组时会来的兵：小队 4 人（ini 的队长武器 + 队员武器），大队 12 人（ini 的三队武器）。

### 界面（`map_buttons.h ComposePanel / ComposeApply`，`hud.cpp MapComposePanel`）

点支援栏里有座位的那一项（或 C 键呼叫已选中的那项）= 武装它并在支援栏右侧打开编组面板：

- 标题：`<名称>  座位 已用 / 总数`；
- 一行小队格（座位 / 4 个）：每格显示该小队的兵种与人数，**点一下移除这支小队**（后面的前移）；
- 三行兵种（游骑兵 / 翼人 / 重装），**点一下加入一整支该兵种的小队（4 人）**；剩余座位放不下一支小队时按钮变灰，点击无效并提示；
- 左键点地图 = 按当前编组投送（`SupportCallComposedAt`），右键 = 取消。
- 阵形菜单与已武装的支援（编组面板）互斥：打开阵形菜单会解除武装（与 `Arm` 的「一次只武装一样」一致；`hud_view` 发现两者重叠后修正）。

### 计划与联机

- 编组随请求发给房主：打包成 64 位（4 位人数 + 每人 4 位兵种），放在请求消息的 `challenge` 字段——请求本来不用这个字段，旧房主也不读它，线格式仍是 v2。
- 新能力位 `kCapLoadout`（hello 能力 8）。房主只有在所有对端都宣告它时才按编组规划；否则按该支援自己的兵员规划，并在 HUD 说明「房间里有旧版，本次按默认兵员出动（自选编组未同步）」（日志 `SUPPORT plan catalog=N: a peer runs an older All Forces (no composed loads)`）。
- `Validate` 放宽为结构校验：步兵 1–12 人、运输机 1–12 名乘员、有人车辆 驾驶员 + 至多（座位数 − 1）名乘客（乘客可含队长）；队长位置规则不变；13 名乘员、6 人坐 5 座的运兵车照样拒绝。旧房主发来的旧计划（4 / 12 人、全员队员）仍然通过。
- 编组超出座位（或格式错）：本机直接拒绝并提示「兵员超过该支援的座位数」，不发请求。
- 投送后：直升机机降按每 4 人一支小队交给运输直升机（`TransportDeliver` 最多 3 支，均与直升机配对）；运兵车 / 轻卡到达后乘客成为与车配对的小队（4 座 = 1 支）；步行入场的每支小队各走各的；运输机空降照旧。

## 2. 支援到场的上车声（原版上载具音）

### 根因（逆向，EDF.dll 只读）

- 车辆 `+0x628`（16 位）：低 n 位 = 第 i 个座位有人（车辆上次看到的），第 i 位左移 `[+0x620]`（= 座位数，`0x629450` 设置时 `0x629C8F` 写入）= 该座位本帧有变化。
- 座位扫描 `0x62EEC0`（循环 `0x62F160..0x62F1BD`）：座位乘员（seat `+0x268`）与它的位不一致 → 翻转该位并置变化位；`0x634940` 清座位时同样置变化位。
- 车 / 直升机 / 机甲的更新（`0x674B1A` / `0x652713` / `0x6437D0`）调用 `0x632A60(车, 搭乘预设, 降车预设)`（车的 `car_base_se_table[8] 搭乗 / [9] 降車`）：有变化位的座位，有人就在座位处播搭乘音，没人播降车音（`0x7B4510`）；基类更新 `0x630596`（`and [+0x628], [+0x624]`）清掉变化位。
- 支援的机组是在空中 / 车里**直接创建并入座**的（`BoardAirborne → NpcSeatCrewNow → RideVehicle`），车辆的下一次扫描把这些座位当成「刚有人上来」，于是播原版搭乘音。

### 修法

- `src/seat_events.h`（纯逻辑）：`Quiet(mask, shift, seat)` = 「这个座位一开始就有人」时车辆应有的位（置占用位、清变化位），算法逐位照抄原生（座位位是 8 位 `shl al,cl`，8 号以后的座位原生不跟踪；变化位是 16 位 `shl ax,cl`，超出 15 位即无）。
- `npcai.cpp NpcSeatCrewNow`（只用于「生成即入座」）在每个入座成功的座位上写 `Quiet`。步行上车（`NpcBoardCrew`）、下车照常发声。
- 签名守卫：`0x632AC6`（`mov ecx,[rsi+0x620]; shl al,cl; test [rsi+0x628],al`）与 `0x62F1AA`（`mov [rsi+0x628],dx; mov ecx,[rsi+0x620]; shl ax,cl`）字节不符时不写，日志 `NPCAI vehicle seat events not as read`，行为退回原来（有声音），不会写错内存。

## 3. 运输机空投载具（澄清需求，本轮**未实现**，只做了逆向；后续已实现为直升机投送：docs/airdrop-vehicle-re.md）

原版有现成的空中投送链（`docs/online-re.md` §2.3、`docs/player-jet-re.md` §13.1）：载具请求 Weapon_Sub → 信号弹 → **Transporter508**（slot 50 `0x5E5070` 生成集装箱）→ **Transporter_Container**（V509 集装箱）→ 落地卸车态 `0x5E8C00` 按集装箱 `+0xB80` 的 SGO 路径 `CreateObject` 载具（`0x5E8FDC`），`SetTeam(veh,5,1)`，`veh+0x67C = container+0xBA0`，然后删除集装箱。本轮新查到：

| 事实 | 地址 | 置信度 |
|---|---|---|
| 集装箱配置函数 `0x5E8B40(container, shared_ptr<父对象>*, const wchar_t* 载具SGO, 载具设定*, float 等级)`：父对象写 `+0xB70/+0xB78`，路径写 `+0xB80`（wstring），设定经 `0x5E44F0` 拷进 `+0xC38`，等级写 `+0xBA0` | `0x5E8B40`，唯一调用点 `0x5E5687`（Transporter508 slot 50） | H（代码） |
| 集装箱由 `CreateObject 0x11945E0` 生成，InitParam 虚表 = `Transporter_Container::InitParam`（`0x17D7818`），带派生网络 ID（`0x776790`，`+0x778` 计数） | `0x5E5218..0x5E5260` | H |
| 运输机持有集装箱（`+0x790/+0x798`）；**释放**是运输机 slot 47 `0x5E5CE0` 调集装箱 `0x5E84D0`，之后集装箱自己落地、卸车、删除自己 | `0x5E5D3D` | H |
| 脚本 `CreateVehicle2` 的「空投方式」`0x633280` 只应用设定、写 `+0xE30=2 / +0xE34=等级`；`+0xE30` 只在网络快照 `0x62FBF0` 用到，**载具本身不会从空中落下** | `0x633280`、`0x62FBF0` | H |

结论与取舍：

- 可复用原版投放（不自写伞降）：插件运输机飞到目标上空时，生成 Transporter_Container → `0x5E8B40` 配置 → `0x5E84D0` 释放，集装箱按原版落地并生成载具。按原版设计**一个运输者一次只带一个集装箱 = 一辆载具**；集装箱生成载具时不看载具大小（原版用它送 59×77 m 的航母、普罗透斯），所以坦克 / 运兵车 / 轻卡都能投，不存在「运输机装不下」的取舍（运输机只是载体，载具在集装箱里）。
- 没有实现的原因：还缺两项原生参数没有逆清——`Transporter_Container::InitParam` 的其余字段（派生 ID 在联机下的含义），以及 `0x5E8B40` 第 4 个参数「载具设定」的结构（原版来自请求武器 `Ammo_CustomParameter[4][3]`）。盲调会在用户游戏里写错对象内存。原版卸出的载具是空车（队伍 5）：「有人」变体需要在落地后让同机空降的小队登车（`NpcBoardCrew`），还需要拿到卸出的载具对象（卸车态不返回它）。
- 下一步：用 `0x5E5687` 处的实参（在原版载具请求运行时）抓取设定结构；或直接借用插件已安装的载具请求武器（`tools/call_weapons.py` 已生成运输机 + 集装箱 + 载具 SGO 的请求行）在目标点发射一发请求弹，让原版整条链执行——这条更省逆向，但运输机是原版 V508 而不是插件运输机。
