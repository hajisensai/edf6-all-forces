# 玩家直升机左右抖：压坡反馈环（2026-10-11）

## 复现与根因

用户明确为自己驾驶直升机。现有本机日志在鼠标停止、横向键为 0 时仍记录偏航反向、roll 达到 ±1。
这不是 #140 的 NPC 避墙横推；玩家走 `heli.cpp AimFly`。

旧实现把原生姿态航向基底的差分平滑后存到 `Pilot.turn`，再用实际前向速度乘这个测得的转速计算自动压坡。
原生 `0x654A80` 在 `0x654B76..0x654E05` 先撤去记录的 pitch/roll、投影回水平、恢复航向。
机体尚未跟上目标压坡时，这个航向包含压坡自身的姿态瞬态；把其导数重新作为压坡目标形成反馈。
旧的水平偏航测试只积分 Y 轴，把 pitch/roll 留在机身外，未覆盖这条路径。

`tests/heli_yaw_native_audit.py` 新增全三维原生姿态仿真：执行原版 `0x654A80`、`0x6CE8D0`，
记录原生角速度并用 Rodrigues 公式在三轴积分机身矩阵。40 秒固定鼠标航向、下俯前飞场景，
旧控制在后 20 秒出现 **40 次横滚反向，最大压坡输入 1.000**。
夹具不调用 DllMain、不启动/附加游戏、不写安装目录；Havok 碰撞和相机不在验证范围。

## 修复

`heliaim.h PlayerBankInput` 用航向与速度指令计算压坡：Instructor 的 cyclic 目标速度 × 朝鼠标目标所需的转弯速度。
转速取已有 `kTurnGain` 和玩家转速上限，投影到原生 row 0 的转向符号；到达目标航向时压坡归零。
刹停/后飞按目标速度压坡，避免机头已抬起时仍用惯性前飞速度维持前飞压坡。
`AimFly` 删除测得转速的压坡状态；A/D 横移、原生偏航的速率反馈与逆滞后控制继续使用原路径。

验证：

- `heli_player_input_test` 113 项生产路径检查：向 row 0 的目标转弯保持正确压坡方向，已经朝向目标时测得偏航瞬态不能再驱动压坡。
- `heli_aim_check` 全部通过，覆盖鼠标跟随、横移、压坡、升降和悬停。
- 三维原生测试 20 个组合（俯仰 −0.6/−0.4/0/+0.4/+0.6 rad，机身响应 0.025/0.125，左右目标航向）：
  后段无压坡反向，最大航向误差 **0.0168°**，压坡输入最大 **0.0034**。

游戏内碰撞、实际画面与双机同步仍未实测。
