用户原话（五张截图作为视觉证据）：

- 除了喀秋莎其他俩卡车方向盘都原版的纸糊的

## 根因与变更

相机的 `Ride` 原来只拷贝眼点位置，保留原版世界水平朝向。改为从同一根 `vc_eye_<seat>` 获取正交化的完整矩阵，座舱和相机共同跟随席位骨骼。当前座舱视线沿席位标记，独立炮手瞄准镜继续由 sightzoom 接管。

仪表原来用屏幕四角投影和二维 HUD 单应映射，字不会随屏幕真正变形，也没有模型遮挡。新生成的座舱把数字段、刻度、标签、表针、条形读数、警告灯与导航触点建成模型网格；每个活动部件有 `vc_i_<seat>_<screen>_<control>` 骨骼，绑定数据在游戏线程的完整 HUD 快照产生后更新，只在载具模型绘制期间改 `inst+0x30` 姿态，绘制后逐字节恢复。原生骨骼世界矩阵、物理、武器与网络状态不改。三维表面参与游戏原本的深度遮挡。新模型关闭二维仪表与铺满视图的飞行 HUD；准星/目标标记、遥控瞄准镜继续保留。旧模型缺少活动骨骼时保留旧仪表路径，必须重新生成资源才能看到新仪表。

步兵原来以左手距枪轴 0.18 m 为逐帧显隐门槛，并对前臂/手掌施加不同旋转和包围盒吸附。改为两只手保留各自原生动画的握枪点、换弹动作与手指姿势；肩部目标只在两段骨长允许范围内移动，用连通的两段骨链解算共享肘部。肩甲随上臂，避免袖口边界分别变换；两段骨长保持不变。`FirstPersonArmIk` 仍控制矫正；旧 `FirstPersonHoldArc` / `FirstPersonWristMax` 配置保留解析兼容，新的骨链不使用独立绕枪轴滚动。

轻卡 `V512_KEITRUCK` / BGP 和拖挂车头 `V513_TRAILERTRUCK01CAB` 原来只有额外屏幕，继续用原版内饰。改用现有 pickup/cab-over 资产，先按原车壳适配，再移除限定车厢范围内朝向驾驶员的旧内表面，保留外壳与玻璃。玻璃关闭 `Window_Normal_Noise` 的法线强度，降低不透明度、反射和边缘雾化。改动在源模型摘要校验之后进行。

贴图准备工具的分辨率上限从 1024 改为 4096；这只保留原始资产已有的细节。当前 F-16 源贴图最高仅 1024，不能把放大当作高清重制。新仪表的刻度与标签使用几何，不依赖这张低分辨率图集；剩余舱壁、原模型装饰与旧机械表图案仍受源资产质量限制。

实机复查进一步发现，导入座舱还继承了坦克模板的 0.6 漫反射倍率和金属度，导致贴图偏暗。座舱改用非金属参数、保留源颜色；仪表文字/表针改用原生 `Light01` 自发光材质及它实际要求的 `param_r_m_occ_light` 贴图槽。普通部件继续用原生不透明材质。

后台测试的 `TestBoardVehicle` 支持可选 `@精确骨骼名`，例如 `506_Helicopter@bomber501`。原版直升机、战斗机与萨扎比共享 506 类，仅按类筛选会随机测到另一种模型；无后缀的现有测试保持兼容。

## 追加反馈：电刃刀握持与武器屏弧线

用户原话：「这个武器手持效果不对」「这表盘上好像有什么东西」。附件中可辨认的是电刃刀五式与喀秋莎武器屏。

- 静态核对：Root.cpk 武器表第 737 行 `hWeapon046`，中文名电刃刀五式，原生类 `Weapon_Swing`。旧 `AnchoredTransform` 每帧消除整根武器根骨的旋转，适合枪械沿枪口方向摆放，却同时消除了刀、锤、盾等原生持握转角和挥击转角。现在按经过映像范围校验的原生 RTTI 类契约，为 `Weapon_Swing`、`Weapon_ImpactHammer`、`Weapon_PileBanker`、`Weapon_Shield` 保留角色瞄准系中的原生旋转；根的位置继续按第一人称握把定位，手臂、手掌与武器共用同一个变换。没有为某个武器编号编造旋转补丁。
- 屏幕弧线确认为驾驶室模型表面的凸起。`real_cab` 原本只用屏幕中心与四角射线找放置深度，随后还会对驾驶室执行 `squeeze`。喀秋莎驾驶室中，屏幕内部一条约 6.7 mm 的凸起漏过了五条射线，实际穿进了显示面。现在在驾驶室变形完成后，将附近三角形裁到完整屏幕矩形，按所有裁剪交点的最前深度留出面板间隙，连同屏幕和外框一起放置。远处真正挡在前面的方向盘仍保留为遮挡物。
- 回归：合成凸起、后方表面、独立前方方向盘；实际 truck_cab 的状态屏与武器屏各采样 651 个点，修复前武器屏 64 点被穿插，修复后两个屏均为 0。新离线预览中的弧线消失。
- 实机：`fencer_melee_fp.ini` 强制装备电刃刀五式、FG7 手持格林机炮、曲面护盾、雷电·原力巨刃，检查待机、攻击和切换；刀的攻击截图可见刀身挥出，弹量从 5 降到 4。截图在本地 `tmp/fp-melee-runtime/`。DLL 实测 SHA-256 为 `3854a45e18c12da803faf148af3dc4e419ccf1c9d64719566f5608516f49f3b1`，与游戏内临时放置文件一致；测试后 DLL/配置逐字节恢复。
- 此次屏幕位置变化需要重建座舱模型；仅更新 DLL 无法改变已安装模型里的屏幕位置。
- 放大复查还发现仪表字符缺笔画：坦克模板的顶点位置为 half4，在驾驶室的模型坐标处，量化误差足以超过字符与黑色底板之间 1–2 mm 的间隙，导致两层三角形交叉。新造座舱网格改用 float4 位置声明，保留其余顶点元素并同步增加 stride/后续偏移；还移除了旧屏幕与新底板重合的四边形。近景离线渲染已能看到完整矩形字符段，标签与数字/警告灯的间距也分开了。

## 追加反馈：后座、跑步拉伸、激光偏位（2026-10-16）

用户原话：「武器没后座动画」「跑步会成橡皮人」「激光和枪位置不同」。截图中的组合为 M1 渡鸦、岩雷鸟 HA2。

### 根因和处理

- 后座原先依靠相机帧轮询 `weapon+0xBD0` 的正增量。实机连发观测为 `counter 0 events 1`：实际开火发生，轮询却没有读到正增量。现在在已有枪口火光创建挂点记录所属手的实际射击事件，下一次相机步进消费一次；与计数器观测取较大值，避免重复计数。开火后座使用独立的即时后移/抬枪通道，再阻尼回正，不再把微小射击速度混入通用移动弹簧。游戏原本的射击方向、伤害和网络数据不变。
- 压扁非手臂骨骼并不等于得到手臂网格：肩部混合权重三角形仍连接着身体，冲刺姿态会把它们拉成长片。现在颜色绘制只提交完全属于同一只可见手臂的三角形；连接躯干或跨左右手臂的面不提交。原 VB/IB 不改，过滤索引缓存在独立 GPU 缓冲里，绘制后恢复原 IB 绑定。非手臂画面骨骼也不再塌到眼点；阴影/第三人称继续走原路径，身体原生绘制仍执行以保持可见性和次级物理更新。
- 过滤依据每次绘制实际绑定的 VS 骨骼调色板，从当前 LOD 的骨名取得所有权。Root.cpk 中飞翼潜行兵主模型和 LOD 的骨序确实不同，不能拿基础骨序直接过滤所有 LOD。原生 60/64 字节蒙皮顶点声明均已核对。
- 岩雷鸟的直线激光是独立 `WeaponAttachment_LaserSight`，此前只有火光/抛物线提示跟随视图模型。现在只在本机武器的激光绘制期间，将可见起点乘该手的视图变换；真实射线起点/方向、命中落点、其它角色的激光不改，绘制后恢复附件状态。

### 证据和边界

- 新增 `fp_skin` CPU/WARP 测试：纯手臂面保留，混合躯干/肩部以及跨手臂面排除，骑乘时不提交身体颜色面；覆盖 60/64 字节声明、原顶点不改、原 GPU 绑定恢复。真实 D3D 软件设备的过滤测试通过。
- `fp_ride_lifecycle` 新增真实开火事件消费/去重、激光所属武器判断/起点变换/落点不改/逐字节恢复，以及 LOD 骨序选择回归；`fp_view_check` 检查后座首帧踢动、回正和连发上限。
- `fp_render_native_audit.py --dll EDF.dll` 对照当前原生二进制校验调用点、指令前缀、准备/材质通道/状态刷新调用关系、激光子对象偏移；另核对四个兵种及其 LOD 的蒙皮声明和手骨。已显式对实际 EDF.dll、Root.cpk 运行通过。常规 CTest 没配置 `EDF6_NATIVE_DLL` 时此项明确跳过。
- 单人后台实机：M1 单发/连发、切换岩雷鸟、激光、原生冲刺 `0x29E`；另跑飞翼潜行兵的 64 字节顶点路径。截图可见手臂正常显示、激光接回枪口、冲刺没有原图长片。Ranger 日志主网格索引约 `110919 -> 35808`，WG 主网格约 `69522 -> 14298`，非手臂网格为 0。
