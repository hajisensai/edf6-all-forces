## 根因一：开局「炮塔张开」= EDF6 构造函数播了 4.1 不播的片段（事实）

4.1 在构造时**不给船体和中型炮放任何片段**：船体构造 0x24ECE0 只按名找 `main` 播放器，初始状态 0x252700 不播片段；中型炮构造 0x258070
同样，初始休眠态 0x259CD0 不播片段，直到脚本动作 8（`+0x900`）才进 0x259D20 播 `appear` 并把播放器速度写成 1.0。所以 4.1 里两者在被
脚本启用之前显示的是模型的绑定姿态。

EDF6 的两个借来的构造函数**会**放片段：

| 对象 | EDF6 构造放的 | 数据里它是 | 结果 |
|---|---|---|---|
| 船体（UfoCarrier508 构造 0x4F6710） | `close_state`，速度 1（0x116C2D0 + 0x116DF20） | `MOTHER301_ALIAS` 把它别名到母舰的 `close` 片段：987 帧，从**张开**姿态（舱口骨骼转出、`weak` 在 −300）合上 | 出生时腹部张开、弱点露出，约 16 秒才合上 |
| 中型炮 ×10（EventAnimationObject 构造） | `default` | `MOTHER_PART_REST` 把它别名到中型炮唯一的片段 `appear`：141 键约 558 帧，`waist` 从 y 0 伸到 −360、四个束口舱门打开 | 约 9 秒内十门炮全部伸出并一直保持（片段不循环） |

绑定姿态（从 MDB 读）：船体的 = `close` 的末键（舱口 (0,−364.6,0) 不转；`weak` 绑定 y 0、片段里 −100，都在壳内）；中型炮的 = `appear`
的首键。4.1 里十门中型炮是第二阶段的武器（只有 M210 / M603 / M993 的脚本用动作 8 放出来），M016 / M110 / M123 根本不放；移植版每一关
开局就伸出，再加上腹部张开——这就是「一开始就是二阶段」和「炮塔莫名张开」。伸出的炮管指向斜下方外侧，船体低的关（y 600 / 410）
看上去扎进地面（推断：没有实机截图核对伸出后离地多少）。

**已排除**（事实）：状态机初值与 4.1 一致（船体合着 0x252700、主炮 close_state 0x256950、中型炮休眠 0x259CD0、板甲休眠 0x25D360、
舱门 close_state 0x25BB00）；进二阶段的条件（主炮对象删除后才接受弱点伤害、`+0x2F0` 由脚本 3020 写）照 4.1；脚本动作映射照 4.1
（M016 只发 3 / 7 / 4，M110 同，M123 不发任何动作）；UfoCarrier508 自己的舱门状态机初始是 0x4F82E0（等生成器波次，不放片段），
`0x20100` 与 `0x1000000D` 都被本类拦下，不会让载具自己去开舱。主炮、舱门、舱盖的 `default` 是静止的 `close_state`，与 4.1 一致。
联机：每台机器自己跑构造，问题与联机无关（推断）。

## 修复一

`src/edf41mother_pose.h`（纯逻辑，`tests/edf41mother_pose_test.cpp`）定每类在 4.1 里的静止姿态怎么落到 EDF6 构造已经开始的片段上；
`src/edf41mother.cpp` 用游戏自己的播放器设定函数（速度 0x116DF20、时间 0x116DF40，各两段指纹，不符只关这一项）：

- 中型炮第一帧、仍在休眠：时间 0、速度 0（`appear` 首键 = 绑定姿态，收着）；被动作 8 启用时 `PlayAppear`：`appear` 从 0 播、速度 1
  （= 4.1 0x259D20 写的 1.0；状态相同时 SetState 不重置时钟，所以显式写时间）。
- 船体第一帧、仍在合着态：时间 = 片段长度（`close` 末键 = 合上）。在 HullMain 之前做，M603 创建当帧的动作 3 照常在同一帧播 `open`。
- 不改数据，不需要重新生成 `edf41port/`。

## 根因二（附带发现）：部件的受伤消息号写错（事实）

GameObjectBase 槽 9（0x54A530）`add edx, 0xF0000000; cmp edx, 0xF`：伤害消息是 **0x10000000**（第 0 项 → ApplyDamage 0x547C30），伤害队列
0x543920 对直击和范围伤害发的都是它。本类 `PartMessage` 用的是 `edf41classes.h` 的 `kMsgDamage = 0xF0000000`，从来对不上：主炮 / 中型炮的
受伤音与「took」日志从未出现过（不影响扣血）。本类改为 0x10000000（`kMsgHit`）。`edf41classes.h` 的常量和 401 里的同名用法没动（并行任务
在改 401），合并时请一起看。

## 片状炮台伤害（「飞弹打片状炮台没伤害」）

片状炮台 = `mp_Panel` 的 125 块板甲（`UfoMother301_Panel` / `_Panel02`，EventAnimationObject 底）。

**已确认的事实**
- 4.1 0x250520：部件 `+0x900`（启用）为 0 时 `+0x1E8 bit0` = 免伤，只有强制伤害能过；板甲只由动作 13 启用。M016 / M110 / M123 的脚本
  **从不发 13**，M130 要等蚁群杀到 40 以下才发。所以这几关的板甲在 4.1 里同样打不动——不论子弹还是飞弹。移植版 `Masking` 照此
  （`kNoHpLoss` 位）。玩家若是在这几关（玩家最先遇到的三关）打的，这是 4.1 原样（推断：不知道玩家在哪一关）。
- 静止的两圈（第 3、4 组 63 块，`+0x904`）在 4.1 里不可锁定、不登记队伍，但启用后能挨打；移植版相同。
- 子弹能打坏启用的板甲：2026-10-15 实机 r02_M130_base，DevShoot 的 LaserBullet02 打掉 122/125 块。
- 飞弹 / 火箭（AmmoExplosion > 0）只走范围伤害：子弹核置 0x10，直击队列被清空（0x23268E），命中时调 ApplyAreaDamage 0x542670：
  按层 13（0x106070 → 0xD929F0(13)）做 AABB 查询，再对每个刚体：取对象（0x108200）、队伍关系（0x22E800，读刚体用户数据 +8 的队伍）、
  最近点（0x11AA270）、遮挡射线（0x11A77C0，GDI 标志 0x1000 时跳过），通过的发 0x10000000（0x541FF0 → 0x543920）。
- EventAnimationObject 构造把部件全部刚体放到碰撞层 **0x11**（0x5B6401 `0x6E9320(ragdoll, 0x11)`）；敌人本体用层 7（UfoCarrier508 0x4F6018、
  虫类 0x369A5C）。

**没能离线定下的**：层 13 的查询会不会碰到层 0x11 的刚体。EDF6 的 hkpGroupFilter（Config<5,5,5,16>，碰撞表在对象 +0x58，32 项）的默认构造
0xA3E710 是全开，但游戏用的那份是反序列化拷贝（0xA3E650 / 0x67DE40），表的内容来自数据，代码里没有写表的地方——读不出来。
若不相交，所有 EventAnimationObject 底的 4.1 部件（301 全部部件、401 全部面板、UfoRobo 活着时）都吃不到任何爆炸伤害（推断，未证实）。
**本次不按猜测改碰撞层**（改层会连带改变与地面 / 玩家的物理碰撞）。

**为实机判定加的开发开关**：ini `Edf41DevShootBlast`（默认 0）> 0 时，`Edf41DevShoot` 的每颗弹改成该半径的爆炸弹，走的正是飞弹那条范围
伤害路径；配合 `Edf41MotherForce=16`（各组启用不开火），日志里板甲的「took」行（本次修好的 0x10000000）与 `destroyed` 行直接回答
「爆炸能不能打到板甲」。
