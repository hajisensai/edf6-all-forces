对象：4.1 赫克托 21 个变体（`HECTOR301*` / `HECTOR401*`），EDF6 类 `EDF6_Berserker_Large`，插件 `src/edf41ai.cpp` + `src/hector_ai.h`。

## 3. 找到的问题与根因

### 3.1 战斗中横着走（主要问题，H）

- **4.1**（AI `0x223470`）：有目标时朝向目标 = 目标位置 − 自身位置（`0x2234B6..0x22353C`，任何距离都一样，没有路线），
  身体按 clamp(10 × 角差, −1, 1) × 0.03 rad/帧 转过去（`0x223874..0x2238A6`；10-17 文档写的「−0.85」不对，下限是 −1），
  行走命令**只写局部 z**（`+0x338`，`0x2238AE`）：前进 1，后退期 −1。永远沿自己的朝向走，不会横移。退速的旧记录误写成 0.85，审查更正见 4.1。
- **EDF6**：有目标时 Berserker 处于跟随状态 `0x34D890`：MoveTo 走向 `0x3408D0` 给的点（`+0x1A38` 对象 `+0x80` 加目标速度方向 × 提前量
  `+0x94`，即目标旁边的一个位置；不是寻路，M：`+0x80` 由谁更新没追），FaceTarget 却对着 `*(+0x1A38)+0x20`（目标）。于是身体对着玩家、
  腿往旁边的点走。走路状态 `0x540710` 只在行走向量偏 ±11.25° 以内才选 walk_l / walk_r（`0x53C4A0`，参数 0.3927 × 0.5），
  其余都播 walk_f / walk_b → 腿向前迈、身体横着滑。
- 插件原来只在 `near`（150）内接管，理由写的是「类自己的目标点会绕障碍」——`0x3408D0` 不是寻路，这条前提不成立（H）。
- 实测：修前 43 % 的行走帧偏离朝向 > 11°；id 11 在 (464, −299) 对着 426 m 外的玩家、行走向量偏 60°（局部 0.87, 0, 0.49）往一个点挤，
  被挡住原地踏步 140 s（H，`tmp` 日志 f=592..8392 位置不变）。

### 3.2 原地转身播 `stand`，脚底打滑（H，量小）

- 4.1（`0x2220E0` 选模式、`0x2224E0` 选状态与速率，每帧）：按这帧转角、缓动后的局部速度、行走命令决定——三者都≈0 站立；有转角且
  没命令（或转角 > 0.4 × 速度）播 turn_l / turn_r，速率 |转角| × v_turn_animation_speed（112）；否则按速度较大的局部轴播
  walk_f / b / l / r，速率 |速度| × v_walk_animation_speed（10）。
- EDF6 站立状态 `0x5405B0`（虚表槽 59）只在 FaceTarget 夹角 `+0x12A4` 超过 `+0xFA4` = 0.1（`0x53ABE8`）时才播转身，而 Berserker
  三个走路状态给 FaceTarget 的上限正好是 0.1（`0x34D8E9` / `0x34D95A` / `0x34DA6A`），所以永远不转身，速率也是夹角 × 112（比 4.1 快 3.3 倍，
  4.1 是实际转角 ≈ 0.3 × 夹角）。修前实测 180 帧「站立动作 + 身体在转」。

### 3.3 核对过、与 4.1 一致的（H）

- 行走速率：EDF6 `+0xFD4` = v_walk_animation_speed / 60（`0x53CFB1`），速率 = |缓动速度（单位/秒）| × 它 = 4.1 的 |0.1/帧| × 10 = 1.0。
  实测实际速度 ÷ 动画速度中位数 0.99–1.01，不滑步、不空踏。
- 根运动：4.1 的 walk 片段原地循环（waist xz 首尾相同，`globalSRT` 无平移通道），EDF6 叠加的根运动（`0x53D838` 读主播放器，
  `0x53D842` ÷ 1/60）为 0；只有 turn_*_start 有 0.33 单位 / −0.14 rad 的小根位移。
- walk_l = 局部 +x、turn_l = 偏航增大：两边约定相同（4.1 `0x2225CF`，EDF6 `0x53C4ED` 窗口 + 构造 `0x53CE3D`）。
- 瞬移：两次实跑都没有单帧 > 2 单位的位移（倒地起身、翻越在 10-17 已去掉）。

## 4. 修复

- `src/hector_ai.h` `Steer`：有目标时任何距离都接管（4.1 没有路线）；`PickGait` / `GaitRate`：4.1 的模式 / 状态 / 速率规则。
- `src/edf41ai.cpp`：
  - MoveTo 三处（`0x34D8D8` / `0x34D955` / `0x34DA65`）：目标点改成「自身位置 ± 100 × 自身矩阵 z 行（压平）」——只沿朝向前进 / 后退，
    速度 1 / 1 / 0（站定半径内），a = b = 0；
  - FaceTarget 三处（`0x34D8FD` / `0x34D96A` / `0x34DA7A`）：有目标时一律对着目标（`FaceHook`）；
  - 主播放器设状态（`0x116BFC0`，`0x540697` / `0x5406C1` / `0x5406DF` / `0x540821`）与设速率（`0x116DF20`，`0x5406F5` / `0x54083E`）：
    赫克托换成 4.1 的选择（从类自己的状态表 `+0x1000 / +0x1004 / +0x1008 / +0x101C..+0x1028` 取，战斗时它们已换成 walk_battle_*）。
  - 只作用于表里的赫克托（SGO `edf41_hector`），其它走路敌人不变；没有目标时仍用类自己的走法。
- 离线：`tools/hector_ai_check.cpp` 新增步态 20 条、改「远处也接管」2 条（686 项 0 失败）；`tools/selftest.py` `edf41_hector_gait`：
  插件的状态槽表与 `hector::Gait` 顺序、各钩子点、Steer 远处接管、FaceHook 用目标、MoveTo 只沿朝向；有游戏时核 EDF.dll 这些调用点的目标与
  构造函数按名字绑定的槽；有两作时核 CAS 的 10 / 112。
- 验证：`build.cmd`（/W4 /WX）通过；offline_checks + ctest 291 项 0 失败；`py -3.12 tools/selftest.py` 282/282（无游戏分支另测通过）。

### 4.1 合并审查更正（2026-10-18）

- **退速的根因（H，静态）**：旧记录把 `0x2237FF` 载入的常量当成 −0.85；当前 EDF41.exe（TimeDateStamp `0x57AAB039`）实际是
  `movss xmm7, [0xAB6B58]`，该浮点数为 **−1.0**。直到 `0x2238BB`，`xmm7` 没有再写；`0x22389E` 读 `+0x278`，`0x2238AE` 写前进命令，
  `0x2238BB` 把同一命令乘 `xmm7` 后写回 `+0x338`。`+0x278` 构造默认 1（`0x28D0EF`），所以前进与后退都是 **6 单位/秒**。
  插件 `kRetreatSpeed` 改为 `kWalkSpeed`，离线覆盖后退速度与动画速率 1；native 回归检查上述真实常量和指令链。上方实机对照是更正前
  0.85 退速版本的历史记录，没有用它冒充更正后实跑。
- **探针动态启用竞态**：原先先换虚表入口、再给 `realFrame` 赋值，游戏线程可在窗口内调用空原函数。改为先完成原函数 / 图像初始化，再用
  `InterlockedCompareExchangePointer` 发布入口；同时验证期望原入口，保留期间可能装上的其它钩子。
- **探针身份 / 容量**：原先只按裸地址且最多 64 条记录，第 65 台起互相覆写槽 63，地址重用还会拿旧位置比较。改为可增长记录，并核对象
  `+0x30` 的 weak-this 控制块；新实例重新编号并清位置 / 帧号，首帧不做跨实例跳变判断。原 M113 12 台的对照不受容量问题影响。
- 聚焦离线验证：MSVC `/W4 /WX /permissive-` 编译探针与独立检查，100 个同时跟踪实例保留各自帧号 / 位置，第 64 槽地址复用后新编号、
  帧号归零且不影响第 65 个实例；`hector_ai_check` 687 项 0 失败。更正后的退速和探针未另开游戏实跑。
