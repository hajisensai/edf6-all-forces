## 本次修改

- `src/room_ui.cpp` / `src/room_ui_logic.h`：关闭配装页时仍绘制独立的「载具与 NPC 配装」入口提示；显示当前配置的键盘键与手柄组合。默认是 F2 / L3+R3，自定义组合也按实际各键命名。手柄读表验证失败、组合含无法读取的按键位时，不展示这个不可用的手柄入口。
- 提示与原页面输入所有权绑定：弹出原生子窗口、过场、菜单已打开、关闭键仍未松开时隐藏；关闭 RoomLoadout / Enabled 后撤回。提示用 TextField，不加入原页面焦点或按键回调。原菜单输入、释放关闭键后的恢复、预览与屏幕析构链路保持原有契约。
- `tools/room_layout.py`：每页 12 行，保留原有滚动；最后可选行 674–714、状态区 736–878、三条帮助 896–930 / 932–966 / 968–1002，避免同一条提示塞下所有动作。帮助按单位列表、单位行、字段三个层级展示实际可用操作，并明确关闭会放弃未保存修改。
- 入口位于 974–1008 的左侧区域。读取本机原版布局核对：在联机聊天框下方、原生 MainFrame 控制提示左侧；不修改 Coop 所用的 `LYT_MAINFRAME.SGO`。
- `pylib/outfit41.py`：生成外观包时验证原生主色 / 副色色槽 0 / 1 在战斗 SGO、菜单 SGO 与每个 LOD 中一致。每个实际被网格引用、使用双染色 shader 或 `param_cm0_cm1_occ` 遮罩的材质，都必须有两条有效的 `change_color0/1` float4 与有效遮罩引用。头发、透明头盔和发光眼等非染色材质不被强制改色。

## 角色资源核对

截图 6 的盔甲、头盔和翅膀与项目已有的 EDF4.1 PALEWING 外观及此前生成的预览一致；截图 5 的「绝望阴影再袭」即现有 EDF4.1 追加项。EDF6 四个 CPK 的 SoldierInit / OBJECT / MENUOBJECT 中未发现可直接补入的第五套官方外观。现有四兵种模型保留原版颜色槽；本次没有增加一个重复角色，也没有从截图假造新模型。

本次验证没有发现现有颜色路由被截断的静态证据，因此未增加冗余运行时染色 hook。新增约束在生成阶段拒绝会丢失颜色的资源；四兵种 12 个生成文件的 SHA-256 与现有注册表逐字节复现，资源内容没有变化。
