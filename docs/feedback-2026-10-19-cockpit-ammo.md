## 现状（改前）

第一人称进入载具时（`FirstPersonHideStockHud=1`，默认）原版 HUD 关闭，插件第三人称的挂载条 / 武器块 / 飞行 HUD 也让位（`hud.cpp` `screensOn`）。读数只在座舱里的实体仪表上：

| 仪表 | 来源 | 改前 |
| --- | --- | --- |
| 武器屏 `weapons` | `pylib/cockpit_instruments.py` `instrument` | `AMMO` 五位、`SLOT` 一位七段数字 |
| 飞行屏 `flight` | 同上 | 速度、高度两块 270° 指针表 + 三位航向数字 |
| 导航屏 `map` | 同上 | 航向画成 0–360 的 **270° 指针表**，威胁点在表面上 |
| 状态屏 `status` | 同上 | 车体缩略图、耐久百分比、燃料条 |
| 原模型仪表替换（F-16 / C-130 / AH-64 / UH-60 / 卡车等） | `pylib/cockpit_retrofit.py` `_dial` | 速度、高度、**航向、俯仰**、升降、燃料、动力、耐久一律是 270° 指针表 |

坦克、BMPT、格雷普、卡车 / 喀秋莎、机甲、原版直升机、插件战机 / 旋翼机、C-130 系列都走这条路径（有 `vc_i_` 骨骼的新生成座舱）。旧模型的 `cockpit_screens.inc` 单应映射路径与遥控武器站 `RwsDisplay` 不在本次范围。

## 根因

1. **七段数字随屏幕变形**。`digits()` 的格宽是「字段宽度 ÷ 位数」（按屏宽），格高却是屏高的固定 0.16：一位的 `SLOT` 横跨 70% 屏宽，被拉成两块扁方块（用户问「这底下的武器是什么意思」的那一块），在直升机屏上还压住「武器」二字；五位数字随屏幕比例或矮胖或瘦长。孤立的「1」只剩两根竖条，看不出是数字。
2. **武器信息不全、不可辨**。改前没有武器类别、弹种、装填进度、弹尽、备用武器；第一版改成序号格子后，「1」「2」仍看不出是什么弹。
3. **仪表种类用错**。所有读数共用一种 270° 指针表：航向是没有起止的圆周量，却画成 0 到 360 两端分开的指针表；俯仰同样是指针。真实座舱里航向是罗盘卡 / HSI，姿态是人工地平线，高度表是整圈两针。
4. 控件只有显隐、横向缩放、270° 旋转、平移四种姿态，做不出转动的罗盘卡、整圈指针与随俯仰滚转移动的地平线；读数里也没有滚转角。

## 改动

### 新的控件模式与读数（`src/cockpit_instruments.h`、`src/firstperson.cpp`）

| 模式 | 作用 | 用在 |
| --- | --- | --- |
| `e_<field>_<v>` | 字段等于 v 时显示（一组里选一个） | 弹种图标 / 标签、当前格的框 |
| `h_<field>_<only>` | 罗盘卡按航向反转，当前航向停在上方基准线下；`only` 1 仅地面、2 仅飞行 | 导航屏、飞行屏地面态、备用罗盘 |
| `w_<field>_<per>` | 指针每 `per` 转一整圈 | 高度表长针 1000 m、短针 10000 m |
| `g_<pitch>_<k>_<limit>` | 地平线卡沿自身竖直方向按俯仰下移（k/10000 屏高每度，最多 limit），再按滚转反向转动；仅飞行 | 飞行屏与备用姿态仪 |
| `Z_…` | 七段数字补前导零 | 航向 074 |

- 新增字段追加在 `Field` 末尾，旧模型字段编号不变，旧 `slot`/`ammo` 照填。
- **滚转角**：`FirstPersonInstrumentReadings` 用乘员座位标记 `vc_eye_<seat>` 的世界矩阵（行：左、上、前）算 `atan2(left.y, up.y)`，右翼下沉为正；仅飞行载具有效（与俯仰、升降相同）。
- 移动控件只要「控件名 + 枢轴 + 朝向 + 范围」完全相同就共用一根骨骼（地平线卡的天、地、刻线三块），`cockpits.graft` 与骨骼预算测试同一规则。`g_` 与 `t_` 一样按 extent 缩放骨骼轴：地平线卡以屏高为单位移动。
- 邻席看到的 `e` 控件隐藏。航向、高度、速度、升降、俯仰、滚转是整车读数（`cockpit_instruments.h VehicleField`），所有席位共用：邻席面板上的罗盘卡、高度针、姿态卡和航向数字照常转动；没有读数时（`ready=false`）收起，不再停在原姿态叠在一起（2026-10-20 审查 B1：原先邻席只放行 l/c/p/v/u/e，新 h/w/g 走 `continue` 保持原姿态，地面罗盘卡与飞行姿态卡叠显且不转）。判断在 `SeatPoseOf`（`fp_view_check` 覆盖）。

### 武器屏：弹种分色的 MFD（`weapons()`）

- 弹种类别 12 种（`hud_cue.h` `CockpitRound`，Python `ROUNDS`）：MG、GUN、AP、HE、HEAT、CAN、BEAM、RKT、MSL、AAM、BOMB、SPC。每类有固定颜色（参考战雷：穿甲蓝、榴弹黄、破甲橙、导弹红 / 空空青、火箭粉……）、缩写标签与专属弹头剖面图标（尾翼脱壳穿甲弹、钝头榴弹、带炸高探针的破甲弹、霰弹罐里的弹丸、火箭、导弹……）。
- 原版载具按武器自身数据分类：能量武器 BEAM；火箭 RKT；制导 MSL；有弹种标签的炮按标签（AP/HE/BEAM/HEAT/CAN）；无标签的抛射武器 HE；逐发装填的大炮 GUN；其余 MG。插件战机按挂载图标分类。
- 武器屏、第三人称挂载条（`StockCells` / `JetCells`）和切换横幅用同一张列表与同一个选中规则（`hud_cue.h SeatArms`：原版载具按 SideOrder 排列，选中 = 火控所选 → 瞄具所跟 → 第一件；插件战机 = 挂载 + 机炮，选中 = 当前挂载 → 机炮）。原先武器屏按 selected→sight→0、挂载条只认 selected，直升机门炮手等没有 selected 的席位两边框的不是同一件（2026-10-20 审查 B2）。
- 布局：顶行当前弹种标签（彩色）+「装填中」/「弹尽」；中部彩色弹头图标 + 四位大号弹数；弹匣条（25% 刻度，装填时由琥珀色装填进度取代）；「STORES」分区线下每件武器一格：彩色小图标 + 弹种缩写 + 一根余量条（该武器装填时改为装填进度），当前武器亮框。武器超过 3 件时格子是包含当前武器的滑动窗口。单武器席位不显示 STORES 分区。
- 七段数字：固定宽高比、加粗笔画、两端削角的笔段且每个接缝留同样的缝隙（4、7 的笔画彼此分开），位间距 1.3 个字宽，**未点亮的段以暗色常显**（真实液晶 / 荧光屏的样子），孤立的「1」读得出是一位数字。

### 飞行屏：主飞行显示（`flight()`）

- 中央人工地平线：天蓝 / 地棕、地平线与 ±5°/10° 俯仰梯、坡度刻度、固定飞机符号；地平线卡在屏面圆窗后方移动，屏面挡住窗外部分。没有飞行读数时（读数缺失）窗内改为罗盘卡、飞机符号隐藏。
- 飞行屏只装在飞机 / 直升机座舱里：逐个核对 `cockpit_kits.KITS`，带 `flight` 屏的只有 `heli_gunship(_pilot)`、`heli_utility`、`jet_f16(_narrow)`、`plane_deck(_gun)`；地面载具（坦克、卡车、机甲）没有飞行屏，所以不会出现 IAS 空速表与 ×100 m 高度表。地面车的速度与航向在原模型仪表替换的仪表簇（160 km/h 速度表、罗盘，`GROUND`）与机甲的导航屏上。
- 空速表（270° 标准圆表，标 IAS 与 km/h）、高度表（整圈 0–9，×100 m，长针 1000 m 一圈、短针 10000 m 一圈）。
- 航向三位数字补零，标 HDG，装在留足内边距的读数框里（`readout`：框线离数字 0.4 个数字高）。宽屏三表一排；中等宽度地平线在左、空速与高度上下叠在右；竖屏地平线在上、两表在下。所有内容离边框至少 4.5% 屏幕（测试覆盖 7 种屏幕比例）。

### 导航屏：水平状态显示（`nav()`）

旋转罗盘卡（半径随屏幕比例收缩，罗盘与距离环离边框和标题留边；每 10° 刻度、30° 长刻度、N/E/S/W 与 3/6/12… 数字），上方固定基准线，中心本机符号，两圈距离环，威胁点按真实方位与距离显示（`T_` 的 extent 改为等比，宽屏上方位不再被拉伸）。

### 原模型仪表替换（`cockpit_retrofit.py`）

- 航向 → 备用罗盘：罗盘卡随航向转动，固定基准线与飞机标记。
- 俯仰 → 备用姿态仪：天 / 地 / 地平线 / 俯仰梯在圆窗后移动，前方表圈挡住窗外部分。
- 高度 → 整圈高度表（两针）。空速、升降、燃料、动力、耐久保持原来的标准圆表。

### 统一样式

所有玻璃屏加细线边框与分区线；配色：白青色读数、青色标题 / 单位、暗青边框、琥珀色指针 / 基准线 / 装填、红色告警，状态屏同一风格。字形全部是预烘焙的模型几何（`tools/make_label_glyphs.py` 补 K、x 与「装填中」「弹尽」各语言字形），运行时不依赖字体。

### 第一人称换武器提示（`src/hud.cpp`）

几何屏写不出武器的准确名称：第一人称下切换武器时，沿用第三人称挂载条的 `LoadoutBanner`，在视图下方显示 1.5 秒本地化全名与弹数；平时不常驻。原版弹药 HUD 在第一人称仍关闭，不重复。

## 验证

- `tests/cockpit_instruments_test.py`：武器屏 12 类控件、每类独立颜色、格内标签不出格且不压图标；7 种真实屏幕尺寸上数字比例、区块不重叠、四语言标签不出屏；飞行屏有空速针、高度两针、地平线卡、地面罗盘卡、补零航向且没有航向指针；导航屏是罗盘卡；所有部件在屏面内、空速表 / 地平线遮罩 / 高度表 / 航向数字互不重叠。
- `tests/cockpit_retrofit_test.py`：备用罗盘 / 姿态仪 / 高度表的控件；罗盘与高度表的刻字在表面内；姿态卡枢轴在表心，卡面盖满圆窗且最大位移仍在表圈遮挡内。
- `fp_view_check`：`ArmReadings` → `Pose` 链路（单图标、每格弹种、单框、装填 / 弹尽、滑动窗口）；航向 090 时罗盘北转到左；高度 2500 m 长针指 5、短针指 2.5；仰 10° 右坡 30° 时地平线下移 0.045 屏高且右侧抬起；俯仰超限停在遮罩内；地面无姿态卡、显示罗盘卡；航向补零。
- `tests/cockpit_build_test.py`（真实模型、所有适配席位）骨骼预算，见 PR 描述。

## 未验证 / 风险

- **未实机**。预览是正面平面绘制，没有透视、遮挡、发光材质观感。重点需要实机看：
  - 地平线的俯仰 / 滚转方向（滚转取自座位标记矩阵，符号按「左 = 行 0、上 = 行 1」推导，未在游戏中核对；若方向反了只需改符号）。
  - 移动卡片在屏面 / 表圈后方是否被正确遮挡（依赖 2–3 mm 的深度差）。
  - 罗盘转向：航向增大时卡片逆时针转。
- **DLL 与座舱模型必须一起更新**：新模型配旧 DLL，旧 DLL 不认识 e/h/w/g/Z，弹种图标会叠在一起、罗盘与地平线静止。新 DLL 配旧模型照旧工作。
- 姿态卡的俯仰行程有限：飞行屏随屏幕比例约 ±13°（竖屏）到 ±22°，备用姿态仪约 ±16°，超出后整张地平线卡（含俯仰梯）停在行程尽头，大仰角 / 俯角时只表示「超过该角度」，不再给出准确俯仰。
- 插件战机挂载没有弹匣上限读数：大进度条与刻度隐藏，格子只表示有 / 无。
- 坦克炮塔相对车体的方位指示没有做：需要新增读数字段和骨骼，地面车骨骼余量虽够，但不在本次范围，可另开。
- 原版制导武器统一归为 MSL（反坦克 / 空对地 / 防空没有区分的数据）。
- HEAT / CAN 依赖 #216（`reticle::Shell` 新增 heat、canister）；`CockpitRoundOfArm` 直接按 `reticle::Shell` 枚举分类，不再用裸整数 4 / 5。
- 字段号与弹种顺序只有一份：`pylib/cockpit_fields.py`。`tools/gen_cockpit_fields.py` 由它生成 `src/cockpit_fields.inc`（`Field`、`kRows`、`CockpitRound`），CI 的生成文件检查跑 `--check`，selftest `cockpit_fields_current` 核对生成结果和已建模型的旧编号；`pylib/cockpit_instruments.py` 与 `tools/instrument_preview.py` 从同一张表导入（2026-10-20 审查 B6）。
