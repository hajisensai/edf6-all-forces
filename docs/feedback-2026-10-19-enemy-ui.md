# 敌方操控入口与技能界面

本页记录界面层与输入契约；原生技能目录、动作执行和联机接管由 `enemy_control` 负责，界面不把未知技能伪装成可用。

> 2026-10-19 晚第二轮（用户原话：「操控怪物的时候上下左右是反的，而且有些莫名奇妙不能操控，而且这个展开和收起会自动变，我不好点，而且我点不了怪，怎么选中怪物」；补充：「不要搞切换之类的，一共几种攻击方式……不需要切换」）。下面是改后的契约，旧的「悬停选敌 / 悬停展开 / 先选技能再按发动」全部作废。

- **选目标只由玩家的动作决定**：M 地图里左键点击敌人的地图标记（光标下没有我方单位时）选中它；手柄 L3 选中屏幕中心 90 px 内的敌人，没有就保留已选目标，再没有就选最近的可操控敌人；卡片名字两侧的 `<` `>`（手柄进卡后左右）按与玩家的距离由近到远切换可操控敌人。拾取同一位置时优先可操控的家族（`EnemyControlPickable`：已注册的 4.1 控制器或有原生输入档案的类），巢穴、部件、要塞之类只在附近没有可操控单位时才被选中，并由卡片说明原因。以前是光标每帧经过哪个敌人就换成哪个，鼠标移向卡片途中会换掉目标。选中的目标在地图上有青色括号和「操控目标」字样。
- **卡片展开 / 收起只由玩家改变**：单击标题、选中目标、L3 会展开；单击标题收起。悬停不改变卡片高度。已操控和等待接管期间始终展开。
- **每种攻击一个固定按键，不用切换**（`src/enemy_control_bindings.h`）：目录第 i 种攻击固定绑定第 i 个键：键鼠 左键、右键、E、R、F、G、X、B、侧键1、侧键2、1–9、0；手柄 RT、LT、RB、LB、A、B、X、Y、十字上 / 右 / 下 / 左。避开移动（WASD、空格 / Ctrl）、M 地图键和插件在步行时的热键（Q、T、Y、C、Z、V、N、中键、F 键、[ ]）。原生「开火」动作（记录 +0xD0）也算第一种攻击，第二位本地玩家只有这一个。按住型攻击按住期间保持，单发型每次按下触发一次。关图时左下 HUD 列出「键 → 攻击」，M 卡每行前面标出它的键；超出按键数的攻击在 M 卡上按住该行发动（`EnemyControlHoldAbility`，不改选中状态）。不再有「选中技能」与「按住发动」行。
- **方向**：EDF 世界 +X 在 +Z 的左边（`map_cam.h Right`），旧代码把屏幕右取成 `up×forward`（实际是左），所以 A/D 和摇杆左右反；鼠标 / 右摇杆的偏航和俯仰积分也取反了（右移让航向增大＝左转，下移让仰角增大＝抬头）；左摇杆前推时 +0x24 为负（`0x56D920` 键盘路径给前进键写 −1，`docs/heli-input-re.md` §4、`player-jet-re.md`），旧代码直接当前进量用。统一放到 `src/enemy_control_camera.h`，原生移动换算、4.1 Argo（`edf41robo.cpp`）和 4.1 母舰（`edf41mother.cpp`）都改用同一约定。W/S 在键盘上原来就是对的。
- **不能操控的原因要说清楚**：骑乘时以前报「需要当前本地玩家角色」，现在单独报「请先下车：只有步行时才能操控敌方单位」（`Reason::riding`）。没有原生输入档案的家族（MovingFortress、UfoMother511、EDF6_GrandMother、EDF6_Jormungand 等多部件结构）仍不准入，卡片显示原因。
- 「返回原玩家」始终是独立操作，等待接管或恢复时也有返回入口。单纯关闭 M 保持当前操控。
- 控制中显示当前原生阵营编号；无对战时明确保留原敌方阵营，对战继承成功时显示跟随玩家对战阵营。原角色暂停与保护说明只在核心发布 `sourceProtected=true` 时显示。
- M 卡与地图外常显界面均显示受控单位真实当前/最大生命值，来自受控目标的公共 HP 字段；未知、负哨兵值、非有限值或无效上限明确显示不可用，不借用受保护原角色的血量。
- 原生动作没有可读冷却证据时显示“由原生动作规则判定”，不显示假就绪或 0 秒冷却。

未实机验证：按键手感、各家族目录顺序是否符合直觉（目录顺序沿用原生按键位与攻击表顺序）、手柄扳机阈值（1/4 行程）、大型怪物在地图上点击的命中半径。

界面和点击绑定 `owner[32]`、`target[32]`、`ownerHumanKey`、`revision`、`lease`、`profileHash`、控制阶段及选择技能。渲染线程只读取完整复制页，不读取原生对象；地图候选在游戏线程保持弱引用。视口用不解引用的本地玩家键匹配，另一位本地玩家的 HUD 不得覆盖此地图的命中区。

窗口失焦、按键释放、技能/目标/权限变化、退出地图与任务重置都会结束界面技能按住状态。手柄卡退出后，A/B 直至全部释放仍归本次手势所有，避免变成地图居中、关闭或摆放操作。

离线验证：`tests/enemy_ui_logic_test.cpp` 的 44 项检查覆盖技能分页、末页、空目录、大目录、身份变更、焦点、按键排空以及发动的按下/保持/释放；`mapcmd.cpp`、`hud.cpp`、`map.cpp` 用 `/W4 /WX /permissive-` 独立编译；HUD 729 项四语文本检查通过。独立只读审查发现的待接管返回、压缩字号与 R3 焦点交接问题均已修复。实机的动作时机、技能反馈和双机接管仍需整体验收。

真实生产布局补充验证：`tests/enemy_hud_layout_test.cpp` 把整份 `hud.cpp` 放在原有离线 native 绘图记录器上执行，共 65,954 项检查，覆盖四语、六种视口、横竖分屏、两位本地玩家隔离、active/pending/restoring、目标 HP 已知/未知、全部技能页与末页，以及八挂载/敌控/PvP/摆放的整套地图堆叠。修复了受控卡上移前提前隐藏、闲置候选永久占满右栏、摆放空间不足时入口完全消失的问题；空间不足时保留原摆放标题入口。原 HUD 全部四语场景、PVP/thermal 34,120 项、钻头绑定 5 项、地图 runtime 200 项、地图 identity 11 项也已重新编译执行通过。
