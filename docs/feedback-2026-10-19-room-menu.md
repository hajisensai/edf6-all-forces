# 2026-10-19 房间 F2 菜单与 4.1 皮肤

用户原话：「房间界面f2太垃圾了，换成游戏自带的那种。还有我怎么没办法把我的皮肤换成4.1的，因为我没通关4.1吗。不是的话修复」；「做的太烂了。排版ui之类的你可以不用顾虑原版，原版不方便直接把代码改到方便为止不就好了」。

## 1. 房间 / HQ 配装菜单 → 游戏自带对话框

调研：原版「从列表里选一项」的窗口是 `HUiDialogBox`（`LYT_HUIDIALOGBOX.SGO`），士兵画面的更换模型弹窗、联机房间自己的若干选择框都用它；它的框体、按钮、焦点、鼠标、键盘 / 手柄确认与取消、音效、开合动画都是游戏的。旧配装页是插件自绘的文字行和色块，只能用方向键 / Ins / Del / Home。

修复：菜单整体改为一串原生对话框（`src/room_dialog.cpp` 照抄原版弹窗构造；`src/room_dialog_logic.h` 决定每页内容）。单位列表 → 单位 → 士兵 / 挂点 / 乘员 → 取值，每一层都是游戏自己的窗口；长列表分页，取值页打开在当前值；Esc / B / 右键返回上一页；有未保存修改时关闭会先询问。数据模型、ini 回写、变体生成、房间预同步与 3D 预览沿用原实现。逆向与生命周期见 [room-native-dialog-re.md](room-native-dialog-re.md)。

对话框相关代码签名不符时退回旧的覆盖层菜单（日志 `HOOK roomui native dialogs=0`）。

## 2. 皮肤换不成 4.1

根因（静态反汇编，已核）：原版「更换士兵模型」按钮只在**更换模型已解锁**时出现——士兵画面初始化 `0x8A9B15` 把 `GS+0x300` 抄到画面 `+0x7A4`，弹窗只在 `+0x7A4 != 0` 时构造（`0x8AB59C`）；`GS+0x300` 在任务结算 `0x70D933` 置 1，条件是 `0xDF990`「当前任务列表最后一关已通关（任一难度、任一兵种）」。4.1 外观是插件加进这个弹窗的第 6 项，于是被原版进度门槛一起挡住：没通关过任一任务列表的最终关，就打不开弹窗。不是「没通关 4.1」，也不是有意设计（4.1 外观的规则里，未解锁只用于「4.1 任务包默认穿 4.1」）。

修复（`src/outfit41.cpp`）：未解锁且该兵种 4.1 文件已安装时，士兵画面每帧更新前把 `+0x7A4` 置 1 并换成解锁后的操作说明（与 `0x8A9B37..0x8A9BB1` 相同的文字表查找与赋值），让弹窗可以打开；弹窗里只留「配合任务」（原版第 0 项，未解锁时存档本来就是它）和「绝望阴影再袭」，其余 4 个原版外观用游戏自己的条目析构 `0x8E170` 去掉，仍由原版通关解锁。已解锁的存档行为不变。条件不再成立（Enabled=0、文件被删）时把自己置的 `+0x7A4` 还原为 0。
