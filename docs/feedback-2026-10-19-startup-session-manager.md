# 启动时会话对象尚未创建导致崩溃（2026-10-19）

用户反馈：「启动不起来游戏」。本机 18:19 的真实崩溃转储、Coop 栈和全军出击日志一致：`C0000005 at EDF.dll+0x7748F7`，读取 `0x38`。游戏目录的三个 DLL 与 `352436f` 安装凭据哈希一致。

该构建对应的 PDB 将调用链精确映射为 `EML6_Load(plugin.cpp:1171)` → `InstallEnemyControlNetwork` → `Publish` → `InSession`。原生 `0x7748F0` 先读取 `EDF+0x20B2890` 的会话 manager，再读取 `manager+0x38`；本轮 RAX 为零。它不使用传入 RCX，不能将错误归因于函数的空参数。

EDFModLoader 的同步插件加载发生在游戏创建会话 manager 之前。网络桥安装时立即发布状态，越过了这条初始化边界。旧 `b08c592` 的 17:14 启动也在相同地址失败，不能仅凭最近安装时间归因于 NPC 机甲帧逻辑。

修复分两层：安装只绑定回调，首次游戏线程 transport 更新才发布实时状态；公共会话查询显式处理 manager 未创建、释放与替换，继续使用经真实原生代码校验的在线判据，不缓存首次缺失，不用延迟启动或重试绕过。

回归需调用生产公共查询，覆盖未创建、离线、在线、释放及重新创建；生产网络桥测试另要求安装及重复安装均不查询原生会话。真实游戏启动验证与离线、冻结包校验分别记录。
