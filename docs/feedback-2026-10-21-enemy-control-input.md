# 操控怪物：键位与准星（2026-10-21）

用户原话：「操控怪物绑定的键位不对吧，我怎么左键往右走，右键往后走，wasd没反应。操控怪物的时候没隐藏武器准星。」

## 移动 / 视角：按士兵自己读手柄对象的方式读（`src/enemy_control_pad.h`）

静态反汇编（EDF.dll `0x678CCB46`）：士兵的左摇杆 `0x56D920`、右摇杆 `0x56DBC0` 先判手柄路径——手柄对象（`human+0x340`）`+0x2D68` 非 0，或 `0x1183D70` 返回的字节（`0x1FEEE1C`）为真：
- 手柄路径：摇杆就是对象本身的 `+0x0C / +0x24`（前推为负）和 `+0x3C / +0x54`，不乘记录号（`0x56DA0C`、`0x56DE6C`）；
- 键盘路径：记录 `[human+0xD40]`（步长 `0xA80`）的按键字节 `+0x610` 前、`+0x628` 左、`+0x640` 后、`+0x658` 右（`0x56D99D..0x56D9E4`），鼠标位移 `+0x66C / +0x684`，游戏除以 24（`0x1766014`）。

旧 `enemy_control.cpp Sample` 不分路径，把记录的 `+0x0C / +0x24` 当左摇杆：键鼠玩家那两个浮点不是摇杆（士兵在键盘路径从不读它们），用户看到的就是鼠标键在推移动；士兵真正走路用的按键字节完全没读，WASD 另由 `GetAsyncKeyState` 补，且只在记录号 0 时生效。现在移动和视角与玩家士兵同源：跟随玩家自己的键位设置，第二位本地玩家读自己的记录。WASD 旧路径为何在用户机器上完全无效没有复现（推测与上述浮点覆盖 / 记录号有关），新路径不再依赖它。

## 攻击键：先攻击、后移动动作（`src/enemy_control_binding_order.h`）

目录按原生按键位列出（`enemy_control_catalog.cpp List`），第 i 个键绑第 i 项。士兵类的第 0、1 项是「跳跃」「进入／退出掩体」，所以左键跳、右键退回掩体。现在键位顺序按玩家自己的键：左键 / RT = 该家族主攻击（士兵：装备武器齐射，相当于开火），右键 / LT = 副攻击（士兵：举枪瞄准，相当于缩放），其余攻击按目录顺序，跳跃、掩体、翻滚、起飞、侧步、奔跑、开合甲壳、舱门这类移动动作排最后。只改本机键位顺序：技能 id、目录哈希和网络协议按原生顺序计算，不变，联机双方仍按 id 对齐，无需升协议。

## 准星

`infantryscope.cpp CrossDrawHook`（原版准星绘制第 3 槽，已串接）对 `EnemyControlReplacesPlayerHud` 为真的士兵直接返回，与护甲条 / 武器栏同一判据（`docs/hud-re.md` §9.3.1）。

## 验证

- `tests/enemy_control_runtime_test.cpp`：手柄路径各本地玩家用自己对象的摇杆；键盘路径下记录浮点不推移动、W/S/A/D 与鼠标 /24、P2 记录独立；`0x1183D70` 代码取标志字节；士兵目录键位顺序与左键开火 / 右键瞄准。变异：去掉排序、键盘路径改读浮点、改读记录浮点、士兵开火不排第一，均变红。
- `tests/enemy_control_crosshair_guard.py`：准星钩子在原函数之前对受控玩家返回；删掉那一行即变红。
- 未实机：键鼠 / 手柄实际手感、各家族攻击顺序是否顺手、准星实际消失。
