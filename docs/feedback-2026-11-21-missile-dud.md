# 2026-11-21：导弹未解除保险撞击仍有爆炸火球（哑弹表现）

## 来源

没有新的测试站编号。这是 `docs/feedback-2026-10-25-missiles.md` 后续 3 留下的未完成项。当时用户原话（2026-10-26）：

> 天启导弹打到自己是指会在自己身上爆炸，射不出去

后续 3 加了战斗部保险：导弹出膛后，只要爆炸还罩得住发射它的车，就不解除保险，近炸引信不触发，直接撞上也只算单体伤害、没有范围伤害。
当时文档写明「未做：未解除保险时撞击仍有原版的命中特效（火球大小随爆炸半径），只是没有范围伤害」。实际看到的是：近距离锁定后
导弹撞上目标，车不掉血，可撞击点照样炸出一个按 12 m 爆炸半径画的大火球，还有爆炸声，看上去和「在自己身上爆炸」没有区别。

## 现状核对（修前，origin/main `60ee06f1`）

`src/missile.cpp` Arm 在保险未解除时只清 core+0xAF4 的 0x10（`fuze::HitFlags`），别的都没动。这样只去掉了范围伤害，火球和爆炸声都还在。

## 根因（静态 H：EDF.dll 指令逐条读过，`tests/missile_dud_native_audit.py` 逐字节核对）

一发 MissileBullet01 撞上东西时，伤害、声音、火球是三件事，各由弹体上的一个字段控制。保险原来只管了伤害：

| 表现 | 原版代码路径 | 由什么决定 |
|---|---|---|
| 范围伤害 | 命中处理 `0x2321B0`：`0x232616 test al,0x10`，有 0x10 走 `0x542670` 范围伤害（半径 GDI+0x58 = core+0x788），没有就走 `0x543920` 单体伤害 | core+0xAF4 的 0x10（后续 3 已经在管） |
| 爆炸声 | 同一个命中处理里 `0x2325CD bt eax,0xA`，置位才在 `0x2325EE` 用 `0x7B4510` 播 core+0xA70 的 preset（武器的 AmmoHitSe。模板 `V_506HELI_MISSILE01` 是 `common_damages_explode_M`，原版 113 个 MissileBullet01 武器里 106 个是 `common_damages_explode_S/M/L/LL/XL/X_limited`，其余 7 个是 `impactKanshakudama_limited` / `impactMissle_FORK`，也都带爆炸半径） | core+0xAF4 的 0x400。init 在 `0x231D3D or r9d,0x600` 给每发弹都置上。弹体核心 `0x22E000..0x240000` 和导弹类代码里只有这一处读它 |
| 火球 | 命中时 `0x230CA0`（由 `0x23238F` 打中刚体、`0x23256D` 打中地面调用）把命中点、法线记进 core+0x6C0 的命中表（0x50 字节一条，计数在 core+0x6D8）。导弹类更新 `0x26A880` 一开头 `0x26A8AC` 看到命中表非空，就在第一条记录的点和法线上调 `EffectGenUtil::Explosion`（`0x2E5ED0`），尺寸 = `[B+0xB60]`（core+0xA20）÷ 5（`0x26A8C1` / `0x26A8C9`，常量 5.0），然后 `0x2318E0` 结束这发弹 | core+0xA20（AmmoExplosion 原值） |

- 火球跟伤害无关：它不在 `0x542670` 里画，命中表也不看 0x10。所以只清 0x10 时，火球和爆炸声原样出现，大小还是按 12 m 爆炸半径算的。
- core+0xA20 在 init 之后只剩火球尺寸这一个读者。init 在 `0x2320A9 → 0x2320BD` 把它拷进 core+0x788，范围伤害用的是 core+0x788。
  `0x22E000..0x240000` 里 `0xA20` 这个位移只出现在 `0x2320A9` 一处，导弹类 `0x266000..0x26B000` 里 `0xB60` 只出现在 `0x26A8C1` 一处。
  AutoTurret 早就用过这一点（`autoturret/src/plugin.cpp`：改 C+0xA20 只放大高射炮弹的火球，不改伤害）。

## 原版有没有「不爆炸的撞击」表现

没有可以照搬的：

- 原版没有不爆炸的 MissileBullet01。本机 Root.cpk 的 WEAPON 里 113 个 MissileBullet01 武器，AmmoExplosion 写死数值的 27 个都 ≥ 4 m，
  其余按等级插值，起点也都不是 0；命中音效 106 个是 `common_damages_explode_*`，7 个是 `impactKanshakudama_limited` / `impactMissle_FORK`（这几把同样有爆炸半径）。
- 这个类撞上东西时，唯一的画面就是 `0x26A8AC` 按爆炸半径画的 Explosion，类里没有火花或碎屑的分支。实弹类（SolidBullet 系）的撞击
  火花是它们自己的代码，导弹类用不了。

所以哑弹按「原版这一发去掉爆炸」来做：伤害照原样走单体伤害，不画火球，不放爆炸声。弹体照原版在撞击处消失（`0x2318E0`）。没有另做火花：
原版没有对应的效果，凭空加一个就是新造的表现。

## 修法

- `src/fuze.h`：
  - `HitFlags` 在保险未解除时同时清掉 `kAreaOnHit`（0x10）和 `kHitSound`（0x400），解除后两个都恢复。原版 init 给每发弹都置了 0x400，
    所以恢复后就是原版的值。
  - 新增 `HitFireball`：保险未解除时火球尺寸写 0，解除后写回爆炸半径。没有爆炸的弹不动。
- `src/missile.cpp`：
  - `kBlast` 改读 core+0x788（真正的爆炸半径）。core+0xA20 改作 `kFireball`，由 Arm 每帧按保险状态写入。
  - Guide 在命中表非空（`kHits` = core+0x6D8）时直接返回：弹已经撞上，原版这一帧就会画火球并结束它。保险状态要保持撞击那一帧的判断。
    不这样做的话，撞击后的位置可能刚好让保险重判为「已解除」，哑弹又会变回火球。
  - InstallMissiles 挂钩前核对这几处原版字节（`kDudSites`：`0x26A8AC`、`0x26A8C1`、`0x2325CD`、`0x232616`、`0x2320BD`），对不上就和
    原来的签名不符一样不挂。
- 写入时机：Arm 在原版更新之前运行（`UpdateHook` 先 Guide 再 `nextUpdate`）。撞击发生在同一次原版更新里（`0x235D50` 之内），所以命中处理
  读到的 0x10 / 0x400 是本帧 Arm 刚写的。火球在下一帧更新开头画，这时 Guide 因为命中表非空不再改 core+0xA20，火球尺寸也就是撞击那一帧的。
- 范围：所有插件导弹（战机、地面车副武器、潜艇母舰、沙扎比）都走这同一处。NPC 驾驶的武器没有友伤位，出膛即解除保险，不受影响。
  近炸（到期爆炸路径）和已解除保险的撞击也不受影响。

## 联机

- EDF6 联机复制的是开火，不复制子弹：开火机器 `0x690CC0` 经 `0x694910` 发射击消息，每台机器各自 `0x696FD0` 生成自己那份弹，
  各自跑 `0x26A880`（`docs/fp-soldier-re.md` §2.3）。火球和命中音效都在各机自己的那份弹上本地生成，不同步。打敌人 / NPC / 物件的伤害只看开火机器上的弹；
  打玩家（`0x5A3600`）和载具（`0x6347C0`）则由**被打方**用它本机的重放弹判定（同 §2.3、`damage.md` §2），友伤也一样。
- 插件的 UpdateHook 在每台机器每份弹上都运行（联机要求全员同版本插件），用的是同一套判据：子弹 owner 的载具刚体包围盒对爆炸立方体。
  所以各机对同一发弹的判断一般一致，哑弹在各机上都是哑弹。
- 可能不一致的边界：判据用的是各机本地的弹位置和车体位置，联机有位置差。如果导弹恰好在「刚好够得到 / 刚好够不到」的那一帧撞上，
  一台机器可能画了火球、另一台没有。不只是画面和声音：发射车 / 队友的车与玩家由被打方用本机重放弹判伤，所以被打方那台若判为已解保，
  仍会吃到范围伤害（反之亦然）。这个边界在后续 3 的范围伤害保险里就已经存在，不是本次引入；本次只是让火球和爆炸声跟着同一判据走。没有实机验证。

## 测试

- `tests/fuze_test.cpp`（ctest `fuze`）：用实机日志里的标志 0x610，保险未解除时为 0x200（0x10 和 0x400 都清），解除后回到 0x610；
  出膛就解除保险的弹保持原值；没有爆炸的弹不动；其他位（0x20、0x200）不受影响；`HitFireball` 未解除为 0、解除为爆炸半径。
  另外用后续 3 的天启实测数据走一遍（车旁 → 哑弹，22 m 外 → 原版爆炸、音效、火球）。
- `tests/missile_dud_native_audit.py`（ctest `missile_dud_native`，需要 `EDF6_NATIVE_DLL`，没有就跳过）：逐字节核对上表的全部原版指令，
  包括命中表的写入与读取、火球尺寸 ÷ 5、Explosion 和结束弹的调用、0x600 / 0x400 / 0x10 三处、core+0xA20 → core+0x788 的拷贝和范围伤害用的 GDI；
  确认 `0xA20` / `0xB60` 位移在弹体核心和导弹类里只出现在那一处，`bt r32,0xA` 只在 `0x2325CD`；并核对插件源码的 `kDudSites` 与字段。
