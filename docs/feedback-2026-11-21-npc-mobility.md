# 2026-11-21 反馈：NPC 飞翼冲刺、NPC 剑兵冲跳

## 玩家原话

> NPC飞翼增加冲刺(原版就有的那个功能，之前NPC不会用)

> NPC剑兵(如果配装合适)增加冲跳(冲刺快速接喷射)，并且需要改进AI使其能自主判断何时完整冲跳何时只冲或只跳(即喷射)

## 原因（逆向见 [npc-mobility-re.md](npc-mobility-re.md)）

- 飞翼冲刺键是意图块 `d7B`，原版 NPC AI 从来不写它（全 `.text` 只有输入映射和第 4 槽的清零写它），所以 NPC 飞翼从不冲刺。插件以前被围时给飞翼按的 `d76` 加侧推，对飞翼是起跳 / 起飞，不是冲刺。
- 剑兵的冲刺和推进跳是两只手武器的副功能键 `d72` / `d73`：武器 `SecondaryFire_Type` 5 = 冲刺、4 = 推进跳（装备 306 / 307 可互换）。原版 NPC 只在目标远时隔帧按 set 0 的副功能键，不分冲跳 / 只冲 / 只跳，次数也浪费在插件当时的摇杆方向上。

## 实现（`src/npcai.cpp` Mobility，纯逻辑 `src/npc_mobility.h`）

- 只驱动本机拥有、非脚本控制的步行士兵；在原版 Think 和插件的 `Drive` 之后改写意图块，不加新的游戏 hook。
- 飞翼（`NpcWingDash`）：
  - 按键前按原版门槛预检：冲刺许可位、不在占用动作、没倒地 / 被抓、没过热，另外要求没有武器持着动作锁（不打断换弹）；
  - 能量预算：冲完至少剩 `NpcWingDashReserve`（默认半槽，空中至少 0.6）和再冲一次的量，所以不会触发原版「能量不够也冲、清零并过热」；
  - 何时冲：被围后撤时冲出去；战斗 / 撤退 / 移动命令的目标点超过 `NpcWingDashFar`（默认 25 m）、前方 15 m 通畅、路线 8 m 内不拐弯、不朝最近的敌人时冲过去；跟随时超过两倍距离冲回来；开火中不冲；两次间隔 `NpcWingDashSec`（默认 1.5 s）；
  - 方向沿寻路的下一段路线（满杆），不直线冲向目标。
- 剑兵（`NpcFencerMobility`）：
  - 每帧按两只手武器的 `SecondaryFire_Type` 和换算标志判定哪只手冲刺、哪只手推进跳；有这种手时，先清掉原版对这两只手的按键，再由插件决定；
  - 冲跳：目标点 ≥ `NpcFencerDashJumpRange`（默认 45 m）、前方 25 m 通畅、着地、两只手一冲一跳且都有次数 → 按冲刺，确认进入冲刺后在第 2~4 帧按推进跳（冲刺速度仍高于飞行入口的 42 上限，动量全部带走）；
  - 只冲：目标点 ≥ `NpcFencerDashRange`（默认 15 m）且前方 18 m 通畅，或很远但没有推进跳可用；被围后撤时朝后撤方向冲一次（冷却 `NpcRollSec`）；
  - 只跳：下一个路点高出 2 m 以上、12 m 以内且坡度陡于 1:2，或前方 3 m 腰高被挡，或 1.5 s 没走出 1 m；路点就在 3 m 内时摇杆归零原地直上；
  - 附近（2 × `NpcDangerRange`）有敌人时，移动用的冲刺至少留 `NpcFencerDashReserve`（默认 1）次给闪避；按住扳机的那只手、动作取消窗口、换弹中都不按；次数、冷却全部每帧从游戏字段读，不自己记。
- 校验与失败：按下后 3 帧内没看到生效（飞翼进冲刺状态、剑兵次数减少）算一次未生效，连续 5 次就对该士兵关掉并记一行日志；安装时逐条核对签名，不符只关对应功能并记一行。
- 现有 NPC 模板里没有一只手冲刺、另一只手推进跳的剑兵（左手都是 AI 盾），所以默认出场的剑兵只会只冲（打桩机 SP）或只跳（SSG / SMC）；完整冲跳要玩家给 NPC 换装或支援装备的换算参数生效时才出现。

## 测试

- 离线：`npc_mobility_check`（能量预算、门槛、理由；配装判定与换算；冲跳 / 只冲 / 只跳 / 不动的选择；冲跳时序；未生效计数）。
- native 审计：`tests/npc_mobility_native_audit.py`（签名、状态入口、`d7B` / `d72` 的全部写入点、在替身对象上实跑飞翼扣能量）。
- 实机（待做）：`Debug=1` 看 `WDDASH` / `FENCERMOVE` 日志与 `+0x5D0`（飞翼 `0xE39`、剑兵 `0xA38`），确认飞翼不出现过热，记冲刺 / 冲跳的实际位移，据此调 `NpcWingDashFar` 等默认值。
