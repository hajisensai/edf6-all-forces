# 2026-11-21 反馈：载具导弹出膛方向、自动副炮、NPC 绕开载具

**全部是离线分析与离线检查，没有进游戏实测。**

## 用户原话（同一批反馈里的几句，原样）

- 「类似通古斯卡的导弹没有跟随发射架方向射出去」（这批反馈里出现两次）
- 「修一下sidecannon、mab的骨骼」

## 1. 通古斯卡类导弹不沿发射架出膛（已修）

### 根因

插件导弹出膛方向 = 挂点（holder）骨骼的前向行（炮口模式 0，`0x633DD0` 每帧拷到 `weapon+0x150`；`docs/feedback-2026-10-25-missiles.md`）。
插件的导弹也从这条线量锁定锥。两辆车的导弹挂点在只偏航、不俯仰的 `cannon_main` 上，而玩家看到的发射架是抬起来的：

- **2S6 通古斯卡**：八具 9M311 发射箱（`9m311_rocket`）和导弹挂点都挂在 `cannon_main`。真车的发射箱装在两门 2A38M 的炮架上，随炮俯仰；
  游戏里炮抬起来对着飞机，发射箱却一直水平，导弹水平出膛再拐上去（`docs/feedback-2026-10-25-missiles.md` 后续 1 当时明确「没改」）。
- **MIM-104 爱国者**：发射箱（`gun` 部件，`cannon_slide_l`）随俯仰抬起，PAC-2（原生两炮位）跟着发射箱走；但 PAC-3 的挂点写死在
  `cannon_main`（`pylib/emplacement_model.py`），发射箱斜指天空时 PAC-3 仍水平出膛——正是「没有跟随发射架方向」。

天启的导弹巢固定在炮塔两侧（原作就是不俯仰的巢，且在耳轴后 1.4 m，绕炮耳轴转会压进炮塔），开普勒等原版车的挂载挂在原版炮位旁，
都与发射架一致，不改。

### 修法

- `tools/prep_wt_tracked.py` `TUNGUSKA`：`9m311_rocket` 挂到俯仰骨骼 `cannon_l`，`missile_bone='cannon_l'`（导弹挂点只能是一根骨骼，
  `make_tracked_combat` 检查；`cannon_r` 与它同一条耳轴线、同一俯仰角）。发射箱的碰撞仍并在炮塔（`collision['cannon_main']` 显式列出），
  与 BMPT 的发射架同一做法：放进 `cannon_l` 会让左炮的刚体横跨炮塔包住右炮（兄弟刚体互相碰撞，D93250）。
  `models/wt_tunguska` 用本机 Sketchfab 源（`D:\APP\edf6-models\downloads\wt_tunguska`）重新生成：先确认旧规则逐字节复现入库文件，
  新规则只有发射箱零件（21760 个三角形）从 `cannon_main` 换到 `cannon_l`、四个导弹炮口的骨骼换成 `cannon_l`，碰撞逐项相同。
- `pylib/emplacement_model.py`：炮台的导弹管口（爱国者 PAC-3）挂 `cannon_l`（俯仰铰链，不随后坐）。`tests/test_emplacement.py` 改为钉住 `cannon_l`。
- 结果：导弹沿抬起的发射架出膛，锁定锥也从发射架方向量起（玩家把炮 / 发射箱对准飞机即可锁定）；NPC 的判射同样读这条线。

### 未实机

- 通古斯卡发射箱随炮俯仰时有没有穿进炮塔侧面（箱尾在耳轴附近，抬到高仰角时尾端下沉）；导弹是否从箱口沿箱体方向出膛。
- 爱国者高仰角发射 PAC-3 的出膛。

## 3. 自动副炮（已改）

### 核实

2026-10-30 用户的原话是「一些炮塔可以是**自动无人炮塔**（需要可开关）或者一些应该是独立的座位」（`docs/multi-weapon-keys.md`）。当时落地时，
除了有自己炮塔骨骼的炮手座（空座时自己转向开火，符合原意），还把**驾驶座开火键上的挂载**也设成了 `auto`：天启与开普勒的防空导弹、
X-Morph 斗牛犬 / 蝎狮的导弹塔、美洲虎 S 型的防空导弹与四座侧炮塔高射炮。这些挂载没有自己的炮塔，弹道沿驾驶员的瞄准方向
（美洲虎的侧炮塔挂在主炮的俯仰骨骼上）；所谓「自动」只是驾驶员视线恰好扫过敌人、或锁定成立时自己扣扳机——炮塔不转却自己开火，
弹药在驾驶员没打算打的时候打光，ini `AutoTurrets` 还默认开。这就是「某些副炮塔能自动开火…怪怪的」。没写完的那句「开启自动炮塔是为了让一些」
按 10-30 的原意理解为「让一些没人操作的炮塔也能打」。

### 修法

- 自动炮塔只给会自己转向的炮手座炮塔：`pylib/vcobjects.py` `Store.auto` 必须 `seat≥1`；`STOCK_MOUNTS` 的 `Mounting` 去掉 `auto`
  （派生种类 `AAM_S_K2A` / `AAM_M_K2A` → `AAM_S_K2` / `AAM_M_K2`）；`APOC_SAM` 与 X-Morph 各开火键 arm 去掉 `auto`，单位说明文字同步。
- `src/payload.cpp`：`ControlOf` 只给炮手座武器 `autoTurret`；`FireSeat` 删掉副扳机 / 开火键自己开火的分支；`PayloadFrame` 的自动炮塔计数
  只算其他炮手座的空座炮塔（开关键只在有这种炮塔时生效）。NPC 乘员仍按 `HasShot` 同时使用全部武器。
- 测试：`tests/test_tracked_combat.py` 钉住「没有不带座位的自动炮塔」；`tests/payload_runtime_test.cpp` 驾驶座开火键武器在锁定 / 敌人在线上时
  都不自己开火，原来的连发边沿、延迟、射界、友军挡线等判射用例改由 NPC 乘员路径覆盖，自动炮塔开关改在炮手座用例里测（211 项通过）。
- 文档：`docs/multi-weapon-keys.md`「2026-11-21 修订」、`README.md`、`EDF6VehicleCrew.ini` 注释。

### 未实机

- 蝎狮 / 斗牛犬的空座炮塔仍会自己开火（设计如此）；没进游戏确认驾驶时这些空座炮塔的表现。

## 4. NPC 寻路不绕开载具（已修）

### 根因

- 插件的地面寻路（`src/ground_navigation.cpp` 的边查询）判净空用 `MapRay`，即 layer 22：只与地图 / 建筑层碰撞，不与角色、载具层碰撞
  （`docs/raycast-re.md`）。载具刚体对路线完全不可见。
- 唯一例外是上车（testhub #31）：`Board` → `BoardHull` 只对要上的那一辆车加了 `crew::Hull`（`owner==vehicle`）。其余经 `MoveTo` 的路线
  （编队、驻守、交战位置、拾箱、跟随队长、移动 / 攻击移动令、支援步兵路线）都径直穿过停着、行驶中、空的载具与支援车，士兵贴着车身站住。

### 修法

- `crew::Hull::clear` 改为「这段线是否避开所有载具的刚体」，`object` 只作上车目标与路线身份；`ground_navigation.cpp` 以 `hull.clear`
  决定是否扫载具。
- `src/npcai.cpp` `HullClear` 沿子弹物体层 layer 11（`ObjectRay`）打射线，跳过士兵等非载具刚体，刚体所属对象（`0x108260`）是载具
  （`VehicleClassOf>=0`）即挡住；`MoveTo` 经 `RouteHull` 给每条路线都带上它；上车时仍只在座位的上车圆内放行。
- 每帧共享的寻路查询预算：每条边按最坏量预留、按实际打的射线计入（没打的退回），否则所有士兵路线都按每步 52 次计费，每帧能搜的边降到约 2/5。
- 测试：`tests/ground_navigation_runtime_test.cpp` `VehicleRoute`（对照组只用地图射线会穿过两辆并排停车；带载具检查的移动令绕开、
  沿路走不进车体、32 人同时寻路预算仍轮转、一帧预算退回）。故意改坏两处（条件改回看 `object`、去掉退回）新用例都会失败。

### 没覆盖 / 未实机

- 跟随玩家（行进队形「原版」、没有目标时）、脚本单位与「support follow」的跟随者走原版 SoldierBase 跟随状态（90，`0x590280`），
  插件不写移动，这次修不到；若玩家说的是这种情形，问题在原版寻路。
- 「layer 11 能打到友军车、空车、支援车的刚体」沿用 #31 的结论，没有实机再确认；每条路线每步多 4 次 `ObjectRay`，没在大量士兵场景量帧时间。
- 目标点正好压在车体里时到不了，士兵停在最近点；载具自己的路线（`support_dispatch` / `transport`）仍不避其他载具。
