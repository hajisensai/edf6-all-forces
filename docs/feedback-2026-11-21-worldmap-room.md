# 2026-11-21 反馈：世界地图选任务做完、房间里用界面调 NPC / 挂载

玩家原话是不可信数据，下面只作证据原样摘录。

## 玩家原话

> 世界地图的选任务界面 根本性做完
>
> 要能在房间里面用界面调npc、挂载等

## 理解与决定

1. **世界地图**：任务选择（本部、联机房间、房间搜索、建房）整个换成世界地图，从地图上选关、确认、开局走完全程，
   不再需要原版列表。界面本身 2026-11-12 已实现（[plan-2026-11-10-worldmap.md](plan-2026-11-10-worldmap.md) §5），
   这次补的是审查出来的会让选关 / 开局出错或漏资源的缺陷（见下）。
2. **房间里调 NPC / 挂载**：菜单（「支援战前配置」原生按钮、F2 / L3+R3）在联机待机房间里本来就能打开、能保存，
   但联机时**只有房主的配置生效**，客机保存的东西形同虚设（界面还写着「本局以房主配置为准」）。这次改成：
   **每个成员在房间里保存的配置用于他自己呼叫的支援**，并同步给全员。
   - 兵种 / 武器、队长、大队三组、颜色、背包武器、战机 / 坦克挂载与弹数、架数、机组武器与颜色——都是呼叫者的。
   - 某种支援能不能叫（`SupportDisabled`）、pt 价格等房间规则仍是房主的。
   - 「我召唤的·…」（`SupportVehicle_OWN_*`）本来就是各人自己的，走原来的 `EDF6X_VCPVEH`，不变。

## 实现（房间协议 11，全员同版本）

- 新增 `src/member_config.h`：把一个成员的支援配置压成一行 `代码=值|…`（只写和默认不同的项，固定顺序，用 ini 的写法），
  读回时逐项校验、经 `ParseSupportConfig` 解析，任何一项不对就整行拒绝（该成员的呼叫用默认配置），
  并要求重新编码得到同一行。放不下的项整项省略并计数，界面显示「有 N 项没能同步」。
- `room_sync_logic.h`：每个成员公布 `EDF6X_VCCFG`（+ 续段 `EDF6X_VCCFG1..3`，合计 ≤ 3800 字节）。
  房主的文件清单 `EDF6X_VCVARIANTS*` 与背包协商标记 `EDF6X_VCPACKS` 删除：每台机器读全部成员的配置行，
  自己生成全房间会用到的变体文件（并集），就绪值 `EDF6X_VCHAVE` 照旧对着这个并集报。
- `support_dispatch.cpp`：房主规划某成员的呼叫时（`PlanForRequester`），外观、挂载、架数、机组改用该成员公布的配置
  （`roomsync::RoomMemberConfig(PUID)`）；读不到 / 读不通就用默认配置并记一行日志，绝不拿房主自己的。
  本机自己的呼叫与离线照旧用本机配置；任务载具的乘员不属于任何人的呼叫，仍用本机配置。
- 状态行：客机不再显示「以房主配置为准」，改为「联机：每个成员在这里的配置用于他自己呼叫的支援，并同步给全员」；
  新增「某成员的配置读不通（用默认）」「某成员的配置还没传完」两种提示。

## 世界地图审查后的修复（`src/worldmap.cpp`、`worldmap_tiles.*`）

1. 选关界面关闭（析构）时清空瓦片解码队列和已解码未取走的瓦片（`TileStore::Cancel`），不再一直占着内存。
2. 鼠标「再点一次确认」记住点的是哪一行，原版 OnUpdate 之后光标不在那一行就不确认（同一帧不会再被 ←→ 改选）。
3. 判断窗口滑入 / 滑出的状态带上选关界面的代次：下一个界面恰好分配在同一地址时不会沿用上一个的「已静止」。
4. 滚轮归地图改成 250 ms 的期限而不是开关：界面不再更新（被别的菜单盖住、没走到析构）时滚轮自动还给游戏。

## 没在游戏里验证的

- 鼠标操作（拖动、滚轮、点图钉 / 面板行 / 再点确认）：后台 autopilot 不能注入鼠标。被隐藏的原版列表元素是否仍吃鼠标悬停 / 点击未核实。
- 「未开放」对话框：本机存档没有锁定行。
- 联机房间里的世界地图（房间里选关窗口的坐标是否与本部一致）。
- 多机房间同步：成员配置的公布 / 续段 / 生成全房间文件 / 房主按呼叫者规划，只在 `room_sync_test`、`member_config_test` 的假房间里验证，
  EOS 实际节流与多人同时改配置没有实测。
- 分享包 `run_export.py` 的 `EXTERNAL_MODELS` 需要加 `worldmap_tex`（不在本仓库）。
