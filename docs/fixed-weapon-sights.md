# 固定武器火控

本轮修复根据实际炮口/座位合同确定火控能力，未运行游戏、未写安装目录。

- 原 `GunMarkOf` 把地形交点替换成相机目标距离的近点，固定炮口也获得可移动的圆形标线。现在目标辅助与物理路径分开存储，固定/单轴/未知安装关系只画物理方向和路径。
- 原直升机计算把左右炮口取平均；现在逐管执行真实 `MuzzleFrame` + `RoundImpact`，一侧撞地、一侧飞向空中时不会制造中间落点。
- `PayloadSightWeapons` 只读现有主/副输入、预选和重定向状态；同发去重、一个 optic owner，保持原挂载选择字段。
- 可动炮塔保留有实际射界支持的提前量辅助与标尺。固定枪不进入解耦炮塔相机，不消费不可实现的自由目标方向。

## 原生合同（当前支持 EDF.dll）

`seat+E0` 内两轴自 `+10` 起、步长 `40`；`+0/+4` 为范围，`+28` 为映射表，`+38` 为 64 位数量，表项步长 `38`。模型实例 `vehicle+EE0` 的 `+10` 为骨骼表，`+20` 为 32 位数量；骨骼记录步长 `110`、索引 `+C`、父索引 `+10`。holder `+18` 是实际绑定车辆骨骼。

Mode 0 取真实武器矩阵。Mode 1 必须证明 `weapon+E88 == holder+18`、武器模型存在、炮口骨骼属于 `weapon+FD0` 的记录表、继承链到根（非根 `+8` 为继承）；不能把武器模型骨骼索引冒充车辆模型索引。未知关系保守降级为物理标线。

`tests/weapon_mount_native_audit.py` 只读 EDF.dll 指纹与 Root.cpk，核对 506 固定机炮、409 可动机炮/固定火箭、410 门炮、卡车机枪、505 坦克、401 炮塔及实际生成 artillery 的固定水平射界，共 23 项。缺游戏文件返回 77。

## 验证边界

`fixed_weapon_sight_test` 直接调用生产 `vhud.cpp` 与 `rounds.cpp`，采用原生布局夹具和可控地形；`heli_physical_sight_test` 直接执行生产求交。`hud_view` 用生产 HUD 绘制五类 `_mock` 场景，背景与输入均为模拟，字体只读来自 Root.cpk；不是游戏截图。

无游戏/双机验收；预测只求地形与建筑的碰撞，不宣称命中敌人。最多四路径/武器，现有同发武器的各路径互不平均；射散和网络滞后仍是预测的物理边界。

本地结果：插件 MSVC `/W4 /WX`、并行 3 构建通过；7 项定向 CTest 全通过、零 skip。固定炮口生产夹具 22 条、直升机 18 条、炮塔运行时 44 条、payload sight 66 条、payload click 50 条，原生审计 23 条通过。四语言 `hud_view` 布局和标线数量检查通过，8 项相关 selftest 通过。

负对照：恢复“相机目标覆盖物理路径”以及取消固定枪门控后，真实生产夹具 22 条中 6 条失败；恢复修复后 22/22 通过。图像输出 `build/fixed-visuals` 是离线模拟，不入发布包。
