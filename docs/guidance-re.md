# 原版追踪弹的比例导引（`src/guidance.cpp`）：逆向笔记

EDF.dll TimeDateStamp 0x678CCB46，全部为 RVA。置信度：H = 读反汇编确认；M = 强推断；L = 猜测。
只做了静态分析（capstone / pefile + Root.cpk SGO），没有启动游戏。实现见 `src/guidance.cpp`，导引律 `src/pn.h`（离线测试 `tests/pn_test.cpp`）。

## 0. 先更正两处已有文档

- **vtable**：任务里给的 `0x17A1DA8`（MissileBullet02）和 `0x179F9D8`（HomingLaserBullet01）是**工厂（Factory）vtable**，见 hud-re.md 第 226 行的表；`0x17A1BD0` 是 MB01 的工厂。
  - 子弹对象本身的 vtable（`edfre.vtable_of`）：MB01 `0x17A1C10`，**MB02 `0x17A1E28`**，**HomingLaserBullet01 `0x179FA48`**。（H）
- **CP[9] 在 MB01 / MB02 里不是「导引持续时间」**。（H）
  - MB01 的判断（`0x269BFE cmp edi,ecx; ja 导引` / `0x269C02 test ecx,ecx; jne 跳过`，edi = 点火后帧数 − CP[8]）：
    只有 `t−CP8 > CP9` 或 `CP9 == 0` 时才导引。所以 CP[9] 实际上是**再加一段延迟**。type 2 的 `0x269FFE` 也一样。
  - MB02 同样（`0x26D5CA`）。
  - HomingLaser 才是真正的持续时间（`0x24FB78 cmp edi,ecx; jb 导引`）。
  - 原版只有 Ranger 的 MLRA（AWEAPON143，CP9=5）CP[9] ≠ 0，所以影响很小。docs/missile-re.md 表里的「CP9 = 持续时间」需要改正。

## 1. MissileBullet01：type 1 与 type 2

两个类型共用的部分：

- **调用**：update `0x26A880`（签名 `48 89 5C 24 18 55 56 57 41 56 41 57 48 8D 6C 24`）在点火之后：
  - 继承速度 ×0.9（`0x26AA26`）；
  - `edi = age(+0x1400) − CP7[0]`；
  - 按 CP[0] 分派：`0x26AA76 call 0x269EE0`（type 2，`E8 65 F4 FF FF`），`0x26AA85 call 0x269AF0`（type 1，`E8 66 F0 FF FF`）。
  - 两个函数**各只有这一个调用点**（`callers`）。（H）
- **之后才移动**：`0x26AB2C`–`0x26AB6E` 把 own + inherited 交给 core（`0x235540`），`0x26AB79 0x235D50` 移动，`0x26AB7E` 把 core+0xB80 抄到 B+0x90。所以**导引在移动之前**。（H）
- **导引门**（两型一样）：
  - `t ≥ CP8`（+0x13B8，无符号比较，`jb`），且 (`t−CP8 > CP9` 或 `CP9 = 0`)；
  - 锁定控制块 B+0xB18 的 use count（+8）> 0、条目 B+0xB10 非空、条目 +0x29 ≠ 0 → 瞄准点 = 条目 +0x10；
  - 否则瞄准点 = B+0x90 + B+0x80（正前方一单位，即不转向）。（H）
- **CP[12] 冲过头放弃锁定** `0x26A380(B, &aim)`：
  - B+0x13C0 开关，B+0x13C1 = 已武装；
  - nose·LOS > 0.7（`0x1765A1C`）时武装；武装之后 nose·LOS < 0 就把 B+0xB10 / B+0xB18 清零。
  - 它不改瞄准点。只有 MB01 有这一段。（H）
- **每发随机**：CP0 ∈ {1, 2} 且有 CP[10] 时，构造里 CP6 *= lerp(CP10[0], 1, rand)（`0x2687E1`），CP5 *= lerp(CP10[1], 1, rand)（`0x268947`）。插件应读运行时的 +0x13A4 / +0x13A8，不要读 SGO 里的值。（H）

**type 1 `0x269AF0`：速度矢量的纯追踪**（签名 `48 89 5C 24 18 55 57 41 56 48 8D 6C 24 E0 48 81`）

1. 速度：|own(+0x13D0)| += CP4（+0x13A0，`0x269B59` → `0x4D940` 设长度），再钳到 CP6（+0x13A8，`0x23F4E0`）。导引门之前就做，不受门影响。（H）
2. 转角：`0x4EC40(&axis, &angle, &LOS, &own)` 求 own → LOS 的转轴和夹角。（H）
   - 夹角钳到 CP5（+0x13A4，`0x269CF1`–`0x269D0A`）；
   - `0x64B90` 生成四元数，内联旋转 own；
   - **写回 own 的三条指令：`0x269E28`（x）、`0x269E80`（y）、`0x269E71`（z）**。
3. 姿态：`0x269E86 0x4E220(&M, &own)` 由速度生成姿态矩阵，4 行全抄到 B+0x60..0x9F。（H）
   - 0x4E220 第 4 行恒为 (0,0,0,1)，所以 **B+0x90 在移动前会被清零**，`0x26AB7E` 才写回。
   - 门之前也会走到这一步。
4. **最大侧向加速度 = 当前 |own| × CP5**（m/帧²）。（H）只转 own；继承速度不转，只是叠加。

**type 2 `0x269EE0`：推力加机头转向，速度有惯性**（签名 `48 89 5C 24 18 55 57 41 56 48 8D 6C 24 C0 48 81`）

1. 推力：own += CP4 × nose（nose 是 B+0x80，即矩阵第 3 行，`0x269EF5`–`0x269F43`），再把 |own| 钳到 CP6（`0x269F53`）。
   推力**每帧都沿机头**，门开不开都一样。（H）
2. 门没开（t < CP8）时直接返回（`0x269F60 jb 0x26A368`）：机头不转，只沿机头加速。（H）
3. 门开了：
   - `0x4EC40` 求 nose → LOS 的夹角，钳到 CP5（`0x26A100`–`0x26A119`）；
   - sin / cos（`0x12DA8B8` / `0x12DA8B2`）构造旋转，乘到姿态矩阵 B+0x60..0x8F（写入 `0x26A2ED`–`0x26A306`）；
   - 再 `0x26A30B call 0x511C0` 正交化。
   - **速度方向不直接转**，只转机头，速度靠推力慢慢拐过去。（H）
4. **速度的最大侧向加速度 ≈ CP4**（推力全部用在侧向时；在极速上被钳长度后，等于转角 CP4/CP6 rad/帧）。CP5 只限制机头的转速。（M：推导）

**怎么关掉原版转向而不改数据（MB01）**

- **推荐**：像 `src/splitmissile.cpp` 那样**重定向两个调用点**（`RedirectCall`，只在它们仍指向 `0x269AF0` / `0x269EE0` 时写入）。替换函数签名 `(B, uint t)`，无返回值。
  - 不是 PN 对象时直接尾调原版：插件自己的弹、锁定无效、门没开、开关关闭，都属于这种情况。
  - 是 PN 对象时由替换函数自己实现（见 §7）。
  - 原版数据一字不改。
- **为什么不能在 update 前改速度**：
  - 前置钩子（插件现在的 Guide）写入的速度，紧接着会在同一帧被 type 1 / 2 重新朝 LOS 转最多 CP5。插件自己的弹是靠 CP8 = 1e6 让门永远不开，才躲过这一步。
  - 对原版弹只能「调用前临时把 +0x13B8 写成 0xFFFFFFFF、调用后还原」。这会改数据，而且 type 2 门关时机头不转，PN 需要自己转机头。不推荐。
- **为什么不能在 update 后改**：update 后位置已经按原版速度走了一帧，下一帧原版又会把速度转回去，两者互相拉扯。

## 2. MissileBullet02（血腥风暴等）

- vtable `0x17A1E28`，ctor `0x26AF70`，update `0x26E4C0`（`48 89 5C 24 18 55 56 57 41 54 41 55 41 56 41 57`）。
- 状态机 B+0x14A0。飞行状态 `0x26EC10`（`40 53 48 81 EC 80 00 00 00 48 8B D9 85 D2 75 38`）。（H）
- **锁定**：同 MB01（条目 B+0xB10，控制块 B+0xB18，+0x29 / +0x10），每帧在 `0x26D601` / `0x26DA30` 读。没有 CP12 冲过头逻辑（不调 0x26A380）。（H）

**布局**（ctor 里按 CP 下标存放，`0x26B21F`–`0x26B9BA`）。和 MB01 的差异：**速度字段前移 0x10，延迟和持续时间前移 4**。（H）

| CP 下标 | MB02 偏移 | MB01 偏移 | 含义 |
|---|---|---|---|
| CP0 | +0x1380 | 同 | 导引类型 |
| CP3 | +0x1390 | 同 | |
| CP4 | +0x13A0 | 同 | 加速度 |
| CP5 | +0x13A4 | 同 | 每帧最大转角 |
| CP6 | +0x13A8 | 同 | 极速 |
| CP7 | +0x13AC / +0x13B0 | 同 | |
| **CP8** | **+0x13B4** | +0x13B8 | 导引延迟 |
| **CP9** | **+0x13B8** | +0x13BC | 附加延迟（见 §0） |
| own 速度 | **+0x13C0** | +0x13D0 | |
| 继承速度 | **+0x13D0** | +0x13E0 | 飞行状态里每帧 ×0.9（`0x26EC69`） |
| 每帧重力 | **+0x13E0** | — | |
| 帧计数 | **+0x13F0** | +0x1400 | |

- CP12–15 是分裂参数（split-missile-re.md）。CP10 随机在 `0x26BCC2`（CP6）和 `0x26BE18`（CP5）。（H）
- **转向函数**：type 1 `0x26D4B0`、type 2 `0x26D8D0`。算法与 MB01 相同，只是偏移不同。（H）
  - type 1：转角钳在 `0x26D6B6`，写回 own 在 `0x26D811` / `0x26D863` / `0x26D854`；矩阵行 0..2 写入后**还原 B+0x90**（`0x26D89A`）。
  - type 2：转角钳在 `0x26DAEA`，`0x511C0` 在 `0x26DCF5`。
  - 签名：type 1 `48 89 5C 24 18 55 57 41 56 48 81 EC 30 01 00 00`，type 2 `48 89 5C 24 18 48 89 7C 24 20 55 41 56 41 57 48`。
- **两个函数都返回 bool = (t ≥ CP8)**（`0x26D54B setae r14b`、`0x26D956 setae r15b`）。飞行状态只有在返回真时才做分裂判定（`0x26ECCF test al,al` → `0x26ED9C call 0x26CF00`）。**替换函数必须原样返回这个值。**（H）
- **调用点**：`0x26ECBE call 0x26D8D0`（type 2，`E8 0D EC FF FF`），`0x26ECCA call 0x26D4B0`（type 1，`E8 E1 E7 FF FF`）。
  - 另外 `0x26DEBF` / `0x26DECF` 是无引用函数 `0x26DE60` 里的 jmp（死代码，xrefs 和 callers 都为空，M）。
- **数值**：血腥风暴系列 5 把都是 type 1，CP4 0.04 / CP5 0.05 / CP6 1.5 / CP8 30 → a_max = 1.5 × 0.05 = 0.075 m/帧² ≈ 27.6 g。
- **子弹**：子导弹是 RocketBullet01（不导引）；分裂后母弹不再转向。

## 3. HomingLaserBullet01（Wing Diver：幻影 / 幽灵 / 芬里尔 / 诱导榴弹等）

- vtable `0x179FA48`，ctor `0x24ECA0`，update `0x2508B0`（`48 89 5C 24 10 56 48 83 EC 70 48 83 B9 18 08 00`）。（H）
- **它就是一颗点状子弹，「头」就是它本身**：（H）
  - 位置在 core+0xB80，移动后抄到 B+0x90（`0x2509FB`）；
  - 速度只有 own（+0x1190），没有继承速度；
  - `0x2509E7` 把 own 交给 core（`0x235540`），`0x2509F6` 移动。
- **激光尾迹**：画面上的折线是挂在 B+0xF50 的拖尾特效，每帧喂当前位置（`0x250A45` → `0x2F6110`）。（M）
  - ctor 构造的另一个对象 vt `0x179FB48`（`0x250B50`）带段数 / 宽度参数，推测就是这条带子。（M）
  - **所以只要转这颗弹的速度，尾迹会自动跟着走。**
- **CP 布局**（ctor 先校验 CP 恰好 10 项，否则销毁，`0x24EDC6`）：（H，与 SGO 数值交叉印证）

  | CP 下标 | 偏移 | 含义 |
  |---|---|---|
  | CP0 | +0x1170 | 类型：0 直飞，1 速度追踪，2 推力 + 机头，3 不交速度（不动） |
  | CP2 | int，可能是 +0x1188 | 尾迹段数（M） |
  | CP3 | +0x1174 | 加速度 |
  | CP4 | +0x1178 | 每帧最大转角 |
  | CP5 | +0x117C | 极速 |
  | CP6 | +0x1180 | 导引延迟 |
  | CP7 | +0x1184 | 真正的持续时间，0 = 不限 |
  | CP8 | +0x118C | |
  | 帧计数 | +0x11A0 | 从出生算，没有点火延迟，`0x250A09` 自增 |

- **锁定**：同一套，在 `0x24FBB0` / `0x24FFD1` 读。（H）
- **转向**：两个函数各只有一个调用点。（H）

  | 类型 | 调用点 | 函数 | 签名 | 算法 |
  |---|---|---|---|---|
  | type 1 | `0x250918`（`E8 43 F1 FF FF`） | `0x24FA60` | `48 89 5C 24 18 48 89 6C 24 20 57 48 81 EC 30 01` | 同 MB01 type 1：转角钳在 `0x24FC66`，写回 `0x24FDC1` / `0x24FE13` / `0x24FE04`，`0x24FE28` 由速度生成矩阵，4 行全写，B+0x90 同样被清零 |
  | type 2 | `0x25090B`（`E8 70 F5 FF FF`） | `0x24FE80` | `48 89 5C 24 18 55 57 41 56 48 8D 6C 24 C0 48 81` | 同 MB01 type 2：推力 CP3 沿 B+0x80，转角钳在 `0x25008A`，`0x511C0` 在 `0x250295` |

- **数值**：大多数 CP4 = 1.0 rad/帧，机头几乎瞬间对准，侧向加速度由速度上限决定。（H）
  - type 1：a_max = |v| × CP4，例如 Ghost Chaser 10 × 1、Psiblade 5 × 0.8。
  - type 2：a_max ≈ CP3（推力），例如幻影零式 0.2、Rapid Mirage 0.2（初速 10，被钳到极速 2）、幻影 5 路 1.0、幽灵 0.01、芬里尔 0.75。

## 4. 其他读锁定条目的类（`find_disp(0xB10/0xB18)` + `0x4EC40` 调用者交叉）

| 类（vtable） | 怎么用锁定 | 结论 |
|---|---|---|
| MissileBullet01（0x17A1C10）/ MissileBullet02（0x17A1E28）/ HomingLaserBullet01（0x179FA48） | 见上 | **PN 对象**（H） |
| EfsBullet（0x179E368，update 0x23F5A0 → `0x23D490`，读 B+0xB10，`0x23D9F3` 调 0x4EC40） | 由特效脚本参数驱动 | 89 个玩家武器 LockonType 全为 0；可能只有敌方弹用（L）。暂不纳入 |

**合理性检查**：
- 原版 type 1 的 a_max 从 9 g 到约 600 g；type 2 是 7–44 g。按游戏单位（m/帧）计算，别按现实 g 去判断。
- 「a_max = 速度 × 转角」只对 type 1 成立；**type 2 要用 CP4**。若对 type 2 也用速度 × CP5，Leviathan 会从 15 g 变成 0.5 × 0.05 = 0.025 m/帧²（9 g），偏差不大；但 Haytal（CP5 0.2、vmax 5）会变成 1.0 m/帧² ≫ 0.12，明显变强。

**其他注意**：
- 8 把 Lk 0 的诱导火箭（Leopard 等，Weapon_BasicShoot，type 1）也会读锁定条目。它们在原版里明显是跟着某个点飞的，条目来源没追到，可能是准星点。（L）
  建议 PN 只处理条目 **+0x08 目标对象非空**的弹（stores-re §7），或者把目标速度当 0。

- 本次扫描：从三个 update（`0x26A880` / `0x26E4C0` / `0x2508B0`）往下 3 层，**没有**以下任何东西：（H，在扫描范围内）
  - 网络函数调用（`0x7748F0` / `0x784210` / `0x7859A0` / `0x630DF0` / 注册族）；
  - 对 B+0x128 所有权位的读取。
  NetworkBullet 子对象的 vtable（MB02 是 `0x17A1EA0`）只有 4 个小访问器，没有逐帧位置同步。（M）

  要求同房间所有人装同一版本、同一设置，和 SplitMissileSurface 一样，写进 ini 注释和 README。

## 7. 各类的 PN 做法

通用做法：
- **重定向**：用 `RedirectCall` 改 6 个唯一调用点（MB01 `0x26AA76` / `0x26AA85`，MB02 `0x26ECBE` / `0x26ECCA`，HL `0x25090B` / `0x250918`）。启动时校验各被调函数的 16 字节签名（§1–§3），不符就不装。
- **替换函数**：`void/bool Steer(B, uint t)`，在 `__try` 里执行：
  - 以下情况尾调原版：开关关闭；插件自家弹（CP8 = 1000000 且 CP9 = 4242）；原版的门没开（MB 用 CP8 / CP9，HL 用 CP6 / CP7）；锁定无效。
  - 以上都不是才走 PN。
- **目标速度**：锁定点逐帧差分，按**条目指针**索引（条目属于目标，多发弹共用一份差分），跳动超过 20 m 视为换目标，规则同 missile.cpp。
- **PN 量**：ω = r × v_rel / |r|²，a = N·(ω × v)，去掉沿速度的分量，再 |a| ≤ a_max。
  - MB01 type 1 的 v 用 own + inherited 算 LOS 角速度，但只改 own（原版也只转 own）。（M）

**type 1（MB01 +0x13D0 / MB02 +0x13C0 / HL +0x1190）**
1. `s = min(|v| + accel, vmax)`：MB 的 accel / vmax 是 +0x13A0 / +0x13A8；HL 是 +0x1174 / +0x117C。
2. `a_max = |v| × turn`：MB 的 turn 是 +0x13A4，HL 是 +0x1178。
3. `dir = normalize(v + a_pn)`，`v = dir × s`。
4. 仅 MB01：调用前先 `0x26A380(B, &aim16)`，保留 CP12 放弃锁定的行为。
5. 姿态：`0x4E220(&M, &v)`。
   - MB01 / HL：抄 4 行（与原版相同，B+0x90 在移动后由 update 写回）；
   - MB02：只抄 3 行，保留 B+0x90。
6. MB02 返回 `t ≥ CP8(+0x13B4)`。

**type 2（推力加机头）**
1. 推力预算 = accel（a_max = accel）。
2. `a_lat = clamp(a_pn, accel)`，`n = (a_lat + sqrt(accel² − |a_lat|²)·v̂) / accel`。可选：限制 n 与当前机头的夹角 ≤ turn，保留原版机头转速。
3. 机头：`0x4E220(&M, &n)` 的前 3 行写到 B+0x60 / 0x70 / 0x80（保留 B+0x90）。
4. `v += accel·n`，再 `0x23F4E0(&v, vmax)` 钳长度。
5. 门没开时尾调原版（原版只沿机头推、不转）。MB02 返回 `t ≥ CP8`。

需要实机确认：
- type 2 改用 0x4E220 生成机头后，滚转（roll）丢失对模型 / 尾焰的视觉影响；
- HL 尾迹在急转时是否正常；
- Tempest / Leopard 的锁定条目来源。

## 8. 插件的实现（2026-10-06）

- 6 个调用点经 `RedirectCall` 改到插件，启动时核对每个被调函数的 16 字节签名，不符的那一个保持原版（日志 `GUIDANCE ... unexpected code`）。
- 走原版的情况：`StockMissilePN=0`；插件自家导弹（CP8 = 1000000，`src/missile.cpp` 在 update 前自己导引）；原版导引门没开；锁定条目无效。
- 走 PN：type 1 侧向加速度上限 = |own| × 转角，速度 = min(|own| + 加速度, 极速)，姿态由 look-to 沿速度生成（只写前三行，B+0x90 留给 update）；
  type 2 推力 = 加速度，PN 要求的侧向分量不超过推力，其余沿飞行方向，机头每帧最多转原版转角，再钳到极速。MB02 的替换函数原样返回 `t ≥ CP8`。
- 目标速度：`src/missile.cpp TrackRound`（锁定点逐帧差分、跳变 20 m 视为换目标、诱饵弹、来袭导弹告警），与插件导弹共用一份。
- 导引常数 `StockMissileNav`（默认 3）。CP12「冲过头放弃锁定」（`0x26A380`）原版武器表里没有，不接。
