# 载具状态 HUD 逆向笔记（`src/hud.cpp`）

EDF.dll TimeDateStamp `0x678CCB46`，地址均为 RVA。可信度：H = 反汇编逐条确认；M = 由调用方式推断、未进游戏验证；L = 猜测。

## 0. 挂点

不新挂钩。复用 `subcarrier.cpp` 已有的 `GaugeHook`（把 `HudPlayer_FollowerDurability` 绘制 `0x8040E0` 里唯一的
`call 0x804300` 改指过来，见 `docs/subcarrier-re.md` §4）。`GaugeHook` 先画原版跟随者血条、再画潜舰替身血条，最后调
`HudDraw(viewProj, ctx=r9, viewport=第5参数, panels, n)`。

| 项 | 内容 | 可信度 |
|---|---|---|
| `0x804300` 的 r9 | 即 `0x8040E0` 的 rdx（HUD 绘制上下文 ctx），原样传给 `0xC2FB0` 的 rdx | H |
| 第 5 参数 | 视口：`+8` 宽、`+0xC` 高（int） | H |
| rdx（viewProj） | 4 行 × vec4；`clip[k] = x*vp[k] + y*vp[4+k] + z*vp[8+k] + vp[12+k]` | H |
| 屏幕坐标 | `sx = W/2 + W/2·ndc.x`，`sy = H/2 − H/2·ndc.y`（左上原点、y 向下）；剔除 `w==0`、`|ndc.x|>1`、`|ndc.y|>1`、`z∉[0,1]` | H |
| 原版血条尺寸 | 半宽 `31·uiW/1920`、半高 `3·uiH/1080`（`ui` = `*(*(0x2137090)+0x10)` 的 `+0x20/+0x24`）；位置在对象 `+0x90` 上方 2 m | H |

### 0.1 缩放基准（`src/hudscale.h`，2026-10-06）

| 项 | 内容 | 可信度 |
|---|---|---|
| 原版 HUD 的基准 | 游戏画面 `ui = *(*(EDF+0x2137090)+0x10)`，`+0x20` 宽、`+0x24` 高（int）；设计分辨率 1920×1080 | H |
| 原版图形 | 跟随者血条 `0x804300`：半宽 `31·uiW/1920`、半高 `3·uiH/1080`（`0x8044B1` 起）；名牌间距 `(…+16)·uiW/1920`（`0x80532A`） | H |
| 原版文字 | 字体缩放同样乘 `(uiW/1920, uiH/1080)`：`0x94E24F` 处 `0.65·(uiW/1920, uiH/1080)`，`0x95CE60` 处 `(uiW/1920, uiH/1080)`，再交给 `0x113A3F0` | H |
| 字形本身不随分辨率 | 字体管理器建字时字高写死 32（`0x963984 mov [rsp+38h],20h`，经 `0x11517F0 → 0x1139BC0 → 0x117C8B0 → 0x1181A50` 进 `CreateFontIndirectW`）；字形按「32 px × 缩放」栅格化，正交投影是渲染目标像素（§2） | H（调用链逐条反汇编） |
| ui 与视口 | `0x8000C0` 拿 `uiH/2` 和视口 y 比较（上下分屏判断），说明 ui 是整块画面、分屏视口是它的一部分；原版分屏时 HUD 仍按整块画面的大小画 | M |

插件以前：图形按 `s = 视口高 / 1080` 缩放，文字的字号却是固定值（`kLineScale` 0.6 等，没乘 s）。实测日志（3840×2160，
`EDF6VehicleCrew.log`）：航向带刻度间距 120 px（= 10°×6 px×2，图形已放大 2 倍），刻度数字「150」量出来只有 23×17 px
（= 1080p 下的大小），所以 4K 下字只有设计比例的一半，和框、圆、行距对不上。分屏的视口若是上下分，`视口高/1080` 还会把
图形也缩成一半，而原版不缩。

现在：`s = 画面高 / 1080 × HudScale`（画面读不到或装不下视口时退回视口高），文字在 `Font()` 统一乘 `s`（`Text::s`），
各模块只写设计值。宽屏（如 21:9）原版文字横向被拉宽（x、y 两个缩放不同），插件保持等比、按高度缩放（圆和字不变形）。
`InstallHud` 核对 `0x94E24F` 与 `0x8044B1` 的读取序列，对不上时 `screen=0`，退回视口高。

## 1. 四边形 `0xC2FB0`（血条的底框和填充都用它）

`0xC2FB0(drawer = *(EDF+0x2139A78), ctx, const float m[16], const float rgba[4], int topology = 5, const float* xyz, int count = 4, void* tex = 0)`

| 项 | 内容 | 可信度 |
|---|---|---|
| m | 行主序 4×4，原版传单位阵 + 第 4 行平移 `(sx, sy, ndc.z, 1)` | H |
| 顶点 | 4 个 float3，顺序 `(-x,-y) (x,-y) (-x,y) (x,y)`，三角带（D3D11 topology 5） | H |
| 颜色 | RGBA float：底框 `0x17F42E0 = (0,0,0,0.5)`；填充按 `hp/max·3` 取 `0x17F6C40` 表（红、黄、浅蓝、浅蓝） | H |
| 第 8 参 | 0 = 用 drawer 自带的白纹理 | M |

插件用同一调用画任意矩形：平移 = 左上角，顶点 = `(0,0)(w,0)(0,h)(w,h)`，z 用 0（文字也用 0）。M：z=0 是否受深度测试影响未验证，原版文字用 0。

`InstallHud` 核对：`0xC2FB0` 函数头、`0x804582 mov rcx,[EDF+0x2139A78]`、`0x8045B3 mov [rsp+20h],5`。

### 2.1 字形缓存（为什么插件的字号必须取有限几档）

文字渲染器的字形缓存在 `[renderer+0x18]+0x98`，所有调用方（原版菜单、兵种名、存档界面、插件 HUD）共用这一份。

| 项 | 内容 | 可信度 |
|---|---|---|
| 查询 `0x117B340` | 量尺寸 `0x1139767/0x1139901`、画字 `0x113BEB2/0x113C07D/0x113C877` 每次都调用；命中时年龄清零（`0x117B470`） | H |
| 键 `0x117B250` | `字符 \| half(缩放x)<<16 \| half(缩放y)<<32`：缩放转半精度后进键，**每个不同的字号是一整套独立字形** | H |
| 未命中 `0x1174150` | `GetGlyphOutlineW` 栅格化，再由 `0x117B140` 在贴图页里按行高分配格子；所有页都满时返回 null，这个字不画 | H |
| 回收 `0x117AFA0` | 由 End（`0x113C5C0` 尾部）调用，按墙钟每 0.3 s（`0x1765A18`）最多扫一轮：年龄 +1，超过 2 的释放格子（`0x117A8B0`）并删掉；分配器 `0x11795E0` 先删空行再分配 | H |
| 原版字号 | 固定几档（救援 1.33，名牌 0.666），所以缓存稳定 | H |

插件的世界血条文字曾按视距连续缩放（`kLineScale × DepthScale`），几乎每帧都是新字号：每台载具每帧栅格化一整套字，
贴图被反复填满、回收，与玩家报告的菜单缺字、显示成别的字（剑兵 → 水兵）和低配卡顿吻合
（「格子复用 → 错字」的最后一环未在游戏里实测，L）。现在 `Font()` 把所有字号吸附到
`kTextScaleStep`（1/32）的格点，字号最多十几档；血条本身仍连续缩放。

### 2.2 原版的线程问题（`src/glyphs.cpp`）

原版自己就会把字显示成别的字（剑兵 → 水兵）或缺字，不装插件也有。逐层排查：

| 层 | 结论 | 证据 |
|---|---|---|
| 格子分配器 `0x11795E0` / 释放 `0x117A8B0` | 没问题 | `tools/atlas_fuzz.py`：把 EDF.dll 映射进测试进程，直接调游戏自己的分配/释放，120 万次随机操作（连续宽高、灌满再大批释放），活格子零重叠、零重复句柄 |
| 缓存逻辑（命中/未命中/只量尺寸/失败删除/回收） | 单线程下自洽 | 逐条反汇编，§2.1 |
| 锁 | **只锁了 GDI 栅格化**：`0x1180ED0` 在字体对象 `+0x29F0` 上自旋锁（拿不到就 `Sleep`），`0x1180FC0` 解锁 | 反汇编（H）。原作者预期多个线程同时用字体 |
| 锁外的共享状态 | 字形表（`unordered_map`）的插入/删除、格子分配/释放、每 0.3 s 的回收、页脏标记置位（`0x11743B7`）与上传后清零（`0x11740E5`） | 反汇编（H） |

两个线程同时进入时，例如 B 刚把新字画进页并置脏、A 随即上传后清零，B 的字就再也传不上 GPU，格子里留着上一个占它的字的旧图；
表、分配器被并发改写也会把格子交给第二个字。表现正是整字替换、字数不变、此后一直错（L：并发的实际发生未在游戏里抓到，
插件日志 `GLYPH thread … enters the glyph cache` 记录每个进入缓存的线程，2 个及以上即为实证）。

修法：缓存的 4 个入口 —— 查询 `0x117B340`、取字宽 `0x117B5E0`（未命中也插入）、回收 `0x117AFA0`、页上传 `0x11740B0` ——
的全部 10 处 rel32 调用改指到插件，在同一把临界区里调用原函数。GDI 自旋锁只在前两者内部拿，外面没有先拿它再调进来的路径，
锁顺序恒为「插件锁 → GDI 锁」，不会死锁。任一签名或调用点对不上就一处都不改（只锁一部分等于没锁）。

插件每次绘制：造一个 r，每行字 begin→measure→end 一次（排版）、begin→draw→end 一次，最后释放；先画全部四边形再画全部文字。
文字路径在 SEH 里，出异常就关掉文字（只剩血条），日志 `HUD the game's text path faulted`。

## 5. 战斗机 HUD（2026-10-05，`hud.cpp` `FighterHud`，数学在 `src/sight.h`）

对玩家正在驾驶的那架插件飞机（`playerjet.cpp` 的 `PJet` 记录，不按机型标记区分，以后玩家能开的任何插件飞机都一样），
游戏线程每帧在 `Fly` 里算好 `PlayerJetSymbols`（`Sight`、`Threats`），随 `PlayerJetReadout.sym` 进快照，绘制线程只读快照。

| 部件 | 做法 | 可信度 |
|---|---|---|
| 斜线、三角形 | 同一个 `0xC2FB0` 四边形：单位变换、4 个顶点直接给屏幕坐标，顶点顺序与 `Rect` 相同（同一绕向）；三角形是第 4 个顶点与第 2 个重合 | 调用 H；任意朝向的四边形 / 退化三角形能否正常画（剔除、绕向）**L，需实机看** |

| 速度 / 高度框 | 屏幕中线左右各 280 px（1080 线），速度 km/h + G、离地高度（无地面 ALT*）+ 爬升率；起落架指示留给 `feat/jet-gear` 分支：速度框下第二行 `(W/2 − 280s, H/2 + 60s)` | 设计 |
| 机炮瞄准具 | 机头方向十字（炮线）；弹着圈 = 现在打出的炮弹在目标距离处的位置 `pos + nose·v·t − ½·g_f·g·t²`；v、寿命、重力系数读机炮武器自身（`+0x894` m/帧 ×60、`+0x898` 帧、`+0x8E0`，座位 0 的第 0/1 个持有者，跳过追踪弹）；喷气机机炮 v = 960 m/s、寿命 1 s、重力系数 0；`AmmoOwnerMove` = 0（原版机炮 SGO），所以炮弹**不**继承飞机速度，提前量里不加本机速度 | 字段 H（与 jet_combat / heli 同一读法）；炮弹沿机身 nose 方向射出 **M**（NPC 喷气机的开火逻辑按此，未对玩家座位单独核实） |

开关：ini `PlayerJetGunSight`（并隐藏原版红线，`docs/aim-line-re.md` 第 5 条）、`PlayerJetFlightHud`、`PlayerJetThreatHud`，默认都开。
文字行上限从 64 提到 96（HUD 最多再加约 30 行：俯仰梯标签 ≤ 10、航向带 ≤ 8、框 6、导弹距离 ≤ 6）。

**离线验证**（`tmp/sight_test.cpp`，不入库：用 cl 编译后直接跑 `src/sight.h`）：静止目标 600 m → t = 0.625 s；
5 组交叉 / 斜向 / 迎头 / 远离的目标，`|d + v·t| = v_b·t` 成立，弹着圈与提前量标记是同一点，按提前量方向射出的直线弹道与目标最近距离 0；
目标比炮弹快 → 无解；重力系数 1、1 s 下坠 7.35 m；D3D 左手透视下正前方方向落在屏幕中心，方向与沿它 1e6 m 的点重合，
水平方向都在中线上，上仰 10° 落在 `H/2·(1 − tan10°/tan30°)`；`Toward` 对右前、左后、正后上方、正后方分别给出右、左、上、下；
航向 +Z = 0、-X = 90、+X = 270。

**需实机确认**：斜四边形 / 三角形是否画得出来（若剔除了，就把顶点 2、3 对调）；弹着圈和炮弹实际轨迹是否重合（炮口偏左右、

**对着敌人 / 对空（2026-10-06，`src/roundaim.h` `GunSight`，`vhud.cpp` `RangeTarget` / `GunMarkOf`）**：用户开 E551（`V_505TANK_DLC_CANNON04L`：11 m/帧、重力系数 0.25、寿命 600 帧、AmmoOwnerMove 0）对着天上的飞碟，HUD 显示「CANNON 3132 m」，反馈「这个好像一直不动也对不上」。日志（`Debug=1`）同期每 2 秒一行都是 `CANNON 24/32 ... hit 0 3132m 4.8s`。

- 根因：没打到地面时弹着圈画的是 `FirstHit` 在 3000 m 处截断的弹道终点（15 帧一段才判一次距离，所以是 3132 m 而不是 3000 m）。这一点只取决于炮口方向；对空时炮塔镜头把炮膛线对准视线 800 m 外的点（`turretcam.cpp` `AimPoint` 的 `kAimFar`），所以这一点永远在屏幕中心附近（离线：视线仰角 5°–60° 时离中心 0.08°–0.47°）——「一直不动」；它表示的是 3 km 处的下坠，和飞碟的距离、移动都无关——「对不上」：静止的飞碟误差不大（这门炮下坠小、视差和下坠互相抵掉一部分：600–2500 m 时把旧弹着圈压在飞碟上只偏 1.8–5.6 m），但飞碟一动就差得远（横穿 40 m/s：600 m 偏 36 m、1200 m 偏 72 m、2000 m 偏 121 m、2500 m 偏 151 m），因为它完全没有提前量。
- 原版怎么做：原版没有弹着点，只有炮口的红色瞄准线（`docs/aim-line-re.md`）：`0x6B3660` 每帧以炮口为起点，每段走「炮口方向 × AmmoSpeed × custom_parameter[1]」、再加「世界重力 × AmmoGravityFactor / 3600」（`0x6899F0` 的循环：`v += g`、`p += v`），画 custom_parameter[0] 段（如 60 段 = 1 秒的飞行）。即只画炮弹头一段的弧线，不算目标、不算提前量；这条线在这套 HUD 开着时被隐藏。
- 改法：取屏幕中心 5°（`kPickCone`）内最近的敌人锁定点（`VisitEnemies`，`proteus.cpp` 标记的同一取法），选中后偏到 15°（`kKeepCone`）内仍跟着它（把弹着圈压到提前量标记上时视线会离开目标一个下坠 + 提前量的角度），速度按锁定点逐帧位移、0.3 s 平滑（超过 300 m/s 视为重生、清零）。对弧线弹（不含榴弹类高弧和火箭）按游戏同一逐帧步进求炮弹对这个敌人的最近经过（`roundaim::Nearest`，算上敌人速度和本车速度 × AmmoOwnerMove）：弹着圈画在那一刻炮弹的位置、提前量标记（十字圆圈，`hud.cpp` `LeadMark`，战斗机机炮瞄准具同一画法）画在那一刻敌人的位置，旁标到敌人的距离；最近经过在寿命结束处（够不着）时两者变暗。炮弹在经过敌人之前先打到地图：照旧画落地点。都没有：只画炮膛十字和武器名（暗色），不再画 3000 m 那一点。
- 离线（`tools/rounds_check.cpp` `SkySight`，E551 的炮和镜头位置）：玩家把新的弹着圈压到提前量标记上时，上面 8 种情形炮弹都在 0.5 m 内经过飞碟（实测 0.00 m）；把 `GunSight` 的测距分支去掉（变异），这 8 条全部变红。

### 7.4 画法

- 弹着点：弧线 = 直升机同款瞄准十字 + 弹着圈（旁标「标签 距离」）；准星附近有敌人时弹着圈测距到它、加提前量标记（十字圆圈，§7.3「对着敌人 / 对空」）；既没打到地图又没有敌人时只画瞄准十字和标签（暗）；高弧 / 榴弹 = 黄色十字（`ImpactCross`，与喀秋莎同一画法）+「标签 距离 飞行秒」；火箭 = 空心菱形；导弹 = 锁定框 / 未锁定时炮口方向的暗圆环 + LockonRange。同标签、落点相距 2 m 内的（左右成对的炮）只画一个。选中的挂载标签加方括号。喀秋莎的发射架（`kMarkLofted`）由 `launcher.cpp` 照旧画十字和散布圈，这里只在列表里列出（ROCKETS），不重复画。

### 9.2 插件怎么去掉它

不跳过绘制、不碰布局节点：只在更新（vtable slot 1 改指 `UpdateHook`，其余原样调用）前后改这张表。

## 10. 暂停菜单（2026-10-06，`src/game_clock.h`、`crew.cpp GamePaused`、`hud.cpp HudDraw`）

用户反馈：「暂停以后hud会飞走」（没有截图，没说是哪块）。

### 10.1 游戏自己的暂停标志（H，静态反汇编）

| 项 | 内容 | 可信度 |
|---|---|---|
| 对象 | `xgs::game::System`，指针在 `EDF+0x20B2958`（vtable `0x1AE2278`） | H |

### 10.2 插件的问题（根因）

1. **游戏时钟没停**（`crew.cpp GameMs`，旧规则：两次读取间隔超过 250 ms 才当暂停）。暂停时载具输入不跑，但镜头第 4 槽照跑，
   炮塔镜头（`turretcam.cpp Camera`，在骑乘镜头 state 2 里）每帧都读 `GameMs`，读数间隔 16 ms，时钟于是整段暂停照走。
   暂停 150 ms 后 `aimed`（`kAimFreshMs`）失效 → 炮塔镜头把镜头交还原版座位视角（`Leave`，15 帧缓出），200 ms 后 `live`
   （`kFreshMs`）失效 → 直接放手，原版镜头自己缓到座位定位点。也就是暂停菜单底下画面转开；恢复时炮塔镜头再从原版视角缓入，画面转回来。
   插件 HUD 在暂停的前 0.5 s 里还在画（快照的墙钟年龄 `kFreshMs` = 500 ms），落在世界上或按方向投影的标记（弹着圈、锁定框、单位血条、
   地平线、俯仰梯）跟着转开的镜头一起移出去，然后消失；恢复时又跟着镜头转回来。同一个时钟还让燃料、冷却等所有按游戏时间的计时在暂停中照走。
2. **HUD 只靠快照年龄判断暂停**：墙钟 0.5 s 才藏，潜舰血条和面板按自己的 1 s（`subcarrier.cpp kGaugeMs`），这段时间里镜头一动就跟着飞。

逐帧的 dt 平滑（`GameStep`、`vhud.cpp Speed`、`stockgauge.cpp FuelGauge`、`hud.cpp TrailOf`）都已经对 dt = 0 和大 dt 做了限幅或判零，
离线看不出发散；问题在时钟本身。

### 10.3 修法

- `GamePaused()`：读上表的 System 暂停位（加载时 `CheckPauseFlag` 核对 `0x934A46` / `0x934ED3` / `0x1196FC0` / `0x11990C0` 的字节，
  对不上就恒为 false，退回旧规则；运行时再核对 System 的 vtable）。
- `GameMs` 改走 `src/game_clock.h`：暂停中读取不推进时钟（读数仍记下墙钟，恢复后第一次读取只走一帧）；没有暂停标志时的长间隔（读盘）仍按一帧 16 ms。
- `HudDraw`：`GamePaused()` 时一笔不画（包括潜舰血条和地图标记）。暂停期间镜头不再被插件交还，画面本来就不动，这一条是让 HUD 与暂停菜单同时消失，不再等 0.5 s。

离线：`tools/pause_clock_check.cpp`（CMake 目标 `pause_clock_check`）按游戏的帧顺序（每帧先载具输入读时钟、再镜头步进读时钟；
暂停 3 s 只有镜头步进）比较新旧规则：旧规则暂停 2880 ms 时钟走了 2880 ms，炮塔镜头在暂停第 160 ms 交还镜头、第 208 ms 放手，恢复后第一帧一步 2896 ms；新规则暂停中时钟走 0 ms、镜头不交还、恢复后第一帧 16 ms；2 s 读盘两者都是 16 ms。`tools/hud_view` 的 `PausedDrawsNothing`：原版坦克场景运行中画出 (465,87)-(1649,861)，暂停时一笔不画。

**需实机确认**：暂停后画面和 HUD 不再移动（炮塔镜头 / 高视角下尤其）；暂停期间插件 HUD 立即消失、恢复后立即出现；
地图打开时按 Esc（暂停菜单同时打开）的表现（地图镜头按墙钟 300 ms 判关闭、15 帧缓回，未改）；用户说的「飞走」若是原版 HUD 的滑出动画（10.1 最后一行），那是原版行为。

### 11.1 游戏的语言设置（H，静态反汇编）

| 项 | 内容 | 可信度 |
|---|---|---|
| 当前文字语言 | 一个 int，`EDF+0x20B2B30`。读取函数 `0xE4000`（`mov eax,[rip+X]; ret`，X 解出来正是 0x20B2B30），写入函数 `0xE4030`（`mov [rip+X],ecx; ret`）；语音语言是旁边另一对（`0xE4070`） | H |
| 取值 | 0 ja、1 en、2 kr、3 cn（繁体，字体 B5）、4 sc（简体，字体 G30）：与选项字符串 `Option_Language_ja/en/kr/cn/sc`（`0x1802638` 起，`0x88F6E0` 按这个顺序列出）一致；启动时 `0x706EF0` 把 Steam 的语言名 english / japanese / koreana / tchinese / schinese 映射成 1 / 0 / 2 / 3 / 4 | H |
| 谁写 | 启动时按 Steam 语言（`0xD62C0` / `0xD90D0`：与 english / japanese / koreana / tchinese / schinese 比较后调 `0xE4030`）；选项改动（`0x9457DE`：选项数据 `+0x310` → `0xE4030`，紧接着按新语言重排字体 `0x94580D call 0x963830`）；另有 `0xABFCF` 一处（同样随后重排字体，调用方未细查） | H（调用者用途 M） |

### 11.2 字形：原版字体链（H）

| 项 | 内容 | 可信度 |
|---|---|---|
| 四款字体 | `0x963830` 用 `AddFontMemResourceEx` 装入 `app:/UI/TT_NewCezanne-DB.ttf`（日文，FOT-ニューセザンヌ DB）、`arudjingxiheikr_bd.ttf`（韩文）、`arudjingxiheib5_bd.ttf`（繁体，Big5）、`arudjingxiheig30_bd.ttf`（简体，GB18030），全部进同一个字体管理器 `*(EDF+0x20B29C0)`（插件 HUD 用的就是它，§2） | H |
| 顺序 | 按语言（edx）选一个 4 元顺序（`0x963935` 起的分支）：ja / en `(日, 韩, 繁, 简)`、kr `(韩, 日, 繁, 简)`、cn `(繁, 简, 日, 韩)`、sc `(简, 繁, 日, 韩)`，依次建成链表；字高 32（`0x963984`，§0.1） | H |
| 逐字回退 | 未命中时栅格化 `0x1174150` 先调 `0x1173E20(链表, 字)`：沿链表对每款字体 `GetGlyphIndicesW(..., GGI_MARK_NONEXISTING_GLYPHS)`，第一款结果不是 0xFFFF 的就用它；都没有时用第一款 | H |

### 11.3 字形缓存压力

缓存键是「字 + 字号」（§2.1），插件字号仍是 1/32 格点上的那几档，没有增加。增加的只是字的种类：`tools/hud_view` 统计每个画面用到的（字, 字号）对，
最多的画面英文 131（map_mid）、简体 147、繁体 146、日文 165（都是 map_low：图例、按键说明、标题）。四页 1024×1024（字体描述的默认值 `0x1137B70`：+0x20/+0x24 = 0x400、+0x28 = 4，M：未追到缓存构造里），
1080p 下 HUD 字号 14–24 px，中日文一格约一个字号见方：165 个字最多约 0.13 MB 像素，占一页的 12%；4K（×2）约一页的一半，四页的八分之一；
不再显示的字约 0.9 s 后被回收（§2.1）。所以中文 / 日文 HUD 不会把缓存挤满（L：与原版菜单同时大量出字的情况未进游戏测）。

### 11.4 文字表与翻译原则

- `src/hudtext.inc`：每条 `HUDTEXT(key, 英, 简, 繁, 日)`，是一个 printf 格式；代码只按 key 取（`Tr(Tx::key)`），`hud.cpp` / `mapcmd.cpp` 里不再有英文或中日文字面量（`selftest hud_text_localized` 扫源码：去掉 printf 转换后剩下的两个字母以上的词只允许 LB / RB / LT / RT / km）。
- 运行时作为标识符传进来的词（弹种标签 GUN / CANNON / MSL / RKT…、插件单位的 role、潜水母舰部件名）在日志里仍是英文，画的时候经 `hudtext::Word` 换成当前语言；表里没有的（武器型号）原样显示。
- 翻译：状态、告警、提示、面板与图例翻译；用词跟原版文本（Root.cpk `ETC/TEXTTABLE_STEAM.{SC,CN,JA}.TXT_SGO`）：飞弹 / 飛彈 / ミサイル、机炮 / 機砲 / 機関砲、加农炮 / 加農砲 / キャノン、装填 / 裝填 / リロード、载具 / 載具 / ビークル、坐席、驾驶席、准星、加速、替换武器、鼠标左键……；插件自己的单位按 README 的叫法（炮舰机、潜水母舰、钻头战车、深渊爬行者、人偶无人机）。
- 保留原文：武器 / 弹药型号（AIM-9X、Mk 82、Hydra 70）、原版载具类名（403 TANK 等）、按键名（Windows 给的键名）和手柄键（LB、RT、A…）、单位（m、km、km/h、s、%）、过载 G、雷达告警圆盘上的 J / M 符号。
- 各语言格式的参数必须与英文一致（同样的 `%d` / `%ls` 顺序）：`tools/hudtext_check.cpp` 逐条核对、并检查没有漏译（与英文相同的只允许 NPC），`selftest` 核对简体字都在 GB2312、繁体在 Big5、日文在 Shift JIS 里（简繁混用会被抓到）。

### 11.5 布局

文字宽度一律实测（§2 的量尺寸），原来按测量排版的都不用改；按固定宽度画的两处改成随文字撑开：挂载切换横幅（原来固定 300 px，日文「ロケット 19/19」会超出面板）

每种语言检查：文字都在屏幕内、面板里的文字不出面板、没有英文里没有的文字重叠，原来的 RWR / 原版载具块 / 自瞄行互不重叠检查在每种语言下也跑。`python tools/hud_view.py DIR` 有游戏时用游戏自己的四款字体按同样的回退顺序出图。

**需实机确认**：选项里切语言后 HUD 是否下一帧就换；繁体 / 日文模式下字形是否与原版菜单同一风格；中文模式下拉丁字母变成比例字体后各行长度（已按测量排版）。

| 开关 | xgs 镜头对象 `+0x200`（byte，1 = 画玩家 HUD）。基类构造 `0x118AFC0` 在 `0x118B03A` 写 1；`CharacterGhostCamera` 构造 `0xF4860 → 0x103740 → 0x118AFC0` | H |
| 谁写它 | 只有 `0x118DF30`（`mov [rcx+200h],dl; ret`），唯一调用者是任务脚本函数 `void SetPlayerHudShow(bool)`（实现 `0x1BA790`，注册在 `0x1E959A`）：对 System 视口表（`0x1195BE0`，`system+0x4D8` 步长 `0x188`，4 个槽，`0x1BA7C0` 起的循环）里每个槽的镜头调一次，调用点 `0x1BA811`（`0x1BA80D movzx edx,sil; call`）。过场演出就是用它藏 HUD 的 | H（全 .text 扫 `+0x200` 的写：其余都是别的类） |
| 谁读它 | 各 HUD 的绘制（第 3 槽）经 Hud `+0x18`（所属镜头）读：`HUiHudBaseObject` / `HuiHudWeaponObject` / `HUiHudDamageObject` 共用的 `0x8168B0`（`0x8168D3`；雷达、武器栏、护甲 / 耐久、伤害方向都是这几个包装类），准星 `HudPlayer_CrossHair 0x8039F0`（`0x803AC9`），救援提示 `HudPlayer_RescueMessage 0x808410`（`0x80843F`）。为 0 时直接跳过绘制 | H |
| 不读它的 | 跟随者血条 `HudPlayer_FollowerDurability 0x8040E0`（插件 HUD 就挂在它的 `0x804300` 调用上，见 §0）、联机状态 `0x8077B0`、聊天 `0x802F10`。原版过场时这几块也不藏 | H |
| 镜头与 HUD 表是同一个对象 | 视口每帧 `0x118DF40`：`call [rax+20h]`（第 4 槽：`CharacterGhostCamera` 的 `0xF86A0`，地图串接的那个）后在同一对象的 `+0x208` 上逐个更新 HUD（`0x118DF4F`）；绘制 `0x118D810` 也走 `+0x208` | H |

结论：用原版的整体开关，不逐个元素去关。跟随者血条不受开关管，由插件自己的 `GaugeHook` 在开关被插件按住时不调原版 `0x804300`。
联机状态和聊天与过场一样保留。原版的「任务文字」（字幕 / 无线电）不是这组 HUD，过场里也照常显示，这里不动。

### 12.2 插件怎么做（`map_stock_hud.h`，离线 `tools/map_hud_check.cpp`）

- 记录 `Record{cam, generation, hidden, want}` 是按住期间这个字节的唯一所有者，在 `hudLock` 下改：
  - 镜头第 4 槽钩子（`CamStepHook`，原函数和地图镜头逻辑以及它的 `__except` 之后）调 `StockHud`：地图视角在这台镜头上
    （`camSide.shown`：缓入、打开、缓回 15 帧）→ 第一次记下当前值为 `want`、写 0，之后每帧保持 0；不在 → 写回 `want`、清记录。
    关地图、镜头钩子出异常（`camSide` 被清）、按 Esc / B、`Map=0`、插件关掉、暂停 300 ms 后地图自动关，全走这一条。
  - `SetPlayerHudShow` 的调用 `0x1BA811` 被 `RedirectCall` 改指到 `HudShowHook`：按住的那台镜头上只改 `want`（关地图时生效），
    其余镜头照原样调 `0x118DF30`。所以地图开着时任务开始过场藏 HUD、或结束过场显示 HUD，关地图后得到的是任务最后要的值。
  - 只写正在步进的那台镜头（它此刻一定活着）；第二个本地玩家的镜头不碰。
  - 换关（`ResetMap` 推进 `generation`）：上一关的记录作废。同一地址的镜头再步进时，记录的是「显示」就写 1（构造值本来就是 1，
    无害），记录的是「隐藏」就什么都不写（可能是新镜头）；新关里脚本先写的值直接写进字节，不被旧记录吞掉。
- 签名（`InstallHudSwitch`，任一不符或改指失败就整个不隐藏原版 HUD，写日志 `MAP the stock HUD's switch: ...`）：
  `0x118DF30` 整个函数、`0x1BA80D` 调用、`0x1BA7C0` 视口循环、`0x8168CF` / `0x80843B` / `0x803AC9` 三处读、`0x118DF4F` 视口步进。
- 插件 HUD（`HudDraw`）：地图开着（`PlayerMap` 有读数）只画地图层（标记、网格、指挥 UI、图例和按键说明，原有逻辑）；地图镜头缓回
  的那 15 帧（`MapOwnsView()` 但没有读数）一笔不画——这时的视图矩阵还是地图机位的，弹着圈、炮塔白框、载具 HUD 会画错位置。
  潜舰血条也在这之后，同样不画。

离线：`map_hud_check` 24 条（打开 / 缓回 / 关闭、镜头钩子出错、地图开着时过场藏 / 显、其它写入、第二台镜头、换关的三种情况、
再次打开）；`hud_view` 的 `MapDrawsMapAlone`：坦克场景上开地图画出的东西与只有地图时完全相同（927 个四边形和文字行），缓回时 0，
关上后坦克 HUD 199 个。

**需实机确认**：开地图时雷达、武器栏、护甲条、准星、跟随者血条都消失，关地图（M / Esc / B）后恢复；地图开着时进过场、过场中开地图
的表现；双人分屏时只藏开地图那位玩家的 HUD（原版 `SetPlayerHudShow` 本身是四个视口一起改）；原版 HUD 布局的滑出动画（§10.1）
在这个开关下是否出现（静态看开关只跳过绘制，不触发动画）。
