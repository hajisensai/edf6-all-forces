# EDF6 道具箱（武器箱 / 护甲箱 / 回复箱）逆向（2026-10-08）

初稿为纯静态逆向；文末补充了私有 EDF.dll 映射中的原生函数验证。全部地址都是 EDF.dll 的 RVA（TimeDateStamp 0x678CCB46），**没有在实机上验证过**。
置信度：H = 直接读反汇编/数据；M = 读法确定、语义推断；L = 猜测。
方法：`tools/edfre.py`（capstone + RTTI + RIP 相对引用）+ `pylib/rootcpk.py` 只读 Root.cpk 的 SGO。未启动游戏，未改任何文件。

## 一句话结论

道具箱**不是游戏对象**：它们是全局单例 `DropItemManager`（`*(EDF+0x20B2988)`）里的一条 `std::list`，每个箱子是 0xE0 字节的 `DropItemManager::Unit`（只是一个渲染节点 + 类型 + 已拾取标志 + 编号），**不在队伍遍历 `0x5E11D0` 里**，但插件可以直接遍历这条链表（H）。
拾取由**本机玩家**士兵每帧在 `SoldierBase::OnUpdate`（第 5 槽 `0x59ABB0`）里调 `Collect 0x2C8AC0` 完成，入口和 `Collect` 内部都要求 `soldier+0x340`（手柄对象）非空——**NPC 士兵走上去什么都不会发生**（H）。
但 `Collect` 的「拾取点」是单独的参数，不取自士兵：插件可以用**本机玩家**当拾取者、把**箱子自己的位置**和一个很小的半径传进去，原样走原版的效果、音效和联机同步，但不能保证只捡这一个箱子：同位或间距小于半径的其他箱子也会被消费（原生验证见 §9）。
武器箱 / 护甲箱只是给全局计数 +1（关底结算才发武器、加护甲），与谁捡无关；回复箱治疗的是**拾取者（玩家）**本人 15% / 30% 最大耐久，外加他的跟随者（招募来的 NPC）各 0.35 × 这个比例（H 代码 / M 参数含义）。

## 4. 拾取

### 4.1 调用点（`SoldierBase::OnUpdate`，vtable `0x17D24D8` 第 5 槽 `0x59ABB0`）

| 项 | 值 | 置信 |
|---|---|---|
| 门 | `0x59B67C: cmp [h+0x340],0; je` 跳过整段——**只有带手柄对象的士兵（本机玩家，含分屏 2P）才拾取**；之后还要 `h+0x2E8 == 0`（活着） | H |
| 拾取点 | `h+0x90`（位置）+ (0, 1.0, 0) | H |
| 半径 | `max(3.0 × 装备参数1, h+0x1B48)`；装备参数来自 `h+0x1A00` 装备表里 `Weapon_Accessory` 的 `0x699380(.., 1)`，没有就 1.0；`h+0x1B48` 构造时 3.0（`0x58D47C`），部分兵种 / 状态改成 4 / 5 / 6（`0x552198`、`0x569B34` 等）。**坐着载具时改用座位的 `seat+0x258`** | H 代码 / M 兵种归属 |
| 队友治疗系数 arg5 | `装备参数0（没有就 1.0）× h+0x1A4C`；`h+0x1A4C` = SGO `soldier_config[1]`（玩家与 NPC 的 SGO 都是 0.35） | H 代码 / M 下标（按 `0x58D657` 的下标 1 读） |
| 回调 | 栈上 16 字节 `{vtable 0x17D2FE8, soldier}`（`Holder<lambda_1>`），第 5 槽 `0x5A4610` 恒真，第 1 槽 → `0x590F10`（给拾取者和跟随者播拾取特效）；用完调第 0 槽析构（edx = 0，不释放） | H |
| 调用 | `0x2C8AC0(mgr, soldier, &pos, radius(xmm3), arg5([rsp+0x20]), &functor([rsp+0x28]))` | H |

### 4.2 `Collect 0x2C8AC0`

```
if (soldier+0x340 == 0) return;                 // 第二道「只有玩家」门
for each node in mgr+0xDE0 list:
  u = node+0x18; if (u+0xC4) continue;
  p = 0x11B15B0(u+0xB0)
  if (|p - pos|² >= radius²) continue;           // 3D 球
  if (联机) 0x2C7D50(mgr, u+0xC8, u+0xC0, soldier); // 房主：广播消息 2；客机：发消息 1 请求
  0x2C7540(mgr, soldier, u+0xC0, arg5);          // 效果
  if (functor.slot5()) functor.slot1(&p, type);  // 特效
  u+0xC4 = 1;
```
（H）。注意 `pos` 和 `radius` 都是参数，和 `soldier` 的位置无关。

### 4.3 效果 `Apply 0x2C7540(mgr, soldier, type, arg5)`

| 类型 | 效果 | 置信 |
|---|---|---|
| 全部 | 拾取者是本机对象（`!(soldier+0x128 & 1)`）时播音效「アイテム取得」 | H |
| 0 武器 | 不联机，或联机且本机是房主（`0x784210`）时：`mgr+0xE04++`、`mgr+0xE08++`。**不给任何士兵加东西**，关底结算按计数抽武器（`0x2C92E0`） | H 代码 / M 结算 |
| 1 护甲 | 同上，`mgr+0xE0C++`；结算时加护甲，拾取当时不加耐久 | H 代码 / M 结算 |
| 2 小回复 | `0x547870(soldier, 0.15 × soldier+0x2F4)`（加到 `+0x2F8`，夹在 `[+0x2F0, +0x2F4]`，死亡时不加）；arg5 > ε 时 `0x549970(soldier, arg5 × 0.15)`：**递归遍历 `soldier+0x550` 跟随者链表**，每个活着的跟随者回复 `arg5×0.15×自身最大耐久` | H |
| 3 大回复 | 同上，比例 0.30 | H |

所以原版「回复箱治疗谁」= 拾取的玩家 + 他名下的跟随者（以 0.35 倍比例）。范围治疗不是按距离，而是按跟随关系（H）。

### 4.4 联机（消息分发 `0x2C8C80`，在 `0x7557AA` 收）

| 消息 | 方向 | 处理 | 置信 |
|---|---|---|---|
| 0 | 生成者 → 全体 | 用同一种子重放 `0x2CA610`（箱子编号一致） | H |
| 1 | 客机 → 房主（`0x2C7D50` 客机分支） | 房主按玩家编号找到那名玩家士兵；`0x2C7B10(mgr,id)` 找未拾取的同编号箱子并置 `+0xC4`；**武器/护甲只在找到时才计数**（防双计），回复照样对该玩家的副本执行；然后广播消息 2 | H |
| 2 | 房主 → 全体（`0x2C7B50`：类型、编号、玩家编号 `[soldier+0x1ED0]+0x48`） | 各机找到该玩家对象，若是远端副本（`+0x128 & 1`）就对它执行 `Apply`（arg5 = 0：不连带跟随者）；按编号把箱子置为已拾取 | H |
| 3 | 客机 → 房主 | 请求替某对象掉落（§2） | H |

- 拾取方本机**立即**生效（删箱、回血、特效），再异步通知房主，没有回滚（H）。
- 武器/护甲计数联机时**只在房主**累加；客机自己捡到时 `Apply` 不计数，靠消息 1 由房主计（H）。各玩家的结算份额从 `GameStatus+0x14FD4..` 的四对计数求和（`0x2C92E0`），这一段没有追完（M）。
- 结论：箱子没有「所有者」，每台机器各有一份同编号的副本，房主仲裁「谁先捡」（H 读法 / M 语义）。

## 5. 对问题的直接回答

1. **对象**：见 §1。不是游戏对象，没有独立 vtable 层次（只有 `Unit` 的 2 槽 vtable `0x17A6C18`）；大小 0xE0；位置 `0x11B15B0(*(u+0xB0))`（或 `u+0xA0`，M）；类型 `u+0xC0`；已拾取 `u+0xC4`；编号 `u+0xC8`。生成链 `0x547C30 → 0x548AE0 → 0x2C7950 → 0x2CA610`。
2. **枚举**：不在 `0x5E11D0` 的队伍遍历里（它们不是 `GameObjectBase`，没有队伍）。直接遍历：`mgr = *(EDF+0x20B2988)`，`head = *(mgr+0xDE0)`，`for (n = *head; n != head; n = *n) u = *(n+0x18)`。**不需要 hook 构造/析构**。必须在游戏线程上遍历（链表在 `0x2CA350` / `0x2CA610` 里改，没有锁）。
3. **拾取**：`0x2C8AC0`；半径默认 3 m（中心在脚上 1 m）；只有带手柄对象的本机玩家士兵会触发（双重门 `0x59B67C`、`0x2C8ACC`）；NPC 走上去**不会**拾取，箱子留在原地。武器/护甲是全局计数（与谁捡无关），回复治疗拾取者 + 他的跟随者。
4. **其他**：上限 128 个；不会超时消失、没有吸附；掉出世界（y < −1000）才删；会被夹回活动区域内。

## 6. 初稿方案（半径拾取已被 §9 的精确单箱实现取代）

1. **枚举**：每帧（在已有的 NPC 第 7 槽钩子里，游戏线程）按 §5.2 走链表，取 `+0xC4 == 0` 的箱子，读类型和位置（调 `0x11B15B0`；调用前按字节签名核对函数头，不符就关掉功能并记日志，同 `layout.h` 里 `kDeleteSig` 的做法）。
2. **派人**：给每个箱子分配最近的空闲 NPC（一箱一人，避免扎堆），NPC 的移动目标设成箱子位置（`npcai` 里加一种 anchor）；距离、敌情、`NpcLeash` 照常约束。
3. **旧方案，不再使用**：NPC 到箱子 1.5 m 内（水平），插件调
   `0x2C8AC0(mgr, 本机玩家士兵, &箱子位置, 0.05f, 玩家原值 arg5, &functor)`：
   - 拾取者传**本机玩家**（满足 `+0x340` 门，武器/护甲正常计数，联机走原版消息 1/2）；
   - 位置传**箱子自己的位置**、半径极小，所以只会捡这一个箱子（不会顺带捡到旁边不该捡的回复箱）；
   - arg5 按原版公式（`装备参数0 × 玩家+0x1A4C`；简单起见可直接读玩家 `+0x1A4C`，没有装备时一致）；
   - functor 用原版的 `{0x17D2FE8, 玩家}`（拾取特效出现在玩家和跟随者身上），或自制一个第 5 槽返回 0 的假 vtable（不播特效）。
4. **回复箱规则**（开关 `NpcPickHealth`）：
   - 走原版路径时，治疗的是**玩家**（15/30%）和玩家的跟随者（×0.35），不是「去捡的那个 NPC」单独回满。所以建议判据：开关打开，**且** 玩家或某个跟随者没满血（玩家 `+0x2F8 < +0x2F4`，跟随者同理）才派人去捡；**全队满血时绝不碰回复箱**。去捡的 NPC 满血不构成禁止理由（它不是主要受益者），这一点要和用户确认。
   - 若用户要求「回复给去捡的那个 NPC 本人」：单机可自己做——`u+0xC4 = 1` + `0x547870(npc, 比例 × npc+0x2F4)`，并且只在 `npc+0x2F8 < npc+0x2F4` 时才派它去。**联机不要这么做**：客机直接置标志不会通知别人（别的机器上箱子还在），房主要用 `0x2C7B10` + `0x2C7B50` 广播，而消息 2 必须带一个玩家编号，其它机器会对那名玩家的副本执行一次回复（副作用未知，L）。联机时只用原版路径，或者联机时禁止 NPC 捡回复箱。
5. **联机**：箱子在各机都有副本；用原版 `Collect` 时同步由原版负责，客机上的捡取由房主仲裁（先到先得）。插件的「派人捡」在每台机器只对本机拥有的 NPC 做（`!(npc+0x128 & 1)`），以本机玩家为拾取者——两台机器同时派人捡同一个箱子时，房主只计一次武器/护甲（H），但两边的回复都会生效（原版玩家同时捡也一样）。
6. **安全检查**：`mgr` 为空（菜单/本部）就整段跳过；`Unit` 的 vtable 必须是 `0x17A6C18`，否则不碰；`Collect` 入口字节核对后才调用。
