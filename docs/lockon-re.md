# 锁定（`src/lockon.cpp`）：逆向笔记

EDF.dll TimeDateStamp 0x678CCB46，RVA。置信度：H 读代码确认，M 推断，L 猜测。全部静态分析，未进游戏。
锁定列表、正在锁定、锁定框与锁定音的基础结构见 `docs/stores-re.md` §7、§8；本篇补全 SGO 参数、多重锁定、开火分配和「是不是玩家的武器」。`w` = 武器对象。

## 1. SGO 参数 → 武器字段（读取 `0x68A920`，锁定段 `0x68D0E8..0x68D49B`）

| SGO 名 | 字段 | 说明 | 置信 |
|---|---|---|---|
| LockonType | +0x6B0 | int。0 和 5 = 不锁定（`0x6963F0..0x696401`、`0x690C2A`） | H |
| LockonTargetType | +0x6B4 | int → 搜索种类 +0xC58：0 → 3（全部），1 → 2，其它不变（`0x696792`） | H |
| Lockon_DistributionType | +0x6B8 | 0 = 每次连射一发一个锁定，其它 = 每颗弹丸一个锁定（§3） | H |
| Lockon_AutoTimeOut | +0x6BC | **字节，取反存放**：`+0x6BC = (AutoTimeOut == 0)`（`0x68D211 sete`） | H |
| Lockon_FireEndToClear | +0x6BD | 字节。只在换弹开始 `0x695D20` 读：置位就 ClearLock | H |
| LockonAngle | +0x6C0 | [0] 水平半角、[1] 垂直半角（弧度） | H |
| LockonRange | +0x6D0 | float | H |
| LockonTime | +0x6D4 | float，取整帧 | H |
| LockonHoldTime | +0x6D8 | float | H |
| LockonFailedTime | +0x6E0 | int 帧 | H |
| （无名）最多锁定数 | +0x6DC | 游戏推导：LockonType 0 → 0；分配方式 0 → min(AmmoCount +0x248, FireBurstCount +0x370)；否则 FireCount +0x368 | H |

士兵配件对手里每把武器写三个倍率（`0x599A30`，人物 +0x1950 的武器数组）：`+0x78E` 可重复锁同一目标、`+0x790` 锁定速度、`+0x794` 锁定距离（写入 H，含义 M）。

## 2. 搜索与多重锁定

- 锁定 tick `0x6963A0`：没有正在锁定的、且列表未满时才搜索（`0x22E5A0` 遍历登记表，每个锥内候选交给 `0x691310`），选中的成为「正在锁定」，进度从 0 开始；
  进度超过 LockonTime 进列表（`0x6965B0`）。所以**一次只锁一个、每个都走满 LockonTime**（H）。
- 正在锁定的目标在锥内：进度每帧加 `+0x790 × 条目+0x24`，失败计数 +0xCA0 清零；在锥外：+0xCA0 加一，超过 LockonFailedTime 就丢掉（`0x68FEE0`）（H）。
- 松开扳机（tick 没跑）时，未完成的锁定被丢掉（`0x6935EA`，标志 +0xBF0）（H）。
- **去重**：`0x691310` 遍历列表，候选的条目已在列表里就不要，**除非**条目 +0x28 或武器 +0x78E 非零；那样同一目标可以反复锁（多个节点指向同一条目）（H）。

## 3. 开火时怎么分

- 开火 `0x690BB0`：锁定武器列表为空就**不开火**（`0x690C3D`）；否则把发数改成锁定数 k：分配方式 0 写 FireBurstCount，1 写 FireCount（H）。
- 每发 `0x696FD0`：从列表第一个节点开始（AutoTimeOut 0 时跳过游标 +0xDC0 个），条目写进子弹参数 +0x60（`0x697718`），子弹初始化 `0x231CC0` 拷到 B+0xB10（H）。
  - 分配方式 1：每颗弹丸取下一个节点，超出列表的弹丸不导引；AutoTimeOut 1 时用过的节点删除。
  - 分配方式 0：一发的所有弹丸共用一个节点，打完后 AutoTimeOut 1 删除该节点，游标 +0xDC0 加一。
  - 结论：k 个锁定 → k 发，第 i 发追第 i 个（最早锁的先发）（H）。
- 已发射列表 +0xCA8 只给 HUD 读，不从锁定列表删东西；开火从不整个清空列表（H）。

## 4. 保持 / 衰减（`0x69412D..0x6942BB`）

- AutoTimeOut 0：每个节点的目标在锥内则计时 +0x20 清零，否则每帧 +1。AutoTimeOut 1：每帧 +1，不看锥（H）。
- 计时达到 LockonHoldTime、条目控制块过期或条目 +0x29 = 0 时删除（H）。连射进行中（+0xE18 ≠ 0）不变化。

## 5. 是不是玩家的武器

- `w+0x120` 是持有者：步兵武器是士兵（四个兵种 vtable：0x17CDF28 / 0x17D0FF8 / 0x17CF5B8 / 0x17CF100），载具武器是载具（写入 H，士兵这一种 M）。
- 步兵：`IsPlayer(士兵)`（人物 +0x354 标志与手柄 +0x340）。NPC 士兵 IsPlayer 为假，且 +0x1A bit 8 置位（M）。
- 载具：找出挂点（座位 +0xC8，数量 +0xD8，武器在挂点 +0x10）里有这把武器的座位，看它的乘员是不是本机玩家（`SeatRider == Rider::player`）。
  旧代码（`stores.cpp ViewAngle`）只看 0 号座位，炮手座的武器认不出来，已改。

## 6. 挑目标的回调 `0x691310(ref, result, ctx)`

- ref = {条目, 控制块}；result +0 |水平角|、+4 |垂直角|、+0x10 深度（比较用的分数）；ctx +0 武器、+8 / +0x10 当前最优、+0x18 最优分数（初始 FLT_MAX）（H）。
- **所有**锥内候选都会进来，包括已锁定的；去重在比较分数之前，所以只改 result +0x10 不影响去重（H）。保留严格更小的分数（H）。

## 7. 插件的做法（2026-10-06）

- 锁定代码只有 `src/lockon.cpp` 一份（原来在 `stores.cpp` 里只管挂载武器）：`WeaponLock`（读）、`ClearWeaponLock`、`NextLockTarget`（切目标）、`PlayerHolds`。
- `0x691310` 前 17 字节搬进跳板，钩子给候选打分（传一份副本给原版，原版只比较分数）：
  - 玩家手里的武器（§5）：离视线中心的夹角平方（`CameraRay`，每帧一次）；挂载武器看 `PlayerJetLockByView`，原版武器看 `PlayerLockByView`。
  - NPC 战机的挂载武器：离机头的 yaw² + pitch²（原来的做法）。
  - 其它（NPC 的原版武器）：原版顺序不动。
  - 加分：候选在列表里每出现一次 +20（多重锁定先锁不同目标），刚切走的目标 4 秒内 +100。
- 切目标（战斗机 Q / X）：有正在锁定的就只丢它（`0x68FEE0(w+0xC70)` 清条目、控制块和进度，+0xCA0 清零），已锁上的保留；没有正在锁定的才整个清空（`0x68FF60`）。被丢的目标排到最后。
- 锥角、距离、阵营、LockonTime、保持、超时、最多锁定数、去重全照游戏自己的。原版 HUD 照常画原版武器的锁定（`0xFA060` 不管谁的武器都画）。
- 没做：步兵的切目标键（Q / 手柄 X 在步兵操作里可能已有用途，没核实）。
