# 导弹（MissileBullet01）逆向与插件导引

EDF.dll TimeDateStamp 0x678CCB46，RVA。置信度：H 读代码确认，M 推断，L 猜测。实现见 `src/missile.cpp`，武器文件见 `pylib/vcobjects.py` 的 `STORES`（挂载与混挂见 `docs/stores-re.md`）。

## 为什么原版导弹会绕圈

- 原版是**纯追踪**，每帧把速度直接转向锁定点，不算提前量（`0x26A380`）（H）。
- 每帧最多转 CP[5] 弧度，与速度无关，所以转弯半径 = 速度 ÷ CP[5]（H）。
  - 例如原版 0.1、速度 10 m/帧时，半径是 100 m。
  - 目标落在这个转弯圈里，导弹就会一直绕着它转（2026-10-04 用户截图）。

## 导弹对象（B）

构造函数是 `0x267910`，vtable `0x17A1C10`，更新函数在第 5 槽 `0x26A880`，签名 `(B, rdx)`。

### 速度

- **自身速度** `+0x13D0`（xyz，m/帧）：每帧沿自身方向加 CP[4]，并钳到 CP[6] 以内（H）。
- **继承速度** `+0x13E0`（xyz，m/帧）：
  - 来源是 `AmmoOwnerMove` × 发射者的速度向量（武器 `0x691FA0`，子弹初始化 `0x231DC3`）（H）。
  - 点火后每帧乘 0.9（`0x26AA26`），约半秒衰减完（H）。

### 其他字段

- **锁定**：`B+0xB10` 指向锁定条目，条目 `+0x10` 是瞄准点，`+0x29` 是有效标志（每帧在 `0x269C35` 读）（H）。
- **核心**：core = B+0x140，以下偏移都相对 core（H）：
  - 位置 core+0xB80。
  - 标志 core+0xAF4（bit0 死亡，0x20 到期爆炸）。
  - 年龄 core+0xAF8（int，每帧 +1）。
  - 寿命 core+0xA08（int）。
  - 爆炸半径 core+0xA20。
- **到期判定**：在 `0x236385` / `0x236899`（H）。

## 插件做法（`src/missile.cpp`）

- **识别自家导弹**：vtable 等于 `0x17A1C10`，且 CP[8] = 1000000（原版导引永远不开始），CP[9] = 4242。不满足就是原版或别的 mod 的导弹，由 `src/guidance.cpp` 按原版数值做比例导引（`docs/guidance-re.md`）。
- **挂钩**：前置挂在更新槽上；签名校验 `48 89 5C 24 18 55 56 57 41 56 41 57`。每帧在原版更新之前做下面几件事：
  1. **速度合成**：继承速度并入自身速度，继承速度清零。这样载机速度向量完整保留，不衰减。
  2. **比例导引**：
     - 视线角速度 ω = r × v_rel / |r|²；所需加速度 a = N·(ω × v)。
     - 去掉 a 沿速度方向的分量，模长限制在最大过载以内。
     - 目标速度由锁定点前后两帧的差得到；锁定点一帧跳动超过 20 m 视为换了目标，不用这一帧的差。
  3. **近炸引信**：
     - 算下一帧内与目标的最近距离，小于爆炸半径 × 0.6（至少 4 m）就立即引爆。
     - 引爆方式：core 标志位或上 0x20，年龄设为寿命，由原版的到期流程在当前位置爆炸并造成溅射伤害。
  4. **战斗部保险**（`src/fuze.h`，2026-10-26）：每帧先看这一步（当前位置和按当前速度的下一帧位置）爆炸能否够到发射它的载具——
     原版爆炸是以爆点为中心、半径 AmmoExplosion 的 AABB 查询，玩家驾驶的载具武器带友伤位（core+0xA26 → GDI+0x60 0x20，
     `docs/swarm-team-re.md`），自己的车在里面。够得到就不解除保险：近炸引信不触发，core+0xAF4 的 0x10 位清掉（命中走 `0x543920`
     单体伤害而不是 `0x232689` 的范围伤害，`0x232616` 处分支，读者只有这一处）；够不到就恢复 0x10、允许近炸。发射者 = 子弹 owner
     （core+0x9A8，弱引用）：离线是载具，联机是坐在车里的玩家（取其 +0x1548 的载具）；载具的刚体 = 部件表 veh+0x1398（个数 +0x13A8，
     0xC0 一个，刚体在 +0x50）加直升机的 +0x1650；每个刚体的世界包围盒由 `src/body_box.cpp`（与 Shield Bearer 的护盾同一取法）算。
     只对带友伤位（core+0xA26 非 0）的弹判：不带的（NPC 驾驶，RideAi 清掉了武器的友伤位）原版爆炸按队伍过滤、炸不到自己的车，出膛即解除保险（2026-10-27 审查改：原来不分，NPC 的天启 / 通古斯卡打贴车的敌人也没了溅射）。部件逐个判，不设个数上限（原来超过 32 个整张表跳过、等于没保险）。
     未解除保险的撞击是哑弹（2026-11-21，`docs/feedback-2026-11-21-missile-dud.md`）：除了 0x10，还清掉 core+0xAF4 的 0x400
     （命中音效 AmmoHitSe 只在它置位时由 `0x2325EE` 播放，`0x2325CD` 是唯一读者），并把 core+0xA20 写 0——命中火球不是爆炸伤害画的，
     而是命中把自己记进 core+0x6C0 的命中表（`0x230CA0`），类的下一次更新在 `0x26A8AC` 看到表非空就在命中点画
     `EffectGenUtil::Explosion`（`0x2E5ED0`，尺寸 core+0xA20 / 5），再结束这发弹。爆炸半径改读 core+0x788（init 从 core+0xA20 拷来，
     `0x542670` 用的就是它），core+0xA20 在 init 之后只剩火球尺寸这一个读者。命中表非空的那一帧（弹已撞上、本帧结束）插件不再重判保险。
  5. **动力段结束后**：每帧损失速度的 0.4%，并抵消掉原版之后会加的 CP[4]，模拟滑行减速。

每种导弹参照一款现实型号：动力段、加速度、极速、过载、导引常数、战斗部按现实取值。锁定距离按游戏世界（±2.4 km）压缩。武器文件按「种类 × 数量」生成，文件名为 `EDF6VC_<种类>_<数量>.SGO`；各机型挂哪些、各挂几枚，见 `docs/stores-re.md` 和 `JETS`。

伤害是普通档的基础值，实际强度照原版放大：任务里放置的和插件呼叫来的 AI 飞机按任务难度放大（`0x54E740`，和原版脚本 `CreateFriend` 一样），玩家飞机的呼叫按呼叫等级取原版 Eros 呼叫的倍率曲线（`tools/call_weapons.py` 的 `request_curve`）。2026-10-04 试过按 ×25 档位、按炼狱档武器数值直接写入，都和游戏自己的难度放大叠在一起，数值过高。

共同设置：
- 继承载机速度向量（`AmmoOwnerMove` 1），不受重力。这只对插件自己的 MissileBullet01 成立（`src/missile.cpp` 每帧把继承速度并进自身速度）。原版导引的弹（MissileBullet02 齐射母弹、原版 MissileBullet01）点火后继承速度每帧 ×0.9，点火前每帧 ×CP[7][1] 并受重力，见下节。
- 弹射初速 0.3 m/帧，舰射为 0.5 m/帧。

地空导弹（毒刺、爱国者一类）：插件目前没有地面防空载具，暂不生成文件；以后加载具时，在 `STORES` 里加一行即可。

AI 战机和潜艇母舰的开火距离读的是武器自己的锁定距离（`src/jet_combat.cpp` 的 `MissileReach`、`src/subcarrier.cpp` 的 `Arm`），插件不再在运行时改写武器参数。

## MissileBullet02 齐射母弹（`STORES['SALVO']`，2026-11-26）

MissileBullet02：vtable `0x17A1E28`，构造 `0x26AF70`，update `0x26E4C0`；状态机与分裂见 `docs/split-missile-re.md`。CP[0..9] 的布局与 MissileBullet01 相同，偏移见下（全部静态，H 除非注明）。

速度与重力：

- 点火前状态 `0x26EDF0`：帧数 `B+0x13F0` < CP[7][0]（`+0x13AC`）时，继承速度 `+0x13D0` 每帧 ×CP[7][1]（`+0x13B0`）再加重力向量 `+0x13E0`；自身速度 `+0x13C0`（初值 AmmoSpeed，方向按 FireAccuracy 散布）不加速；尾焰关。
- 重力向量 `+0x13E0` = core+0xBA0（AmmoGravityFactor × 世界重力，m/s²）×(1/60)²（`0x231C10`，dt 常量 `0x176B040`）。插件实测 1 倍重力 ≈ 14.7 m/s²（`src/jet_internal.h` kGravity）。
- 飞行状态 `0x26EC10`：进入时开尾焰（`0x7B4510`，+0x1180 / +0xF90 / +0x1360 置 1）；每帧继承速度 ×0.9（常量 `0x17A1D80`），**不再加重力**；按 CP[0] 转向（1 → `0x26D4B0`，2 → `0x26D8D0`；装插件且 StockMissilePN 开时由 `src/guidance.cpp` 换成比例导引）；`0x26CF00` 判分裂（点火后帧数）。
- update：core 速度 = (自身 + 继承) / dt（`0x235540`），再走 core 步进 `0x235D50`。步进与两个移动函数 `0x2364D0` / `0x235FA0` 不读 core+0xBA0；core+0xBA0 只在命中反应 `0x233CB0` / `0x2349D0`（core+0xAF0 选的弹跳类）里读（M：扫的是全部 `[reg+0xBA0]` 访问）。所以 AmmoGravityFactor 只作用于点火前那几帧。

**更正**：此前本节「继承载机速度、不受重力」对 MissileBullet02 不成立——它的继承速度点火后约半秒衰减完，导弹若自身速度跟不上，看起来就比载机还慢（用户 2026-11-26：「发射的导弹比飞机飞的还慢」）。

尾焰与颜色（构造，MissileBullet01 构造 `0x267910` 同布局）：

| 参数 | 作用 | 证据 |
|---|---|---|
| AmmoSize | 尾焰宽 = AmmoSize × 0.1（`+0x1364`），头部光焰宽再 ×0.5 | `0x26BE79` |
| AmmoColor | 头部光焰 `+0xF50`（`Particle3_k.dds`，`0x179F728`）颜色 = (r×4, g×2, b)（`+0x1370`，常量 `0x1765A34` = 4.0） | `0x26BEA4..0x26BEF4` |

做不到的：

- 发射节奏：一次扳机一帧最多出 FireCount 发，分配方式 0 时每发一个锁定（`docs/lockon-re.md` §3），256 发至少 256 帧 ≈ 4.3 s。要 2 s 内打完得 FireCount 2 + 128 个锁定（改 SALVO_ROUNDS、`kSalvoLockLimit`、`lockon.cpp` 分配、HUD、`SalvoLocked`），未做。
- 弹体自发光：AmmoColor 只染尾焰和光焰，弹体模型的材质不受它影响；要发光得做一个带发光材质的导弹 RAB（安装管线），未做。
- 母弹尾迹粗、子弹细：尾迹宽绑在 AmmoSize（也是模型尺寸）上，只能改模型大小，未改。

## 未实测

以上都是静态分析得出的结论，还没有进游戏验证。需要在游戏里确认：
- 近炸引爆的爆炸特效是否正常播放（M）。
- 锁定条目里的瞄准点是否每帧都会刷新（M）。
- 齐射（MissileBullet02）：HDR 颜色的实际亮度和 256 条烟尾的性能；点火前 2 m 下坠看不看得出；±80° 离轴目标 PN 能否转过来；飞行中是否真的没有重力下沉（上面 M 的一条）。
