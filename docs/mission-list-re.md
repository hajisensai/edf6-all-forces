# EDF6 任务列表与存档容量：静态逆向

对象：Steam 版 `EDF.dll`，TimeDateStamp `0x678CCB46`。下文地址都是 RVA。
只做了静态分析：没有启动游戏，没有写游戏目录。存档只复制出来看了大小，文件本身是加密的。
反汇编用 `tools/edfre.py`（字符串、RIP 相对交叉引用、capstone 反汇编）。用到这些结论的代码：`tools/make_edf5_campaign.py`、`src/edf5campaign.cpp`（EDF5 战役，计划见 `docs/edf5-campaign-plan.md`）。

可信度标记：
- **H**：有反汇编证据，并给出地址。
- **M**：根据代码和数据推断。
- **L**：猜测。

## 0. 关键对象与布局

### GameDataMgr 单例

- 指针在 `0x20B2890`，大小 `0x150A0`（`new 0x150a0` 在 `0x7c0c4a`），构造函数是 `0xD62C0`。**H**
- `mgr+0x130` 是当前模式对象，由 LoadPackage `0xE2AD0` 填充。**H**
  - `mode+0x18`：ModeList 的当前项。
  - `mode+0x20`：SoldierInit。
  - `mode+0xF0/+0xF8`：任务列表 `table` 的文档引用。
  - `mode+0x118`：TXT 列表的原始 SGO `table`。
- 存档区与文件的对应关系见下表。**H**：两个存档函数都把 `0x16C4` 当作 ModeSave 的长度（`0x7bc438` 与 `0x7bd1cd` 都是 `mov r9d, 0x16c4`）。其余三行是按“文件大小 = 区块长度 + 0x14 字节文件头”对出来的，**M**。

| 区块 | 范围 | 长度 | 对应文件（实测大小） |
|---|---|---|---|
| system | `mgr+0x2E8..0x310` | 0x28 | `SYSTEM.CFG` 60 B |
| common | `mgr+0x318..0x57A4` | 0x548C | `COMMON.CFG` 21664 B |
| **ModeSave（每个模式一份）** | `mgr+0x57A4..0x6E68` | **0x16C4** | `DEFP_<MST>.MST` **5848 B** |
| main | `mgr+0x6E68..0x14B50` | 0xDCE8 | `MAIN.GST` 56572 B |

- 本机存档：`%LOCALAPPDATA%\EarthDefenceForce6\SAVE_DATA\<steamid>\saveslot00\`。`DEFP_M00.MST`、`DEFP_DLC1.MST`、`DEFP_DLC2.MST`、`DEFP_MOD1.MST`、`DEFP_MOD3.MST` 都正好是 **5848** 字节，与各自任务数（147 / 19 / 40）无关，所以是定长。**H**
- 文件内容加密，没有解密。**H**

### ModeSave 布局（初始化函数 `0xDF790`，重置函数 `0xDBA00`）**H**

```
+0x0000  u32  当前任务下标（行号）          ; dbce0: mgr+0x48 = [+0x57a4]
+0x0004  u32  当前难度                      ; dbce0: mgr+0x4c = [+0x57a8]

+0x16A0  2 × 10 字节, +0x16B4.. 杂项
```

```asm
0xdf79b: add rcx, 8
0xdf79f: mov r8d, 0x1400            ; 10 行 × 0x200 列
0xdf7a5: call memset
0xdf7d8: lea rcx, [rbx + 0x14a0]
0xdf7e6: mov r8d, 0x200
0xdf7ee: call memset
```

## 1. 存档容量（问题 1）

### 结论

1. 通关记录**不是**按列表长度动态分配的。**H**
   - 它是 ModeSave 里的定长数组 `clear[10 行][512 列]`，按任务行号直接索引，**完全不检查边界**。
   - 每格一个字节，bit0..4 对应 Easy..Inferno。
   - 行是兵种，实际只用 SoldierInit 数量（4）行。
   - 另有一个每任务一字节的 `seen[512]`，同样直接索引。
2. **上限是每个模式 512 个任务（`0x200`）。** 147 + 110 = 257 < 512，**不会越界**。**H**
3. 超过 512 行时的后果：
   - `clear[c][m≥512]` 会落到 `clear[c+1][m-512]`，与下一兵种串号。
   - `seen[m≥512]` 会写进 `+0x16A0` 之后的字段。
4. 每个模式的存档文件固定 5848 字节，其中 ModeSave 0x16C4 字节。**H**
   - 换列表长度不会改变文件大小或格式。
5. 旧存档（147 条记录）读新列表（257 行）的情况：**H**
   - 行 147..256 在旧存档里本来就是 0（512 列一直在存档里）。
   - 新任务因此全部显示“未通关”，旧记录不受影响。
   - 不需要迁移，也不会破坏存档。
6. 卸载 mod 后同样安全：
   - 列表变回 147 行，行 147+ 的位只是不再被读到。
   - 唯一的残留是存档里的“当前任务下标”可能 ≥147，见第 4 节风险 R5。**M**

### 证据

读通关位 `0xDFA40(modesave, class, mission, diff)`，没有边界检查：

```asm
0xdfa40: mov eax, edx            ; class
0xdfa42: shl rax, 9              ; class * 0x200
0xdfa46: add rax, rcx
0xdfa49: mov edx, r8d            ; mission（行号）
0xdfa4f: movzx r8d, byte ptr [rdx + rax + 8]
0xdfa5a: shl eax, cl             ; 1 << diff
0xdfa5c: test al, r8b
```

写通关位 `0xDFAB0`：

```asm
0xdfab2: shl rax, 9
0xdfabc: movzx eax, byte ptr [rcx + rdx + 8]
0xdfac1: bts eax, r9d
0xdfac5: mov byte ptr [rcx + rdx + 8], al
```

`0xDF950` 扫描“有通关记录的任务数”，循环上限写死为 `0x200` 列 × 10 行：

```asm
0xdf96c: add rax, 0x200 ; cmp ecx, 0xa
0xdf982: cmp edx, 0x200
```

ApplyResult 的通关部分在 `0x70D879`：

```asm
0x70d884: mov r14d, [rcx+0x15000]  ; = mgr+0x48，当前任务行号（0x70f103 写入）
0x70d8c5: mov esi, [rcx+rbp+0x6e90] ; 玩家兵种
0x70d8cc: cmp edi,3 / cmovl ebx,edx ; 难度<3 时从 Easy 起连带标记；Hardest/Inferno 只标自己
0x70d8ef: call 0xdfab0               ; clear[兵种][行号] |= 1<<难度
```

**索引用的是任务在 table 中的行号，不是字段 0，也不是字段 4。** **H**
- `mgr+0x48` 是行号，同一下标也被拿去取字段 1 路径（`0x70f117`、`0x70da60` → `0xE1560`）。

### 在线模式共用同一份存档

- `DefaultPackage/config.sgo` 的 `ModeList`（不加密）里，离线 Scenario（模式 0）和在线 Scenario（模式 1）都用 `M00.MST`。**H**（数据）
- 在线列表 `MISSIONLIST.ONLINE.LIST.SGO` 同样是 147 行。
- 因此：
  - **前 147 行的位置绝不能动。** 只能追加。
  - 离线行 147+ 的通关位在线模式看不到，这无害。

## 2. 列表字段（问题 2）

### 文件格式

- 列表文件是 **DSGO**（`'DSGO'` 头），不是 SGO。**H**
- 每行第 10 项带名字 **`"flags"`**（`names = {10: 'flags'}`）。读 Root.cpk 原文件（`pylib/dsgo.py`）确认。**H**
- 游戏用名字查 flags，不按下标：`0xE0AF0` 调 `0x55A30(row, L"flags")`。
- **新行必须保留这个名字，否则崩溃。** **H**
  - 查不到名字时，`0xE0AF0` 走 `0xe0ba7` 分支，引用变成 `{doc=0, idx=-1}`。
  - 接着 `0x52F50` → `0x52F71` 会解引用 `[0+0x18]`。
  - 结算（`0x70d950`）和任务开始（`0xD8160` 的 6 个调用点）都会走到这里。
  - 生成列表时必须用 `pylib/dsgo.py` 并带上 `names`。

### 读取方式

- 列表经资源加载器 `0x84E80` 装入文档对象，存到 `mode+0xF0`（`LoadPackage 0xE2AD0`，`0xe2f5d` 处取 `"table"`）。
- 每个字段有一个专门的访问器，都在 `0xE0650..0xE1A00`。
- 行数 = `0xE0650`，即 table 子节点个数，**动态，没有上限**。**H**

### 字段表

| 下标 | 示例 | 含义 | 读取函数 / 使用者 | 可信度 |
|---|---|---|---|---|
| 0 | `0.0` | 序号，与行号相同 | 没找到任何读取它的访问器；游戏用的是行位置 | M |
| 1 | `'app:/Mission/EDF6/M000B'` | 任务目录。后面拼 `/mission.bvm`（`0x70f15e`）或 `/before.bvm`（`0x70da9e`） | `0xE1560`（下标 1） | H |
| 2 | `'EDF6/M000B'` | 任务键名。把 `/` 换成 `_` 再加 `.dds`，就是 `MissionList.offline.image.rab` 里的缩略图名（`0xE0D80`）；调试命令也用它按名找任务（`0xE11D0` ← `0xBC120`） | `0xE0D80`、`0xE11D0` | H |
| 3 | `[1.0]` | 后继任务行号列表，详见下方“字段 3” | `0xE1900`（下标 3） | H |
| 4 | `0.0`；分支行 137..142 分别是 39/75/133/117/127/129 | 界面显示用的任务编号，存到选关列表项 `+4`（`0x8a22e8`）。不参与存档 | `0xE1010`（下标 4）← 只有 `0x8A22DC` 调用 | H（数据流）／M（“显示编号”） |

| 7 | `0..3` | 界面主题／背景变体。交给 UI 参数 0x14（`0x840A30`）；`0x83E8A8` 处夹到小于 3 | `0xE0950`（下标 7，带边界检查） | M |
| 8 | `'BGM_E6M23_…'` | 选中该任务时的菜单 BGM | `0xE0A30`（下标 8） | H／M |
| 9 | `0.2 / 0.5 / 1.0…` | 对话进度系数。任务脚本初始化时（`0x222E8A` → `0xD8650`，下标夹到 `count-1`）写进 **TalkManager**（`0x20B29C8`，类名由构造 `0x5D1760` 的 vtable 确认）的 `+0x64`。它不是掉落等级，这条路径上没看到别的用途 | `0xE15D0`（下标 9）；`0xE0AF0` 也顺带返回它 | H（数据流）／M（含义） |
| 10 `flags` | `8`、`24`、`65`、`152`、`264`、`520` | 位掩码，详见下方“flags 各位” | `0xE0AF0`（按名字 `"flags"` 查） | H（位的去向）／L（各位的具体语义） |

**字段 3：后继任务行号列表。**
- 选关解锁：已通关行的后继行解锁（`0x8A2209` 起）。
- 通关后推进：后继恰好 1 个、且小于总行数时，“当前任务”前进到它（ProceedNextMission `0x70F660`）。
- **没有边界检查**，必须小于总行数。最后一行的后继不会被处理（`0x8a21eb cmp r14d, count-1; jae`）。

**flags 各位。**
- bit0..6 与 bit9 组成 TalkManager 的台词过滤掩码（`0x1DE01C`/`0x1DE788` → `0x5DD250`，写 `+0x60`）。
  - bit5（0x20）还会在任务开始时触发一个额外调用（`0x1de0a6`）。
  - `0x1B3812`、`0x1B40AD`、`0x5C6D17` 测试 bit5。
  - `0x95B249` 测试 `flags & 0x227`。
- bit7（0x80）和 bit8（0x100）在**通关时**分别把 `mgr+0x14FFC` 置 1 和 2（`0x70d95c..0x70d97b`），是剧情分支标志。
  - M120 的 flags 是 152，带 bit7。
  - M140B 的 flags 是 264，带 bit8。
- 各位的具体语义（哪种台词集）**L**。

### TXT 列表

- 文件是 `MISSIONLIST.OFFLINE.TXT.<LANG>.SGO`，普通 **SGO**，每行 `[标题, 简介]`。**H**
- 路径由 ModeList 第 6 项第 2 个元素加 `%LOCALE%` 替换得到（`0xE1620`）。
- 访问时按行号**直接取 SGO 节点，不检查边界**。**H**
  - `0x958A60` 和 `0x8A376B`：`[mgr+0x248] + 12*row` 取子节点 0/1。
- 因此 **Root.cpk 里现有的全部 5 种语言（CN / EN / JA / KR / SC）都必须追加到 257 行**。
  - 漏掉任何一种，用该语言的玩家选到新任务时就会越界读出垃圾，可能崩溃。

## 3. 进度、解锁与统计（问题 3）

### 新追加的任务默认锁住 **H**

选关构建在 `0x8A1530`：
- 先把所有行设为状态 4（锁定、隐藏），只有行 0 设为 1（开放）。见 `0x8a2160..0x8a219d`。
- 然后逐行扫描。某行任一兵种任一难度通关（`0x8A4C00` → `0xDFA40`）时，它字段 3 里的后继改成状态 1；如果后继字段 5 为 1，改成状态 2。
- 离线模式（ModeList 第 8 项 = 0）遇到第一个未通关且仍锁定（状态 4）的行就停止扫描，后面的行不显示（`0x8a2330..0x8a237e`；2026-10-09 复核更正，原文写成「开放行」）。

### 解锁规则就是字段 3

- 原表最后一行 `146 M152` 的字段 3 本来就是 `[147]`。
- 现在它指向不存在的行，所以被跳过（最后一行不处理后继；ProceedNextMission 也要求后继小于总行数）。
- 追加以后，**通关 M152 会自动解锁第 147 行**（第一个 EDF5 任务）。
- 追加的行请按 `[i+1]` 串起来。最后一行的后继随便填（不会被读）；保持 `[257]` 即可。

### “最后一个任务”的语义会移到表尾 **H**

- `IsLastMission`（`0x70EDA0`）就是 `mgr+0x48 == count-1`。
  - 追加后，**通关 EDF6 M152 不再播放结局和制作人员表**，改为通关最后一个 EDF5 行时播放。
  - `GetContentID()==0` 时播放的是 EDF6 的结局。
- “首次通关最后一个任务就解锁全难度”的判断（`0x70d901` → `0xDF990`）读的也是 `clear[*][count-1]`。
  - 结果写进 `mgr+0x300`。它属于 system 块，是全局、持久的标志。
  - 已经打通 EDF6 的老存档该标志已是 1，**不受影响**（`0x70d90d` 已置位就跳过）。
  - **新存档必须打完 EDF5 最后一关才会弹出 NotifyAllMissionClear、解锁全难度。**

### 通关率与成就统计会被稀释 **H**

| 统计 | 位置 | 分母 |
|---|---|---|
| Easy..Inferno / AllClearRatio | `0xDC9E0`，`0xdd29f: imul eax,[rsp+0x3c],0x2710` / `div [rsp+0x38]`，`[rsp+0x38] = 0xE0650` | 当前列表行数 |
| 按兵种统计 | `0xD8550` | 当前列表行数 |
| 在线大厅显示的通关百分比 | `0x748111` | 当前列表行数 |

- 列表从 147 行变成 257 行后：
  - 原来 100% 的存档会显示约 57%。
  - 主脚本 `CheckUnlockArmorWeaponLimit` 的门槛 `AllClearRatio >= 7000`（70%）也更难达到。
- Steam 成就或统计里已经解锁的不会撤销。**M**：平台不收回成就，但向 Steam 提交的统计值会下降。
- 新玩家想拿“全通关率”类成就，得连 EDF5 任务一起打。**M**

### DLC 模式

- DLC1 和 DLC2 各有自己的 MST，上限同样是 512。**H**
- 本方案不改 DLC，不受影响。

## 4. 别处是否写死了任务总数（问题 4）

**没有找到写死 147（0x93）或其他小上限的地方。**

**H（已检查的路径）：**
- 选关列表：`0x8A1530` 用 `std::vector`，按 `0xE0650` 的行数 resize（`0x8a2155`）。
- 游标定位：`0x8a2795..0x8a27b2` 按行号线性查找，找不到就退回 0。
- 各项统计：见第 3 节，分母都是动态行数。
- 在线大厅百分比：`0x747ED0`，动态。
- ProceedNextMission 和 IsLastMission：动态。
- LoadPackage 加载：动态。

**唯一的硬上限是 ModeSave 的 512 列。** **H**

**风险点：**

| 编号 | 风险 | 后果 | 可信度 |
|---|---|---|---|
| R1 | 新行缺少 `flags` 名字 | 必崩 | H |
| R2 | 有任何一种语言的 TXT 没追加到 257 行 | 越界读，可能崩溃 | H |
| R3 | 字段 3 里的后继大于等于总行数（最后一行除外） | 选关时 vector 越界 | H |
| R4 | 缩略图 `EDF5_OLD_SCRIPT_Mxxx.dds` 在 `MissionList.offline.image.rab` 里不存在 | 现有 rab 147 张图全是 `EDF6_*`；缺图时的表现没查（可能空白，也可能报错） | M |
| R5 | 卸载 mod 后或进在线模式时，存档里的“当前任务下标”（ModeSave+0）≥147 | 选关游标会退回 0；带边界检查的访问器（如 `0xE0950`）安全；未逐一核对其余无检查的访问器（如 `0xE1560`）在选关前是否会被调用 | M |

R5 的规避：卸载前在离线模式选一个 EDF6 任务并存档。在线模式开房时会重新选任务。

另外核实了 Root.cpk 中 EDF5 任务脚本是否齐全：EDF5 列表 110 行引用的 `MISSION/EDF5_OLD_SCRIPT/<Mxxx>/MISSION.BVM` 全部存在，缺失 0 个。这些目录里没有 `before.bvm`，所以 `seen[]` 不会被写。**H**

## 5. 结论：追加 110 条安全吗

**判断：存档与容量层面安全。** **H**
- 每模式上限 512 行，257 行没有越界。
- 存档定长，不需要迁移；旧存档读新列表时新任务全部是“未通关、锁定”。
- 卸载后旧记录完好。

但有 **3 个必须满足的条件**，和 **2 个会改变原版行为的副作用**。

### 必须满足

1. 用 DSGO 写列表，每行第 10 项保留名字 `"flags"`（R1）。前 147 行逐字不动，只在末尾追加。
2. **CN / EN / JA / KR / SC 五种语言**的 `MISSIONLIST.OFFLINE.TXT.*.SGO` 全部追加到 257 行（R2）。
3. 字段 3 串成 `[i+1]`，且都小于 257（R3）。原表 146 行的 `[147]` 不用改，它会自然接上 EDF5 的第一关。

### 建议的每行取值

参照 EDF6 表中 28 行 `BGM_E6M29_MissionEDF5`（EDF5 时代回放任务）的取值：

| 下标 | 取值 |
|---|---|
| 0 | `147+k` |
| 1 | `'app:/Mission/EDF5_OLD_SCRIPT/Mxxx'` |
| 2 | 唯一键，例如 `'EDF5_OLD_SCRIPT/Mxxx'` |
| 3 | `[148+k]` |
| 4 | `147+k` |
| 5 | `0` |
| 6 | `0`（EDF5 外观） |
| 7 | `0` |
| 8 | `'BGM_E6M29_MissionEDF5'` |
| 9 | EDF5 列表第 4 项的进度 float，或 0.5 |
| 10 `flags` | `8` |

flags 别带 bit7/bit8（它们会改 `mgr+0x14FFC` 的剧情分支标志），也别带 0x20。

### 副作用

两个副作用都属于“行为变化”，不会损坏存档。

**S1. 结局与全难度解锁移到表尾。**
- 打完 M152 不再放结局，改为打完最后一个 EDF5 行时放。
- 新存档要通关最后一个 EDF5 行，才解锁全难度。
- 老存档已经置位的不受影响。

**S2. 通关率等统计的分母变成 257。**
- 显示的百分比下降，70% 解锁武器上限的门槛变难。

### 如果不能接受这两个副作用

**A. 插件补丁（推荐）。** 只改“最后一行”和“分母”两类调用点，不动列表读取。
在插件里记住 EDF6 本体的行数 147，并只在离线 Scenario 模式（content 0）生效：

| 要改的地方 | 位置 | 改法 |
|---|---|---|
| IsLastMission | `0x70EDA0` 内 `0x70edb7 call 0xE0650` | 返回 147 |
| 全通关判定 | `0x70d901`/`0x70d920` 调 `0xDF990`，其内 `0xdf9b8 call 0xE0650` | 用 147 |
| 通关率分母 | `0xDC9E0` 内 `0xdcd3b` 与 `0xdd108` 的 `call 0xE0650`；`0xD8550` 内 `0xd8586`；在线百分比 `0x7480f6` | 用 147，或改成只统计前 147 行 |

**不要直接 hook `0xE0650`**：选关、ProceedNextMission 和加载都要用真实行数。

**B. 单独做一个 EDF5 模式（备选，未验证）。**
- `DefaultPackage/config.sgo` 的 `ModeList` 是明文 SGO。可以加一个模式项，给 EDF5 独立的 MST（例如 `E5.MST`）和独立的三件套列表。这样存档、最后一关、通关率都自成一套。
- 待核实：模式选择界面是否还受加密的 `addon.sgo` 和 DLC 授权门控（ModeList 第 9、12 项，以及 `0x8a2101` 读 `mgr+0x38` 模式下标）。这一点没有核实，**L**。

**C. 分批安装。** 只为绕开容量问题没有必要，257 远低于 512。

**D. 覆盖已有槽位。** 不推荐。
- 在线模式共用 `M00.MST` 和同一套行号，覆盖会让原任务的通关记录挂到 EDF5 任务名下。
- 同时会丢掉原版内容。

## 7. 任务包（ModeList 的模式与「任务包」对话框）（2026-10-09，静态，H 除非另注）

2026-10-09 用户：「任务包里面没有显示 edf5 的主线和两个 dlc」。玩家说的「任务包」是离线模式里按「离线任务模式」后弹出的对话框（标题文本键 `RoomFilter_ContentsName`，简中「任务包」），EDF6 的任务包１ / ２ 就在这里。2026-10-07 版把 EDF5 追加在 EDF6 本篇离线列表第 147 行之后（见 §1–§6），所以它根本不在这个对话框里；而本篇选关又在第一个「未通关且仍锁定」的行停止显示（`0x8A2330`..`0x8A237E`：未通关行状态为 4 时记下 `edi = 行号`，离线模式（行 +0x68 为 0）`edi != -1` 就跳出循环），没打通 EDF6 的玩家看不到第 147 行以后。改为 3 个独立的模式。

### 模式从哪来

- 只读一个包：`app:/DefaultPackage/config.sgo`（`0xDB580` → 包加载 `0xDA8E0`）。包里可选 `DisplayName` / `DisplayDesc` / `DisplayImage`（包对象 `+0x58/+0x60/+0x68`，`0xDAA30`..`0xDAAE3`），`ModeList` 每项生成一个模式对象（`mgr+0x20` 指针数组、个数 `mgr+0x30`；模式对象 `+0` 是包、`+0x10` 是该项的 SGO 节点）。加载时**不按拥有与否过滤**。
- ModeList 项的成员（节点按 12 字节一个，`+0x74` = 第 9 项的值、`+0x80` = 第 10 项）：0 名字键、1 说明键、2 图、3 BGM、4 `MAIN.GST`、5 存档 `<MST>`（文件 `DEFP_<MST>`）、6 `[列表, 文本, 缩略图]`、7 各难度数值、8 是否在线（选关扫描在 `+0x68` 读它）、9 内容编号、10 模式类型（0 离线剧情、1 在线，`GAME_OFFLINE_SCENARIO` / `GAME_ONLINE_SCENARIO`）、11、12 人数。
- `GetModeNo(type, content)`（脚本函数，实现 `0x70E9D0`）按「第 10 项 == type 且第 9 项 == content」取第一个；对话框选中后同样按这两项找模式（`0x8C4CA0`）。**所以每个模式的（类型, 内容编号）必须唯一**，内容编号 0 的副本会被解析成 EDF6 本篇。
- 本机存档里有 `DEFP_MOD1.MST`、`DEFP_MOD3.MST`（见 §0）：别的 MOD 往 ModeList 加过自定义存档名的模式，游戏照样建了存档文件（M，实证但不知那个 MOD 的具体写法）。

### 模式选择界面 `HUiModeSelect`（`lyt_ModeSelect.sgo`）

- 按钮表 `0x8C3740`：遍历全部模式，内容编号 != 0 的不出按钮，若第 10 项为 0 就置 `this+0x7E0 = 1`（「有离线任务包」）；内容编号 0 的出按钮（离线剧情、在线），离线且人数 > 1 的另记一个双人项。
- 按下按钮 `0x8C4E60`：在线 → 直接进；离线且 `+0x7E0 == 1` → 打开任务包对话框（`HUiContentsSelectDialog::InitParam::Build` `0x8BED70`，标题 `RoomFilter_ContentsName`）。
- 对话框列表 `0x8BEE40`：再遍历全部模式，筛选回调 `0x8C4C70` 只留第 8 项为 0（离线）的，内容编号 0 的设为默认项。每项：
  - 名字：包的 `DisplayName`（`0xDA790` 返回 `[[模式]+0x58]`；DefaultPackage 没有这一项）为空时用该项第 0 项的键，经文本表 `0x957EC0` 取当前语言的文字。文本表是 `app:/etc/TextTable_steam.%LOCALE%.txt_sgo`（`0x705F08`；Root.cpk `ETC/TEXTTABLE_STEAM.{CN,EN,JA,KR,SC}.TXT_SGO`，普通 SGO，键 → 字符串）。
  - 能否选：`0xD92B0(mgr, 内容编号)` 查 `mgr+0xE0` 的 `std::set<int>`（`+0x1C` 键）。这个集合由 `0xDBB50` 清空后放入 0，再由 `0xDA600` / `0xDBD40` 加入平台已购附加内容的编号（附加内容列表 `mgr+0xF8`，`0xD3120` 已购、`0xD2600` 编号；数据来自加密的 `app:/AddonSteam/addon.sgo` 和平台查询）。不在集合里的项置灰（`+0xD1`），选中时 `0x8BEAC0` 弹 `ContentSelect_Warning`「尚未购买%MPACKNAME%」，`%MPACKNAME%` 来自 `0xE3F80(内容编号)`：只认 0..2（`MissionPackName1/2`），其余返回空（`0x958F13` 判空，不崩）。
- `0xD92B0` 在 `EDF.dll` 里共 7 处调用：`0x8BEF48`（对话框）、`0x8B5188`、`0x8EC659`、`0x8F64A1`、`0x8FD963`、`0x90069B`、`0x91A655`（后几处在大厅 / 房间，只涉及在线模式的内容编号）。
