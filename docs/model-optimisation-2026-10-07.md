# 生成模型的无损优化与落地（2026-10-07）

用户要求：「优化一下所有模型，顺便检查模型有没有问题，还有模型在平地 / 稍微不平的地面运行」，「优化必须要是无损或者更好的优化」。
本次只改生成器（`pylib/`）和随模型高度走的一张表（`src/booster.cpp` 无人机尾焰）；`Root.cpk` 只读，没有安装、没有改游戏目录。

## 改了什么

| 项 | 做法 | 依据（为什么无损） |
|---|---|---|
| 档案里没人加载的成员 | `graft_pure.prune_members`：只留生成 SGO 点名的那个模型，以及它的贴图表点名的贴图（HD + .lod）。用于 `procmesh.build_archive`（蜻蜓、蜈蚣）和 `jet_models.replace_member`（全部 jet 档案、精英战机） | 生成的 SGO 只点名档案里的一个模型；被删的 LOD、残骸、红色变体和只有它们用的贴图没有任何 SGO 名字指向（逐个 SGO/DSGO 字符串扫描，见下） |
| 钻头车 Blacker 原贴图 | `drill_model.blank_unused_materials`：5 个没有任何网格画的材质（`Caterpi_l/_r`、`v505_tank`、`Light01/02`）保留（SGO 的履带滚动按名字找它们），贴图槽改指档案里已有的 4×4 纯色贴图，贴图表裁到被引用的，原贴图随之出档 | 这 5 个材质改前改后都是 0 个三角形 |
| 零面积三角形 | `procmesh.grid` 不写两角重合的三角形；`procmesh.ellipsoid` 两极的顶点精确落在极点（原来 `sin(pi)=1.2e-16`，远极顶点只在半精度里才重合，近极的退化面能识别、远极的不能） | 被删的每个三角形都有两个角在同一点（按写出的数值比较，-0 = 0）；平滑法线不受影响（零面积的叉积恰为 0，selftest 逐位比对） |
| OBJ 导入的退化 / 重复三角形 | `obj_model.build_meshes` → `drawn_triangles`：丢掉两角重合（按写出位置数值比较）的三角形，以及三个打包顶点与已写出的某个三角形逐字节相同（同绕向任意旋转）的三角形；切线框架仍按整块的全部三角形计算 | 写出的每个顶点与原来逐字节相同；反绕向的同位置三角形（背面）保留 |
| 无人机落地 | `pylib/jet_skids.py`：两条起落橇（见下节） | 「更好的」改动：原模型只为空中设计 |

没有做的：

- 榴弹炮两条履带材质 `v603_kyata_L` / `_R` 参数相同，但 `EDF6VC_ARTILLERY.SGO` 的 `tank_caterpillar_animation` 按名字分别滚动它们（左右履带转弯时速度不同），不能合并，保持原样。
- 沙扎比有 6 对「位置相同、绕向相同」但法线 / UV 不同的三角形：不是逐字节重复，删掉哪一个都不能证明无损，保留。（审计说的 347 个位置重复绝大多数是退化面的重复，随退化面一起没了。）
- 喀秋莎模型（另一位代理在改）里的 4 个零面积三角形来自嫁接网格，不经 `build_meshes`，本次不动。

- 每个被删成员：是 `.mdb` 且没有任何生成 SGO / DSGO 以「本档案 + 该模型」点名，或是贴图且改后模型的贴图表不点名；
- 每个模型：改后三角形（顶点按数值解码、-0 = 0、取规范旋转）的多重集合 = 改前减去被删的，被删的每个都是零面积；被画的顶点集合改前改后完全相同（剪影不变）；材质名、参数、着色器不变，换了贴图的材质改前改后都没有网格画；
- 无人机：原有网格的索引与顶点除 y 外逐字节相同，y 整体上升 0.25 m（半精度重取整最大偏差 0.001 m），新增的一个网格就是起落橇。

## 无人机起落橇

PD607 原本只在空中飞，接地后（`jet_models.grounded`：最低点落到原点）最低点是机腹下的机枪吊舱（骨骼 `gun_tilt`，比机身低 0.66 m），停放 / 降落时坐在枪上，碰撞体（`aircraft_collision` 按模型量的格子）只在中线枪下那一窄条着地：改前接地的 16 个格子都在 x = ±0.07 m。

`jet_skids.add_skids` 加两条直升机式起落橇：轨在 x = ±1.2 m，平直段 z ±1.35 m、两端 60° 上翘 0.15 m，比吊舱低 0.25 m；每条两根支柱（z ±0.9 m）插进 x = ±1.0 m 处的机腹。用模型自己的材质与顶点布局，单影响蒙皮到网格骨骼 `body`（V506 动画驱动的那根），不新增骨骼——插件（`src/gear.cpp`）只摆 `gear_*` 骨骼，看不到它。所有顶点取第一根支柱插入点附近机身顶点的 UV（机身那里的涂装色）。检查 `jet_skids.check_skids`（随 `jet_models.check` 在每次生成时跑）：起落橇是模型最低点、两条轨同高、其余几何离地 ≥ 0.25 m、每根支柱顶端在机腹内、三角形绕向与法线一致。

改后碰撞体着地的 70 个格子全在 x = ±1.09～1.24 m（两条轨），两条 2.7 m 长、相距 2.4 m 的接触线：稍微不平的地面上靠两轨支撑，而不是在一点上晃。

随之更新：`NOZZLE_EXITS` / `NOZZLES` 与 `src/booster.cpp kJetNozzles` 的 7006–7008（无人机、自爆无人机、人偶无人机）尾焰 y 1.005 → 1.255（`check_nozzles` 与 selftest 持平）。从模型量的东西自动跟随：碰撞盒、登机口、座舱相机、`RestOver`（网格骨骼仍在原点，箱中心随模型）。母舰回收（`src/jet_carrier.cpp Recover/Dock`）按「母舰下方 kDockBelow 处 25 m 内」判定后直接删除无人机，与模型高度无关；`HoldOffGround` 用的 `rest` 来自同一套模型盒，一致。

## 后续：沙扎比的碰撞（本次未做，需进游戏验证）

沙扎比的 `heli_rigid_body` 是一个 V506 盒子：中心 (0, 12.805, −1.395)，半宽 (10.805, 12.805, 13.715)，即 21.6 × 25.6 × 27.4 m，布娃娃仍是原版 `Ragdoll_v506_heli.shkt`。底面是整块平面：两脚之间、脚前脚后的空处也算实体，站在稍微不平的地面（一侧隆起、坑、台阶边）时盒子底面搭在最高的凸起上，两脚悬空；斜坡上整盒按一个平面接触。

建议方案（与飞机一致）：

1. `aircraft_collision` 式的复合形状，从沙扎比模型量格子（站立绑定姿势），接触落在两只脚底；`body506.cpp AirframeShape` 目前只放行 jet / playerJet 的标记段（7001–7099、7201–7299），要给沙扎比段（7401–7499）也放行，并让 `aircraft_collision.FILES` / `model_key` 认识 `EDF6VC_SAZABI.MRAB`。
2. 走路姿势会动脚（`src/sazabi_pose.h`），绑定姿势的格子只代表站立；至少需验证：平地站立不下沉、单脚踩上 1 m 台阶时不被卡住、斜坡上不滑、行走和跳跃落地时不穿地。
3. 这一步改的是物理形状，只能在游戏里验收，本次只记录。
