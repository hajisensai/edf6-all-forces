# Mouse aim intent and scope/AutoTurret arbitration (2026-10-08)

Two independent readers used Z: VehicleCrew's SightZoomKey and AutoTurret's AimModeKey. A press could therefore enter the physical optic and simultaneously switch AutoTurret to its lead-circle mode. HUD drawing also admitted that lead/bore/mode overlay while the optic was active.

AutoTurret now defaults to V. The optional additive `EDF6VehicleCrew_SightBindingV1` export reserves a real model-backed optic on the current seat (SightZoomCanMount), even at 1x, before its first press. An old INI binding Z that collides resolves to V without rewriting the INI; changing the effective binding drains held input. A conflicting pad mode button is left unbound instead of stealing its sight button. The unchanged TurretReadoutV1 reports the actual effective binding; optional ModeBindingV1 explains the conflict. Old exports/struct layouts are untouched, and absent optional peers retain standalone behavior.

The physical-optic HUD and AutoTurret lead/mode overlays now have one owner per draw. Mounted-state publication and the actual mask painted that frame both suppress AutoTurret and the normal third-person mouse circle, including the first optic paint before the next HUD publication. Outside the optic, AutoTurret controls sit above the computed loadout dock, rather than overlapping its cells.

The restored open mouse circle is projected only from the turret controller's validated `TurretCamReadout.aim` command (aimValid), in a real decoupled or held free-look state. Moving the physical barrel endpoint does not move this circle. The gun's actual aim/impact stays a separate marker. High observation, fixed/physical-only guns and invalid command points do not fabricate a mouse target; free look shows its held command in cyan. The aimValid producer is the separate overhead-camera patch 1036db3.

A second optional query, TurretObserverV1, identifies the real local player's C observation/return blend or active physical scope. AutoTurret's shared player-control rule does not steer or interpret dragging there, whether locked or unlocked; entering or exiting the scope leaves the user mode unchanged, avoiding the old fallback from CameraTurret=false to autonomous V1 steering. NPC gunner behavior is unchanged. This control gate is separate from the native camera collision-pivot repair.

Validation: both production DLLs built with /W4 /WX; 22 cross-DLL producer/consumer binding, observation and scope enter/exit checks, 198 production scope checks, native embedded-aim and real-gunner regressions, four-language HUD projection/layout checks and viewed offline circle/suppression renders. Export tables retain the old TurretReadoutV1 alongside new optional exports. No game execution or installation writes; live acceptance remains untested.
