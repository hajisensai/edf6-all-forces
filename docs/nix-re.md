## 2. 每帧顺序：第 4 槽 0x644350（H）

1. `0x62EEC0`（VehicleBase 第 4 槽）、`0x5F1DB0`。
2. **`0x645790`**（`0x6443A2` 调用）：
   1. `0x645530(veh+0x1720, veh+0x60, …)`：从角色控制器（veh+0x1720）取变换，再用 **`0x4CD10(matrix, [veh+0x1720+0x2B4])`** 按腿的朝向
      转车身矩阵（`0x6457C9 add rcx,0x1720`、`0x645559 movss xmm1,[rdi+0x2B4]`）。**这一帧画出来的车身朝向就是这里的朝向。**
      `0x645530` 只有这一个调用者，车身矩阵的旋转只在这里写（`0x4CD10` 在 0x618000..0x649000 里也只有这一处调用）。
   2. 动作状态机（veh+0x16E0，状态函数 0x639800、0x63A100、第 54 槽、0x639280、0x638A30、0x639560）：把移动向量按朝向转到世界、
      累加位移 veh+0x1960、累加转角 veh+0x1970（`0x6398BE`），按转向速度放原地转身动画（`0x639F20`、`0x639FF0`）。
   3. **`0x641800`：输入**。veh+0x1540 非 0 且座位 0 有活着的乘员时，`BodyInputController`（veh+0x1530，vtable 0x17DE020，
      RTTI `.?AUBodyInputController@VehicleBegaruta@@`）第 2 槽 `0x6472C0(ctrl, seat+0x2C0)`：
      - ctrl+0x28（veh+0x1558）= −LY（座位 +0x2C4），ctrl+0x30（veh+0x1560）= −LX（座位 +0x2C0），各带死区；
      - ctrl+0xC 位 0 = 按键 & 0x43；
      - ctrl+0x20 / +0x24（veh+0x1550 / +0x1554）只被复位函数 `0x63C4C0` 清零，**没有写入者**：步行没有横移（M）。
      然后每个座位 i 的瞄准输入块 `[veh+0x19E8] + i*0x40`：+0 = −RX（座位 +0x2D0），+4 = RY（+0x2D4），扳机按武器分组写字节。
   4. **`0x6459C7`：每个座位的瞄准**：`(*(seat+0xE0))->slot2(瞄准输入块)`，即 VehicleWeaponAim 第 2 槽 `0x5FBDA0`（或带音效的
      `0x5FCD80`，先调它）。
   5. `0x645A20`：移动向量 veh+0x1950 缓到 veh+0x1550 × veh+0x1978，**转向速度 veh+0x1974 缓到 veh+0x1980 × veh+0x1560**（−LX），
      即 A/D 控制腿的原地转向（H）。
3. **`0x645190`**（`0x6443F6` 调用）：`朝向 += veh+0x1974 × 1/60`（`0x645314 movss [rbx+0x2B4],xmm0`；常数 0x179F358 = 1/60），
   设角色控制器的速度。另有一份同样的 `0x644FB0`（没有直接调用）。
4. 推入全局队列。

结论：**瞄准轴在腿本帧转向之前步进，车身矩阵用的是本帧开始时的朝向**。veh+0x19D4（= ctrl+0x2B4）就是腿的朝向（弧度，无回绕，
与矩阵同一个来源）。联机时第 51 槽 `0x6422A0` 也会写它（`0x6426AC`，按远端插值），只在 `0x7748F0` 为真时运行（M）。

## 3. 瞄准轴（VehicleWeaponAim，座位 +0xE0）（H）

- vtable 0x17D8A68（`VehicleWeaponAim`）或 0x17D8A90（`VehicleWeaponAimAddSe`，构造 0x5FC950；第 2 槽 0x5FCD80 先调 0x5FBDA0 再放音效）。
- 轴在 +0x10，步长 0x40：轴 0 = 偏航（输入块 +0），轴 1 = 俯仰（输入块 +4，负值向上）。每轴 `{+0 min, +4 max, +8 angle, +0xC 速度, …}`，
  参数在 +0x90（`0x5FBC00` 的 r8）。
- `0x5FBDA0`：+0xC0 为 0 时直接按输入步进两轴；不为 0 时看模式 +0xC8：0 / 2 按输入（2 用 +0xB0 存的输入），**1 追目标角 +0xA0/+0xA4**
  （联机路径）。构造时 +0xC0 = 0、+0xC8 = 2。
- `0x5FBC00`：速度按输入平滑，`angle += 速度`；**`max − min` 小于 2π 时夹在 [min, max]**（0x5FBD29..0x5FBD52，碰到限位时速度不再朝外），
  等于或超过 2π 时回绕（0x5FBD59，常数 0x1C369C4 = 2π）。最后 `0x5FC280` 把角度映射到骨骼（轴 +0x28 的条目，步长 0x38）。
- 方向约定：`0x5FACD0`（第 3 槽）用两轴建瞄准矩阵：先按俯仰绕 x 轴转（前向行变为 (0, −sin p, cos p)），再按偏航转，前向行
  (sin a, 0, cos a)。`0x4CD10` 转车身矩阵的约定相同：前向行 (sin ψ, 0, cos ψ)。所以**上半身的世界偏航 = 腿的朝向 ψ + 偏航轴角 a**
  （两公式 H；瞄准矩阵确实乘在车身矩阵上、上半身骨骼与镜头都跟这个瞄准走，M——游戏里瞄准方向和双臂开火方向一致即说明骨骼映射同号）。

## 4. 插件的做法（src/nix.cpp）

- 串接 Vehicle612_nix 第 4 槽（`edf::ChainVtableSlot`，只改 612 的表；504 / 贝加尔塔不受影响）。
- 原版更新之前：座位 0 是本机玩家、瞄准轴是上述两种 vtable、且不在追目标模式时，偏航轴角 `a −= wrap(ψ_now − ψ_last)`，再夹到上下限
  （轴没有上下限时 ±120°），`ψ_last = ψ_now`。随后原版步进加上鼠标、夹限位。于是本帧画出的上半身 = ψ_now + a = 上一帧的世界偏航 + 鼠标。
  到了限位，上半身停在限位、随腿转；鼠标不会推腿（腿只受 A/D）。
- 新上车（或与上次更新相隔超过 250 游戏毫秒）时只记下朝向，不补偿。NPC 乘员（自己的闭环瞄准 `0x63AC40`）和联机别人开的不碰。
- 原版更新之后：用本帧矩阵和两轴角度算出腿朝向、上半身朝向、扭转角与上下限、俯仰和世界瞄准方向，加锁发布（`PlayerNixTorso`，`src/nix.h`）。
- 签名：0x644350 入口、0x6443A2 / 0x6443F6 两个调用、0x6457C9 / 0x645559 / 0x645314（朝向字段）、0x6459D0（座位瞄准循环）、
  0x5FBCF6 / 0x5FBD12（轴的 min / max / angle 偏移）。任何一处不符，功能整个关闭（日志 `NIX code at … not as expected`）。
- 离线验算 `tools/nix_twist_check.cpp`：按上面的帧顺序模拟，腿转 45° 上半身世界朝向漂移 0，到限位后随腿转，鼠标单独转上半身，
  朝向绕到 1000 弧度 / 跨过 ±π 不漂移，无限位轴得 ±120°，关掉时与原版一样跟腿转。

## 5. 需要进游戏确认（L）

1. 偏航轴的实际上下限（上车日志 `NIX v=… stops …`），以及它是否就是 SGO 的 ±70°。
2. `Debug=1` 每秒一行 `NIX v=…: heading H (matrix M) torso T twist W … camera-torso D deg`：H = M（矩阵由这个朝向建出）；
   按住 A/D 时 T 不变、W 反向变化；D 接近 0 且转腿时不变（镜头跟上半身的瞄准）。若转腿时 T 以两倍速度变化，说明骨骼 / 镜头的
   偏航与瞄准轴反号（§3 的 M 不成立），应把 `nix_twist.h` 的补偿改为加。
3. 原版鼠标推到限位时是否另有一路让腿跟着转（静态没找到：转向速度只来自 −LX）。若有，`NixTorsoTwist=1` 时也会照旧发生。
