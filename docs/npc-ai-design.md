## 1. 现有结构与复用

- 车辆侧的每帧层是 `crew.cpp` 的 slot 55 输入钩（`InputHook`），原版输入之前有「前置步骤」（`DrillInput` / `EmcInput`），之后有 `HeliStep` / `GroundStep` 等。D 的回位驾驶放在前置步骤里（§8）。
- 飞机、直升机、深渊爬行者的自制 AI（`heli.cpp`、`jet*.cpp`、`ground.cpp`）各自持表、各自接地图指令。地图指挥（`mapcmd.cpp` / `mapcmd_logic.h`，分支 feat/map-command-npcs，已合进本分支）是唯一的指挥入口：选择、框选、指令分发都在那里。**指挥面板（C）是给它加一类单位（步兵小队）和几条指令，不另写第二套**（§6）。
- 可复用的工具：`VisitEnemiesOf`（敌人锁定点遍历）、`MapRay`（地图射线）、`NearLine` / `FriendInLine`（火线）、`CameraRay`（玩家视线）、`InSession`、`PlayerHuman`、`SeeFrame`。
- 纯决策都放进 `src/npc_logic.h`（无游戏、无 Windows），由 `tools/npc_ai_check.cpp` 离线检查（CTest），与 `mapcmd_logic.h` / `map_cmd_check` 同一模式。游戏侧是新文件 `src/npcai.cpp`。

## 2. 联机原则（每个功能的「在哪端算、怎么同步」汇总在 §9）

1. **步兵 AI 在原版 AI 跑的那一端算。**原版第 7 槽 Think 对远端副本（`h+0x128 & 1`）不写意图块，远端由第 54 槽 `0x595F50` 把复制来的 `+0x1E00/+0x1E10` 写进 `d50/d60`（M）。插件只改「本机拥有」的士兵的意图块，等于替换原版 AI 的输出；它沿原版士兵的复制通道走到其他机器，不需要新协议。
2. **小队关系的写入走原版带同步的路径。**`SetFollow 0x54EC50` 之后调士兵 vslot 39 `0x59C3D0`：客机发消息 13 请求、房主执行并广播消息 12（H）。插件只在**房主**做小队重组（§5.3），避免客机和房主各自重组。
3. **插件自有的指令状态（驻守点、冷却、标记、上车命令）没有跨机通道**：原版没有给插件留消息，插件之间也没有同步协议。所以这类功能和现有地图指挥一样**只在单机启用**，联机时面板显示 `OFFLINE ONLY`。`+0x540`（可招募）不复制（H），解除招募若只在一台机器清，会被另一台的玩家招回去——这是联机不开放解除招募的直接原因。
4. **车辆回位只在房主算**（`0x784210`）：RideAi 的 `DummyVehicleRider` 没有网络身份，每台机器都自认是 0 号座权威（docs/online-re.md §3.4），插件不再增加分叉，只在房主写摇杆。

## 3. 步兵自制 AI（B）

### 3.1 原版 AI 的结构（RE，H 除注明）

- 没有独立 AI 类。AI 是嵌在人物里的状态机 `StateMachine::Agent<SoldierBase>`（`h+0x1BF0`，vtable `0x17D2480`），三个状态都是 SoldierBase 虚函数：89 `0x590710` 守点、90 `0x590280` 跟随、91 `0x58FF70` 交战（HeavyArmor 91 是 `0x566290`）。
- 每帧入口是 vtable **第 7 槽 Think**：AssultSoldier（`0x17CDF28`）、Engineer（`0x17CF100`）= `0x596B50`；HeavyArmor（`0x17CF5B8`）= `0x567080`（先调 `0x596B50`）；PaleWing（`0x17D0FF8`）= `0x580460`（`jmp 0x596B50`）。签名 `void Think(Human* h, const float* dt)`。
- Think 开头 `0x596BAE` 调 `0x56D300(h+0xD50)` **清空意图块**，再跑状态机写意图块。玩家也写同一块（`0x570650`）。随后第 4 槽 `0x572DF0` 消费移动与视角（`0x573B72` → `0x56D350`），第 5 槽 `0x59ABB0` 消费按键。第 4 槽对 `h+0x1A & 8`（在 AI 列表里）的非玩家**不再清块**（M：原版 AI 能工作就说明它们都有这一位）。

意图块（`h+0xD50..+0xD84`）：

| 偏移 | 含义 |
|---|---|
| +0xD50 vec4 | 移动，局部 (x, 0, z, 1)。世界方向 = x·(cosψ,0,−sinψ) + z·(sinψ,0,cosψ)，ψ = `h+0x1244` |
| +0xD60 vec4 | 视角增量 (Δpitch, Δyaw, 0, 1)，rad。`h+0x1230 += d60`，`h+0x1240`（pitch，负 = 向上）/`h+0x1244`（yaw）平滑跟上 |
| +0xD70 / +0xD71 | 第 0 / 1 个 WeaponSet 扳机（按住） |
| +0xD74 / +0xD81 | 下一把 / 上一把武器 |
| +0xD75 | 换弹 |
| +0xD76 / +0xD77 | 跳 / 回避：按下 / 按住 |
| +0xD82..+0xD84 | 直接选第 0..2 把（M：对应 `h+0x1950` 武器数组的前三项） |

- 原版看向目标的写法（`0x5A2B50` MoveAndLook，`0x5A2FFB`）：`0x4E100(out, dir)` 给出 out[0] = −atan2(dy, 水平距离)（pitch）、out[1] = atan2(dx, dz)（yaw），`d60 = wrap(out[0] − h+0x1240) × 增益`、`d64 = wrap(out[1] − h+0x1244) × 增益`。插件按同一公式写（`npc_logic.h` `AimDelta`），符号不用学习。
- 目标：每 60–119 帧（`h+0x1CE0`）`EnumConflictObject` 选最近的已交战敌人，**不限距离、不看视线**；存 weak `h+0x1CD0/+0x1CD8`，赋值 `0x58EB40(&h+0x1CD0, &{obj, ctrl})`。
- **原版交战距离 = max(25, 0.5 × 真实射程)**（`0x590201..0x59024C`，常量 `0x1C36990`=0.5、`0x17A099C`=25），朝向点积 > 0.8 才开火。真实射程 `weapon+0x224` = AmmoAlive × AmmoSpeed（`0x68DB1B`）。这就是「射程太短」（B3）的根因。
- **原版不换武器**（Ranger / Fencer / Air Raider 的 AI 从不写 d74/d81/d82；PaleWing 自己的状态机会，M）——「全程一把枪」（B2）的根因。
- **原版没有友军火线检查**：唯一的门是 `h+0x1CEC` 地图视线（layer 22，只打地图）——「挡枪线、打玩家」（B1）的根因。
- 翻滚：第 65/66 槽收到 d76 且 |d50.x| > 0.35（常量 `0x1790138`）、`h+0x158C & 0x800` 时进侧翻（Ranger `0x552B10`）。Wing Diver / Fencer 的第 68 槽是跳跃 / 推进（M）。原版 AI 只在寻路要求跳时置 d76——「不会翻滚」（B5）的根因。

### 3.2 接管点

- **包裹第 7 槽**（四个士兵 vtable）。`EnsureInputs` 时安装（所有插件都已加载，链在别人之后），槽里不是预期函数就链上去并记日志。
- **原版之前**（pre）：队长阵亡时的继任 / 并队（§5.3），必须赶在原版那段解散代码之前。目标（含标记、集中火力）不改写原版的 `h+0x1CD0`，由 post 的瞄准 / 扳机 / 移动直接体现（§6.3）。
- **原版之后**（post）：改写意图块。移动、视角、扳机、换枪、翻滚。原版刚写完、第 4/5 槽还没消费，所以插件的值与原版 AI 自己的输出寿命完全一样。
- 条件：`CustomNpcAi=1`、非玩家（`+0x340 == 0`）、活着（`+0x2E8 == 0`）、本机拥有（`!(+0x128 & 1)`）、`h+0x1A & 8`（否则第 4 槽会清块，插件不写并记一次日志）、不在载具上（`+0x1550` 空）、队伍与本机玩家友好。
- 关掉 `CustomNpcAi`：钩子只转发原版，不读不写。

### 3.3 每帧决策（`npcai.cpp` Decide，纯函数在 `npc_logic.h`）

```
anchor  = 命令点（驻守 / 前往）| 招募它的那位玩家（已招募；联机时可能是另一台机器的玩家，见 §9）| 原版队长（脚本或 NPC 队长）| 自身原地（自由）
threats = 每帧快照：本机玩家队伍的敌人锁定点（VisitEnemiesOf）
friends = 每帧快照：玩家 + 友军士兵 + 友军载具（队伍遍历 0x5E11D0）
1. 脚本控制（§4.2 判据）→ 只做 §3.4 的火线否决与 §3.5 的换枪，移动 / 目标全交原版
2. 低血（HP < NpcRetreatHp）→ 退到玩家身后（玩家视线反方向 NpcFollowBack 米），不前压
3. 被围（CrowdResponse）→ 后撤 / 侧移 / 翻滚，优先于其他移动
4. 在玩家枪线里（LaneEscape）→ 横移出线
5. 有目标 → 换枪（PickArm）、看向目标（AimDelta）、在战位上打（CombatSpot，离 anchor 不超过 NpcLeash）
6. 其余 → 保留原版移动（跟随队形）
扳机：武器就绪、在真实射程内、瞄准误差小于锥角、地图视线通、ShotClear（友军与玩家不在弹道和爆炸半径里）
```

### 3.4 枪线（B1）

- 玩家枪线 = 从玩家眼睛沿镜头中心（`CameraRay`）到第一处地图命中或 `NpcLaneLength` 米，宽 `NpcLaneWidth` 米（`npc_logic.h` `Lane`）。NPC 在线内就沿垂直方向往自己所在一侧横移出去（`LaneEscape`），战位也取在玩家两侧 `NpcFlankDeg` 度、不取在玩家与目标之间（`CombatSpot`）。
- 开火前 `ShotClear`：弹道线段离任何友军（含玩家）不到「对方半径 + 散布」就不开；爆炸武器的落点离友军不到 1.25 × 爆炸半径（`weapon+0x8B0`，H）也不开。这同时盖住「隔着玩家开火」和「近身用火箭炸到自己人」。
- 脚本单位也做这一步（只会让它少开枪，不会让它多开枪，不影响脚本）。

### 3.5 武器与射程（B2、B3）

- 武器表 `h+0x1950`（指针数组）/ `h+0x1960`（数量）；每把：射程 `+0x224`、伤害 `+0x89C`、爆炸半径 `+0x8B0`、锁定类型 `+0x6B0`（1 = 追踪）、弹数 `+0xBE8`（M：与载具武器同一基类）。
- `PickArm` 按目标距离与类型打分（追踪 / 对空打飞行目标、爆炸打大目标与成群小怪、近距高 DPS），自身爆炸半径内的距离不用爆炸武器，友军靠近目标时不用爆炸武器；现用武器不差于最佳 25% 就不换（防抖）。
- 换枪写 d82+i（M）。下一帧核对当前武器（WeaponSet `h+0x1970` 第 0 组 `+0x40` 解两次指针）是否就是选中的那把；连续 30 帧不一致就**对这名士兵关闭换枪并记日志**（RE 的 M 项被证伪时停用，而不是重试）。
- 交战距离 = `NpcEngageShare` × 最长真实射程（`EngageRange`），代替原版的 max(25, 0.5 × 射程)。

### 3.6 机动（B4、B5）

- `CrowdResponse`：`NpcDangerRange` 米内的敌人按距离加权施压；压力 ≥ `NpcCrowd` 或有敌人进 `NpcGrabRange` → 后撤（加权反方向）；进抓取距离且翻滚冷却好 → 翻滚（d76 一帧 + |d50.x| ≥ 0.6）；只有一只正面冲来 → 横移让开。翻滚只给 Ranger / Air Raider（第 68 槽是侧翻），Wing Diver 同一输入是起跳（也是脱离），Fencer 只后撤。
- 掩体：低血后撤时在玩家身后半圆上取几个候选点，选从最近威胁看过去被地图挡住（`MapRay` 命中）的那个；都不挡就取正后方。
- 转移位置：战位每 `NpcRepositionSec` 秒（或战位离开视线）重新选。

### 3.7 「对玩家有用」（B7）

- 射程翻倍（真实射程）+ 换枪 + 不挡枪线，是主要收益。
- 跟随时战位在玩家两侧、不跑到玩家前面挡路；低血自己退到玩家身后，不需要玩家去捡血箱「救」它。
- 未做（需要另一块逆向，列为后续）：NPC 自己拾取回血箱；工程兵类支援技能。

## 4. 脚本 NPC（A）

### 4.1 相关字段（RE，H 除注明）

- 路线：`obj+0x4A8/+0x4B0` = `AiRouteExplorerBase` shared_ptr，**士兵、载具、敌人偏移相同**。四种 explorer：Simple `0x17D6A08`（SetAiRoute）、Navigation `0x17D6940`（SetAiRouteNavigate，护送 / 引导：跑太前面会把速度倍率降到 0 等玩家）、Mesh `0x17D68F8`、Escape `0x17D1F58`。基类 AI `0x54A000` 每帧：清 `+0x4D0` → explorer slot 3 写下一点 `+0x4C0` / `+0x4D0` → `explorer+0x2C`（走完）就 `0x5478C0` 清空 `+0x4A8` → `+0x380 & 0x800000` 时删除对象。
- 分支选择看车身 / 人物前向（Simple `0x5CF710`：取与前向点积最大的连接点）。
- 脚本等「走完」：`IsAiMoveEnd 0x1C0B10`、`WaitAiMoveEnd 0x1C41B0`、`Factor_AiMoveEnd`（检查 `0x1FAD90`）、`Factor_AiMoveEndOrDie`（`0x1FAFC0`）——**都只看 `+0x4A8 == 0`**。
- 小队：`+0x548` 队长（裸指针）、`+0x550` 跟随者链表、`+0x540` 可自动入队；`+0x380` bit15 FixAiPosition、bit16 FixAiDirection、bit19 遇敌取消路线、bit23 走完删除、bit26 ChaseLeader；`+0x4E0` 朝向令剩余帧。**所有 SetAiRoute 类函数在 `+0x548 != 0` 时什么都不做**（`0x1C492C` 等）。
- 原版**没有**「释放单位」的脚本函数；结束控制只有：路线走完、`CancelAiRoute`、`Unfollow`（清 `+0x548` 且 `+0x540 = 0`）、`FixAiPosition(false)`、`ClearAiObjectDirection`。
- 原版看门狗（H）：有路线时目标点 60 s 不靠近 2 m（且速度倍率 ≥ 0.5），**士兵被瞬移到当前路点**（`0x597549..`），**坦克自毁**（`0x661220` → `0x6329B0`）。

### 4.2 判据（`npc_logic.h` `ScriptState`）

```
scripted(obj) = obj+0x4A8 != 0                       // 自己有路线（H）
             || 根队长（沿 +0x548 走到顶）不是玩家且有 +0x4A8   // 脚本经由 NPC 队长控制（H）
             || obj+0x380 & 0x8000                     // FixAiPosition（H）
             || obj+0x4E0 > 0                          // 朝向令（H）
recruited(obj) = 根队长是本机玩家（H）
script ended   = 上一帧 scripted、这一帧不是（判据 A 的「路线清空」即原版 WaitAiMoveEnd 的条件，H）
```

载具用同一个 `+0x4A8` 判据；另外「0 号座是 DummyVehicleRider 且不是插件 AutoCrew 放的」= 脚本 RideAi 的车（`crew.cpp` `crewedAt`）。

### 4.3 脚本控制期间：移动交还原版（二选一的选择与理由）

选「**交还原版**」，插件只做两件不改变脚本走向的事：火线否决（只会少开火）和换枪。理由（全部来自 §4.1 的 H 结论）：

1. 路线事件只认 `+0x4A8 == 0`，而 `+0x4A8` 只有「依次到达每个路点的到达半径」才会清。插件只要把单位带离路线，`WaitAiMoveEnd` 就永远不返回，**任务卡死**；开到终点区域也没用。
2. 路线分支按单位前向选，插件转向会改走另一条分支。
3. Navigation 路线（护送）按玩家进度把速度降到 0 等玩家；插件若照搬就是重写原版，若不照搬就破坏护送节奏。
4. 原版看门狗会反过来惩罚插件：偏离 60 s，士兵被瞬移、**坦克被原版打死**。
5. 区域类事件（`EventFactor_ObjectAreaCheck`）按位置判，原版自己走就能触发；带 `+0x380 & 0x800000` 的单位走完会被删除，插件接管会改变它消失的时机。

「插件严格按路线执行」等于逐条复刻 explorer、Navigation 速度门与看门狗，收益为零、风险是卡关，所以不选。

### 4.4 脚本结束后转成普通单位（A3，P7）

- 每帧按小队顶端士兵读一次「脚本占用」= 自己有路线、或 NPC 根队长有路线、或 FixAiPosition（只有朝向令不算：脚本让单位转个身不等于接管过它）。占用由真变假（路线走完、`CancelAiRoute`、`Unfollow`、Fix 解除）并保持 `ScriptNpcSettleSec` 秒 → 该小队转成普通自制 AI 单位：移动交给插件、出现在面板里可下令（`npc::ScriptWatch`，只释放一次）。
- 可招募：`+0x540` 是脚本的意图（`CreateFriendSquad` 的参数 / `SetAiAutoFollow` / `Unfollow` 会清 0）。脚本结束后，ini `ScriptNpcRecruit=1` 时插件把这支小队的 `+0x540` 置 1，玩家走近即按原版方式入队；`=0` 时保持脚本给的值。
- 风险（写明）：脚本日后若再对这支小队 `SetAiRoute`，而它已被玩家招募（`+0x548 != 0`），原版函数什么都不做；之后等待「走完」的脚本会立即通过（`+0x4A8 == 0`），但等「到达区域」的脚本会等不到。所以 `ScriptNpcRecruit` 默认 1（用户要求），但只对**判据曾为真、现在为假超过 `ScriptNpcSettleSec` 秒**的单位放开，避免脚本两条指令之间的空档被误判为结束。
- 列表与标记（A1）：脚本单位也进面板，状态列显示 `SCRIPT`（路线中）/ `HOLD`（Fix）/ `ESCORT`（Navigation explorer）/ `FREE` / `SQUAD` / `RECRUITED`；地图上用同一套小队图标，脚本单位灰色、不可选中下令。

## 5. 小队（B8、C2）

### 5.1 数据结构（RE，H）

- 原版没有 Squad 类：小队 = `+0x548` 队长 / `+0x550` 跟随者链表（节点 `[0]next [8]prev [0x10]obj`，`+0x558` size）组成的树。招募 = NPC 队长的 `+0x548` 被写成玩家，由 SoldierBase Think 自动完成：没有队长且 `+0x540 != 0` 时找 10 m 内的本机玩家（`SearchNearPlayer` `0x598D10`）→ `SetFollow(npc, player, false)` + vslot 39 同步。
- 原生函数：`SetFollow 0x54EC50(self, leader, keepOffset)`、`Unfollow 0x54DD40`、`ReleaseAllFollowers 0x54DC60`、`CancelRoute 0x5478C0`、同步 vslot 39 `0x59C3D0(self, leader, keepOffset)`。
- 插件的小队表（`npcai.cpp` `Squad`）不另存成员关系，每帧从原版的树读：小队 id = 根 NPC 队长的对象地址 + 控制块（`ObjRef`），状态 = §4.4 的分类。

### 5.2 招募

保持原版的「走近 10 m 自动入队」，插件不改距离常量（`0x1765A44` 被 913 处共用）。面板里多一条「招募」：对选中的自由小队调 `SetFollow(队长, 玩家)` + vslot 39，等价于原版招募（单机）。

### 5.3 队长阵亡（B8，P3）

- 原版（H，`0x596C1B..0x596D91`）：队长死且无自动复活 → 每个队员 `SetFollow(self, nullptr)`，各自成为自由单位；`+0x540 == 1` 的会**单个**跑去跟玩家。不选新队长，不并队。
- 插件：在任一队员的 Think **之前**（pre），发现其队长已死且无自动复活（`+0x380` bit17）→ 按 `PickLeader` 选新队长（实现里等级都取 0：当前 HP 最高者接任，同 HP 取先列出者；兵种次序没有可靠依据，未采用）；新队长 `SetFollow(新队长, 旧队长的队长)`（已招募的仍挂玩家），其余队员 `SetFollow(队员, 新队长)`，每次都调 vslot 39。之后原版那段代码看到的队长是活的，不再解散。
- 人数少于 `NpcSquadMin` 时，`JoinSquad` 选 `NpcSquadJoinRange` 米内、合并后不超过 `NpcSquadMax` 的同侧小队，整队挂到那支的队长下。
- 只在房主做（§2.2）。

### 5.4 解除招募与冷却（C2，P4）

- 解除：队长 `+0x540 = 0` → `SetFollow(队长, nullptr)` + vslot 39（取原版队长阵亡分支的写法，H）。小队停在原地（招募时原版已清掉路线），插件给它一个驻守点 = 解除时的位置，这个驻守点属于「插件自己领导」：冷却结束后玩家走近、原版把它招募回去时自动作废，小队跟随玩家（见 §6.2 指令的领导归属）。
- 冷却：`Cooldowns` 记 `NpcRecruitCooldownSec`；到时把 `+0x540` 置回 1，原版走近招募重新生效。冷却期间面板显示剩余秒数。
- 单机限定（§2.3）。

## 6. 指挥面板（C，P4/P5）

### 6.1 与地图指挥整合

- 面板就是地图视图（`M`）里的指挥层：`mapcmd.cpp` 的 `Owner` 增加 `squad`，`mapcmd_logic.h` 的 `Order` 增加 `engage`（自由交战）、`focus`（集中火力）、`board`、`dismount`、`dismiss`、`recruit`。选择、框选、Tab 轮换、编队、发令的代码全部沿用。
- 左上角新增小队列表（`hud.cpp` `MapSquadPanel`；右上角是指南针）：每行 = 小队名（兵种 + 序号）、人数 / 存活、状态（§4.4）、当前指令、冷却剩余。数字键 1–9 选中对应行（Shift 加选）。
- 键（地图打开时）：G 驻守指针处（已有）/ V 跟随（已有；对未招募的小队 = 招募）/ X 释放（已有）/ **J 自由交战** / **H 集中火力（打标记目标）** / **B 上车** / **N 下车** / **K 解除招募** / **U 招募**（地图自己的镜头用了 WASD、QE、RF，所以没用 F / C / R）。手柄沿用 X/Y/RB/LB，其余只有键鼠。
- 坦克（§8）也作为地图单位：G 移动驻守点、X 回出生点；不接受跟随。
- 「前往标记点」= G：地图上指针处就是标记点（已有编队落点）。

### 6.2 指令语义（步兵）

| 指令 | 实现 |
|---|---|
| 跟随 | anchor = 玩家，战斗半径 `NpcLeash` |
| 驻守 / 前往 | anchor = 命令点（编队槽），到了在 `NpcGuardRadius` 内打 |
| 自由交战 | anchor = 当前位置，追击半径放大到 `NpcFreeRange`，打完回原地 |
| 集中火力 | 全队目标 = 标记目标（§6.3），不限 MarkInReach，移动半径 = 自由交战的 |
| 释放 | 回到原版行为（anchor 由原版决定） |

指令的领导归属：面板指令只在下达时的领导者之下有效。领导者分三类（`npc::LeadOf`）：插件自己（free / 任意人数的 NPC 小队）、招募它的玩家、任务脚本。原版会自己换领导者（玩家走近自动招募、脚本接管），换了之后旧指令（驻守点、交战区）就作废，否则面板显示「已招募」而小队却被钉在一个新领导者从没要求过的点上。队员增减（free ↔ squad）不算换领导者。

### 6.3 Q 标记（C4，P5）

- 步行、地图关着、游戏在前台时按 `NpcMarkKey`（默认 Q，0x51）：取镜头中心 `NpcMarkCone` 度内最近的敌人锁定点（与普罗透斯 `Mark` 同法），再按一次同一目标取消。HUD 画标记框。
- 所有本机自由 / 已招募单位：标记目标满足 `MarkInReach(位置, 标记, 最长武器真实射程, 指令的移动半径)` 时取它为目标；接到「集中火力」的小队无论远近都取它。实现上不改写原版目标 `h+0x1CD0`：插件的瞄准、扳机、移动已经覆盖原版输出，改写原版目标还要经过它的 weak 引用赋值函数，收益为零。
- 标记只在本机（插件状态，§2.3）；单位的开火结果按原版复制走。

### 6.4 战术编队（2026-10-08 用户：「支持战术编队，支持各种现代编队行进/战术/防御方案」）

- 纯逻辑 `src/formation.h`（离线 `tools/formation_check.cpp`）：形状（`Shape`）、每人槽位（`Offset`：编队锚点右 x、前 z 米）、世界坐标（`World`，右 = 游戏相机的水平右 (-f.z, f.x)）、行进朝向（`Track`：锚点走过 2 米才更新）、交替掩护（`Step`：两半轮流，到位或 `kBoundMost` 8 秒交换）、走不到位置时放弃（`GiveUp`：`kStuckMs` 3 秒内没接近 0.5 米则让给原版跟随 `kRestMs` 6 秒）。
- 接入 `npcai.cpp` `Drive`：在躲避、上车、后撤、躲枪线之后，**没有目标时**走 `FormationMove`；有目标时照旧去交战位置。
- **行进**（`NpcFormation`，步行键 `NpcFormationKey` T / 地图 T）：本机玩家招募的、没有地图指令的小队合成一份名单（`MarchRoster`：按小队表顺序、每队 `Members` 广度优先，只要步行的），玩家是锚点；名单每帧重建，阵亡后后面的人补位；士兵间距 `NpcFormationSpacing`（2~30 米，默认 5）。
- **防御**（`NpcGuardFormation`，地图里选中警戒中的小队按 T）：每个警戒小队自己一份（`Members`），锚点 = 警戒点，朝向 = 下令时玩家→ 警戒点（`SquadCommand` 记在 `Squad::guardFwd`）。
- 地图 T：选中的小队里警戒中的各自循环防御方案（`CycleGuardFormation`），其余（跟随玩家的）只循环一次行进编队（`CycleMarchFormation`），离线 `map_command_runtime_check` `FormationKey`。
- 不寻路：和原版之外的其他插件移动一样，直推摇杆直线走；被挡住时 `GiveUp` 把士兵交还原版跟随（原版跟随会绕路）。
- 联机：只驱动本机权威的 NPC（同 §9）；地图指令联机不可用，步行键的行进编队只影响本机玩家招募的小队。

### 6.4.1 编组（2026-10-08 用户：「支持编组」）

- 火力组就是一个独立的小队（原版跟随树，§5.1）：`SplitSquad` 按 `Members` 顺序单双号对半，奇数位的第一人当新组长、跟原小队队长的上级（招募的跟玩家、自由的没有），其余奇数位跟新组长，偶数位跟原队长——每人都显式重新 `Follow`，不会把某人的下级连带拖走；`MergeSquads` 把另一个小队的队长挂到这个队长下面（合计 ≤ `kMaxSquad` 16）。之后两组各是普通小队：面板各一行、各自的指令和编队。
- 地图键：P 分组（选中的每个小队）、L 合并（并到第一个选中的）；联机拒绝（同 §9 地图指令）。离线 `npc_core_check` 用假的跟随树核对重挂关系。

### 6.5 分散拾取道具箱（2026-10-08 用户：「一键分散拾取箱子。支持开启和禁止拾取医疗箱（因为玩家也需要这个回血，满血的时候也不会拾取）」）

- 逆向见 `docs/itembox-re.md`：箱子不是游戏对象，是 `DropItemManager`（`*(EDF+0x20B2988)`）里的链表（`+0xDE0`），类型 `+0xC0`（0 武器 1 护甲 2 小回复 3 大回复）、已拾取 `+0xC4`；原版只有带手柄对象（`+0x340`）的玩家能捡，NPC 走上去不会捡。
- 纯逻辑 `src/pickup.h`（离线 `tools/pickup_check.cpp`）：`Assign` 每次在剩下的人和箱子里取最近的一对，一人一箱、一箱一人；`Takes`：离玩家 `NpcPickupRange` 以内，武器 / 护甲谁都行，回复箱要 `NpcPickupHealth`、不联机、这名士兵没满血。
- 游戏侧 `npcai.cpp`：`NpcPickupKey`（步行）开 / 召回；`SweepFrame`（每帧一次，`Gather` 里）读箱子、拿跟随玩家的名单（同 §6.4 的 `MarchRoster`）分配；`Drive` 里在躲枪线之后、交战位置之前跑向箱子（开火照常）；`PickUp` 到 1.5 米内时：武器 / 护甲调原版 `Collect 0x2C8AC0`（拾取者 = 本机玩家、点 = 箱子自己的位置（16 字节对齐）、半径 0.05 m、回调的第 5 槽返回 false 不播特效），回复箱置 `+0xC4` 后对这名士兵调原版加耐久 `0x547870`（比例 × 最大耐久）。离线 `npc_core_check` 用假的管理器和记录器核对这几条路径。
- 结束：没有可捡的箱子、`NpcPickupSec` 到、再按一次键、玩家没了、换任务。
- 联机：武器 / 护甲走原版路径（客机由房主仲裁，同玩家自己捡）；回复箱不捡。
- 安全：`Collect`、加耐久、模型位置三个函数入口按字节核对（`InstallBoxes`），不符整项关闭；箱子的 vtable 必须是 `0x17A6C18`。

## 7. 上下车（B6、C3，P6）

- 原版没有让士兵上车的路径（脚本 `RideVehicle` 放的是 dummy，H）。插件用人物侧 `RideVehicle 0x5765E0(Human*, shared_ptr<Vehicle>* byValue, int seat)`：它自己做下旧车、写 `+0x1540/+0x1548/+0x1550`、`SeatRide(force=0)`、切乘车状态；**结束时释放一个强引用**，调用前先把 ctrl+8 加 1（H）。前置：活着、`+0x39C == 0`、座位空；不查队伍 / 掩码 / 距离，所以插件自己查。
- 座位：人物掩码 `+0x31C`（Ranger 1、Wing Diver 2、Fencer 4、Air Raider 8，H）、座位 `+0x30 & +0x34`（M）。只选空的、掩码相容的座位。士兵**不占 0 号座**：真士兵当驾驶员时它每帧会清自己座位的输入（`0x573A7C`），原版车辆 AI 的输出可能被抹掉（H/M），而插件没有给每种车写驾驶器。0 号座空着就交给 AutoCrew 的 dummy。
- 炮手：士兵坐的炮位由插件在 slot 55 前置步骤里调原版 `0x65F6F0(veh, seatIdx, target)`（瞄准写右摇杆、按射程和视线开火，H），目标取该车附近最近的敌人或标记。原版只对 0 号座调它，所以这一步是让 NPC 炮手真的会打（B6「多人乘坐」）。
- 上车流程：B → 选最近的、有空位的友方载具（玩家坐着的优先）→ 每个队员被分一个座位 → 插件把它的移动改成走向上车点（`SeatPoint`）→ 进入原版上车距离后调 `RideVehicle`。下车 N：对每个乘车队员调 `SeatKick 0x62E1A0(veh, seat)`（消息 0x10000015，真士兵会正常落地并恢复步行，M）。
- 已核实 crew.cpp 的顶替（Bump）只处理 dummy（`Rider::dummy`），真士兵坐着的座位玩家顶不了（原版行为），要坐先下令下车；AutoCrew 只看 0 号座，士兵坐炮手座时照常给 0 号座派 dummy 司机。插件只对真士兵调 `SeatKick`（下车，不是死亡）。
- 单机限定。

## 8. 地面载具回位（D，P2）

### 8.1 原版（RE）

- CarBase 第 7 槽 `0x673300`：先 `0x62C120` 清所有座位 `+0x2C0..+0x2E9`，再跑 ActionTable 当前 action `0x661440`（H）。第 4 槽 → `0x673A40` → `0x673B4F` 调第 55 槽，第 55 槽当场读 0 号座摇杆（坦克 `0x67F0A9`/`0x67F14A`，Car `0x65A49F`，H）。
- 所以**在第 55 槽钩子里、原版之前写 0 号座摇杆**，原版读到的就是插件的值；每帧都要写（下一次第 7 槽会清零）（H）。dl=0（`+0x1AD0 & 1 == 0`）时坦克不读摇杆。
- `0x660490` 是走路线时的驾驶（跟随导航代理 `+0xE10`），`0x661220` 是看门狗（§4.1）。`0x661020` 的写法：`seat+0x2C0 = −clamp(偏角 × 10/…, ±1)`（转向），`seat+0x2C4 = −油门 × …`；偏角 > 126° 时加 π、油门 −1 倒车；> 18° 原地转（H，见 §8.3 旧笔记）。
- 没有路线时，`0x6616EB` 用座位 `+0xF0/+0xF4` 调 `0x5FC6E0` 检查炮塔转动范围，**不是武器射程**；不满足时 `0x66172E` 调 `0x661020(r8b=1)` 转动车身瞄敌。`r8b=1` 跳过倒车与油门赋值，油门保持 0（`0x661132..0x6611A8`，H）。原版没有回驻守点的驾驶——被后坐力推开后不会回去。
- 出生点：第 6 槽 `0x6731C0` 把出生位置拷到 `+0x25E0`，没有路线时一直保持（M）。

### 8.2 插件

- 对象：0 号座是 dummy（插件 AutoCrew 或脚本 RideAi 都算）、vtable 第 72 槽是 `0x661440` 的车（坦克、泰坦、格雷普斯），`+0x4A8 == 0`（有路线的交还原版，§4.3）。
- 驻守点：地图指令的驻守点（`TankCommand`）> 第一次看到它时附近的 `+0x25E0`（出生点）> 第一次看到它时的位置。玩家接手、座位空置或任意时长的脚本路线都会撤销旧指令；同一对象恢复 NPC 驾驶时从当前位置重新驻守，不重新采用旧出生点。
- 偏离 > `TankPostHold` 米、且原版本帧写入的 `seat0+0x2C0/+0x2C4` 都为 0 → `ReturnToPost`：近且在身后（> 126°）倒车，否则掉头开；按原版符号写座位摇杆。原版转向 / 油门非零时完整保留，避免用目标距离猜测驾驶所有权。地图列表与下令都重新检查对象身份、死亡、座位、路线、开关、离线状态和记录新鲜度。
- 只在房主（§2.4）。开关 `TankReturnToPost`。

2. `+0x25D4` 卡住标志：`+0x1970==0` 且 |`+0x182C`| ≤ 1.19e-7 视为不动；再结合速度 < 1.0 与 `+0x74` < min(`+0x1B20`, 0.42)。
3. 有路线（`+0x4A8` 且 `+0x4D0`）→ `0x661220`：把 `+0x25E0` 设成下一点 `+0x4C0`，`0xE65A0` **把 `+0x25E0` 写进导航代理的目标**（更正：之前写反了）；60 s 看门狗（§4.1）。
4. `0x660490(veh, dl)`：dl = 有路线 + 有下一点 + 导航代理 `+0xE10` 非空（更正）。
5. 0 号座有武器：`+0x518/+0x520` 目标；开火门 `0x6616AA..0x661791`（TacticsMode `+0xE08`、交战 `+0x4A0`、攻击许可 `+0xE09`）；无路线且炮塔转动范围检查失败 → `0x661020(veh, 目标, r8b=1)` 只转车身；slot 70 `0x65F6F0(veh, 0, 目标)` 瞄准开火。
6. 驾驶输出写 0 号座摇杆块（见 §8.1）。

## 9. 联机与开关汇总

| 功能 | 在哪端算 | 怎么同步 | 联机 |
|---|---|---|---|
| 步兵移动 / 瞄准 / 换枪 / 开火（§3） | 士兵的拥有端（`!(+0x128&1)`），即原版 AI 跑的那端 | 原版士兵意图复制（`+0x1E00/+0x1E10`，M） | 开 |
| 脚本判据、移动交还（§4.2/4.3） | 同上 | 不写东西 | 开 |
| 脚本结束 → 可招募（§4.4） | 每台机器各自判（`+0x540` 不复制） | 判据只读原版状态，各机结论相同（M） | 开 |
| 队长继任 / 并队（§5.3） | 房主 | SetFollow + vslot 39（原版消息 12/13） | 开 |
| 招募 / 解除 / 冷却（§5.2/5.4） | 本机 | 无通道 | 单机 |
| 面板指令（§6） | 本机 | 无通道 | 单机（同地图指挥） |
| Q 标记（§6.3） | 本机 | 无（影响本机拥有的单位） | 开，只影响本机拥有的单位 |
| 上下车 / 炮手（§7） | 本机 | 原版乘车状态复制未核实 | 单机 |
| 坦克回位（§8） | 房主 | 原版位姿复制（dummy 驾驶员的权威问题见 online-re §3.4） | 开（房主） |

已招募小队的「玩家」是**招募它的那位玩家**（小队根队长，`IsPlayer` 对远端玩家同样成立），不是本机玩家：锚点、找目标范围、
站位的侧翼参考、低血撤退都以那位玩家为准（`ServedBy`）。客人招募的小队由房主机器上的插件驱动（士兵归房主），所以这一点在
联机里直接决定客人的小队会不会被拉向房主。远端玩家的镜头读不到：撤退的「身后」改为那位玩家背对最近威胁的一侧；
枪线回避（§3.4）只对本机玩家有，远端玩家本人仍在友军射线检查里。

ini（`[VehicleCrew]`，热加载）：`CustomNpcAi`（总开关）、`NpcFireLane`、`NpcLaneWidth`、`NpcLaneLength`、`NpcFlankDeg`、`NpcWeaponSwitch`、`NpcEngageShare`、`NpcEvade`、`NpcDangerRange`、`NpcGrabRange`、`NpcCrowd`、`NpcRollSec`、`NpcRetreatHp`、`NpcLeash`、`NpcSquadSuccession`、`NpcSquadMin`、`NpcSquadMax`、`NpcSquadJoinRange`、`NpcRecruitCooldownSec`、`NpcMarkKey`、`NpcMarkCone`、`NpcFreeRange`、`NpcGuardRadius`、`NpcBoarding`、`ScriptNpcRecruit`、`ScriptNpcSettleSec`、`TankReturnToPost`、`TankPostHold`、`TankReverseMax`。每项范围检查同其他 ini 项。

顺序与用户建议的差别及理由：

- **脚本判据提前到 P1。**P1 一上线就会改所有友军士兵的移动；如果先不识别脚本单位，护送 / 路线单位会被带离路线，`WaitAiMoveEnd` 卡关、60 s 看门狗瞬移士兵（§4.1）。所以「脚本控制期间移动交还原版」必须和步兵 AI 同时上，A 剩下的部分（面板展示、结束后转换、可招募）留在 P7。
- **坦克回位（P2）紧跟 P1**：独立、小、只碰车辆前置步骤，和小队无关。
- 其余与建议一致：继任 → 面板 → 标记 → 上下车 → 脚本接管与交还。

## 10.1 代码审查后的修正（2026-10-06）

独立审查（子代理）指出的问题与处理：

| 问题 | 处理 |
|---|---|
| 当前武器解不出（§3.5 的 M 项不成立）时，插件一直「切枪中」、扳机恒关，全体友军停火 | 当前武器未知 = 不换枪、不接管瞄准与扳机；原版扳机只做火线否决（用其武器里最大的爆炸半径）；武器表上限 6 → 16 |
| 坦克驻守点过期（玩家开走后 NPC 再接手，拉回旧点） | 0 号座不是 dummy 就作废记录；超过 2 s 没驾驶的记录从当前位置重建 |
| 已招募小队队长死后剩 1 人被并进陌生 NPC 小队 | 已招募小队只并入同样跟着玩家的小队，否则留在玩家身边 |
| 友军快照只取前 128 个，玩家可能不在里面 | 本机玩家固定放第一位；友军 512、敌人 1024 |
| Fencer 第二只手（d71）不受火线否决 | 每只手按自己 WeaponSet 拿的武器判（`h+0x1970` 数组步长 0x150，第 k 组扳机 d70+k，`0x59ACE2` / `0x59B15E`，H）；只有武器不明的那只手才按身上最大爆炸半径判。不能两手一起按最大半径清：那样手持步枪也会因为背着火箭筒而不开火 |
| 对 500 ms 前计数的小队下令（队长可能已死） | 下令要求 100 ms 内计数过，并重核对象、死亡、士兵类 |
| 队长不是士兵类时小队状态错误 | 链顶只走到士兵类；小队状态每帧从顶端士兵的字段读，不依赖顶端自己的 Think |
| 冷却期内队长阵亡 / 关掉 AI | 继任时小队表项（指令、冷却、脚本观察）迁到新队长，冷却期内新队长 `+0x540` 也清；关掉 `CustomNpcAi` 后顶端士兵下一帧恢复 `+0x540`；60 s 没计数的冷却表项可复用 |
| 驻守在半径内仍被原版跟随拉走 | 驻守时半径内站住 |
| 低血后撤每帧最多 5 次射线 | 后撤点每秒重算一次 |
| 炮手无目标时传空指针；标记可能是上一帧的 | 无目标不调用；标记只用本帧列表 |
| `NpcBoarding=0` 时 B 仍有效 | 上 / 下车指令检查开关 |
| 关掉 `NpcFireLane` 后后撤方向错 | 玩家视线与枪线开关分开取 |
| `Wrap` 遇到 inf / 大数会死循环 | 改用 `std::remainder`，非有限值取 0 |
| 只被转过身的小队被当成「脚本放手」 | 脚本观察只看路线与 FixAiPosition |
| mapcmd `Publish` 持锁读游戏内存 | 先在锁外拷位置与小队行 |
| 炮手与回位共用故障计数 | 分开（`npc gunners`） |
| 换枪 30 帧不成就永久关闭 | 放宽到 90 帧 |
