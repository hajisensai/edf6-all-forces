# Real NPC driver mounted weapons (2026-10-08)

The previous intelligent selection path ran only for gunner seats 1 onward. Native CarBase action `0x661440` selects the driver's target and computes movement, then calls seat-fire virtual slot 70 with seat index 0 at `0x66173E`; it also calls it with a null target at `0x6617DB`. Those calls originally always read the first holder's weapon.

The plugin replaces those two six-byte indirect calls with one near call and one NOP, after checking both complete argument-setting contexts and the native aiming function signature. The wrapper retains the original virtual dispatch for players, remote copies, empty/dummy seats, unsupported functions and disabled settings. A living authoritative NPC driver uses `NpcPayloadSelect` with the native AI's exact target; the existing selected-holder helper lends the real holder during that same single native aiming call and restores the list in `__finally`. No new target scan, fake crew, movement pass, weapon creation or extra trigger-pull call is introduced.

The native `0x65F6F0` function writes aim axes (`seat+0x2D0/2D4`) and primary fire intent (`+0x2E4`); it does not write driving stick `+0x2C0/2C4`. The wrapper transfers that one intent to secondary only if selected. If every candidate is empty, outside range or unsuitable for air/ground use, native tracking still runs once and both fire intents remain zero. Native null-target calls clear prior selection. A separate driver intent record preserves the fresh AI result until normal input consumes it; invalid/expired/dead/disembarked/disabled ownership releases prior NPC intent without clearing a human's new controls.

Validation: production driver hook regression (16 assertions including both installed callsites), production payload selection (22 checks, including close cannon, long ground missile, air missile, exhaustion/range fallback), existing NPC gunner and NPC core regressions, and full VehicleCrew `/W4 /WX` build. The optional native contract test disassembles the supported installed EDF.dll to verify callsites, first-holder reads and movement-write boundaries; it does not execute gameplay. No game or installation writes, live-game or two-machine test.
