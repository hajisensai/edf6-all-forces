# NPC 机动：飞翼冲刺、剑兵冲刺 / 推进跳 / 冲跳（逆向）

EDF.dll Steam 版（TimeDateStamp `0x678CCB46`），地址均为 RVA。全部是静态逆向（`tools/edfre.py` 反汇编 + `tests/npc_mobility_native_audit.py` 在替身对象上跑原版函数），没开游戏。置信度：H 读代码确认，M 推断有旁证，L 推测。实现见 `src/npcai.cpp` 的 `Mobility` / `WingDash` / `FencerMove`，纯逻辑在 `src/npc_mobility.h`，玩家原话与实现说明见 [feedback-2026-11-21-npc-mobility.md](feedback-2026-11-21-npc-mobility.md)。

## 1 每帧顺序（H）

- 第 7 槽 Think：`0x596BAE` 清空意图块 `h+0xD50..0xD84` 再跑原版 AI；插件的包裹在它之后改写意图块（[npc-ai-design.md](npc-ai-design.md) §3.2）。
- 第 4 槽：按控制掩码 `+0x158C` 清掉不许的按键——bit 8 不在清 `d72`、bit 9 清 `d73`、bit 10 清 `d7B`/`d7C`（字，`0x573B46..0x573B66`）；再由 `0x56D350` 把本帧 `d50` 摇杆换成局部移动量 `+0x11E0`。
- 第 5 槽：飞翼 `0x5808B0`（主体 `0x5808E0`）读 `d7B`；剑兵 `0x567780` 调各兵种共用的武器组处理 `0x59ABB0`，其中 `0x59AE42` 读 `d72+k`。
- 所以插件在 Think 之后写的按键当帧就被消费，冲刺方向就是本帧写的摇杆；下一帧 Think 时已能看到结果（次数减少、`+0x5D0` 变成该状态的值）。

## 2 支撑状态 `+0x711` 与 `+0x1264`（M+，纠正旧文档）

- `0x573F7C`：`+0x711 != 2` 时 `+0x1264` 每帧加 1，`== 2` 时（超过 16 帧才）按 `+0x6F0` 写速度、调第 47 槽，然后清 0。
- 结论：`+0x711 == 2` 是着地（Havok `hkpSurfaceInfo::SUPPORTED = 2`），`+0x1264` 是**连续腾空帧数**，`== 2` 那段是落地事件。旁证：
  - [fp-render-re.md](fp-render-re.md) §17.2 实测「`+0x711` 在地面上也读到 2」；
  - 剑兵第 5 槽只在 `+0x1264 <= 0` 时回补冲刺 / 推进跳次数（见 §4.5），与「落地才回补」一致；
  - `src/crew.cpp` 的 `kHumanSupport` 注释（2 = 着地）。
- [fp-soldier-re.md](fp-soldier-re.md) §3.1 原先写反（已改）；`src/firstperson.cpp` 的 `c.grounded=h[kSupport]!=2` 按旧说法写，走路晃动因此从未生效（fp-render-re 已记，本次未改代码，待实机确认后另修）。

## 3 飞翼冲刺

### 3.1 按键（H）

- 冲刺键是 `d7B`（按下），不是 `d76`/`d77`（跳 / 飞行）。输入映射 `0x570757` 的四份拷贝把输入对象 `+0x4C1`（按下）写进 `d7B`、`+0x4C0`（按住）写进 `d7C`；写入点 `0x570855`、`0x57094A`、`0x570A80`、`0x570B43`，另外只有第 4 槽 `0x573B66` 清 0。**原版 NPC AI 从不写 `d7B`**（审计脚本扫全 `.text` 钉住这 5 处）。
- `d7C` 在士兵代码里没有读取点；冲刺只看按下那一帧。
- 键位：动作 0x27「Dash/Boost」，键盘默认左 Shift（[keyconfig-re.md](keyconfig-re.md)），手柄是 L3（游骑兵实测）。槽位与动作号的对应是推断（M）。

### 3.2 入口门槛（`0x580B06..0x580B94`，H）

全部满足才进冲刺：

1. `d7B != 0`；
2. `(+0x5D0 & 4) == 0`（不在占用动作里）；
3. `(+0x158C & 0x400) != 0`：冲刺许可位（NPC 常见掩码 `0x7FBF` 带它）；
4. `(+0x39C & ~2) == 0`：没倒地、没被抓、没在载具上；
5. `+0x2FC == 0`：不在紧急充能（过热）；
6. `0x580050(+0x2448, 状态 0x583820)` 为假：当前不在那个冲刺状态里（M）；
7. `0x590D70(h, 2)`：`(+0x5D0 & 4) == 0` 且动作锁等级 `+0x1A30 < 2`。

满足后：`+0x1588 |= 0x40`；调第 31 槽 `0x5804B0(h, +0x2380, 0)` 扣能量；`+0x1264 > 0`（腾空）进 `0x583820`，否则（着地）进 `0x583D60`（两处 `lea` 在 `0x580B66` / `0x580BCA`）。两个状态进入时都写 `+0x5D0 = 0xE39`（`0x58387B` / `0x583DBB`）。冲刺本身没有冷却字段。

### 3.3 能量（H，审计脚本在替身对象上实跑）

- 当前能量 `+0x308`，上限 `+0x304`，每次冲刺一次性扣 `C = +0x2380`（加载函数 `0x5806B0` 按 SGO 参数 0xC9 和能量核心算出，运行时读）。
- `0x54A2E0`：`C >= 能量` 时能量清 0 并返回旧能量；否则扣掉 `C`。`0x5804B0` 随后若 `C > 返回值` 就置 `+0x2FC = 1`（过热）。也就是：
  - 能量正好等于 `C`：清 0，不过热；
  - 能量不够：照样冲，但直接过热；
  - 已过热：`0x5804B0` 什么也不扣（入口第 5 条本来也拦住了）。
- 回充 `0x580D4C`：平时每帧加 `+0x2374`（`+0x2388` 为真时），过热时每帧加 `+0x2378`，充满才清 `+0x2FC`。两个冲刺状态退出时写 `+0x2388 = 1`。`+0x2388` 的清 0 点没找到（冲刺中是否暂停回充未定，L）。

### 3.4 方向与过程

- 方向取 `+0x11E0`（本帧摇杆，H）：`|+0x11E0|² > 0.25`（`0x583947`）才用它，否则正前方；长度设为 48（`0x583988`），x 乘 `+0x23B0`、z 前后分别乘 `+0x23B4` / `+0x23B8`（SGO 0xC8），再按 `+0x1244` 偏航转到世界写 `+0x1200` / `+0x1210`。所以插件按键那帧写满杆。
- 冲刺状态 `+0x5D0 = 0xE39`，bit 1 为 0：视角照常积分，冲刺中可以继续瞄准（H，`0x573B9F`）。能否开火没查（L）。
- 进入时 `0x590A10(h, 0, 2)`：动作锁等级 2、持有者为空；`+0x1A28` 上若有正在换枪 / 装填的武器且等级 < 2，会调它的 vslot `0xA8` 打断（M）。插件因此要求 `+0x1A28` 为空才按；持有者为空但等级 ≥ 2（这里留下的正是这种组合）时 §3.2 第 7 条 `0x590D70(h, 2)` 也会拒绝，插件同样不按（`WingLocked`）。
- 腾空态 `0x583820` 每帧速度 ×0.975，`+0x1094 > 30` 转收尾 `0x583710`（读 `d77`，可接飞行）；着地态 `0x583D60` 每帧 ×0.96，动画结束清速度回常态。位移大小与 `+0x1094` 是否为帧数都没实测（L，静态粗估约 17 m × 参数比例）。

## 4 剑兵冲刺 / 推进跳

### 4.1 输入链（H）

- `0x59AE42`（武器组循环，`r14` = 组号 k）：`d72+k` 非 0、不在载具、没死 → 该组武器 `+0x13B = 1`，`+0x1588 |= 0x100 << k`。武器 `+0x690 == 6`（盾）时另有条件（`0x59AE21`）。
- 武器更新 `0x6934F0` 只在 `+0x13B` 由 0 变 1 时调 `0x698570`：按一帧出一次，同一组要再按必须空一帧。
- `0x698570` 按 `SecondaryFire_Type`（`+0x690`，`0x6985A4`）分发：0 无，1 缩放，4 发消息 0x2003 kind 0，5 发 0x2003 kind 1，6 盾防御。
- 第 9 槽 `0x567250` 收 0x2003：`0x5672B1` 先换算——`+0x2082` 为真时 kind 1 改 0，`+0x2083` 为真时（原）kind 0 改 1；**kind 0 = 推进跳，kind 1 = 冲刺**。`+0x2041`（动作取消窗口）为真时走另一条路（`0x5673E5`），插件不在窗口里按。

### 4.2 冲刺：状态 `0x569D50`，`+0x5D0 = 0xA38`（H）

- 入口 `0x56730E`：`!(5D0 & 4)`、剩余次数 `+0x207C > 0`、若已在冲刺中还要 `+0x2080`（可连冲）、`0x590A10(h,0,2)`。
- 方向取 `+0x11E0`，长度 60，转世界写 `+0x1200` / `+0x1210`；进入时 `+0x207C` 减一（`0x569F52`）、`+0x2070 = 90` 帧、`+0x2080 = 0`；每帧速度 ×0.95；0.4 s 后锁降到 1；计时过 `+0x2074` 秒置 `+0x2080`。

### 4.3 推进跳：`0x566BE0` → 起跳 `0x569810` → 飞行 `0x569A40`（H）

- 入口：当前不在 `0x569810`、`!(5D0 & 4)`、`+0x2068 > 0`、`0x590A10(h,0,2)`；进入时 `+0x2068` 减一、`+0x2060 = 240` 帧。
- 推力 `+0x2050`：推了摇杆 = 摇杆方向水平 9 × `+0x206C`、竖直 12；没推（`|+0x11E0|²` 小于 `0x566C97` 的常量）= `(0, 25.2, 0)` 原地直上。
- 飞行入口把 `|+0x1210|` 压到 42 以内（1764 = 42²）带进空中，之后每帧 ×0.98。

### 4.4 冲跳的时序（H 代码 / M 帧数）

- `0x566BE0` 不查冲刺状态，`0xA38` 没有 bit 2；冲刺拿锁时持有者为空，`0x590A10` 见持有者相同直接放行（`0x590A4A`）。所以冲刺里任何一帧按推进跳都会被接受。
- 冲刺第 k 帧速度 60 × 0.95^k，k ≤ 6 时仍 ≥ 42（0.95^7 × 60 ≈ 41.9）。按 §1 的顺序，第 F 帧按冲刺、F 帧进入，F+1 帧插件看到次数减少；插件在 k = 2..4 帧按推进跳（`kBoostFirst..kBoostLast`），留出余量又不超过 6。前提是起跳段 `0x569810` 期间没有别的代码衰减 `+0x1210`（M）。
- 反过来，飞行状态 `5D0 = 0`，空中也能冲刺。

### 4.5 次数与回补（H）

| custom_parameter 键 | 字段 | 含义 | 合并 | 默认 |
|---|---|---|---|---|
| 300 | `+0x2078` / `+0x207C` | 冲刺次数（上限 / 剩余） | 取大 | 2 |
| 301 | `+0x2074` | 连冲间隔（秒） | 取小 | 0.5 |
| 302 | `+0x2064` / `+0x2068` | 推进跳次数 | 取大 | 2 |
| 305 | `+0x206C` | 推力 | 取大 | 1.0 |
| 306 | `+0x2083` | 推进跳改为冲刺 | — | — |
| 307 | `+0x2082` | 冲刺改为推进跳 | — | — |

- 第 82 槽 `0x567690` 遍历副武器（`h+0x1A00`）读这些键。
- 第 5 槽 `0x567780`：`+0x1264 <= 0`（着地）时，`+0x2060 == 0` 回补推进跳；不在冲刺状态且 `+0x2070 == 0` 回补冲刺。
- 原版 NPC 模板：右手 set 0，左手 set 1 是 AI 盾（type 6）。打桩机 SP 只有冲刺（AiHeavyDash01 = 4 次），SSG / SMC 只有推进跳，SC 都没有——**现有模板里没有一只手冲刺、另一只手推进跳的 NPC**，完整冲跳只在玩家给 NPC 换装（两手各一种）或换算参数生效时出现。

### 4.6 原版 NPC 的用法（H 代码 / M 条件）

- 第 91 槽 `0x566290`（`0x566699`）与第 88 槽 `0x566F90`（`0x56706C`）在目标远时**隔帧**写 `d72 = [h+0x1BF8]+4 & 1`，次数在哪儿用掉由当时的摇杆决定。插件接管的剑兵每帧先把这两只手的 `d72+k` 清 0，再自己决定（`FencerMove`）。
- 远端副本的 Think 在 `0x5670A7` 清 `d71` / `d72`；拥有方由 `0x567A00` / `0x567C10` 发包（推进跳 0x15 / 0x17，冲刺 0x14 / 0x16）。接收方处理没追（L）。

## 5 插件怎么用（`src/npcai.cpp` Mobility）

- 只对本机拥有、非脚本控制、在走路的士兵（与 Think 包裹同条件）；`Drive` 写完移动后调 `Mobility`。`MoveTo` 把本帧的目标、下一个路点和方向记进士兵表，`Evade` 记下被围时的反应。
- 飞翼：先按 §3.2 预检（含第 7 条等级 `+0x1A30 < 2`，再加 `+0x1A28` 为空），能量预算 `能量 − C ≥ max(NpcWingDashReserve × 上限, C)`（空中预留至少 0.6），所以绝不会触发清 0 或过热；理由按优先级：被围后撤（`evade`）、战斗 / 撤退 / 命令的目标点超过 `NpcWingDashFar` 且前方 15 m 通畅、不朝最近的敌人（`goal`）、跟随时超过两倍（`follow`）。按键那帧写满杆、`d7B = 1`，间隔 `NpcWingDashSec`。飞翼不再按 `d76` 侧推（那是起飞）；冲刺关掉时（全局关，或这名士兵连续未生效被单独关掉 `mobOff`）才保留旧的起跳脱离。
- 剑兵：按两只手的 `SecondaryFire_Type` 与换算标志判定能力，按距离 / 高差 / 前方障碍 / 卡住 / 剩余次数 / 附近敌人选「冲跳 / 只冲 / 只跳 / 不动」（`npc_mobility.h Choose`），冲跳的推进跳按 §4.4 的窗口。按住扳机的那只手、动作取消窗口、武器持锁（换弹）时都不按。
- 校验：每次按下后 3 帧内没看到生效（飞翼 `+0x5D0 == 0xE39`，剑兵次数减少）算一次未生效，连续 5 次就对该士兵关掉并记一行日志。签名表 `kWingDashSigs` / `kFencerMoveSigs` 在安装时逐条核对，不符只关对应功能（`NPCAI wing dash off: signature …`）。
- `Debug=1` 日志：`WDDASH <h> why=… e=…/… C=… goal=… clear=… air=… stick=(x,z)`、`WDDASH refused …`、`FENCERMOVE <h> hands: …`、`FENCERMOVE <h> <act> why=dodge|way|boost-up|boost-ledge|boost-stuck …`。
