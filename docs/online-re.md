# 联机：呼叫、生成、载具权威与位姿复制（静态逆向）

EDF.dll TimeDateStamp `0x678CCB46`，下文地址全部是 RVA。纯静态分析（`tools/edfre.py` + capstone），没有起游戏，也没有两机实测。
置信度：**H** = 指令里直接读到；**M** = 有代码证据的推断；**L** = 推测，要实机确认。
背景与计划见 `D:\APP\edf6-models\online-gunship-research.md`（本文回答它 §3 阶段 1 的四个问题）；
已知事实来自 `docs/heli-input-re.md`、`docs/decoy-blast-re.md`、`docs/airstrike-re.md`、`docs/mission-airstrike-re.md`、
`autoturret/docs/re-notes.md`。

一句话结论：**EDF6 联机不复制「生成」，只复制「输入」和「事件」**。呼叫、投送、诱饵这些对象由每台机器按同样的输入各自生成，
再用一个由父对象推导出来的网络 ID 绑在一起；载具由「座位 0 乘员所在的机器」发送位姿，其他机器一边用复制来的摇杆输入跑同一套
物理，一边把刚体平滑地拉向收到的位姿。

## 1. 远端玩家的空袭兵呼叫（RadioContact）在本机怎么走

### 1.1 发送端（呼叫者的机器）

`Weapon_RadioContact`（vtable `0x17E4FB0`）的确认态 `0x6A9270`（phase 0）：

| 步骤 | 地址 | 置信度 |
|---|---|---|
| `0x691240(weapon, 1)`：武器的操作者是不是另一台机器上的人（`owner+0x120` 的 slot 11 = `0x62D950` 问操作者，返回对象 `+8` 的 bit0）。本机玩家返回 0，再问 `0x68FDE0(weapon, 2)`（向 owner 发消息 `0x2000` 问能不能呼叫），不行就回 idle `0x6A9F90` | `0x6A92B7`..`0x6A92E3` | H |
| 联机时（`0x6910B0`：会话成员表有本机）：如果 `+0x1960`（「这次呼叫是网络收来的」）为 0，就 `+0x1930` 序号加一，构造**消息 9** 并发出：`float heading(+0x1650)`、`vec3 target(+0x1640, 12 字节)`、`u64 seed(+0xBC8)`、`u8 序号(+0x1930)`，经 `owner+0x120` 网络接口的 vfunc `+0x70` 发送 | `0x6A92ED`..`0x6A93B5` | H |
| 如果 `+0x1960` 为 1（收来的呼叫）：清零，不再转发 | `0x6A92FD`..`0x6A9306` | H |
| 本机操作者才扣一次（`0x6956C0`，推测是弹药 / 冷却）| `0x6A9511`..`0x6A953D` | H 路径 / M 含义 |
| 计时 `+0x1654` 帧后切到呼叫态 **`0x6A8B50`** | `0x6A95E4`（`lea rax, 0x6A8B50`） | H |

### 1.2 接收端（其他每一台机器上，那位玩家的武器副本）

- RadioContact **slot 30 = `0x6A8610`** 是网络消息接收：读消息类型（`0x12B4BB0`），不是 9 就交给基类 `0x6922F0`。是 9 时读
  `float`、`vec3`、`u64`、`u8 序号`；序号按 8 位回绕比较，比 `+0x1930` 新、且 `0x691240(weapon,1)` 为真（这把武器确实由别的机器操作）
  时，存进 `+0x1930`（序号）、`+0x1940`（目标）、`+0x1950`（航向）、`+0x1958`（种子），置 `+0x1960 = 1`。（H）
- 武器每帧更新 slot 5 **`0x6A8760`**：先跑基类 `0x6934F0`；联机时，若状态机（`+0x1610`）不在确认态 `0x6A9270`、也不在呼叫态
  `0x6A8B50`，并且 `+0x1960` 为 1，就把收到的值拷进 `+0x1640/+0x1650/+0xBC8`，调 `0x6A8460`，**切进确认态 `0x6A9270`**——和本机玩家
  按下呼叫后走的是同一个状态。（H，`0x6A8786`..`0x6A8821`）
- 确认态到时切进呼叫态 `0x6A8B50`；它的 phase 0 **没有任何「本机 / 远端」判断**：用 `+0xBC8` 推一步 LCG 当种子、用 `+0x1650`/`+0x1640`
  建矩阵，**直接在 `0x6A8DFB` 调 `IFC_Start 0x2B5DA0`**。（H，`0x6A8B50`..`0x6A8E19` 逐条读过）
- 其后 `IFC_Update 0x2B87A0` 在 `0x2B8DDB` `CreateObject` 轰炸机，**不调用任何网络注册函数**（`0x78xxxx` 注册族的调用者列表里没有它，见 §2.2）。（H）

### 1.3 另外两个 `IFC_Start` 调用者

- `0x6A8137` 在 `0x6A7BD0` 里——`0x6A7BD0` 是 RadioContact 的**构造函数**（`0x6A7B70` 是工厂：`new 0x1970` 后调它），这次调用只是初始化
  IFC，不是网络路径。（H）
- `0x2A9B62` 在 SmokeCandle（`0x2A9900`）里，炮击 / 载具投送的烟幕弹，与 RadioContact 无关。（H）

### 1.4 结论：情形 1（H）

原版设计就是**「复制呼叫，每台机器各自生成轰炸机」**：消息 9 带着目标、航向和 64 位种子，所有机器从同一个种子起算，生成同样的
轰炸机、投同样的弹（确定性重放）。所以远端玩家的呼叫在本机**一定会走到 `0x6A8DFB`**，`src/airstrike.cpp` 的 `RadioStartHook`
在每台装了 mod 的机器上都会触发：**每台机器各自 `LaunchCall` 出自己的一架插件飞机**（研究报告 §0.1 的情形 1）。
`RadioBomberHook`（`0x2B924E`）这时不会触发，因为 `RadioStartHook` 已经把架数清零，`IFC_Update` 不再生成轰炸机。

- 没装 mod 的机器：照常生成原版 KM6 轰炸机（同一种子，所以和呼叫者「本来会看到的」一样）。（H）
- 装了 mod 的机器：各有一架插件飞机，起点和航线由各自的插件逻辑决定，**不共享**；插件飞机的 `owner` 是那位远端玩家的人物。（H 路径 / M 后果）
- 插件飞机由 `CreateObject` 直接生成，没有注册网络身份（它的 `+0x128` 字为 0，见 §3.3），任何机器都不会为它发位姿。（M）

## 2. `0x7813A0` 不是「生成包」，载具投送也没有生成包

### 2.1 `0x7813A0` 的真实签名（H）

`0x7813A0(mgr = *(img+0x20B2AC8), weak_ptr<SceneObject>* obj, const NetId* id, int r9 = 0, byte remoteOwned)`

- 先 `0x22FCA0` 从对象取出它的 `NetworkObject`，`0x7765A0` + `0x774BD0` 把 `id` 写进去；
- 再 `0x782720(mgr, ..., obj, ..., remoteOwned, 1)` → `0x782880`：把 `NetworkObject+8` 的字设成
  **bit0 = remoteOwned（另一台机器的），bit1 = !remoteOwned（本机的）**（`0x782945`..`0x782976`），挂进网络对象表。只有在房间里
  （`0x7828C6` 读到房间对象）才做。
- 参数里**没有 SGO 路径、类 ID、矩阵或 InitParam**。对象本身由调用者在本机 `CreateObject` 出来，`0x7813A0` 只是给它一个网络身份。

调用者只有 3 处（H）：诱饵生成 `0x29E780` 的 `0x29EC34` / `0x29F418`，以及 `0x2A1560` 的 `0x2A1B87`。诱饵那处的 `id` 来自
`0x763CD0(&id, bullet+0x120)`：父子弹 NetworkObject 的身份（`vfunc+8` → `0x785050`，再拆出一个 16 位低字节和 24 位计数），
`remoteOwned` = 父对象 `+0x128 & 1`，和 InitParam `+0x30` 是同一个值。

### 2.2 网络注册族（H 地址 / M 用途）

同一模式的注册函数共有一组（都调 `0x774BD0` 写 ID、`0x782720`/`0x782880` 入表）：

| 函数 | 调用者（节选） | 用途 |
|---|---|---|
| `0x7813A0` | 诱饵、`0x2A1560` | 子弹派生对象，`remoteOwned` 由调用者给 |
| **`0x781950`** | 烟幕弹 `0x2A7820`、`0x2AA260`；**Transporter508 slot 50 `0x5E5070`（生成集装箱）**；**集装箱卸车态 `0x5E8C00`（生成载具）**；Transporter_Formation slot 50 `0x5EA6C0` | 载具投送链。`remoteOwned = !IsHost`（`0x781A0C`..`0x781A16`），即**房主是注册拥有者** |
| `0x781630` | `0x324290`、`0x37DAB0`、`0x4C79C0` 等十余处 | 敌人 / 生物类（未细查） |
| `0x7834F0` | `0x1DE348`、`0x215120`、`0x216E90` 等 | 任务脚本生成（未细查） |
| `0x781C40`、`0x782280`、`0x782F70`、`0x7832F0`、`0x783790`、`0x7803C0` | 各 1–3 处 | 未细查 |

`0x784210` = **IsHost**：不在房间时返回 1；在房间时比较房间对象 `+0x20`（本机成员）和房间 `+0x30 → +0x18`（房主）（`0x734F00`）。（H 代码 / M 语义）

### 2.3 载具投送：每台机器各自生成，再用派生 ID 绑定（H 代码 / M 结论）

- 烟幕弹 `SmokeCandleBullet01` 的 `0x2A7820`：无条件 `CreateObject`（`0x2A7AD6`）运输机、`SetTeam`；在房间里（`0x7859A0`）
  时用 `0x784A10()` 和弹体字段推导 ID（`0x776790`），`0x781950` 注册。
- Transporter508 slot 50 `0x5E5070`：`CreateObject`（`0x5E5260`）集装箱；联机时（`0x7748F0`）`0x781950` 注册（`0x5E5406`）。
- 集装箱卸车态 `0x5E8C00`（由 `0x5E84D0` 切入，`0x5E5D3D` 调用）：**无条件**按集装箱 `+0xB80` 里的 SGO 路径 `CreateObject` 载具
  （`0x5E8FDC`），`SetTeam(veh, 5, 1)`，`veh+0x67C = container+0xBA0`，经载具 vfunc `+0x170` 交给它装备 / 设置；联机时
  （`0x7748F0`）调 `0x54EDB0`，用 `0x776790(&id, 父对象, container+0xC30 计数)` 推导 ID（`+0xC` 类型 = 5），**`0x781950` 注册**（`0x5E92B8`），
  然后删掉集装箱自己（`0x118A1B0`）。
- 所以投送来的车不是「房主生成、发生成包、客机照包生成」，而是**每台机器都跑同一条投送链、各自 `CreateObject` 同一个 SGO，用同一个派生
  ID 把它们认作同一个网络对象**。前提是每台机器上都有那颗烟幕弹（子弹由 `NetworkBullet` 复制，M）和那个 SGO 文件（两边装同一个 mod）。
- **注册拥有者是房主**：房主机器上载具 `+0x128` 字 = 2（bit1），客机上 = 1（bit0）。但这一位只在 `veh+0x1A & 8` 的载具上决定运行权
  （§3.1 第一行）；直升机的位姿发送看的是座位 0 的乘员。

问题 2 的答案：载具请求的投送（Weapon_Sub → SmokeCandleBullet01 → Transporter508 → 集装箱 → 载具）**不经过 `0x7813A0`**，走的是同族的
`0x781950`；整个链路里**没有带 SGO / 矩阵的生成包**，远端也没有「收包后 CreateObject」的接收端——接收端就是远端自己跑的那条投送链。

## 3. 载具的网络权威

### 3.1 「谁在运行这台载具」：`0x630F90(veh, bool hostFallback, bool preferSeat0)`（H）

返回 0 = 没人，1 = 本机，2 = 别的机器。按顺序：

1. `veh+0x1A & 8`（某类载具标志，未细查）→ 返回 `(veh+0x128 & 1) + 1`，即注册拥有者（§2.3）。
2. 遍历座位，找第一个有活乘员（`seat+0x268` 计数 > 0）的座位；`preferSeat0` 时只认座位 0 的乘员：是 → 返回 `(rider+0x128 & 1) + 1`；
   找到的不是座位 0 → 返回 2。
3. 一个乘员都没有 → 座位 0 的 **`+0x300` 对象**（weak，ctrl `+0x308`）：上车时由 `0x6313F0` 写入的「最近一位乘员」（`0x633FE0` 上车路径
   `0x63419F` 调它，`+0x310 = +0x330 = 1`），下车后只要那个人还活着就一直保留 → 返回 `(它+0x128 & 1) + 1`。
4. 还没有 → `hostFallback` 时房主为 1、其余为 2；否则 0。

### 3.2 `0x630DF0(veh, int seat, int role, int mode, bool wantLocal)`（H）

- 不在会话（`0x7748F0` 为假）：直接返回 `wantLocal`（单机永远「是本机」）。
- `role != 0` 时先核对座位角色，`mode != 0` 时要求该座位有活乘员（`mode == 1`）。
- 座位 0：`local = (0x630F90(veh, 0, 1) == 1)`（**不带房主兜底**）；其他座位：`local = !(rider+0x128 & 1)`，没人时为 0。
- 返回 `local == wantLocal`。

用法：复制写 slot 7 用 `0x630DF0(veh,0,0,0,1)`（座位 0 是本机的才发位姿）；直升机 slot 51 用 `(veh,0,0,0,0)`（座位 0 不是本机的才
做远端修正）。

### 3.3 回答问题 3

- **权威 = 座位 0（驾驶员）乘员所在的机器**（H）。驾驶员换人，权威**立即跟着换**——它不是存下来的状态，每帧按当前乘员的 `+0x128`
  bit0 现算。（H）
- 驾驶座空了：权威留在**最近一位驾驶员**（座位 0 `+0x300`）那台机器，只要那个人物对象还在。（H 代码 / M 语义）
- 驾驶座空、但有炮手：`0x630DF0` 对所有机器都判「不是本机」，**没人发位姿**，各机器的物理各跑各的。（H）
- 一个人都没坐过：同上，没人发；注册拥有者（房主）只在 `veh+0x1A & 8` 的载具上起作用。（H）
- `+0x120+8` 是 `NetworkObject+8` 的标志字：bit0 = 另一台机器的，bit1 = 本机的；人物、乘员、子弹、载具都是这一套（`0x782880` 写入）。
  **从未注册**的对象（插件自己 `CreateObject` 的飞机、RideAi 放进去的 `DummyVehicleRider`）这个字为 0，bit0 为 0，即**在每台机器上都被
  当作「本机的」**。（H 写入点 / M 对插件对象的推论：`0x633030` RideAi 和它的生成路径不直接调用注册族，见 §3.4）

### 3.4 插件怎样判「我是这台载具的权威」

最省事、和原版完全一致的写法：**直接调游戏的 `0x630DF0`**（纯查询：只加减引用计数，不写任何东西）：

```cpp
using SeatLocalFn=bool(__fastcall*)(void* veh,int seat,int role,int mode,bool wantLocal);
const bool authority=reinterpret_cast<SeatLocalFn>(image+0x630DF0)(veh,0,0,0,true);   // 单机恒为 true
```

调用前确认 `veh+0x608` 座位数组非空（`0x630F90` 会读座位 0 的 `+0x268`/`+0x308`）。等价的手写版：`online = 0x7748F0()`；不在会话就是权威；
否则看座位 0 活乘员的 `+0x128 & 1 == 0`，没有乘员看座位 0 `+0x300` 对象，再没有就「不是权威」。

注意一个现有隐患（M）：`AutoCrew`（RideAi 放 NPC 驾驶员）如果在**客机**上给房主拥有的载具放了本机的 `DummyVehicleRider`，那台客机就会
认为自己是权威并开始发位姿，和真正的驾驶员 / 别的机器抢。插件的 NPC 驾驶在联机时必须只在一台机器上做（建议：房主，`0x784210`）。

## 4. 位姿复制

### 4.1 写（slot 7 `0x6559D0` → `0x655C10`，H）

掩码（slot 7 构造，`this = veh+0x120`；`[this+0x1C8]` 非零直接返回）：

| 位 | 条件 | 序列化（`0x655C10`，`r14 = veh`） |
|---|---|---|
| `1\|2` | 座位 0 本机（`0x630DF0(veh,0,0,0,1)`）**且**发送节流器 `veh+0x1D80` 到点（`0x77C1F0`） | bit1：从 Havok 刚体（`veh+0x1650 → +0x100 → +0x58 → +0x20` vfunc `+0x80`，`0x97D870` 取 4×4）取**位置**，存进 `veh+0x1D60` 并写出（`0x761B20`，vec3）；bit2：同一矩阵转**四元数**（`0x63DA0`），存 `veh+0x1D50`，写出（`0x7617B0`，压缩四元数） |
| `4` | 同上，且座位 0 有活乘员 | **座位 0 的摇杆块** `seat+0x2C0`（`0x62F740`，0x17 = 位宽标志）：驾驶员的输入本身 |
| `8` | 同上，且燃料变化（`0x5EF880`） | 燃料（`0x5EFA40`） |
| `0x10` | 节流器 `veh+0x1D94` 到点（**不要求**座位 0 本机） | 每个座位：若该座位乘员是本机的（`0x630DF0(veh,i,0,1,1)`）且瞄准器变了（`0x5FB7E0`），置一位；写出这组位，再逐个写瞄准器（`0x5FBBC0`）。即**炮手的瞄准由炮手自己的机器发** |

**没有速度**，只有位置、朝向、驾驶员摇杆、燃料、各炮位瞄准。

节流器 `0x77C1F0`（`{int 倒计时, int 间隔, int 最小, int 最大, byte 快速}`）：倒计时减到 0 时触发，间隔在「快速」位为 0 时翻倍、夹在
[最小, 最大]。`VehicleHelicopterBase::SerializeUpdateInterval`（`0x655AB0`，RTTI 里的名字）和 slot 51 每帧调 `0x77C270`：本机是驾驶员、
或 lambda_1（`0x656C30`：刚体相对上次发出的位姿动过了）为真时，间隔重置为最小值并置「快速」。**最小 / 最大间隔的数值静态没找到**
（ctor `0x64E3D0` 不写 `+0x1D84..+0x1D8C`），要实机读（§7 的 `tx=` 字段）。（结构 H / 数值 L）

### 4.2 读（slot 8 `0x6501E0`，H）

收到 `1|2`：清 `veh+0x1D74`（已收敛）和 `veh+0x1D78`（距上包帧数），读位置进 `veh+0x1D60`、四元数进 `veh+0x1D50`。收到 `4`：
`veh+0x1D7C = 0`，先清再读座位 0 摇杆块（`0x62C120`、`0x62E950`）。`8`：燃料（`0x5EF8A0`）。`0x10`：逐座位读进瞄准器（`0x5FAAE0`）。

### 4.3 远端怎样应用：每帧软拉，不外推（直升机 slot 51 `0x651F90`，H）

`0x651F90` 是 HeliBase / 506 / 409 / 410 共用的 slot 51（每帧网络步骤）。联机、没死时：

1. 两个节流器的「快速」更新（§4.1）。
2. 若座位 0 **不是**本机（`0x630DF0(veh,0,0,0,0)`）：
   - `veh+0x1D7C` 计帧：**30 帧没收到摇杆就清零座位 0 摇杆块**（`0x62C120`）。
   - `veh+0x1D74 == 0`（还没收敛）时：读当前刚体变换；`veh+0x1D78` 加一；混合权重 `w = veh+0x1D70`：前 15 帧每帧 `-0.05`，之后每帧 `+0.05`，
     夹在 **[0.07, 1.0]**——也就是收包后前 15 帧每帧向目标拉 7%，之后在约 19 帧内爬到 1.0（直接对齐）。四元数向 `+0x1D50` 插值（`0x640D0`，
     再归一化 `0x64500`），位置向 `+0x1D60` 线性插值，**直接写回刚体变换**（`0x6CE820(veh+0x1650, 矩阵)`）。
   - 收敛判据：`w` 已到 1.0，或位置误差 ≤ 0.005 m（座位 0 有人）/ 0.01 m（无人）且朝向点积 ≥ 0.999 / 0.99 → 置 `+0x1D74 = 1`，直到下一包都不再修正。
3. 座位 0 是本机：清 `+0x1D74/+0x1D78/+0x1D70`，不修正。
4. 最后 `0x62E6C0(veh, 1)`：逐座位，乘员是**别的机器的** → `0x5FBA20`（瞄准走网络），否则 `0x5FB880`（本地输入）。`mode = 1` 意味着
   直升机的**空**炮位走本地，这点和地面载具不同（autoturret 的笔记说的是地面载具）。

### 4.4 远端副本每帧跳过什么

**什么都不跳过**（H）：直升机 slot 60 `0x652630` 的 slot 55（输入）`0x6543A0`、slot 57（物理 + 武器）`0x6519A0`、slot 58 里都没有任何
`0x630DF0` / `0x7748F0` / `+0x128` 判断。远端副本照常把座位 0 的摇杆块（复制来的）拷进 `veh+0x1540..`，照常跑旋翼、姿态、积分——
**原版是「输入重放 + 位姿软修正」**：远端按驾驶员的输入自己飞，`0x651F90` 把漂移拉回来。开火由 `0x62D950` 的操作者判断（autoturret 笔记）
保证只在操作者的机器上发射。

### 4.5 VEHICLE410（布鲁特）

- 副表（`NetworkObject` 接口）逐项对比 `0..15`：HeliBase `0x17DF988`、410 `0x17DF530`、506 `0x17DB440` **完全相同**（只有 slot 0 的析构 thunk
  不同）：slot 7 `0x6559D0`、slot 8 `0x6501E0`、slot 11 `0x62D950`、slot 15 `0x654760`。409 的 slot 7/8 是自己的 `0x64C3D0`/`0x64A530`。（H）
- 主表 slot 51 都是 `0x651F90`，slot 60 都是 `0x652630`。（H）
- 410 slot 55 `0x64E080`：先调基类 `0x6543A0`，再逐个炮手座位按 `seat+0x2E4 ≥ 0.8`（`0x62DE50`）写扳机块 `veh+0x2030 + i*0x20`。扳机本身不复制；
  远端炮手坐进副本后，**他自己的机器**写扳机、`0x62D950` 认他为操作者、只在他的机器上开火，子弹由 `NetworkBullet` 复制；他的瞄准经
  掩码 `0x10` 复制给别人（§4.1）。（H 代码 / M 端到端）
- 侧门炮手座位被远端玩家占着时：座位乘员是复制来的人物（`+0x128` bit0 = 1），`0x62E6C0` 让本机这个炮位走网络瞄准 `0x5FBA20`。（H）

## 5. 对炮舰机设计的意义

1. **身份问题由原版解决**：用原版载具请求投送一台 410 底的炮舰（`EDF6VC_*.SGO`），每台机器各自生成、用派生 ID 绑成同一个网络对象。
   不需要发生成包，也不需要 `0x7813A0`。前提是**所有机器都装了同一个 SGO**（缺文件的机器会在 `CreateObject` 处崩——airstrike-re §4）。
2. **权威判据**：`0x630DF0(veh,0,0,0,1)`。玩家驾驶 → 驾驶员机器是权威；没人驾驶 → 最近的驾驶员；从没人驾驶 → 没有权威。
3. **NPC 驾驶（插件飞控）只在一台机器上放**：RideAi 的 `DummyVehicleRider` 没有网络身份、在每台机器上都算「本机」，谁放谁就自认权威。
   插件在联机时只让**房主**（`0x784210`）给炮舰放 NPC 驾驶员并跑飞控；客机不放、不写。现有的 `AutoCrew` 在客机上也会这么做——这是现有
   代码的联机隐患，炮舰之外的载具同样受影响（M，待实测）。
4. **远端副本也会跑原版直升机物理**，用的是复制来的座位 0 摇杆。所以：
   - 插件现在把飞控写进 `veh+0x1540..`（输入块）或直接写 Havok 速度（506 slot 57 `PlayerJetBodyStep`）——这些都**不会被复制**；远端只会按
     座位 0 摇杆块飞，再被软拉回来，每 15 帧以上一次的跳变会很明显。
   - **推荐**：插件的飞控输出改写成**座位 0 摇杆块**（`seat0+0x2C0..+0x2E8`），在权威机器上写；它经掩码 `4` 复制到所有机器。再让插件的
     飞行模型（固定翼也好，410 原版也好）在**每台机器**上都以座位 0 摇杆块为输入运行（远端的 slot 55 只在座位 0 有活乘员时拷摇杆；远端
     座位 0 是空的（NPC 驾驶员不复制），所以插件在远端要自己读 `seat0+0x2C0` 喂飞行模型）。这就是原版的「输入重放 + 软修正」，两边模型
     一致时修正量很小。注意远端 30 帧收不到摇杆就清零（`+0x1D7C`）。
   - 插件**不要**在非权威机器上写刚体速度去「追」位姿：`0x651F90` 每帧直接写刚体变换，两者会打架。
5. **速度**：复制里没有速度，远端不外推。固定翼 150 m/s 时，一包的延迟（未知，见 §4.1）乘速度就是可见的位置误差；软拉 7%/帧 + 15 帧后
   硬对齐，意味着收包间隔越长、拉回越突兀。**发送间隔是阶段 0 必须量的数**。
6. **侧门炮交给原版**（§4.5）：远端炮手在自己的机器上瞄准和开火，瞄准复制给驾驶员和别人，弹道由子弹复制。插件的 `DemoIndirectFire`
   炮弹（现在的 SHELLS）是本机对象，联机时只在开炮的那台机器上存在。
7. **呼叫式炮舰（现在的空袭兵呼叫）在联机里天然是 N 架**（§1.4）。要么联机时改走载具请求（问题 2 的路径），要么只在呼叫者自己的机器上
   `LaunchCall`：`RadioStartHook` 里用 `0x691240(weapon, 1)`（武器操作者是另一台机器 → 跳过插件生成、但仍把架数清零，让远端机器什么都
   不出，或者不清零让它出原版轰炸机）。这个改动小，可以先做。

## 9. 呼叫切换限制复核与恢复（2026-10-06）

`5b44144` 根据第一次客机崩溃的时间相关性，临时禁用了联机呼叫切换和任务轰炸机接管。需要区分三个结论：

- **本机选择污染远端呼叫是真实代码问题**：旧 `CallOf` 将本机 `picked` 用于所有插件呼叫，远端玩家呼叫的直升机也会变成本机所选机种。
- **任务轰炸机只在房主接管的判断已被撤回**：`cc2af6f` 记录第二份报告中客机也执行了任务轰炸机初始化，且禁用接管后仍在相同位置崩溃；该提交已经恢复 `JetMissionStrike` 的联机行为。本次保持恢复后的路径。
- **不能将机种不同直接当成该崩溃的已证实根因**：§1 的插件呼叫飞机不注册网络身份，§2 的投送载具则使用派生网络 ID。两者不能据生成数量或顺序直接类推。`cc2af6f` 后续记载的原因是房主 AutoTurret 给 NPC Titan 增加了副炮，而客机对应槽仍为空；本轮未取得原始报告和 dump，不能把历史提交描述当成新的两机实证。

本轮重新反汇编本机 `EDF.dll`（时间戳 `0x678CCB46`）：`0x630900` 从载具消息读取武器 holder 序号，检查序号小于 `vehicle+0x648` 后，从
`[vehicle+0x638] + index*0x48 + 0x10` 取武器指针，`0x630939` 直接 `mov rax,[rcx]`，没有空武器检查（H）。这能证明空槽消息路径，
并与 NPC Titan 的槽布局差异吻合，但不能单独证明本机呼叫选择导致跨机对象错配。

发送路径也有本地/网络之分（H）：HeliBase 的 NetworkObject vtable `0x17DF988`，`+0x70` 指向 `0x773B50`。
没有 `NetworkObject+0x10` 注册描述符时，它经 `0x773D65` 转到 `0x773A70`，只把消息复制进 `this+0x38` 本地队列；
有注册描述符和有效 ID 才经 `0x773CFC` 调用网络发送 `0x774DC0`。`GameObjectBase` 构造函数 `0x5456E0..0x5456E9`
将网络标志和描述符初始化为零。因此未注册飞机出现不同机种，不等于其消息会按另一台机器的生成次序配对；也不能单凭 `0x630939` 判断消息来自房主。

### 恢复后的所有权范围

`CallPick` 不再按会话状态禁用。`RadioStartHook` 从原版 `IFC_Start` 参数的 `+0` 取得这次呼叫的所有者，传入 `CallOf`；只有
`IsPlayer(owner) && !RemoteRider(owner)` 时才应用 `picked`。远端、NPC、未知所有者保持武器原定义；未标记的原版武器不被选择器转换。
本地分屏的两名玩家仍共享本机选择。恢复“按各武器原样”后，本机呼叫也回到原定义。

所有者来源由指令核实（H）：`0x6A8C47` 读取 `weapon+0x120`，随后取得引用并转换为 `GameObjectBase`，`0x6A8CC1/0x6A8CC9` 把
对象/控制块写入 `[rbp+0x20]/[rbp+0x28]`；`0x6A8DF7` 把 `&[rbp+0x20]` 作为参数传给 `IFC_Start`。后者 `0x2B5DCA..0x2B5DE8`
将参数 `+0/+8` 原样复制进 IFC 的所有者引用。

这没有新增选择同步协议：原版消息 9 仍只携带 §1 的字段，别的机器按所装备武器的原定义生成飞机。因此本次恢复的是本机选择能力与正确的作用范围，
不是“各端显示相同的自选飞机”或“联机飞行已同步”的承诺。`tests/call_pick_test.cpp` 直接执行生产选择器，覆盖在线切换及本机/远端交错呼叫。
未启动游戏，也未进行两机 E2E；安装不同载具数据造成的空槽消息问题不在此选择器修复范围内。

## 10. 联机门（W5，2026-10-06）

插件在每台机器上都对自己那份副本做同样的事；凡是结果必须只算一次、或者会和原版复制打架的，都先问 `src/online_authority.h`。判定规则是纯函数（`tests/online_authority_test.cpp` 逐条覆盖），读游戏的部分在 `src/online_authority.cpp`。除它和 NET 探针（`netprobe.cpp`，只记日志）以外，没有模块自己调 `0x7748F0` / `0x784210` / `0x630F90` / `0x630DF0`，`tests/online_gate_guard.py` 守着这一点。

### 10.1 接口

| 函数 | 含义 | 单机 |
|---|---|---|
| `InSession()`（netprobe.cpp，原有） | 在会话中；`0x7748F0` 字节对不上时按**不在会话**（单机原行为），日志 `NET session check off` | false |
| `OnlineHostOnly()` | 只该在房间里做一次的事：单机或房主 | true |
| `IsOnlineAuthority(obj)` | 这个对象上插件工作的**结果**算在本机（伤害、NPC 的决定）| true |
| `OnlineRunsHere(obj)` | 本机运行这个对象自己的模拟（飞控、驾驶）| true |
| `OnlineMaySeatNpc(veh)` / `SeatNpcRider(veh, spawned)` | 本机可以给它放 NPC 乘员；后者是插件调原版 RideAi 的唯一入口 | true |
| `OnlineShotCounts(owner, Shooter)` | 这一发插件伤害弹在本机结算（每发恰好一台机器） | true |
| `NoteLocalCopy(obj, parent)` / `SetSpawnOwner(owner)` / `CopyOwnerOfCaller(human)` | 记录插件副本归谁（呼叫者 / 投掷者 / 救援的本机玩家；载具母舰的无人机随母舰） | — |

规则（`online::Authority` / `RunsHere` / `MaySeatNpc`）：

- 注册过的载具：`0x630F90(v, 1, 1) == 1`（座位 0 乘员的机器，否则最近一位驾驶员的机器，否则房主）。
- 座位 0 是**没有网络身份**的乘员（RideAi 的 DummyVehicleRider）：只有房主是权威。客机只要放了一个，原版就会把它当成本机的（§3.3）。
- 插件自己 `CreateObject` 的对象（`+0x128` 低两位为 0）：每台机器都运行自己那份（`RunsHere`）；结果算在**生成它的那台机器的玩家**那份上（呼叫者、投掷者、救援的玩家；母舰放出的无人机随母舰），没有记录的算房主那份（`Authority`）。玩家坐在别人机器所属的副本里开火不结算：那台机器上同一架飞机的副本由 NPC 照样作战。
- 伤害（`ShotCounts`）：插件副本只看归属，谁开火都一样；注册过的载具上，本机玩家自己扣的扳机（`Shooter::localPlayer`，炮舰的玩家炮弹 / 机炮）在本机结算；载具自己的伤害（NPC 乘员、驾驶员的撞击 / 钻头 / EMC）算在载具的权威上。`tests/online_authority_test.cpp` 用两机判定表断言每种情形恰好一台结算。联机时 `localPlayer` 的弹在注册载具上把 IFC 归属（伤害信息里的攻击者）设成开火的本机玩家而不是载具（`ShooterIsAttacker` / `OnlineAttacker`）：coop 的命中权威（W3，`docs/net-re/damage.md` §9.2 #9）按攻击者的机器判定，攻击者是载具时会判给载具的运行机器，与这里的结算机器不同，整发丢失。单机和插件副本仍以载具为攻击者（击杀归属、队伍、不打自己机体照旧）。归属改成玩家后，原版子弹的自身排除只比较归属指针（`0x232AA0` 第 1 步，`core+0x9A8`；基类单个忽略对象 `+0x30` 对子弹恒为 0，`docs/bullet-pass-re.md` §3.2），不沿玩家的乘坐链排除载具，炮口在载具碰撞体里生成的弹会打中本车；所以子弹候选收集器钩子（`jet_hooks.cpp AddBodyHook`，原已为僚机穿透装上）在联机时把「归属是本机玩家、候选是他乘坐的载具（人物 `+0x1548`）」的候选排除（`SparesRide`）。爆炸不用处理：发弹单元的爆炸只伤与其队伍（`+0xD0`，取自归属 `+0x314`）敌对的对象。收集器钩子没装上时不改攻击者。
- 其他注册对象：看它自己的标志位，bit0 为 0 就是本机的。
- 会话函数字节对不上：`0x7748F0` 不对按单机；`0x784210` / `0x630F90` 不对时联机下注册对象谁都不是权威（本机记录过归属的副本照常），日志 `NET authority off`。
- `IsPlayer` 改为只认**本机**玩家（另一台机器复制过来的玩家人物带着玩家标志，`RemoteRider` 为真），所以 `Rider::player`、玩家定位（`SeePlayer`）都只指本机玩家。区分 NPC 和玩家用 `IsAnyPlayer`；「有玩家在车上，交给他」用 `AnyPlayerIn(seat)`（AutoCrew 不放 NPC、410 门炮 AI 不覆盖别人的门炮、NPC 直升机的玩家乘客模式、喷气机回收不删有人的机）。

### 10.3 没做到的，和原因

- **插件飞机 / 无人机 / 星导者生物的网络身份**：没做。注册族（`0x7813A0` / `0x781950`）只给对象挂一个 ID，ID 要由每台机器从同一个父对象推导（投送链用 `0x776790(父对象, 计数)`），而且所有机器要同时生成同一个 SGO；呼叫飞机的父对象（RadioContact 武器）的 NetworkObject、推导函数的计数来源都没静态确认，注册后 506 机体的复制（slot 7/8）、插件写 Havok 速度（`PlayerJetBodyStep` / `JetBodyStep`）和原版软拉怎样相处也没法静态判断。现在做到的是「各机从同一点、同一机种、同一种子生成」，之后各飞各的、目标各选各的。
- **投掷的无人机**：只在投掷者本机变成插件无人机，别人看到原版巡逻炸弹（README 已写明）。别的机器上那颗炸弹是复制来的子弹，不经过武器的发射钩子（`SubShotHook`），本机认不出它是插件的投掷物。
- **星导者生物**：`primer.cpp` 的随机种子取自对象地址，各机不同；它们是插件本机生成的对象，同上没有身份。
- **任务脚本放的 NPC 载具**：脚本在每台机器上各跑一遍，每台机器都放了自己的 DummyVehicleRider。插件现在只让房主替它飞 / 开，但原版自己会让每台客机也发位姿（座位 0 是「本机的」）——这是原版行为，插件改不了，要真机看 `NET auth=`。
- **客机玩家上房主 NPC 开着的车**：客机上座位 0 是空的（NPC 不复制），房主那边座位 0 被 NPC 占着，原版上车（`0x5765E0`）对占用的座位只让乘员下车然后失败。座位两边不一致的后果没有静态结论。
- **玩家驾驶直升机的鼠标飞行（`AimFly`）和悬停辅助（`PlayerAssist`）**：只在驾驶员本机生效（IsPlayer 修正后也不会再替别人的人物跑）。其他机器按复制来的原始摇杆和原版参数飞，与驾驶员机器上的飞行模型不同，靠位姿软拉对齐。座位 `+0x2B0`（手柄 / 键鼠）是否复制没确认，没法在远端照样重放。
- **AutoTurret（另一个 DLL）**：远端驾驶的载具，本机仍会转动空炮位，但开火由操作者判定（`LocalOperator`），NPC 炮手只在放它的机器上（AutoCrew 改成房主之后就是房主）。没有接入本门（它不链接 `online_authority.cpp`）。
- **原版命中判定**：§6 未知的「伤害在哪台机器结算」仍未实测。插件伤害现在只在攻击方权威机器生效；如果原版是「被打的那台机器判定」，客机驾驶的载具对房主拥有的敌人造成的插件伤害要靠 W3（命中权威）把伤害消息送到房主。

### 10.4 自制 NPC AI（PR #53–#59）怎样接入

- 「只有房主决定」：用 `OnlineHostOnly()`，不要再加 `IsRoomHost()`（p7 在 netprobe.cpp 里新加的那个和它是同一件事）。
- 「这个士兵由本机运行」：用 `IsOnlineAuthority(soldier)` / `OnlineRunsHere(soldier)`，不要自己读 `+0x128` bit0（规则相同，但没注册的对象会按房主处理）。
- 「这辆车上的 NPC 坦克 / 炮手由谁开」（npcpost.cpp 写座位 0 摇杆、`NpcGunnersInput`）：`IsOnlineAuthority(vehicle)`；座位 0 摇杆写在权威机器上本来就会经掩码 4 复制。
- 插件伤害弹走 `ShellMake` 就自动过 `OnlineShotCounts`；NPC 士兵开的算载具 / 士兵权威（`Shooter::vehicle`），只有本机玩家自己扣扳机才传 `Shooter::localPlayer`。插件新生成的对象调 `NoteLocalCopy`。
- 放 NPC 乘员一律走 `SeatNpcRider`；让 NPC 下车（`SeatKick`）也只在 `OnlineMaySeatNpc(vehicle)` 的机器上做。
- 区分「NPC 士兵 / 玩家」用 `IsAnyPlayer`：`IsPlayer` 现在只认本机玩家，p7 `npcai.cpp` 里 `!IsPlayer(o)` 当作「是 NPC」的几处（553、802、813、816 行）合并前要改成 `!IsAnyPlayer(o)`，否则房主会把客机玩家当成可招募的 NPC。
- 标记键（Q）、地图命令：本机输入。小队由房主决定时，客机玩家的标记 / 命令要么只在单机生效，要么需要一条新的联机消息，现在没有。
