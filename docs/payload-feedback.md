# Ground vehicle payload HUD and NPC selection (2026-10-08)

Ground vehicles now use the same weapon glyph strip and selected-store banner as aircraft. The entries come from the current seat's live holders, use the installed weapon names and ammunition, skip fuel/expired holders, and wrap after four cells. Vehicles without extra stores do not advertise a switch. The stock HUD capacity now agrees with the payload reader (eight arms, up to sixteen holder entries).

The previous trigger redirect was one global local-player vehicle. `payload.cpp` now records a live object identity, seat, source controls and chosen weapon per seat; authoritative NPC seats can coexist with the local player. The holder pull checks freshness, current occupant authority and continued membership of the chosen weapon. `NpcPayloadSelect` selects only loaded weapons with an actual muzzle and readable round, respecting native engagement/lock range, projectile lifetime for ballistic weapons, air/ground store roles and near-blast exclusion. Healers are not enemy weapons.

`NpcGunnersInput` invokes this API for existing CarBase gunner seats (index 1 onward). The stock driver AI remains responsible for driving seat 0; its two native aiming callsites are now wrapped to select a real mounted weapon for the same target (see `npc-driver-payload-feedback.md`). Target altitude uses the object's base position above the first map floor, rather than its elevated lock point; when the floor is unknown it does not claim the target is airborne. This is a terrain-based classification, not a complete enemy taxonomy.

Native aiming must read the selected weapon, not merely redirect the final trigger. Supported EDF.dll `0x65F74F..0x65F75A` and `0x660019..0x660024` both read `seat+0xC8 -> first holder -> weapon+0x10`. For the synchronous `0x65F6F0` call, the plugin supplies a temporary copy of the holder-pointer list whose first entry is the selected **existing** holder. It does not mutate holder identity or count, rejects nested calls and restores the list in `__finally`. The result's native primary trigger is moved to the Titan secondary trigger only when that control is selected. Secondary inputs are also reclaimed on target loss/authority change.

Validation: production `payload.cpp` runtime fixture (19 checks), extended production NPC gunner fixture (22 checks), NPC core regression, plugin `/W4 /WX` build, stock payload installer wiring check, and complete four-language HUD layout recorder. The latter includes an eight-store fixture using long weapon names. The native byte contract was read from the supported local EDF.dll; this is not an actual gameplay or two-machine test. The synchronous native call itself is substituted by a recording callback in the NPC regression.

Generator capability fixes are separate: unsupported coaxial machine-gun additions must be removed and installed SGO resources regenerated. This runtime change never creates a mount or a weapon model.
