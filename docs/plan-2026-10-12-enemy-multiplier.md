# 方案：所有敌人都按倍率增加 + 游戏内动态调倍率（2026-10-12，只出方案，未写代码）

## 用户原话

> 增加敌人改成所有敌人都会增加，并非单独的生成，并且支持动态修改刷怪倍率。先给我出方案看看

地址是 EDF.dll（`0x678CCB46`）的 RVA。H / M / L 同其它文档。

## 1. 现状：「增加敌人」现在怎么做的

「增加敌人」不在 all-forces 里，是联机修复 **EDF6Coop（hajisensai/edf-coop-stable）** 的 `[Mission] ExtraEnemies`，
代码 `multislot/src/spawn.cpp` / `spawn.h`、钩点表 `patches.h SpawnHooks()`：

| 现在的规则 | 出处 |
|---|---|
| 只在**联机且超过 4 人**时生效；单机和 ≤4 人房间完全不改 | `spawn.cpp ShouldScale`：`players > kVanillaPlayers && OnlineSession()` |
| 倍率是写死的公式：`1 + 0.2 × (人数 − 4)`，32 人封顶 ×6.6，不能调 | `ScaledEnemyCount`、`kEnemyScalePlayers = 32` |
| 只改「成群生成」的数量：`CreateObjectGroup 0x1D8B40`（`0x1D8E5F`）、`CreateAreaObject 0x1D7490`（`0x1D7A4B`）、空中航线编队 `0x1AF968`、生成器 `SetEnemyGenerator 0x1C2F97` / `SetInstantEnemyGenerator 0x1C3235`、即时区域生成 `0x1B5434` / `0x1B59C0`、时空船舱员 `0x1CAF52` | `SpawnHookHandler` |
| **脚本一个一个放的敌人（`CreateEnemy`，native `0x1AD220`）不复制**——ini 原话：「enemies a mission places one at a time are not duplicated yet」 | `EDF6MultiSlot.ini` `[Mission]` 注释 |
| 只有白名单里的 29 个类会变多（蚂蚁、蜘蛛、蜂、人形、蛙兵、龙、Nephila……）；巢、锚、运输船、蛋、Boss 一律不变，名单外的类也不变 | `kMultipliedClasses` |

所以用户感觉「只有单独的生成」/「不是所有敌人都增加」的原因有三条：①单机根本不加；②单个放置的敌人不加；③白名单外的类不加。

## 2. 关键约束：联机时敌人是怎么对齐的（决定方案能不能动态）

来自 `edf-coop-stable/docs/net-re/world.md`（H）：

- 任务脚本**在每台机器上各自执行**，每台机器自己 `CreateObject`；对象的网络 ID = **生成这条脚本语句的字节码偏移**（`0x7834F0`，key = `0x10AC6E0(vm+0x70)`），拥有者是房主。所以各机器必须**以相同顺序生成相同数量**的对象，ID 才对得上。
- 敌人派生物（蛋孵化、运输船卸货、巢穴、Boss 放出的东西）经 `0x781630` 注册，ID = (父对象身份, index, sub)，拥有者跟父对象。
- 波次推进 / 增援 / 全灭判定由**房主求值、带序号广播唤醒**（`0x21FC00` → `0x225860`，序号 `+0x4A0`，`0x7736D0` 写 `(线程键, 序号, 0, 0)`）；被唤醒的线程在每台机器本地执行生成语句。

推论：
- 倍率必须**全房间一致**，否则对象数量不同、ID 错配（Coop 现在的「全员同一设置」就是这个原因）。
- 「动态改倍率」在联机下不能各机器各自生效，必须由房主决定，并保证**每台机器从同一条生成语句开始用新倍率**。

## 3. 方案

### 3.1 放在哪个工程

- **倍率本身（钩生成）放 Coop**：钩点、按类判断、联机人数都在那里，现有测试（`tests/spawn_test.cpp`、`load_test.cpp`）可直接扩展。
- **游戏内调倍率的界面放 all-forces**（它有 HUD / M 地图界面 / 按键框架），通过已有的扩展接口（`coop_extension_api.h`，或新加一个 in-process 导出函数 `EDF6CoopSetEnemyScale`）把倍率交给 Coop。只装 Coop 的玩家用 ini + 热键，同样能调。

### 3.2 「所有敌人都增加」

1. **单机也生效**：去掉「联机且 >4 人」的门，改为 `倍率 = 人数系数 × 用户倍率`（用户倍率默认 1.0，人数系数保留原公式，可关）。
2. **单个放置的敌人也复制**：钩 `CreateEnemy` native `0x1AD220`（以及同族的 `CreateEnemy*` 变体，要逐个列：`docs/debug-spawn.md` 只核过这一个）。原对象照常生成后，再按倍率生成 `n−1` 个副本：
   - 位置：原位置周围按固定图案偏移（2–4 m，确定性，不用随机数），贴地或保持空中高度与原对象一致；
   - 队伍 / 等级 / 激活与原对象同参数（`SetTeam 0x54EE70`、`SetLevel 0x54E740`、`0x548D50`，H）；
   - **联机 ID**：副本经 `0x781630` 以「原对象的派生物」注册（index = 副本序号，sub = 固定标记），ID 可推导、拥有者跟原对象（房主）——与蛋孵化、运输船卸货是同一条原版路径，各机器绑定一致（M：要实机确认非虫类敌人走这条注册后状态复制正常）。
   - 脚本只持有原对象的句柄：「等这个敌人死」这类条件只看原对象，副本不阻止任务推进；`AllEnemyDestroy` / `TeamObjectCount` 会把副本算进去（H：按队伍计数）。
3. **类名单改成黑名单**：默认所有 team 1 的可移动敌人都乘；只排除会破坏任务的固定物（巢、锚、时空船本体、运输船、蛋、蛛网、`ShootingTarget`）和**剧情 Boss**（母体、Grandmother、Jormungand、移动要塞、BigGreyBoss……）。Boss 是否也乘做成开关（见 §6）。
4. **小数倍率不丢**：每个生成点（脚本字节码偏移 key）各一个累加器，`count × 倍率` 的小数部分累加到下次。数量 1 的单个敌人在 ×1.5 下就是「每两只多一只」。累加器只依赖脚本顺序，各机器一致。也支持 <1（减少敌人），但数量 ≥1 的组至少保留 1。

### 3.3 动态改倍率

- **界面**：all-forces 的 HUD 加一个「刷怪倍率」条（热键 +/−，或 M 地图支援栏里一行），档位 0.5 / 1 / 1.5 / 2 / 3 / 4 / 6 / 8 / 10；显示当前倍率和场上敌人数。
- **生效时机**：从**下一次生成**开始（下一波、下一个生成器注册、下一次增援）。已在场上的敌人不动。
- **可选「立即补齐」**：按一次键，把场上现存的每个可乘敌人按新旧倍率差补副本（同 §3.2 的副本路径，以「派生物」注册）。默认关，见 §6。
- **正在运行的生成器**（巢穴、`SetEnemyGenerator`）：注册时的总数已经定了；要逆向生成器对象里「剩余数量」字段，动态时按比例改写（L）。
- **联机一致**：只有房主能改；改动经扩展通道广播 `(新倍率, 生效序号)`。生效序号用**房主的脚本唤醒序号**（`+0x4A0`）：房主在广播第 S 次唤醒之前先发「从唤醒 S 起倍率 = m」，客人收到唤醒 S 时按它对应的倍率生成。两条消息走不同通道，可能乱序——客人必须在倍率消息到之前**不执行**序号 ≥S 的唤醒，这要钩客人的唤醒消费 `0x224930`（暂存唤醒，等倍率消息到）。备选（更简单，也更稳）：把倍率直接塞进唤醒消息里那两个写 0 的字段（`0x7736D0` 的后两个参数），与唤醒原子到达——前提是确认接收方不读这两个字段、旧版本收到非 0 也不出错（L，需逆向接收端）。
- 第一阶段可以先做「联机时只能在任务开始前改，任务中改只在单机生效」，把联机动态放到第二阶段。

### 3.4 上限保护

- 场上敌人数上限 `EnemyCap`（默认 1500，可调）：超过时新生成按原数量（不再乘），HUD 提示「已达上限」。理由：每台机器都要模拟全部敌人（Coop 已有的结论），倍率 ×10 的蚂蚁海会把房主帧率打穿。
- 实测记录：典型大关（例如蚁巢关、空中航母关）在 ×1 / ×3 / ×6 时的敌人数与帧时间，写进文档。

## 4. 分阶段路线

| 阶段 | 内容 | 验收 | 工作量 |
|---|---|---|---|
| P1 | 单机生效 + ini `EnemyScale=1.0` 可调 + 黑名单替代白名单 + 小数累加器（全部在 Coop `spawn.cpp`） | `spawn_test` 覆盖：单机 ×1.5 / ×3、黑名单类不乘、累加器跨两次生成；实机：测试场 + 一个正式关卡数敌人数 | 1–2 会话日 |
| P2 | 单个放置的敌人复制（钩 `CreateEnemy` 及同族 native），副本以派生物注册 | 单机：一个只用 `CreateEnemy` 放敌人的关卡，敌人数 = 原数 × 倍率；任务能正常结束；联机双机（`tests/gamenet` + 两台机器）两边敌人数、ID 一致，副本受伤 / 死亡两边同步 | 3–4 会话日（含逆向 `CreateEnemy*` 全族和派生物注册） |
| P3 | 游戏内调倍率（all-forces HUD / M 地图 + 热键），单机即时生效；联机只允许任务前改 | 录像：任务中改倍率后下一波数量变化；联机任务前改，双机一致 | 2 会话日 |
| P4 | 联机任务中动态改（唤醒序号同步或唤醒消息字段）、可选「立即补齐」、运行中生成器的剩余数量 | 双机：任务中途房主改倍率，接下来三波两边数量和 ID 一致（日志对比），不卡波次 | 3–4 会话日（逆向量最大） |

## 5. 风险

- **ID 错配**（联机最大风险）：任何一台机器多生成或少生成一个，后面的对象全部错位，表现为敌人瞬移、打不死、任务不结束。对策：倍率只由房主决定；全员版本检查（Coop 已有版本握手）；P2 的副本走派生物注册，不占用脚本 key。
- **任务逻辑**：有的关卡用「某个敌人死亡」推进剧情，副本不影响；有的用「敌人数 < N」推进，倍率大时推进变慢——这是倍率本来的含义。
- **Boss 复制**：多个 Boss 可能触发剧情脚本只认一个，另一个永远不死，任务卡住。默认不复制 Boss。
- **性能**：上限保护；房主帧率。
- **和 all-forces 其它功能的关系**：NPC 部队、地图标记、自动瞄准都枚举敌人，数量 ×10 时它们的每帧开销要实测（地图收集已有上限 4096，`camera-re.md` §8.6）。

## 6. 需要用户拍板

1. 倍率是否默认在单机也开（默认 1.0 等于不变，所以影响只在用户调了之后）？
2. Boss（母体、Grandmother、Jormungand、移动要塞等）要不要也复制？推荐默认不复制，给开关。
3. 动态改倍率是否需要「立即补齐」场上现有敌人，还是只影响之后的生成？
4. 联机任务中途改倍率的优先级：可以先只做「任务开始前改」吗？
5. 倍率上限和场上敌人上限：最大开到 ×10、场上 1500 只可以吗？
6. 「人数越多敌人越多」的原公式要保留并与用户倍率相乘，还是由用户倍率完全取代？
7. 调倍率的入口：HUD 热键、M 地图里一行，还是两者都要？
