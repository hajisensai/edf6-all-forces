> 增加第一人称，要求完美实现，支持各种战术动作，可以完全修改游戏，游戏做不到就修改。先给我出方案看看

本文只有方案。地址都是 EDF.dll（TimeDateStamp `0x678CCB46`）的 RVA。
置信度：H = 已有文档里反汇编确认过；M = 读法确定，时序或语义是推断；L = 还没逆向。

结论：**不需要从零做**。镜头钩点、FOV、瞄准链都是现成的；第一人称最难的「身体 / 武器怎么画」VR 版有可直接搬的实现（许可证允许）。真正要新做的是：第一人称的取景与手感、战术动作、以及它们对命中判定和联机的影响。

## 2. 目标定义（「完美实现」拆成可验收的条目）

1. 步行时镜头在眼睛位置，看不到自己的头和身体内壁；低头能看到自己的腿和脚（可关）。
2. 手里的武器画在合适的位置（类似 viewmodel），开火时子弹和枪口焰从枪口出，打到准星指的地方。
3. 四个兵种全部可用：游骑兵、翼人（飞行 / 背推）、空降兵（投放 / 无人机遥控）、重装（双持、冲刺、跳跃推进）。
4. 坐车 / 开飞机 / 机甲：驾驶舱或炮手视角；与现有炮塔镜头、开镜缩放兼容。
5. 战术动作：冲刺、下蹲、探身（左右）、滑铲、翻越 / 攀爬矮墙、机瞄开镜（ADS）、屏息（狙击）。
6. 第一 / 第三人称一键切换（默认 V 以外的键，V 已被自动瞄准占用），切换有平滑过渡；被击倒、翻滚、被抓（蚂蚁叼走、巨人抓取）等强制动作时自动切到第三人称或做专门处理。
7. 联机：别人看到你的下蹲 / 探身；你的第一人称不影响别人。
8. 不晕：头部晃动可调、FOV 可调（60–110°）、运动时镜头稳定。

## 4. 分阶段路线

每阶段都能单独发版，后一阶段不推翻前一阶段。

### P1：步行第一人称（核心）——约 3–4 个会话日
- 在 all-forces 插件里新建 `fpview.cpp`（镜头）+ `fpbody.cpp`（身体 / 武器），从 EDF6VR 搬头骨骼取点、隐藏身体、武器跟骨骼的代码（保留原作者署名与公共领域声明）。
- 眼睛 = 头骨骼位置 + 前移 0.08 m；朝向 = 瞄准角（`human+0x1230`），不跟头骨骼的动画晃动（可调 `HeadBob` 0–1）。
- 切换键 + 平滑过渡（0.25 s 插值眼睛位置和 FOV）；ini `FirstPerson=0/1`、`FirstPersonKey`、`FirstPersonFov`。
- 检测到 EDF6VR.dll 已加载时整个功能不启用（两边钩同一个镜头，必须二选一），日志写明。
- **验收**：四个兵种步行、开火、换武器、被击倒、复活；子弹落点 = 准星（50 m 外靶子偏差 < 0.3 m）；看不到头内部；离屏截图对比（autopilot）。

### P2：武器视图与 ADS ——约 3 个会话日
- 每类武器（步枪 / 霰弹 / 狙击 / 火箭 / 喷火 / 翼人长矛 / 重装双持……）一套握持偏移，开镜时武器移到视线中心（ADS），狙击沿用原版倍率（`weapon+0x784`）。
- 子弹出射：采用「从眼睛出、终点不变」，枪口焰仍画在武器枪口；近距离不再偏。
- 后坐与晃动：开火时视角上抬 + 回落（纯镜头，不改弹道）；屏息键压低狙击镜晃动。
- **验收**：每个兵种至少 3 把武器截图；近距离 3 m 内射击落点检查；狙击开镜无模型穿插。

### P3：载具第一人称 ——约 2 个会话日
- 驾驶座 / 炮手座直接用座位的 `カメラ１` 定位点（`camera-re.md` §3b 表），没有合适定位点的车（坦克驾驶座在车内）新加「驾驶舱点」表；与 `turretcam.cpp` 共用摆放和观察键。
- 飞机：机头前方点；直升机：驾驶舱点。机甲（Balam / Proteus / 沙扎比）：头部骨骼。
- **验收**：每类载具（坦克、泰坦、直升机、战机、机甲、骑乘物）截图，HUD（`vhud.cpp`、实体瞄具）位置对得上。

### P4：战术动作 ——约 6–8 个会话日（最大的一块）
| 动作 | 做法 | 难点 |
|---|---|---|
| 冲刺 | 按住 Shift 提高移动速度（各兵种速度字段） | 需逆向速度字段；不改体力系统（游戏无体力） |
| 下蹲 | 程序化姿势（髋下沉、膝弯，`sazabi_pose.h` 同类 IK）+ 镜头降 0.6 m + 移动速度降低 | 碰撞体高度（§3 未逆向）；如果改不了，下蹲只影响镜头和外观，**不影响被击中**——这一点要用户拍板 |
| 探身 Q/E | 镜头左右偏 0.4 m、滚转 10°，上半身骨骼侧倾；子弹从探身后的眼睛出 | 与 Q 锁定键冲突，需改键 |
| 滑铲 | 冲刺中按下蹲：给一段前向速度并保持下蹲姿势 0.8 s | 写速度的时机（参考 `vehicleram` / `physics`） |
| 翻越 / 攀爬 | 前方射线测出 0.5–1.8 m 的矮墙时按跳跃：0.4 s 内沿弧线移到墙顶 | 角色控制器会不会把人拉回 |
| 屏息 | 狙击镜晃动减小 3 s | 无 |
- 联机：下蹲 / 探身 / 滑铲是「别人要看到」的状态，经扩展通道每次变化发一条（不到 16 字节），对端用同一套程序化姿势画出来。没装插件的对端看到原版姿势（兼容，不出错）。
- **验收**：每个动作的录像；联机双机（本机测试场 + `tests/gamenet`）互看姿势。

### P5：「游戏做不到就修改」的部分（按需）
- 真正缩小碰撞体（被击中判定）、新动作的专门动画（如果程序化姿势观感不够），需要改 Havok 角色控制器参数或新做 MAB 动画——工作量和风险都最大，只在 P4 实测后确有必要时做。

## 5. 风险

- **与 EDF6VR 冲突**：两个插件钩同一镜头；靠互斥检测解决，不支持同时开。
- **晕动**：第一人称在 EDF 的高速移动（翼人飞行、重装冲刺、背推翻转）下容易晕——提供 `ViewFollowsBody=0`（VR 版同名选项）、FOV、头部晃动开关。
- **镜头穿模**：巨型敌人贴脸、狭窄建筑内；near 平面调小 + 眼睛退回头骨骼内侧。
- **HUD**：原版 HUD 的准星以第三人称为准；第一人称下准星画在屏幕中心即可，但锁定框、实体瞄具、炮塔镜头的 viewProj 都已经从真实 viewProj 取（`player_view.h`），风险低。
- **性能**：第一人称本身无额外开销；程序化姿势每帧几十个骨骼写入，可忽略。
- **联机**：只改本机镜头不影响别人；战术动作若改了碰撞体会影响伤害权威（敌人子弹由房主判定），所以 P4 默认不改碰撞体。

## 6. 工作量

P1–P3（能玩的第一人称，含载具）：约 8–9 个会话日。P4 战术动作：6–8 个会话日。P5 视实测而定。

## 7. 需要用户拍板

1. 子弹从「眼睛」出（准星准，主流 FPS）还是从「枪口」出（更真实，近距离会偏）？推荐眼睛。
2. 下蹲 / 卧倒是否必须真的缩小被击中判定（要改游戏物理，风险高、联机伤害权威在房主）？还是先只做视角和外观？
3. 第一人称切换键用哪个（V 已是自动瞄准，Q 是锁定，探身也想用 Q/E）？是否整体重排按键？
4. 被抓 / 倒地 / 翼人翻转这类强制动作：自动切第三人称，还是坚持第一人称（更晕）？
5. 能否直接搬用 EDF6VR 的第一人称代码（公共领域，许可证没问题），并在检测到 EDF6VR 时禁用本功能？
6. 战术动作里优先级：冲刺 / 下蹲 / 探身 / 滑铲 / 翻越 / ADS，先做哪几个？
