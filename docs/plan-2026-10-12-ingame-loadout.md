# 方案：在游戏里调整 NPC、载具挂载与外观（2026-10-12，只出方案，未写代码）

## 用户原话

> 调整npc、载具挂载外观等要在游戏里面，不是在游戏外调整。先给我出方案看看

## 1. 现状：现在是怎么在游戏外调的

见 `docs/feature-2026-10-09-loadout-editor.md`：

| 部分 | 现在 | 出处 |
|---|---|---|
| 编辑入口 | 安装器控制台菜单 **8**（或 7 → l），只能在游戏外运行 | `tools/installer.py manage_support(game, loadout_only=True)` |
| 唯一真相源 | `EDF6VehicleCrew.ini` `[VehicleCrew]` 的 `SupportPreset_*`（小队：兵种、人数、颜色）和 `SupportVehicle_*`（坦克主炮 HE/AP + 挂点；战机挂点） | `support_config.cpp`、`support_loadout.h ParseSupportPreset / ParseVehicleLoadout` |
| 生效方式 | 颜色和挂载**不是改内存**，而是由 Python 生成**新的 SGO 文件**：彩色士兵模板 `EDF6VC_NPC_<兵种>_<色>.SGO`、配好挂载的车 `EDF6VC_LO_<车>_<64位编码>.SGO`、挂载武器 `EDF6VC_<挂载>_<数量>.SGO` | `tools/support_loadout.py`（从 Root.cpk 读模板改字段写回） |
| 加载 | 任务开始时 `support_variants.cpp` 扫描 `Mods/OBJECT/EDF6VC_NPC_*` / `EDF6VC_LO_*` 并预载（最多 64 个） | `PreloadSupportVehicles` 同一时机，`kPreload 0x7A3780` |
| 联机 | 每个单位带 64 位变体编码（`Unit::variant`），文件名由内容决定；房主确认全员都有这个文件才用，否则按原版并写「待生成清单」，下次安装器补生成 | §1.5 |
| 游戏运行中 | 安装器只保存 ini，**提示退出游戏后再保存一次**才生成文件 | §3 第 4 条 |

**所以「必须在游戏外调」的根因**不是界面，而是：颜色和挂载靠预先生成的 SGO 文件，生成器是 Python、读 Root.cpk，并且文件要在任务开始时预载。
当初没选运行时方案的理由（文档 §1.5 末）：「SGO 要从 Root.cpk 读模板、按格式写回，战机还依赖 make_jets 的产物。把这套搬进 C++ 插件，量大且风险高。」

## 2. 目标

1. 在游戏里打开编辑界面（任务中暂停时 / M 地图里 / 任务开始前），能改：小队编组（兵种、人数、队长）、每人颜色（主 / 副色）、坦克主炮与挂点、战机挂点；之后再扩到载具颜色。
2. 改完**这一局就生效**（下一次呼叫），不用退出游戏。
3. 有预览：至少显示文字清单 + 颜色色块；理想是 3D 预览（在测试场或地图镜头里看到那个兵 / 那台车）。
4. 联机照样生效（延续 2026-10-09 用户的硬要求：「颜色和载具变体必须联机生效」）。
5. ini 仍是唯一真相源：游戏内编辑器读写同一份 ini，用同一个 C++ 解析 / 校验函数（`support_loadout.h`），游戏外的安装器菜单 8 保留。

## 3. 关键问题与三条路线

核心问题：**改了以后，对应的 SGO 文件从哪来、什么时候能用**。

### 路线 A：游戏内界面 + 后台调用现有生成器（改动最小）
- 界面在插件里；保存后插件**在后台启动安装器的无界面生成命令**（`EDF6VehicleCrew安装器.exe` 已内含 Python 和 `support_loadout.py`，加一个 `generate --quiet` 子命令即可），游戏运行时往 `Mods/OBJECT` 写新文件是安全的（文件未被加载）。
- 问题：新文件要**预载**才能 `CreateObject`。现在只在任务开始时预载。需要逆向「任务中途预载」是否安全：`kPreload 0x7A3780` 在任务进行中调用、以及 `WaitPreload` 之后才加进来的资源能否被 `CreateObject` 使用（L，最关键的未知）。
  - 如果可以：保存后几秒内生成 + 预载，**本局下一次呼叫就生效**。
  - 如果不行：本局用已经预载过的变体，新组合**下一关生效**；界面上明说。
- 联机：沿用现有 Bloom 过滤器 + 待生成清单；对端缺文件时，对端插件也在后台生成（对端知道编码就能生成同名同内容文件），不用退出游戏。

### 路线 B：运行时直接改对象（不生成文件）
- **颜色**：逆向士兵模型的换色常量——`soldier_color` 的 `change_color0/1` 解析后写到模型 / 材质的哪里，运行时改对象内存即时变色（L，未逆向；可参考 `docs/mdb-format.md` 材质段和 SGO 解析路径）。做到之后颜色无需任何文件，也能「改完立即变色」，场上已有的兵也能改。
- **挂载**：`stores.cpp InstallBuilds` 已经在运行时按武器表给载具补造挂点（H）。改成「按变体编码里的挂点列表」直接造（武器 SGO 用现有的 `EDF6VC_<挂载>_<数量>.SGO`，这些是有限集合：挂载种类 × 16 种弹数，安装时一次全部生成），就不再需要每种组合一份载具文件。
- 联机：变体编码本来就完整描述了单位（64 位），对端拿到编码就能在运行时做出同样的东西，**不再需要文件预检和待生成清单**。
- 代价：两项逆向（换色、按编码建挂点的边界：武器表项数、后坐数对、炮塔参数），是三条路线里技术上最「对」的，也是工作量最大的。

### 路线 C：把生成器移植进 C++ 插件
- 插件内读 Root.cpk、写 SGO。文档当初已否决：量大、和 Python 双份实现要一直同步。**不推荐**。

**推荐**：先 A 做界面和「下一关 / 下次呼叫生效」，同时逆向两个未知（中途预载、运行时换色）；逆向结果好就把颜色和挂载逐项迁到 B，A 的生成路径留作回退。

## 4. 界面放哪、长什么样

- 入口：
  - **M 地图**（已有 RTS 式支援栏、可点击按钮，`map_buttons.h`、`hud.cpp MapSupportBar`）：支援栏每一行旁加「编辑」按钮，点开右侧面板。用户已经习惯在 M 地图里做支援相关的事（2026-10-09 反馈）。
  - 任务开始前（任务选择 / 装备界面）要不要能改：原版装备界面是游戏自己的 UI，要往里面加东西需要逆向它的 LYT 布局（L）；推荐先只在任务中 M 地图里做，任务开始前改用「在测试场 / 第一关开局的 M 地图里改」。
- 面板内容（照游戏外编辑器的结构，鼠标和手柄都能操作）：
  - 小队：每个格子一个兵（兵种图标 + 颜色块），点格子换兵种 / 颜色（调色板 16 色 + 自定义 RGB），加 / 删格子，标队长；
  - 载具：选车 → 挂点列表（主炮 / 机炮 + 挂点 1…n），点挂点选挂载和弹数；「恢复原版」；
  - 底部：校验结果（复用 `ParseSupportPreset` / `ParseVehicleLoadout` 的错误文字），「保存」「取消」。
- 预览：P1 文字 + 色块；P3 在面板旁用地图镜头对准一个**预览生成的单位**（只本机、不入任务，参考 `debug_spawn.cpp` 的生成路径），关面板时删除；联机时不生成预览单位（避免 ID 问题），只给文字预览。
- 游戏输入：面板打开时吞掉鼠标 / 键盘（M 地图已有这套输入保持，`camera-re.md` §8.3）。

## 5. 分阶段路线

| 阶段 | 内容 | 验收 | 工作量 |
|---|---|---|---|
| P1 | M 地图里的编辑面板（小队 + 载具挂点 + 颜色），读写 ini，用 C++ 解析器校验；保存后后台调安装器生成文件；新组合**下一关生效**，已预载过的组合本局即生效 | 离线：面板布局与点击命中（同 `tools/map_buttons_check.cpp` 的方式）、ini 往返与游戏外编辑器一致；实机：改一个小队颜色 + 一辆坦克挂点，下一关呼叫看到效果 | 3–4 会话日 |
| P2 | 逆向「任务中途预载」；可行则保存后本局立即可用 | 实机：同一关内改完 → 等生成完成提示 → 呼叫即生效；连改 10 次不崩 | 2 会话日（逆向为主，结果可能是「不可行」） |
| P3 | 运行时换色（路线 B 颜色）：场上的兵也能即时改色；联机只发编码 | 实机截图：改色前后；联机双机颜色一致 | 3–4 会话日（逆向为主） |
| P4 | 运行时按编码造挂点（路线 B 挂载），取消载具变体文件 | 坦克 / 四种战机所有挂载组合的生成测试（离线 + 实机抽样）；联机双机挂点一致 | 3 会话日 |
| P5 | 3D 预览、载具颜色（需另外逆向载具换色，原版载具是否有 change_color 位还未查） | 截图 | 2–3 会话日 |

## 6. 风险

- **中途预载可能不安全**：资源管理器在任务中加新资源可能与流式加载冲突。P2 的结论决定「本局生效」能不能做；做不到时 P3/P4 的运行时方案是唯一出路。
- **联机**：路线 A 下对端缺文件仍会回退原版（现有行为）；路线 B 完成后才能真正做到「改了全房间立刻一致」。
- **游戏外编辑器**要保留且行为一致：两个编辑器都只写 ini，用同一套校验，测试里加「同一组操作两边写出同一行 ini」。
- **输入冲突**：M 地图已占用很多键；面板打开时只认鼠标点击与少数键。

## 7. 需要用户拍板

1. 入口放在 M 地图里可以吗？还是要一个单独的热键菜单（任务中任意时刻打开）？
2. 「改完立即生效」是硬要求吗？如果中途预载被证实不安全，能接受 P1 的「新组合下一关生效」作为过渡，直到运行时换色 / 建挂点（P3/P4）完成？
3. 「外观」除了 NPC 颜色，还包括什么：载具颜色 / 涂装、NPC 头盔或装备外形、载具挂载的外形？范围决定 P5 要不要做。
4. 是否需要 3D 预览？还是文字 + 色块就够？
5. 游戏外的安装器菜单 8 保留还是删掉（推荐保留，两边同一份 ini）？
