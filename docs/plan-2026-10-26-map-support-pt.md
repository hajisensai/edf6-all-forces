# 支援全部在 M 地图里用 pt 召唤（2026-10-26）

用户原话见 [feedback-2026-10-26-map-support.md](feedback-2026-10-26-map-support.md)：「所有插件支援改成m里面消耗pt召唤，空袭兵召唤的支援武器删掉。支援要有攻击警告红圈，直升机等没有红圈的可以给出路线预览图之类的」。

## 1. pt 从哪里来（逆向，EDF.dll `TimeDateStamp 0x678CCB46`）

原版空袭兵的呼叫 / 载具请求（武器 `ReloadType`（`+0x208`）= 2，菜单文本「$0pt」）每帧在 `0x693EAC..0x693F1E` 装填：

```
693EAC  mov  rax,[rsi+120h]          ; 武器的主人（士兵）
693EB3  movsxd rcx,dword [rax+314h]  ; 主人的队伍
693EBA  cmp  ecx,-1 / je ; cmp ecx,7 / jge      ; 只认 0..6 队
693EC4  mov  rdx,[0x20B2978]         ; 队伍管理器（与 heli.cpp / damagestats.cpp 的 kTeams 同一全局）
693ECB  imul rcx,rcx,38h
693ECF  mov  rax,[rdx+38h]           ; 队伍行数组，每行 0x38
693ED3  movss xmm6,[rcx+rax+30h]     ; 该队的累计得分（float）
693ED9  subss xmm0(=xmm6),[rsi+0E80h]; 减去武器上次看到的得分
693EE4  cvttss2si eax,xmm0           ; 截成整数
693EE8  cmp eax,5DCh / jbe           ; ≤1500 原样
693EEF  eax-=1500; powf(eax,0.8)+1500 ; >1500 的部分打折（0.8 在 0x176B014，powf 是 0x12DA8E2 的导入跳板）
693F18  sub [rsi+0E68h],eax          ; 从剩余装填量里扣
693F1E  movss [rsi+0E80h],xmm6       ; 记下这次的得分
```

武器生成时（`0x68FC85`、`0x69823C`）把当时的队伍得分写进 `+0xE80`。结论（H）：**pt 是“本队累计得分”每帧的增量**，同队每一把 pt 武器都按整份增量充能；谁往 `+0x30` 写分没有追到（全文扫描只找到上面这些读），所以“得分 = 本队造成的伤害”只是推断（M），写在 README 的待实机确认里。

插件的做法（`src/support_points_logic.h`，离线检查 `tests/support_points_test.cpp`）：~~每台机器一个 pt 池~~（2026-10-27 起全队共用：房主为每个队伍各记一池、读每队的得分，队员经 SPTS 通道看和花自己队那一池，`src/support_points_net.h`），每帧读队伍的得分，按原版同一公式（整数截断、>1500 打折）把增量加进池子。原版每把武器各充各的；这里所有支援共用一个池子、呼叫时扣，这是用户要的「消耗 pt 召唤」。签名（`0x693EAC` 起 27 字节、`0x693ECB` 起 14 字节）不符时不攒 pt，池子停在起始值，日志 `SUPPORT PT ... profile mismatch`。

- 每关开始 `SupportPtStart`（默认 6000：原版呼叫开局是满的），最多 `SupportPtMost`（默认 30000，最贵的天罚的两倍），所有价格乘 `SupportPtScale`（默认 1，0 = 免费）。
- 呼叫被接受时扣：离线在规划开始时扣、规划被拒 / 没生成出来退回；联机在房主受理（`Session::Submit` 里同步发出的 accepted 通知带回请求号）时扣，之后房主拒绝 / 超时 / 取消 / 中断退回，出动（active）后不再退。炮击和天罚在本机开始时扣，开不起来不扣。出击的第二波（锤与砧、引导打击）随第一波付过，不再扣；所以它也只跟着第一波真正出动才来：离线在第一波生成出来后、联机在第一波请求 active 后开始计 `then_after`，第一波被拒 / 没生成 / 超时 / 取消 / 中断（pt 退回）时第二波一并作废（`airstrike.cpp SupportFollowUpQueue / SupportFollowUpSettle`）。
- 联机请求号（`Session` 的 `nextRequest_`）在整个会话对象生命期内只增不减，换 epoch / 退出房间也不清零，pt 账本、第二波、海上救援都按请求号对账；换 epoch 或退出时本机仍在等结果的请求一律收到 interrupted（与 `Suspend` 一致），pt 退回。本机同时等结果的请求最多 `kRecentRequests`（4）个，再多 `Submit` 当场不受理（不扣 pt），保证每个请求都等得到自己的结果。
- 不够 pt 时支援栏把那一项变暗、价格标红，点了提示「pt 不足：需要 X，现有 Y」，什么也不发。

## 3. 删掉的武器行（42 行）

「空袭兵召唤的支援武器」= `tools/calls.py` 里 `brings` 为 `jets` / `helis` / `sub` / `barrage` / `ultimate` 的行（`Call.on_map`）：32 种飞行支援（守点 / 跟随、各母舰、潜水母舰、炮舰机、救护直升机、11 种出击）、9 种远程炮击、天罚。保留为武器的：载具请求（玩家喷气机、自驾飞机、喀秋莎、自行榴弹炮、钻头战车、边三轮、沙扎比、无畏舰、新载具与固定炮台……）、3 种投掷式无人机、4 把登车狙击枪、重力枪——它们是空袭兵自己拿着用的武器或载具，不是「呼叫来打一轮」的支援。

存档按行号记武器，删行会让后面的行全部前移、装着被删武器的存档在主菜单闪退。所以「删」= 原位换成卸载时用的占位行（`EDF6VC_RETIRED_<KEY>`：模板的原版行，名字标「已卸载」），行号不变：

- `tools/call_weapons.py stack` 每次安装都把这 42 行写成占位行（新表追加时也一样），不再生成它们的 SGO；旧安装留下的 `Mods/WEAPON/EDF6VC_CALL_<KEY>.SGO` 若是本工具写的（清单 + sha256 核对）在同一个事务里删掉，别人改过的保留。
- 插件（`src/airstrike.cpp Grant`，在 `0xDC550` 之前）把这些占位行的「已拥有」和 NEW 位清掉：装备界面里消失；`0xDC550` 的最后一段会把「装备着但未拥有」的槽换回 SoldierInit 默认武器（`docs/loadout-re.md` §8.3），所以存档里还装着旧呼叫武器的也不会崩，读档后那一格变回默认武器。日志 `CALLS N support call weapons are on the map's bar now: no longer owned`。
- 不做兼容层：原来接管空袭兵呼叫的钩子（`IFC_Start` 的 `RadioStartHook`、联机选择编码 `SeedSendHook` / `call_net.h`、局内 `[` `]` 切换 `CallNextKey` / `CallPrevKey` 与 `overlay.cpp`、天罚的卫星发射钩子与「原版光束」配对）全部删除；原版轰炸机、维斯塔、火卫一、卫星呼叫完全不再被插件碰。

## 4. 支援栏

- 目录（`support_call.h`）：飞行支援（`kCalls`）→ 步兵 → 地面载具 → 运输 → 直升机投送 → **炮击 ×9、天罚**（新，`kStrikes`）→ 海上救援（最后，不在栏上）。炮击和天罚不经房主规划：本机开始，自己的联机通道告诉别人（§6）。
- 栏顶显示 `支援  当前 / 上限 pt`；每行名字右边是价格（买得起琥珀色、买不起红色），买不起或本关禁止的整行变暗；悬停提示里也有价格。
- 条目从 48 增到 58，一列放不下（高 UI 缩放的窄屏更是如此），所以栏分 4 个标签页（`support_call.h SupportTab`）：航空、出击、炮击、地面，每页最多 11 行；标签在池子那行下面，点击切换（命中码 `map_buttons.h SupportTabHit`），`[` `]` 选到别的页的条目时自动切到那一页。先试过多列排布，窄屏（960 宽、1.75 倍）放不下且压住右侧面板，弃用。
- 新图标：炮击（三发落弹 + 红圈）、天罚（光柱 + 红圈）。

## 5. 攻击警告红圈与路线预览（`src/support_warning*.{h,cpp}`）

- **红圈（攻击范围）**：炮击按它自己的发射计划（`barrage_plan.h Plan`，地面取目标高度）算出每一发的落点，取包住所有落点的圆、再加每发的爆炸半径（徐进弹幕的圆心在目标前方）；天罚是风暴半径 220 m + 外圈主炮爆炸 55 m；地毯轰炸是沿航线的矩形（前后 150 m、左右 80 m，再加 20 m 爆炸）；死亡回旋是 110 m 的圈。圈贴着地形画（每个点向下打一次地图射线），红色、呼吸闪烁，圈上方写名字和剩余秒数；从开始一直显示到最后一发落地（炮击按计划的结束帧，天罚到主炮最后一圈）。
- **路线（没有固定落点的）**：飞机 / 直升机 / 母舰 / 运输 / 地面载具按房主下发的部署矩阵，从入场点画一条青色线到目标点（出击再沿航线延长到离场：喷气机 900 m、直升机扫射 450 m），末端箭头；守点的直升机在目标点画出盘旋圈（`HeliGuardRadius`），喷气机守点、地面支援画 40 m 的落点圈，导弹猎手画 300 m 的待机圈。显示 30 秒。
- **M 地图里的预览**：在支援栏点了一项、指针放在地面上时，指针处即时显示这次呼叫的红圈或路线（虚线、淡一些）；飞行支援的入场点用和真正规划同一个函数（`PreviewAirRoute`，每秒最多算 4 次）。
- 红圈和路线在 M 地图上和平时画面上都显示；每台机器各自画（炮击 / 天罚在各机开始时画，部署在各机套用房主计划时画），所以队友也看得见。

## 6. 联机

- 房间协议升到 3（`src/mod_room.h`）：旧版本找不到也进不了新房间，新版本拒绝旧房间（遵守「联机不适配旧版本」）。EDF6Coop 从导出读协议号，不用改。
- 飞行 / 地面 / 运输支援照旧走房主的支援事务（只多了一个“炮击不进房主规划”的拒绝）。
- 炮击：新通道 `BRGS`（`src/barrage_net_protocol.h`，能力位 `kExtBarrage`）。呼叫者那台机器开始炮击后广播一次「种类、目标点、航向、伤害、呼叫者的原生 ID」，各机按同一个种子算同一份计划、在自己那份呼叫者身上开火；伤害只在呼叫者机器结算（`ShellMake`）。同一条消息收到两次只开一次。中途加入的人看不到已经开始的炮击（炮击只有十几秒，没有补发）。
- 天罚：沿用原来的 `ULTS` 通道（呼叫者广播、每秒补报、中途加入追帧）。
- pt 各机各攒各的，不同步；房主不核对 pt（同版本房间，不防作弊）。

## 8. 未实机验证

- 队伍得分 `+0x30` 是否就是“本队伤害”、联机时各机读到的值是否一致（各机各攒，不影响正确性，只影响多少）。
- 占位行清掉拥有位后，存档里装着旧呼叫武器的那一格是否如静态分析所说回到默认武器；装备界面是否不再显示它们。
- 支援栏标签页在游戏里的点击与排版（离线 hud_view 已检查各分辨率下不重叠、可点）；价格文字是否和名字挤在一起。
- 红圈贴地形的效果（陡坡、屋顶上）、平时画面里远处圈的可见性、预览在指针移动时的刷新。
- 炮击联机：客机是否在同一位置同一时间看到同一组弹（计划同种子，制导火箭各机按自己看到的敌人瞄）。
- 价格手感（全部按原版 0 星 pt 或参照原版载具请求定的，没玩过）。
