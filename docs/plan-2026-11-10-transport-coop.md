# 运兵车 / 运输直升机与 NPC 协同（测试站 #45 第 4 条）设计（2026-11-10）

原话见 `docs/feedback-2026-11-10-wheel-follow.md`：「让运兵车和运输直升机与NPC一起行动。行动前会计算距离/速度，会自动选用最快方式，并且自动选用最近载具。npc不会抢载具，会自动分配」。

## 已实现（最小版本）

- **按距离分座、不抢座**：`src/ride_along.h` `Assign` + `src/npcai.cpp` `BoardInto`。一支小队上一辆车时，按角色顺序每次取最短步行距离的（队员, 空座）一对；别的小队正走向的座位保留给它（`Reserved`），不重复分配。地图 B、运输配对上车、跟随玩家随车都走这一条。离线覆盖：`tools/ride_along_check.cpp`。

## 未实现：自动选「最快方式 + 最近载具」

### 约束（来自以前的用户决定）

- 2026-10-10 用户删掉了「远距离命令自动等车」（`TransportAutoRange`）：远距离移动让小队原地等车，「站原地冷暴力我」。所以**任何方案都不能让小队站着等**：步行出发是默认，车只在「它能更早到」时才用，并且等车期间小队照样往目标走（车追上来接）。
- 不造人、不造车：只用场上已有的、有空座的友方载具（`FriendlyVehicle`、`OnlineMaySeatNpc`）。
- 联机全员同版本；方案涉及新的命令语义时升命令协议与房间协议。

### 方案

1. **估时**（纯函数，放 `src/transport_logic.h`，离线可测）：
   - 步行：`ground_navigation` 的路径长度 / 兵种步行速度（游骑兵、空降、剑兵按跑速，飞翼按飞行均速）。
   - 乘车：小队到车的步行时间（各队员到其座位的最大值）+ 车到目标前停车点（`groundStandoff` / `heliStandoff`）的行驶时间（车的极速取 `docs/vehicle-top-speed-re.md` 的齿轮表末行，直升机取其巡航速度，按 0.6 系数估实际均速）+ 下车时间（`unloadMs` 上限）。
   - 只有乘车估时 < 步行估时 × 0.7（留余量，避免来回摇摆）时才选车。
2. **选车**：候选为半径 `kBoardFar` 内、空座数 ≥ 小队人数一半、无人驾驶或由本方 NPC 驾驶的载具；按 1. 的总估时排序取最小。玩家正在驾驶的车不选（不替玩家开车）。
3. **分配（多支小队同时下令）**：先给每支小队算出各候选车的估时，再按「估时收益最大的小队先选」的贪心依次占车与座位（座位用现有 `Reserved` 保留），占满的车从后续候选中去掉。这一步替代「各自找最近的车」导致的抢车。
4. **执行**：选中车后走现有 `TransportPair` + `TransportOrder`（`transport.cpp`）：车有司机就开过来接、没司机就由小队的驾驶资格成员开；小队不原地等，继续沿路径步行，车到达 `groundReach` / `heliReach` 内再上车。上车超时（`boardMs`）或车被毁就解除配对、继续步行。
5. **界面**：M 地图命令卡加「自动运输」开关（默认关，打开后点移动 / 攻击移动才走上面的流程）；地图上把小队与所选车之间画虚线。

### 联机

- 估时与选车在小队的权威机器上算（房主运行客机玩家的小队）；配对与座位保留只在权威端存在，不发网络消息。
- 「自动运输」开关作为命令参数随移动命令下发：需要命令协议 v11 与房间协议升号（与本次的 v10 / 9 分开，届时一起升）。
