新整备界面走同一条路，不再拼原版弹窗。

## 1. 总体做法

- 一个「整备」整屏界面，四个页签：武器 / 支援编成 / 载具（机甲是载具的一种）/ 选择任务；Q / E（LB / RB）切页。
- 绘制：把 `worldmap_gpu` 的私有管线和 `worldmap_text` 的文字抽成共用的 `ui_gpu` / `ui_text`（世界地图改用它们，行为不变），
  整备界面的皮肤（标题条、底部按键提示条、棕色菱格底、银角框面板、斜切按钮、橙色光标、页签）全部用 `Painter` 画。
- 挂点：本部 `HUiHQMain` / 联机房间 `HUiRoom` 的 Draw 槽（同世界地图挂 `HUiHQMissionSelect` 槽 2 的做法），整备界面打开时整屏盖住；
  输入沿用 `room_ui.cpp` 现有的「菜单打开时挡住房间 / 本部输入」。
- 数据模型不重写：支援 / 载具 / 机甲继续用 `room_menu.h` 的模型与校验、`loadout_store` 的保存、`room_sync` 的成员配置同步。
  换掉的是「怎么显示、怎么操作」：原生弹窗链 `room_dialog.cpp` 整体由新界面替换（不保留旧路径，「旧代码不好用就替换」）。
- 入口：原生菜单项「支援战前配置」改名「整备」，打开新界面；F2 / L3+R3 保留。

## 2. 分阶段

每阶段单独可合并、离线测试齐全；实机验收项列在阶段末。

### 阶段 1　整备方案（数据层）　← 本次先做

- 一套方案 = 名字 + 支援三族 ini 键的完整取值（含「没有这个键」= 原版）+ 玩家四兵种各 6 格武器（WeaponTable 行号的**名字**，不存行号：
  行号随武器表安装变化）+ 当前兵种。
- 存在 `Mods/Plugins/EDF6VehicleCrew.presets.ini`（ASCII，原子写），最多 8 套；另记「当前方案」与「任务键 → 方案」。
- 切换方案：支援部分一次 `SaveSupportLoadouts`（方案里没有的键写空 = 删掉，保证切换后与方案完全一致）；玩家武器部分在游戏线程写
  `GS+0x6E98`（只写**已拥有**且槽位类别允许的行，否则该格不动并计数提示）。
- 纯逻辑 `src/loadout_preset.h`：解析 / 序列化 / 校验 / 由当前 ini 抓取 / 生成切换要写的键表 / 任务记忆；`tests/loadout_preset_test.cpp`。
- 进度（2026-11-24）：纯逻辑与离线测试完成（`loadout_preset` ctest，含两万步随机编辑 / 切换 / 读写回环）。
  文件读写、切换时的 `SaveSupportLoadouts` 与 `GS+0x6E98` 写入随阶段 2 的界面一起接（没有界面时没有触发点，先不写死代码）。

### 阶段 2　界面框架

- `ui_gpu` / `ui_text` 抽取（世界地图回归测试不变）；`src/armory_skin.h`（皮肤元素，纯几何：给出每个元素的矩形与颜色，可离线测）。
- `src/armory_logic.h`：页签、焦点（左列表 → 中预览 → 右详情）、方案栏、按键（键盘 / 手柄 / 鼠标命中）状态机；纯逻辑离线测。
- `src/armory.cpp`：挂 Draw、输入所有权、打开 / 关闭生命周期（画面析构、过场、子窗口时隐藏），替换 `room_dialog.cpp`。

### 阶段 3　支援编成 / 载具 / 机甲三页

- 按设计稿三栏：左单位列表、中 3D 视窗 + 行表、右字段（◀ 值 ▶）与色块。机甲在载具列表里，选中后中右两栏换成装配（4 武器槽 + 机体 + 核心）。
- 联机：页右上角标「我的呼叫 / 房主规则」（`SupportDisabled`、pt 价格只读显示）。

### 阶段 4　3D 视窗

- 4a（单模型，已有能力）：把原版 `UiHQ_3DModelView` 的显示位置 / 镜头移到设计稿的视窗里。需逆向视图的屏幕矩形与镜头（msg 7、view+0x304 等，M）。
- 4b（多模型：整队 4 人、机甲换件后的整体、载具挂载）：原版视图只能显示一个模型（§0）。候选：
  (1) 第二个及以后的视图实例（`room-3d-preview-re.md` 方案 B 的风险：构造读 GS 槽、全屏 3D 空间叠加）；
  (2) 插件自己用游戏的模型资源在私有渲染目标里画（要逆向菜单渲染器的绘制入口）。先做逆向报告再定，**不在定案前写代码**。
- 机甲换件后的外形：生成的机甲变体已有（`player_vehicle.cpp`），预览加载它的菜单 SGO 需要 `menu_preview.py` 给机甲变体生成菜单版。

### 阶段 5　武器页

- 替换 `HUiHQWeaponSelect` 的格子：系列折叠（同系列不同等级合成一行）、来源筛选（EDF6 / 5 / 4.1）、搜索、超出等级上限变灰。
- 数据：武器表（WeaponTable，含移植行）+ 拥有位（`GS+0xEB50` / 重定位后的记录，`weapon_records.h`）+ 等级上限谓词（`weapon-level-cap-re.md`）。
  系列 = 名字去掉末尾编号 / 型号后缀的规则，由生成器从武器表算好（`tools/gen_weapon_series.py` → `src/weapon_series.inc`），不在运行时猜。
- 写装备：`GS+0x6E98`（与原版 UI `0x7DD8AB` 写同一处，H）。需逆向原版换装后通知 3D 预览 / 存档脏标记的调用（msg 4 已知，H；脏标记 M）。
- 进度（2026-11-24，分支 `feat/ui-weaponpage`）：框架加了页面头部行 / 3D 预览留洞 / 页面自取按键与输入框 / 光标重定位
  （`armory_logic.h`，`armory_skin.h` 的 ClipToRect / DiamondsAround / PanelAround）；武器页纯逻辑 `weapon_page_logic.h`
  （兵种分页、槽、类别、来源、搜索、系列折叠、持有数、Lv 范围、超上限灰显、▲▼ 对比、收藏、试拿）与离线测试；
  运行时接入 `armory.cpp`（替换只读玩家页）。统一写入：GS+0x6E98 / +0x6E90 只经 `weapon_equip.cpp` 写（方案切换改走
  `SetClassSlots` / `SetClass`），消息 4 只经 `roompreview::ShowPlayerWeapon` 发。脏标记：原版确认路径上没有（M），不做。
  未做 / 未验证：全部未实机；属性对比只有等级；只能预览当前兵种；洞可能被 HQ 的顶栏 / 底栏盖住；不清 NEW 位。

### 阶段 6　选择任务页

- 世界地图已实现；本阶段只改：整备页签栏与方案栏、同地点任务聚合成一个图钉（点开在右栏列出）、右栏「本关出动」第一行选方案（任务记忆，阶段 1）。

## 3. 风险（直说）

- 阶段 4b 可能做不成「同屏多个模型」：原版渲染器是单例设计。做不成时整队预览退回「选中的那名士兵」，机甲退回「当前选中部件所在机体」，会在界面上如实标出。
- 阶段 5 改的是存档里的装备：写错会让存档装上不存在 / 未拥有的武器（原版会闪退，`CLAUDE.md`「别删存档里仍装备着的武器行」）。只写已拥有且类别匹配的行，写前写后都校验。
- 所有界面部分**只能离线测逻辑与几何**；字体、遮挡、手柄 / 鼠标手感、联机房间都要实机验收。按铁律，游戏开着时只编译不装。
