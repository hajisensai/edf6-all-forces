# 2026-11-28 方案：出击准备（整备）与世界地图的交互重设计

来源：[feedback-2026-11-28-armory-redesign.md](feedback-2026-11-28-armory-redesign.md)。设计稿：https://claude.ai/artifact/QZ1gTVxH4iBAPARdGGxC1L （私有，7 张 1920×1080 画板：01 总览、02 房间、03 武器抽屉、04 小队、05 载具 / 机甲、06 流程 / 保存 / 按键、07 世界地图）。
取代 [plan-2026-11-24-ui-rewrite.md](plan-2026-11-24-ui-rewrite.md) 的界面部分（§1 总体做法、阶段 2/3/5/6 的操作方式）。数据层（阶段 1 方案、`weapon_equip` 单一写入、`room_menu.h` 模型、`loadout_store`、`room_sync`）保留。
证据级别：H 已有代码 / 逆向证实，M 推断，L 设计选择或待验证。

## 1. 现状的问题（为什么重做）

- 三列左右钻取（列表 → 条目 → 详情），返回键要一列列退；光标在哪一列靠颜色猜。
- 保存规则有三种：武器装上即生效；小队 / 载具要保存，切页签时隐式保存；关闭时弹「保存 / 放弃 / 返回」。方案切换会丢掉没保存的修改。
- 按键分散：Q/E 切页签、Z/C 切兵种或视角、A/D 切类别、1–8 选方案、R 存方案、F 方案菜单、Tab 搜索、PgUp/PgDn 首字跳转；手柄左摇杆不能移动光标。
- 「任务」是一个页签，实际作用是跳转到地图；地图有自己的另一套页签和缩放键（LB/LT、Z/C）。
- 兵种在武器页里分「浏览」和「真换」两种，后者藏在「换成这个兵种」里；这次闪退就是从这条路进去的。
- 机甲藏在载具页的「我召唤的·机甲」里；小队预览只显示一个人。
- 底部最多 4 行红字状态栏；灰掉的武器要进详情才看得到原因。
- 世界地图：图钉显示聚堆里的任务数，选中聚堆后还要再选一次才拆开；↑↓ 按剧情顺序移动，地图跟着跳；难度在原版弹窗里选。
- 画面交接时露出原版本部 / 选关的滑入滑出动画（反馈第 2 条）。

## 2. 新的交互模型（L，按设计稿）

- **两层**：第 1 层「出击准备」一屏显示全部配置（兵种、武器槽、小队、载具 / 机甲、外观、方案、下一关）。在卡片上按 A 打开第 2 层抽屉 / 编辑页。B 永远是关掉最上面那层，关掉后光标回到原来那张卡上。
- **只有一种保存规则**：改了就生效。支援编辑在抽屉关闭时一次原子写入（`SaveSupportLoadouts`），之后后台生成模型，出击时等生成完。方案是快照：当前状态与方案不同就标「已修改」，由玩家在 Y 菜单里选「更新方案」或「另存」。不处理也不丢。每一步都能撤销。去掉 `Popup::unsaved`、页面 Dirty / Discard、「放弃了几页」的提示。
- **兵种**：一排按钮，点哪个就换成哪个（`weapon_equip` SetClass），随时能换回。去掉「浏览其他兵种」模式。
- **统一按键**（设计稿 06 表）：十字键和左摇杆都能移动光标；A 确认，B 关闭最上层，X 次要动作，Y 更多 / 方案；LB/RB 换类别或机型，LT/RT 换兵种或槽位；右摇杆转模型；≡ / Space 选关出击；键盘直接打字即搜索。底栏只显示此刻能用的 4–6 个键。
- **通知**：一行，写正在发生什么（生成进度、房主规则未到等）。错误写在出错的那一项上。
- **世界地图（重写）**：左侧任务列表是主操作面，按章节分组，列出状态和地名；↑↓ 走列表，地图自己平移过去。图钉显示任务名和状态，不显示数字；同一地点多关时展开成名字列表。右栏显示简介、难度（就地选）、出动方案和出击按钮。鼠标仍可拖动、缩放地图，点图钉也能选。B 回出击准备，地图不再有自己的页签栏。
- **画面所有权**：从进入本部 / 房间的第一帧起到出击，插件画面一直盖着。原版本部菜单、选关窗口的滑入滑出动画不露出。
- **外框重做**：用户说的「遮罩」是原版最前面那层外框（应是 `HUiMainFrame`）：「选择任务」标题条、四角圆环、四周科幻边框、底部「Enter:决定 Esc:返回 Y:变换勋章」提示条。整层隐藏，由插件的顶栏 / 底栏取代，各页共用一套，不再和插件画面互相压着。

## 3. 架构

- 保留：`room_menu.h` 数据模型与校验、`loadout_store`、`loadout_preset.h` / `armory_presets.cpp`、`weapon_equip.cpp`（GS+0x6E98 / +0x6E90 唯一写入）、`weapon_page_logic.h`（系列折叠、过滤、对比、NEW / UP 标记）、`room_sync`、`ui_gpu` / `ui_text` / `text_fit.h`、`room_preview`（含多视图）、`menu_callouts.h`（挂点投影）。
- 替换：
  - `armory_logic.h` 的三列焦点状态机 → 新 `armory_nav.h`：枢纽卡片网格 + 一层抽屉的导航与按键状态机（纯逻辑，离线测）。
  - `support_pages.h` 的行表 → 小队编队视图、载具挂点视图的纯逻辑（`squad_view_logic.h`、`hardpoint_view_logic.h`）。
  - 保存模型 → `armory_edit.h`：编辑会话、撤销栈（支援部分快照为 ini 键表，武器部分快照为 6 兵种 × 槽位行名）、方案已修改判定（与方案快照比较）。
  - `worldmap_logic.h` 的聚堆 / 拆堆、↑↓ 剧情跳转、页签条 → 列表优先的选关模型（`mission_list_logic.h`），地图镜头跟随所选任务。瓦片、投影、航线、绘制管线保留。
  - 画面交接：一个通用的「插件拥有屏幕」状态机（`screen_owner_logic.h`），HQ / 房间 / 选关共用，取代 `ar::Handoff` 和 worldmap 的 Slide / Still 门。
- 新兵种分支（`claude/zero-worldline-gear-plan-43905e`）带 6 兵种、外观页、armory_tabs.h。阶段 2 起基于它合进 main 之后的 main 来做；阶段 1 现在就能在 main 上做。

## 4. 分阶段

每阶段都有离线逻辑测试，单独可合并。实机验收攒到最后一次跑（一次启动依次采：本部进入、地图往返、房间进入、切兵种、各抽屉、出击）。

| 阶段 | 内容 | 依赖 / 逆向 |
|---|---|---|
| 0 | 两个 bug：切兵种闪退（`claude/1128-zw-preview-crash`）、交接露出原版画面（本分支） | 进行中 |
| 1 | 原版外框（`HUiMainFrame`）隐藏 + 插件顶栏 / 底栏：逆向外框的绘制入口与能否单独关掉（M，待逆向） | 阶段 0 第二项先落地；不做「隐藏失败就退回原版外框」的分支 |
| 2 | `armory_nav.h` + 枢纽总览（01）+ 统一按键 + 底栏 / 通知；旧三列页面接到抽屉里，先保证功能不丢 | 新兵种分支合入 main |
| 3 | 保存模型 `armory_edit.h`：即时生效、撤销、方案「已修改 / 更新 / 另存」；删掉保存对话框与 Dirty | 阶段 2 |
| 4 | 抽屉逐个重做：武器（03，复用 weapon_page_logic）、小队编队（04）、载具挂点图（05，挂点位置用 menu_callouts 的骨骼投影）、外观 | 阶段 2、3 |
| 5 | 房间版（02）：成员、准备状态、开始条件（取自 room_sync 闸门）、房主规则内嵌；「准备」键 | 阶段 2；联机协议如需加准备位则全员同版本 |
| 6 | 世界地图重写（07）：列表优先、图钉显示名字、地点展开列表、右栏简介、就地选难度、出动方案 | 难度写入点逆向（M）；不放敌种（用户 11-28 删掉） |

## 5. 风险与未定（直说）

- **整队同屏 3D**（04）：靠 11-24 加的 3 个额外 `UiHQ_3DModelView`，从没实机验证过。做不成就只显示所选士兵，并在界面上如实标出。
- **就地选难度**（07）：需要逆向原版难度弹窗写入的位置和确认路径。逆向出来之前保留原版难度弹窗，不做替代分支。
- **即时生效的代价**：每次支援改动都要重新生成模型。改为抽屉关闭时提交一次，生成放后台并可合并；出击等生成完，进度写在通知行。
- **原版外框**：外框在地图之后绘制（plan-2026-11-10-worldmap.md §5），压在插件画面上面。能否单独关掉、关掉后原版输入 / 提示逻辑是否受影响，还没逆向（阶段 1）。外框里的「Y:变换勋章」等功能键要在插件底栏里有对应项，不能隐藏后就丢了。
- 所有界面都只能离线测逻辑与几何。字体、遮挡、手柄 / 鼠标手感、联机房间都要实机验收。按铁律，游戏开着时只编译不装。
