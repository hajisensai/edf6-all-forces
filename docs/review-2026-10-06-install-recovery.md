# 2026-10-06 代码审查：安装恢复与配置读取

基线：`main` 的 `b69f347`。本轮检查了公共内存/补丁层、任务重置、载具输入、安装/卸载与配置读取，以下为实际复现并修复的问题；不代表穷尽全部游戏内行为。

## P2：AutoTurret 升级中断后丢失文件及说明行的归属

`autoturret/tools/build.py` 原先在写入文件后才保存 SHA。升级时清单已有旧 SHA，因此新文件落盘、清单保存失败后，重装会以“其他 MOD 修改”为由拒绝，卸载也会留下自己的文件。说明行的顺序恰好相反：清单先记录新内容，表还没写就中断时，卸载会把仍在磁盘上的旧说明误认成外部修改。

现在写入前持久化文件的旧 SHA 与 `pending_sha`、说明行的 `previous` 与新内容，成功后清除待写状态。重装及卸载都识别两端状态，首次备份保持不变；识别不依赖失败版本的生成器，也不会放行之后另一个 MOD 写入的不同内容。无新字段的旧清单仍走原兼容逻辑。

## P2：INI 节名大小写造成升级设置不可见和载荷误禁用

`tools/installer.py` 按大小写敏感的节名匹配，遇到 `[vehiclecrew]` 会另加 `[VehicleCrew]`。实际调用 `GetPrivateProfileIntW` 证明 Windows 命中第一节，读不到第二节新增的选项。`tools/make_stock_stores.py` 的相同判断还会把用户已开启的 `StockHeliStores` 当作关闭。

两处统一按不区分大小写的节名匹配；原有设置、注释、节名拼写与其他节保留。

## P2：安装检查把缺失文件误报为已安装

新安装第一次写文件就失败时，文件 SHA 和清单 SHA 都为 `None`，`check` 的直接相等比较会输出 `ours` 并返回成功。现在要求文件存在、SHA 匹配且没有待写状态；未完成的说明行也不能使检查通过。
