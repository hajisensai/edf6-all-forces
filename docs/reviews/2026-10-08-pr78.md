# PR #78 集火标记审查

审查原始 head `091e6f9`，共同基线 `363143e`；在已整合当前 main 的 `6aaa7f1` 上修复，保留 NPC 联机炮手与救护直升机治疗改动。

## 已修复问题

1. **P2：跨帧 hover 把旧地址重新当作新目标。** `MapCommandEats` 从上一帧缓存裸指针，`MapCommandFrame` 随后让 `NpcMarkEnemy` 重新取得当时的控制块。对象死亡、脚本删除、内存失效或地址复用时，旧输入仍能消费 Q 并标记替代对象。新增生产夹具在原实现有 14 项失败。现在捕获原始对象/控制块身份，在按下和派发时分别验证，并在失效内存边界局部拒绝目标。
2. **P2：长期标记没有持有身份控制块。** 原实现只复制 `ObjRef`，虽然模仿 `jet.cpp Alive` 检查强引用，却没有该模块配套的 weak 持有；对象和控制块地址都复用时仍能误认。现在 hover、按键锁存、长期标记均拥有控制块弱引用，不延长敌人实体寿命；取消、死亡、关闭地图及任务重置成对释放。计数回归覆盖最后一个 weak 恰好调用一次控制块删除槽。
3. **P2：关闭 NPC AI 后地图仍可吞标记键并创建标记。** 地图入口缺少 `Enabled` / `CustomNpcAi` 条件。现在所有标记入口及发布遵守开关；关闭时不显示 hover、不消费标记键，保存的活目标仅暂停发布。地图关闭立即撤销旧 hover、按键锁存、渲染视图与读出，保留单位选择；快速重新打开不会使用 300 ms 新鲜度窗口内的旧目标。
4. **CI 守卫过期。** `map_wired` 仍要求已删除的 NPC `KeyHeld` 文本，`npc_ai_wired` 仍提取已删除的 `MarkTick`。两个失败均已复现，现改为检查真实玩家帧入口、地图/TV 输入屏蔽、按住状态跟踪及地图关闭失效接线，定向 2/2 通过。

同时确认：标记不再因暂时不可锁定而消失；死亡、删除、过期强引用及对象复用会清除；玩家帧即使没有友军士兵也可标记或下守点指令；地图中按住 Q 关闭地图、TV 输入占用、全局禁用均不会误发步行标记。标记仅影响本机拥有的 NPC，地图指令原有单机限制未改变。
