# 支援创建、机组来源与瞄准视角反馈

基线 PR #91 (`1e6ea44`)；玩家实际安装的 DLL SHA256 为
`35AA2BEE0D64CE5ECC98EBAA355B462D30E9BB153760656148BDD93703BC5B03`。
本轮读取日志和资源，不运行游戏、不修改用户安装。

## 支援不能安排

日志 `20:54:58.401 SUPPORT soldier creation fault` 出现在首次车辆初始化期间，后续换关仍被进程级故障门拒绝。
`soldiers=1` 仅说明接口签名和安装成功，不能证明兵员已经创建。真实 Ranger 普通/队长资源及依赖齐全。

原生 `11945E0` 将输入矩阵传到 `SceneObject` 构造，`1189CB0` 使用 `MOVAPS`，要求 16 字节对齐。
网络计划中的普通 float 矩阵不保证此对齐。士兵与航空载具现在都在真正调用原生创建函数前复制到
`alignas(16)` 的本地矩阵，不修改网络包布局。真实原生构造前缀的负对照复现异常；生产边界复制后通过。
这不是完整游戏世界构造尾部验收。

首次构造/配置/预载异常原因保持到进程结束，提示区分配置关闭、未预载、构造故障，不再统称“资源不可用”。
不清除故障标志重试：异常可能中断原生 manager 计数和半构造状态，已触发故障的旧进程需要退出后重新启动。

## 载具乘员来源

- 原生 RideAi 意图或已有真实脚本 Dummy 表示地图希望有 AI 机组；保留该意图，等待适配器初始化完成再调度真实 NPC。
- 玩家普通 CreateVehicle2 召唤、仅观察到空的地图对象或路线字段不构成机组创建授权。
- 自定义电台航空支援继续通过统一兵员/载具事务、全员确认及实际登车后激活。
- 旧原生轰炸接管隐藏原版飞机并创建无人替代机，无法保证机组和携带原生指针的 BombLoad 跨端生命周期。
  现保留原生飞机的任务飞行、投弹、伤害与清理，不再替换成可登乘的无人自定义飞机；不影响统一调度的电台支援。

## 俯瞰与瞄准

本轮 C 抽动发生在稳定的 `high=1` 状态，不是上一轮开关反复接管。把真实地表落点直接用作原生相机碰撞
查询起点会产生 t=0 命中，原生 `F6760` 将眼睛挤到焦点附近，使俯角在正常值、0 和 -90 度间跳变。
仅将碰撞锚点沿原光轴向眼睛移动原生安全距离，真实弹着焦点和视线保持不变，仍执行正常相机碰撞。

Z 留给同一玩家、座位与武器真正可用的实体瞄具，自动瞄准默认改为 V。旧 INI 的 Z 冲突时使用有效 V
并显示对应提示，不改写个人配置；手柄冲突键不被第二个功能占用。只按弹种推测“有瞄具”不能保留按键。
实体瞄具、俯瞰和返回过渡期间，自动瞄准既不叠加其提示层，也不转动玩家炮轴；退出恢复原模式，不隐式切模式。
普通第三人称恢复由有效鼠标意图 `r.aim` 驱动的空心圈，与实际炮口落点分开，固定炮口/观察视角不虚画该圈。
