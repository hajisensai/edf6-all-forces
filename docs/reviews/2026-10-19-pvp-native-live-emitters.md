# 原生 PVP 持续发射体与队伍恢复

适用 Steam `EDF.dll` TimeDateStamp `0x678CCB46`。本次只修原玩家、普通支援 NPC 和载具原生 PVP 路径；受控树复用同一严格类型读写器，但保持自身独立租约。

## 原生根因

`WeaponBase+214` 是新发射的队伍来源。`69749F → 6974F8 → 69750E → 69759D` 对模式 1 且 `C34` bit 14 未停止的现存束执行保活并跳过 `6976CF` 的新弹初始化，因此只改武器 214 不会更新现存束的 `B40/894`。盾击没有普通 core，只能使用其独立 `EF0` 与 `E98/EA0` 完整来源弱身份。

全部 29 个原版 WeaponBase 主虚表共享 F20/F28 列表，不能只支持 NPC 的四个武器类。中性适配器认证每表全部 41 槽，校验完整双向列表与来源弱身份，仅输出真正保活束。普通已发弹丸即便保留在 F20 里仍保留逐发快照。

`SetTeam(54EE70)` 还会在非 -1 队伍时覆盖 318；关闭 314 为 -1 时不会同步 318，且同队伍/同登记状态可以提前返回。GunBattery2 与 RadioContact 实际读取 318，因此 314 与 318 必须独立保存、应用和恢复。

## 生命周期

- 每条真实 Weapon214/束缓存保存自身 SceneObject 完整弱身份、原始值和本次快照标识；调用方不查询尚未发布的请求状态。
- 已存在束的 B40/894 分别保存；PVP 期间新生束从该确切武器的已保存 214 基线派生，不能保存临时队伍，也不能拿 body 基线代替武器基线。
- 不再出现在保活快照的缓存独立还原并保留基线，防止同一来源重入时丢失原值。存储销毁或完整弱身份失效才退休释放。
- 恢复先处理独立存储，再读取 owner；owner/holder 死亡、脱容器或销毁不阻止存活束恢复。只读/不明状态保留完整基线与弱身份，后续重试。
- 同 owner 某缓存恢复失败时，已经恢复的武器来源基线也保留，确保协议重新应用前一状态不会误记基线。
- 原生死亡保持 314=-1；318 跟当前逻辑队伍。退出时不撤销期间发生的原生死亡或复活，分别还原逻辑侧与记忆侧。缓存原生关闭值 -1 不重开。
- 原路径遇已由 controlled-PVP 租约持有且无原路径账本的对象，跳过整份 body/cache 写集合，普通载具仍正常收集；若已有原路径账本则拒绝并保留，恢复也等待另一租约释放，避免座位 rider 重叠双写。
- 原路径与控制器共用 `enemy_control_identity.h` 的 current / gone / unknown 身份判定。只有强引用归零或可读的 control 身份替换才允许丢弃原值；对象或 control 暂不可读、逻辑场景删除但仍有强引用均保留恢复账本与支援 owner，不能回收其缓存槽。锁定点另区分 owned / absent / unknown；未知时既不宣称禁用成功，也不重复创建。

## 证据与验证边界

`tests/pvp_native_live_emitters_test.cpp` 直接运行生产原路径、生产类型适配器与真实 controlled-PVP core。使用 PE 对应的虚表/RTTI 与双向弱链 ABI，原生 SetTeam/锁点调用为内存 fixture。覆盖四职业 × 29 原版武器类、已有束切队 1→2→退出、新生束来源基线、DLC FireType1 普通弹不改队、盾 EF0、停止束退休、同地址新弱身份、真正 VirtualProtect 只读恢复失败与重试、owner/weapon 死亡零 owner 读取、314/318 独立恢复及自然死亡/复活、已知受控 rider 无旧账本跳过、旧账本重叠保持拒绝且恢复不覆盖另一 writer。

`tests/pvp_native_fixture.cpp` 另以真正 `VirtualProtect(PAGE_NOACCESS)` 覆盖对象页、仍存活的 control 页以及独立锁定点页，检查失败时保留完整原值、owner 和 weak 引用，权限恢复后归还 314 / 318 / 注册位 / 不计数位，并复用同一锁定点。最初的对象页用例连接修复前原路径产生九条失败断言，确认原路径曾把不可读对象当作已销毁并错报恢复成功。

验证使用直接 `cl`、`/W4 /WX /O2 /MT /permissive-`，不使用 Ninja。现有 native fixture 与继承 fixture 同样通过。`pvp_native_live_emitters_audit.py` 和 `pvp_controlled_npc_native_audit.py` 只读支持版本 DLL 的真实字节与虚表，不加载或执行游戏。

这些是源码、ABI fixture 与原生静态契约证据，不等同于实机、装包或双机联机验收。未写游戏目录，未控制运行中的游戏，未改变伤害/碰撞谓词。
