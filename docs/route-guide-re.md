# 原版引导路线（`RouteGuide`）为什么穿墙：逆向笔记（`src/route_guide.cpp`）

EDF.dll TimeDateStamp 0x678CCB46，全部为 RVA。置信度：H = 读反汇编确认；M = 强推断；L = 猜测。
只做了静态分析和离线测试（`tests/route_guide_test.cpp`、`tests/route_guide_native_test.cpp`），**没有进游戏实测**。

2026-10-10 用户：「5 代任务里引导玩家的路线指向有点怪，原版就有，6 代里也有」「是原版的指向方向叠加出来的线，感觉指到墙里面了」。

## 0. 那条线是什么

- 玩家看到的「一串箭头连成的线」是 `RouteGuide`（vtable 0x17D64A0）自己画的一条带：顶点表在 +0x270（每点 0x30 字节），贴图相位 = 时间×4 − 累计距离×0.667，所以看起来是一串往前滚的箭头。（H）
- `RouteGuide_Arrow`（GUIDEARROW.SGO，vtable 0x17D6520）是另一个单体箭头，只由 SGO 工厂 0x5CAC20 生成，`DispRouteGuide*` 不创建它。（H）
- 寻路用的是 Havok navmesh（`ai::Character`，0xEBA20 在全局 0x20B2AB8 上创建，navmesh 0，存在 +0x1B0）。每帧 0x5C9D20 设起点 = 玩家、终点 = +0x1D0，再置 `[char+0x68] |= 0x40` 请求寻路；结果拐点在 char+0x288，个数在 char+0x2A0。不是 RMPA 路线点，也不是 Simple / Rough / Mesh 那几个 RouteExplorer。（H）
- **寻路结果本身贴着墙走；是画线的代码把它改坏的。**

## 1. 构造与参数

构造函数 `0x5C6C10(this, InitParam*)`，返回 this；InitParam 整段拷到对象 +0x120（对象偏移 = 0x120 + 参数偏移）。只有三个调用点（`callers`）：（H）

| 调用点 | 原字节 | 来源 | 模式 +0x150 |
|---|---|---|---|
| 0x1A7EDC | `E8 2F ED 41 00` | AngelScript `DispRouteGuideToArea[EX]` 工厂（0x1B3760 → 0x1B38A0），存档恢复 0x5C5FE0 也走这里 | 2：区域中心 +0x180 |
| 0x1B4528 | `E8 E3 26 41 00` | AngelScript `DispRouteGuideToObject[EX]`（0x1B4000 → 0x1B4190） | 1：跟随物体 +0x168 / 控制块 +0x170，物体没了自删（0x5C9DA0） |
| 0x21F681 | `E8 8A 75 3A 00` | EDF5 BVM 原生 **1200**（0x21F380；低字节 0xB0 的编号都落到这个 case，0x213CBA） | **0**（0x21F44C `mov [rbp-0x49], r14d`，r14 = 0） |

| 字段 | 含义 | 默认 |
|---|---|---|
| +0x190 | 距离半径：玩家进到这个距离内线淡出（0x5C9B60、0x5C9A10） | 脚本传 |
| +0x194 | 删掉离路线起点（玩家）不到这么远的拐点（0x5C7BF6） | 15 m |
| +0x198 | 删掉离上一个保留拐点不到这么远的拐点（0x5C7CF6） | 7 m |
| +0x19C | 写进寻路设置（替换默认 10000），推测是节点上限（M） | 1000 |
| +0x1A0 | true 画折线，false 画曲线（0x5C804F `cmp byte [rcx+0x1A0],0` / `jne` 跳过 0x5CA140） | false |
| +0x2D8 | 帧间平滑系数（0x5C6CEE 写 0.04；全局 0x20B2890 的 0x20 标志置位时 0.08，0x5C6D21） | 0.04 |
| +0x2DC | 曲线张力 | 1.0（0x20 标志时 3.0） |

## 2. 画线算法（0x5C9710 → 0x5C7990）

```
if 寻路拐点数 > 2: 复制到 +0x290
else 连续 > 10 帧: 路线 = [玩家, 目标]                   // 0x5C97C0
pass1: 删除 |p[i] − p[0]| < +0x194 的拐点               // 0x5C7B5B
pass2: 删除 |p[i+1] − p[i]| < +0x198 的拐点             // 0x5C7C56
if n > 3: p[i] = old[i] + (p[i] − old[i]) × +0x2D8       // 0x5C8BD8..0x5C8BF9，按下标配对
所有点 y += 1
+0x1A0 == false: 0x5CA140 画 Hermite 曲线（起止取相邻两段的中点，拐点只当切线）
否则直接把各点连成折线
```

## 3. 缺陷（按对「线指进墙里」的贡献排序）

1. **曲线切掉拐角（H 结构，M 系数）**：navmesh 拐点就在墙角上，曲线只过各段中点，拐角处的曲线顶点大约落在拐点和两段中点连线之间，切进墙角一侧。
2. **拐点被删（H）**：玩家 15 m 内的拐点全删，相邻不足 7 m 的也删，线从玩家直拉到更远的拐点，正好穿过眼前的楼角。
3. **按下标平滑（H）**：拐点数一变，旧第 i 点和新第 i 点不是同一个拐点，混出来的点落在两个无关拐点之间，约 25 帧才收敛，期间线滑进墙里。
4. **EDF5 BVM 的线指向地图原点（H 代码，未实测）**：模式 0 时 0x5C9D20 既不读 +0x168 也不读 +0x180（只处理 1 和 2），终点 +0x1D0 一直是构造时的 0。这是 EDF6 移植 BVM 时留下的，EDF5 原版没有。
5. 寻路失败 10 帧后画玩家到目标的直线（0x5C97C0，H）：拐点数 2 也就是没有拐角的直路，所以只在真的搜不出路时穿墙；不改。

## 4. 修正（`src/route_guide.cpp`，ini `RouteGuidePath=1`）

- 三个构造调用点先逐个核对仍是 `call 0x5C6C10`，再一起改到包装函数；包装先调原构造，再改字段（`src/route_guide.h routeguide::Corrected`）。任何一处对不上就整套不装，原版行为不变。
- 改的全是游戏自带的参数模式，不碰寻路：
  - +0x1A0 = true：沿 navmesh 拐点画折线（修 1）；
  - +0x194 / +0x198 不超过 1 m：拐点不删（修 2；保留 1 m 是因为太短的段没有意义，带子的滚动相位沿段长走）；
  - +0x2D8 = 1：每帧直接用当前路线（修 3）；
  - 模式 0 且 +0x168 有物体：改成模式 1 跟随脚本点名的物体（修 4）。
- 影响：EDF6 自己的任务和 EDF5 任务的引导线都从圆滑曲线变成贴着走廊的折线，转角变硬。脚本自己用 EX 传的更小的删除距离照旧。
- 签名（插件安装前逐条核对）：0x5C6C10 函数头、0x5C6CEE、0x5C804F、0x5C7BF6、0x5C7CF6、0x5C9D32（读模式）、0x5C9DFA（模式 1 读 +0x168）、0x21F44C。
