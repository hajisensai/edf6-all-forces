# 沙扎比（MSN-04）：逆向与实测笔记

EDF.dll TimeDateStamp 0x678CCB46。计划见 `gundam-plan.md`，代码 `src/sazabi.cpp`、`pylib/sazabi_model.py`、`tools/make_sazabi.py`、
`tools/prep_sazabi.py`。置信度：H = 反汇编里看得到 / 文件逐字节核对过，M = 推断，L = 猜测或待实机。

## 1. 模型来源与资产管线

来源：用户提供的 Sketchfab「P-Japran color ver」（glTF：`scene.gltf` + `scene.bin`）。glTF 的 `asset.extras` 写明原模型是
kunnatee 的「SAZABI MSN-04 Gundam」，授权 **CC BY-NC-SA 4.0**（页面写的 CC BY 更宽，按严的来）。所以模型和由它生成的文件都不进仓库，
放在模型目录（`obj_model.model_dir('sazabi')`），发布包附 `LICENSE.txt`（署名、非商用、同协议）。(H)

实测（`tools/prep_sazabi.py` 读的就是这些）：(H)
- 252,848 三角形，68 个网格对象。对象**不是按部位分的**：Sketchfab 按材质合并后再切成每块约 5000 三角形，每块包围盒都覆盖全身。
- 20 个纯色材质（`baseColorFactor`，线性），没有贴图、骨骼、动画。三个带发光：`14___Default` 青（单眼）、`13___Default` 黄
  （推进器喉部、浮游炮喷口）、`15___Default` 红（胸灯）。
- 坐标与游戏一致：Y 上、+Z 前、+X 机体左侧。脚底 Y=-84，浮游炮舱顶 Y=1108。
- 焊接顶点后的连通块 682 个，就是一块块独立的装甲板 / 骨架零件（胶佩式），可以每块刚性挂一根骨骼。
- 两臂姿势不对称：右前臂垂到大腿外侧，左前臂前伸；骨段按左右分别标（`BONE_SEGMENTS`）。
- 自动求关节（子零件与父零件接触区中心）不可靠：内骨架与外甲交错，接触区不在转轴上（骨盆、大腿算到原点）。改用人工标定的骨段起点，
  渲染校验（白点落在肩、肘、腕、髋、膝、踝上）。
- 浮游炮：每侧 3 个，每个是一整块 1036 三角形、含发光材质 `13___Default` 的零件；各挂一根骨骼（放出时缩到 0）。
- 不带武器：光束步枪、盾、光束战斧由安装器另建。

尺寸按原设（用户 2026-10-06：「按原设身高」）：全高 25.6 m（1192 单位 → 0.021477 m/单位），反推头顶 ≈ 23.0 m，与原设頭頂高一致。
起初减面到 62,545 三角形（复古巴拉姆 54,468），用户实机看了觉得面数太低（「模型的面数好像也好低」，2026-10-07），平板装甲也被减出尖刺；
现在不减面，保留全部 252,848 三角形（加上武器 253,220，10 个网格），安装时生成约 1.5 分钟。整机平移让最低点落在 y=0。

材质（`pylib/sazabi_model.py`）：车身借黑豹坦克 `v505_tank` 材质（钻地车在游戏里用过，单 UV），三种发光色各复制一份复古巴拉姆的
`light` 材质（`snd_BRDF_Common_Light_NoOcc`）。颜色是一张 128×128 色板（每色 16×16 格，前 4 级 mip 仍纯色），粗糙度 / 金属度另做
同布局的两张。生成后读回逐字节一致、绑定矩阵为单位阵、每个顶点 100 % 挂一根 `sz_` 骨骼、脚底在地面（`check_archive`）。

## 2. 插件写的骨骼姿态怎么上屏

先前的推断（`drill-re.md` §5.4：「画面姿态只覆盖 CAS 骨架里有名字的骨骼」）**静态上不成立**：

- 每帧把**所有**骨骼记录的 world（`rec+0xB0`）抄进画面姿态数组（`inst+0x30 + i*0x40`）的是 `0x1100F10(inst)`，循环骨骼数
  （`inst+0x20`），没有按骨骼的条件。调用链：载具 vtable 第 3 槽 → `0x630220` → `0x6C06A0(veh+0xE40)` → `0x1100F10(veh+0xEE0)`
  （`0x6C06D7`）。506 / 504 / 612 直接用 `0x630220` 当第 3 槽。(H)
- 唯一的门：`0x6C06A0` 查 `[AnimationModel+0x31C] & 1`，加载时（`0x6BBDDA`）由 `0x6BB890` 第 4 个参数置位；载具在 `0x629618`
  传 1，所以对载具恒开。(H)
- 绘制走 `0x1104100` → 调色板 `0x11009A0`：每骨骼 `逆绑定 × drawn[i]`。`[this+0x482]` 恒为 0，只选实例指针，两边是同一个实例。(H)
- CAS 加载时按名字给**全部**模型骨骼建绑定（`0x6BCC41`–`0x6BCD26` → `CASController::Initialize` `0x6BD354`），求值
  （`0x1165A90` → `0x1165B40`）只写 `rec+0x70`（局部），只写片段里有通道的那几项（平移 / 旋转 / 缩放各一位）。(H)
  没有通道的骨骼局部矩阵保持插件写的值。(M：逐节点采样 `0x116C810` 没跟)
- world 由第 45 槽的 `SetWorld 0x1100B90` → `0x1100010` 按 `local × parent` 重算，只算 `rec+8 == 1` 的记录。(H)
- `0x1100D50` / `0x1103C80` 是死代码（没有调用者、不在 vtable，只有 unwind 表引用）。(H)

结论：
- **不要**给沙扎比做自定义 CAS 或在 CAS 里给 `sz_` 骨骼加通道——那样 CAS 每帧会把插件写的局部矩阵写回绑定姿态。沿用 V506 的 CAS；
  它只认 `mdl` / `globalSRT` / `body` / `rotor` / `tailRotor` / `bend_roter*` / `rearWheelSus`，模型里这三根前者放在它
  `default` 片段给的位置（`body` 在 (0, 1.637, 0)），后几根模型里没有（喷气机同样没有，能飞）。
- 插件每帧只写各骨骼 `rec+0x70`，world 由引擎自己的第 45 槽合成、第 3 槽上屏（最多晚一帧）。
  **实机更正（2026-10-07，H）**：曾经自己调 `SetWorld(veh+0xEE0, veh+0x60)` 求当帧生效，结果整台机体每隔一帧被画高约 12.7 m，
  一高一低两个沙扎比来回闪（用户：「沙扎比有两个，一个底部的阴影，一个上面一点的，两边一直来回闪」）：`veh+0x60` 是载具矩阵，
  它的位置是碰撞盒中心（离脚底 12.7 m），不是模型原点；引擎给根记录的是扣掉 `heli_rigid_body[0]` 的矩阵。已删掉这次调用。
- 钻头 / 舵面当时「看着不动」的真正原因静态没找到（候选：钻头每帧限转 9° 加上棱纹的视觉混叠、舵面太小）。实机时看 0.8.0 的
  `drawn pose` 调试行是否跟着 `written` 走。
- CAS 的读取用 `pylib/cas_pose.py`（另一会话为改绑定姿态后重定向原版动画写的读取器）。复古巴拉姆 `V515_RETROBALAM.CAS` 有 64 个片段，含 `stand` / `walk_*`，可作走路姿态的参照。曾写过一个只追加的「往 CAS 里加骨骼」工具（提交 ae2effd 的 `pylib/cas.py`，三份原版 CAS 上校验过），按上面的结论不需要，已删；实机若证明结论有误再从历史取回。

## 3. 底层类型：506 机体 + 标记

见 `gundam-plan.md` §0。标记段 7401–7499 归沙扎比（`body506.cpp kMarks`；喷气机 7001–7099、潜艇 7101、玩家喷气机 7201–7299）。
注意 `calls.py` 里登机枪的 7301 是子弹标签（`AmmoHitSizeAdjust`），与载具的速度增益标记不是同一处，但仍避开。

座位镜头（`vcobjects.SAZABI_SEAT_CAMERA`，模型坐标）：眼睛 (-8, 28, -52) 在右肩后上方、模型包围盒外（模型 x -11.1..10.8，
y 0..25.5，z -15.1..4.6），注视点 (0, 13, 10)：整台机体连脚都在画面里、前方留出瞄准视野（模拟 `tools/sazabi_pose_view.py cam`
挑的，2026-10-07）。喷气机用的「视线须越过机尾顶部」校验不适用于人形：越肩视角本来就看机体背面。

**MAB 定位点（上车点、镜头）挂在 `mdl` 上，而沙扎比的 `mdl` 落在模型原点（脚底），不是碰撞盒中心（实测，H）**：
2026-10-07 实机 `frames` 日志：载具位置 (-308.80, 13.19, -49.10)，`mdl` (-308.85, 0.37, -50.50)，正好是载具位置减
`heli_rigid_body[0]` = (0, 12.805, -1.395)；按「`mdl` = 碰撞盒中心」写的上车点落在 (-320.31, -12.43, -51.91)，地下 12.8 m；
镜头同样低了 12.8 m（眼睛在胸口高度、看向脚下：截图里机体挡住画面中央，光束看起来往一侧打，浮游炮飞出画面上方）。
喷气机的 `mdl` 则实测在碰撞盒中心（`vcobjects.py` 镜头一节引的 DoorLog）。原因未查明（沙扎比的骨架 `mdl` 下挂
`sazabi` / `globalSRT` / `body`，锚点是 `body`；喷气机只有 `mdl` → 网格骨骼）；构建按实测处理：`Jet.locators_on_origin`
（只有沙扎比为真）让 `door_point` / `place_seat_camera` / `check_door` / `check_seat_camera` 从模型原点量（`mdl_at`），
喷气机的 SGO 逐字节不变（33 个 `JETS` 的 `jet_sgo` 前后 sha1 一致）。布娃娃（`_jet_ragdoll`，按碰撞盒中心偏移）对沙扎比
是否也该改，没有实测，待机体被击毁时看。

同一次实测确认插件的坐标系没有错：机体 x/z 轴、`sz_root` 的世界矩阵、枪口骨骼的 z 轴三者一致（都朝 -z 前进方向），
步枪瞄准点在正前方 800 m。
