# 步兵瞄准镜画中画（InfantryScope=2）：设计与逆向

EDF.dll TimeDateStamp `0x678CCB46`，地址为 RVA。证据级别：H = 反汇编 / 生产代码已在用并核对；M = 读法确定、语义或时序推断；L = 推测。
起因与原话见 `docs/feedback-2026-11-10-pip-scope.md`（测试站 #32）。**本轮只做离线实现与离线测试，没有启动游戏。**

## 1. 目标

镜外视野保持原版不放大的 `π/4`，只有屏幕中央圆形镜片里显示瞄准镜倍率的画面（写实战术射击游戏的「镜内放大」）。
`InfantryScope`：`0` 原版、`1` 整屏放大 + 目镜（2026-10-11 的旧默认）、`2` 画中画（新默认）。

## 2. 两条路与这次的选择

| 方案 | 做法 | 画质 | 代价 / 风险 |
|---|---|---|---|
| A. 真第二视角 | 每帧再用窄 FOV（`π/4 / 倍率`）渲染一次世界到离屏纹理，合成进镜片 | 镜片里是原生分辨率 | 世界渲染要跑两遍（剔除、阴影、延迟光照、后处理），需要逆向出「多一台相机 / 视口」的完整生命周期；离线无法验证 |
| B. 本帧中心放大 | 世界渲染照常用 `π/4`，世界结束时把屏幕中心 `1/m` 大小的区域放大 `m` 倍画进镜片 | 镜片分辨率降为 `1/m`（4 倍镜 ≈ 1/4，8 倍镜 ≈ 1/8），高倍率明显发糊 | 只多一次全屏复制 + 一个圆形区域的绘制；与热像共用已验证的世界结束钩子；可在 WARP 上离线逐像素验证 |

任务要求优先 A。这次**实现的是 B**，原因：

1. A 的入口不是一个可以「多调一次」的函数。世界渲染是 Umbra 可见性查询回调驱动的：`xgs::umbra::Commander` vtable
   `0x1AE5288`，第 1 槽 `0x1AE5290 → 0x11E2120` 就是热像钩住的世界开始 / 结束所在的函数（`0x11E223D`、`0x11E3AE2` 都在它里面）
   （H：指针扫描 + `tools/edfre.py func_start`）。它没有直接调用者，由 Umbra 对每台相机的查询回调进来；要多渲染一个视角，
   得让引擎多一台登记过的相机 / 视口，而不是在插件里重放一次 Commander。
2. 引擎确实支持一帧多个视口：本机分屏每名玩家一个视口（`0x1198C40` 建视口，`docs/edf5-online-re.md`），且 `0x1198C40`
   有菜单等多处调用者（`0x93764`、`0x95AC3`、`0x9DA82`、`0xA170C`、`0xBB535` …，H：调用点；用途 M），说明视口是通用对象。
   但视口的渲染目标是不是可指定的离屏纹理、分辨率能否独立、阴影 / 后处理是否按视口分开、销毁时机，全都没有逆向证据（L）。
   在这些没有核实前写进插件，等于往渲染线程里加一个不知道生命周期的对象，不符合「根因、不猜」的规则。
3. B 的每一步都能离线验证（§5），且镜片里看到的角度与原版开镜完全一致（§3.3），只是分辨率低。作为第一版先交付可用的画中画，
   A 作为后续工作写在 §4。

## 3. 实现（方案 B）

### 3.1 镜头步：镜外不放大

- 原版：`CharacterGhostCamera`（vtable `0x1768C10`）第 4 槽 `0xF86A0` 每帧在目标分支 `0xF8906..0xF8916` 写
  `cam+0x24 = π/4 / cam+0x410`；投影 `0x118DFF0` 和 Umbra 视锥 `0x118DD30` 之后才读 `cam+0x24`（H，`docs/zoom-re.md` §1–§2）。
- `src/infantryscope.cpp CamStepHook`：链在同一槽上（`sightzoom.cpp` 管坐车，这里只管步行），原函数返回后，
  若这台相机的目标（`+0x350` / `+0x360`）是开镜中的本地玩家、模式 2 且镜片可用（§3.4），而 `cam+0x24` 正是原版刚写的
  `π/4 / cam+0x410`（`scope_pip.h Unzoomed`，同一次浮点除法，容差 1e-5），就写回 `π/4`。别的逻辑写的 FOV（状态 1 特写的缓动）不动。
- 下次调用原函数前，若字段仍是自己写的值就撤回成原版值（`sightzoom.cpp` 同样的做法）：原版无目标分支不写 FOV，
  所以关镜、死亡、换模式都不会把相机留在不放大的状态。
- 不碰 `human+0x1D0`：步兵瞄准灵敏度 `0x570780` 仍按倍率降低（H，`docs/zoom-re.md` §1），开镜时镜外视野也转得慢，
  与战术射击游戏的开镜灵敏度一致。命中判定沿镜头中心射线，FOV 改变不影响落点（`docs/zoom-re.md` §4）。
- 剔除用的是不放大的视锥（更宽），不会剔掉镜片里应当看见的东西。

### 3.2 世界结束：画镜片

- 位置：热像已钩的世界结束 `0x11E3AE2 → 0x11B63A0`（`docs/thermal-render-re.md`），在原生后级 screen compute 与屏幕 HUD 之前。
  `thermal.cpp EndHook` 先做热像合成，再调 `InfantryScopeWorldEnd`（热像只在载具观瞄，镜片只在步行，同一视图不会同时出现）。
- 只画开镜那名玩家的视图：`firstperson.cpp LocalViewPlayer(view)`，没有匹配时只认第一个相机槽的视图（`thermal.cpp ViewPlayer` 同法）。
- 放大倍率按**这一帧自己的投影**算：`view+0x60` 是该视图的投影矩阵（行主序，`[5]` 为纵向缩放），`firstperson.cpp DrawFrustum`
  已在用（H，`docs/fp-render-re.md` 2026-10-17）。渲染线程比游戏线程晚 0–3 步（fp-render-re §17.2），所以不用镜头步刚写的值。
  `m = cot(scopeFov/2) / view.proj[5]`（`scope_pip.h Magnification`）：焦距之比，不是倍率本身（4 倍镜时 m≈4.2，8 倍时≈8.5）。
  原版放大过的帧（相机已退回、或还没撤回）`m≈1`，不画、也不算失败。
- `src/scope_pip_gpu.cpp Magnifier`：D3D11.1 `SwapDeviceContextState` 隔离全部管线状态；把世界颜色目标整张复制到私有纹理，
  scissor 限在镜片外接方框，像素着色器在圆外 `discard`，圆内按 `centre + offset / m` 双线性采样。深度、其他像素、原生绑定都不变。
  只支持单采样、单 mip / 单 array、单个全尺寸视口、可采样的颜色格式（含游戏的 `R16G16B16A16_FLOAT`）。

### 3.3 镜片几何与 HUD

- 镜片：半径 = 视图短边 × `kLensRound`(0.30)，圆心在屏幕中心；镜筒黑边宽 `kRim`(0.16) × 半径；镜片最外 10% 四档渐暗。
  都在 `src/scope_pip.h`。
- `hud.cpp InfantryScope`：`cue.lens` 为真时只画镜筒黑边、镜片边缘渐暗和镜片里的分划，镜外不压暗；分划焦距用
  `LensFocal(h, scopeFov) = 0.5·h·cot(scopeFov/2)`，与原版放大后整屏的焦距相同，所以分划角度与原版开镜一致。
- `cue.lens` 只在「这名玩家最近一个世界视图里镜片真的画了」且画面 250 ms 内画过时为真；否则按模式 1 画整屏目镜。

### 3.4 什么时候退回模式 1 的画面

`scope_pip.h KeepUnzoomed`：要模式 2、世界结束钩子已装（热像 `Install` 成功）、本任务没拒绝过这块表面，并且
（开镜后 500 ms 试用期内，或这次开镜以来镜片画过：`lensAt >= openedAt`）。否则镜头步不撤回放大，HUD 画整屏目镜。表面不支持（多重采样、
**本机分屏的半屏视口**、未知格式、设备资源失败）时 `lensRefused`，写一行 `INFANTRYSCOPE ... this mission` 日志，直到下个任务
（`ResetInfantryScope`）再试。一次开镜里镜片一直没画过，试用期一过就退回原版放大。
不用「镜片 250 ms 内画过」判定（审查 2026-11-10 改）：暂停时士兵的预更新（`MapHumanFrame`）不跑（M：与载具输入同属暂停的对象循环）、开镜提示 200 ms 后过期，
镜头第 4 槽照跑（`docs/hud-re.md` §10），暂停中的帧都是原版放大的；渲染卡顿超过 250 ms 时镜头也会重新放大；之后渲染出来的都是原版放大帧（`m≈1`，不画镜片），`lensAt` 再也不更新，这次开镜就一直卡在模式 1 的画面直到关镜。
现在镜片停画期间画面保持不放大、HUD 不画镜框（`cue.lens` 仍按 250 ms 判），下一帧世界视图就重新画上镜片。

## 4. 待办：真第二视角（方案 A）

按顺序，每步先逆向出证据再写代码：

1. 视口对象：`0x1198C40` 的参数、返回对象布局、渲染目标从哪来（交换链还是可指定纹理）、尺寸与 FOV 字段；对照分屏两个视口的
   实际 Commander 调用（`view+0` 视口编号、`view+4`），确认每个视口独立跑一遍 Umbra 查询 → Commander（M → 需 H）。
2. 菜单里 3D 预览（武器 / 兵种）的视口是否渲染到离屏纹理再贴到 UI 上；若是，复用同一路径让第二台 `SceneCamera`
   （`0x118AFC0` 构造，FOV `+0x24`）渲染到一张镜片大小的纹理（L）。
3. 第二视角的成本：阴影级联、延迟光照、粒子是否按视口重复；只渲染镜片外接方框大小（如 0.6×短边 的正方形）可把像素成本压到主视图的 1/3 左右。
4. 合成：世界结束时用第二视角的纹理替换本方案的「本帧中心」采样源，`scope_pip_gpu.cpp` 的镜片 pass 与 HUD 不变。
5. 验证：需要实机或 `tests/autopilot` 后台驱动，看分屏 / 菜单 / 任务切换时视口的创建与销毁不泄漏、不崩。

## 5. 离线验证

- `scope_pip_check`：模式值、焦距比倍率、镜片几何在各种视图比例（含分屏形状）里、scissor、`Unzoomed` / `KeepUnzoomed` / `LensDrew` 的边界。
- `scope_pip_gpu`：生产 HLSL 在 D3D11 WARP 上逐像素：镜片内为中心放大的渐变、镜片外不写、原生绑定不变、不支持的表面不动。
- `infantry_scope_pip`：生产 `CamStepHook`（替身原版步按 `0xF8906` 写 FOV）与 `InfantryScopeWorldEnd`（WARP 设备、视图块带投影）：
  试用期、镜片维持、停画（暂停 / 卡顿）后仍不放大且下一帧重画镜片、本次开镜从没画过时退回、撤回自己的写值、别的 FOV 不动、模式 0 / 1、钩子没装、表面拒绝与任务重置、另一名玩家的视图不画、
  原版放大帧不画也不算拒绝、半屏视口拒绝后镜头恢复放大。
- `hud_layout`（`hud_view`）：三种分划的画中画场景，镜筒黑边、镜外不压暗、刻度数字都在镜片里。
- selftest `infantry_scope_pip_default_migrates`：ini / crew.h / 范围一致，安装器 11-10 迁移一次、不覆盖玩家自己的值。

## 6. 需要实机确认

- 镜片清晰度（方案 B 的固有缺陷）是否可接受；原生后处理（泛光、景深、抗锯齿）叠在镜片上的观感。
- `view+0x60 [5]` 在步行主视图上确为该帧投影（离线以 firstperson 的用法为据）；开关镜、换武器的过渡没有一帧双重放大或没放大。
- 帧率（每帧一次全屏颜色复制）。分屏应退回模式 1 的画面并写日志。联机房间里只影响本机画面（不涉及房间协议）。
