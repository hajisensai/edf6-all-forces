# 步兵瞄准镜画中画（InfantryScope=2）：设计与逆向

EDF.dll TimeDateStamp `0x678CCB46`，地址为 RVA。证据级别：H = 反汇编 / 生产代码已在用并核对；M = 读法确定、语义或时序推断；L = 推测。
起因与原话见 `docs/feedback-2026-11-10-pip-scope.md`（测试站 #32）。**两轮都只做离线实现与离线测试，没有启动游戏。**
脚本：`tools/edfre.py` + capstone（只读 EDF.dll）；离线审计 `tests/scope_lens_native_audit.py` 钉住 §4 / §5.1 的主要 H 项（清单见 §6）。

## 1. 目标

镜外视野保持原版不放大的 `π/4`，只有屏幕中央圆形镜片里显示瞄准镜倍率的画面（写实战术射击游戏的「镜内放大」）。
`InfantryScope`：`0` 原版、`1` 整屏放大 + 目镜（2026-10-11 的旧默认）、`2` 画中画（默认）。

2026-11-10 第二轮（维护者对「镜片是放大本帧中心、倍率越高越糊，能否先接受」的回答：「画质不能接受」）：
镜片改成**第二个视口以镜片视角真渲染**的画面，分辨率与镜片的屏幕像素 1:1，与倍率无关。旧的「本帧中心放大」（方案 B）删除。

## 2. 方案选择

| 方案 | 做法 | 画质 | 结论 |
|---|---|---|---|
| A. 第二视口真渲染（**采用**） | 引擎第 4 个视口槽（下标 3）挂一台 `TraceCamera`，每帧以镜片视角、镜片大小的正方形渲染整套世界（剔除、阴影、延迟光照、半透明、远景），在主视口后处理之前把它画进主视口的世界颜色 | 镜片像素 = 镜片视角的原生渲染，倍率越高不再变糊 | §4 的逆向证明视口是带独立渲染目标的通用对象，引擎自带同类用法（调试命令 `stereo_camera`） |
| B. 本帧中心放大（第一轮，已删除） | 世界结束时把屏幕中心 `1/m` 区域放大 `m` 倍画进镜片 | 镜片分辨率 `1/m` | 维护者否决 |
| C. 超采样重画镜片区域 | 主视口整体按倍率提高分辨率 | 8 倍镜要 64 倍像素 | 不可行 |

## 3. 镜头步与镜片几何（两轮相同）

### 3.1 镜头步：镜外不放大

- 原版：`CharacterGhostCamera`（vtable `0x1768C10`）第 4 槽 `0xF86A0` 每帧在目标分支 `0xF8906..0xF8916` 写
  `cam+0x24 = π/4 / cam+0x410`；投影 `0x118DFF0` 和 Umbra 视锥 `0x118DD30` 之后才读 `cam+0x24`（H，`docs/zoom-re.md` §1–§2）。
- `src/infantryscope.cpp CamStepHook`：链在同一槽上（`sightzoom.cpp` 管坐车，这里只管步行），原函数返回后，
  若这台相机的目标（`+0x350` / `+0x360`）是开镜中的本地玩家、模式 2 且镜片可用（§3.3），而 `cam+0x24` 正是原版刚写的
  `π/4 / cam+0x410`（`scope_pip.h Unzoomed`，同一次浮点除法，容差 1e-5），就写回 `π/4`。别的逻辑写的 FOV（状态 1 特写的缓动）不动。
- 下次调用原函数前，若字段仍是自己写的值就撤回成原版值：原版无目标分支不写 FOV，所以关镜、死亡、换模式都不会把相机留在不放大的状态。
- 不碰 `human+0x1D0`：步兵瞄准灵敏度 `0x570780` 仍按倍率降低（H，`docs/zoom-re.md` §1）。命中判定沿镜头中心射线，FOV 改变不影响落点。
- 同一个钩子撤回放大时调 `scopelens::Want(相机, 原版视角)` 要镜片视口（§5.2）；不再要（关镜、换模式）就不再调用，200 ms 后过期，
  镜片视口不再渲染。

### 3.2 镜片几何与 HUD

- 镜片：半径 `r` = 主视口短边 × `kLensRound`(0.30)，圆心在屏幕中心；镜筒黑边 `kRim`(0.16) × 半径；镜片最外 10% 四档渐暗（`src/scope_pip.h`）。
- 镜片要显示原版开镜的角度：镜片里离圆心 `d` 像素的点对应 `tan = d / F`，`F = LensFocal(h, scopeFov) = 0.5·h·cot(scopeFov/2)`
  （与原版放大后整屏的焦距相同，分划刻度因此不变）。
- 镜片视口的正方形边长 `S = ceil(2r)`（`LensViewSide`），纹理正好铺满镜片直径，镜片里的像素与渲染像素 1:1。
  它的竖直视角 `φ` 满足 `r·cot(φ/2) = F`，即 `tan(φ/2) = r·tan(scopeFov/2) / (0.5·h)`（`LensViewFov`；与 `S` 无关）。
- `hud.cpp InfantryScope`：`cue.lens` 为真时只画镜筒黑边、镜片边缘渐暗和镜片里的分划，镜外不压暗；分划焦距取
  `LensFocal(h, lensFov)`，`lensFov` 由**这一帧镜片视口自己的投影**反算（`LensShownFov(h, r, yL) = 2·atan(0.5·h / (r·yL))`，
  `yL` = 镜片视口投影的 `[5]`），所以分划与镜片里的画面严格对齐，与游戏线程发布的倍率差几帧也不会错位。

### 3.3 什么时候退回模式 1 的画面

`scope_pip.h KeepUnzoomed`：要模式 2、镜片的钩子全部装上、本任务没拒绝过，并且（开镜后 500 ms 试用期内，或这次开镜以来镜片画过）。
否则镜头步不撤回放大，HUD 画整屏目镜（模式 1 的画面）。拒绝（写一行 `INFANTRYSCOPE ... this mission` 日志，直到下个任务
`ResetInfantryScope` 再试）的情形：本机分屏（视口 1 或 2 有相机）、视口 3 被别的相机占用、建的相机 3 秒内没进视口 3、
工厂没建出相机、主视口表面不支持（多重采样、局部视口、未知格式、设备资源失败）。镜片视口的目标不是 `S×S`（改分辨率的那几帧）
只是那一帧不画（日志一次）。一次开镜里镜片一直没画过，试用期一过就退回原版放大。
镜片停画期间（暂停：暂停时整帧不重渲染，§4.6）画面保持不放大、HUD 不画镜框，下一次渲染就重新画上镜片。

## 4. 逆向：视口、相机与渲染命令（2026-11-10 第二轮）

### 4.1 System 的 4 个视口槽（H）

`xgs::game::System`（`*(EDF+0x20B2958)`）里 `system+0x4D0` 起 4 个视口槽，步长 `0x188`。`0x1195BE0(system, i)` 返回 `&槽.相机`
（`system+0x4D8+i·0x188`），55 处调用者用它取「第 i 号玩家的相机」。槽内字段（相对槽首 `system+0x4D0+i·0x188`）：

| 偏移 | 内容 | 证据 |
|---|---|---|
| `+0x00` | 视口模式 int（`0x11978D0` 里 0 / 1 / 2 / 3 分支；3 多录一条 `0x112A7F0`） | H 读；写入者未找到（插件不改它，视口 3 读到非 0 时拒绝） |
| `+0x08 / +0x10` | 当前相机 `weak_ptr`（对象 / 控制块）；`0x1193FA0(槽, weak_ptr 按值)` 换当前相机：旧相机 vtbl[7] 摘下、新相机 vtbl[6] 挂上，并析构传入的 weak_ptr | H（`0x1193FA0` 全函数） |
| `+0x18 / +0x20` | 该视口拥有的相机 `std::list<shared_ptr>` 与个数；个数非 0 才建渲染目标 | H（`0x119B410` 尾插、`0x11997A0` 读 `+0x20`） |
| `+0x34..+0x40` | 视口矩形 `{x, y, w, h}`（int） | H（`0x1198C40`） |
| `+0x44 / +0x48` | 渲染目标尺寸 `w, h` | H（`0x1198C40` 写，`0x11997A0` 建目标时读） |
| `+0x68 / +0x88 / +0xA8` | 3 张 G-buffer，`+0xD0`（`+0xC8` 字节为真时才有）/ `+0xF0` 颜色，格式 `0xA` = `R16G16B16A16_FLOAT` | H（`0x11997A0`：`0x1121F70` 建 5 张同描述纹理） |
| `+0x110 / +0x130` | 深度（格式 `0x27/0x28/0x29` = `R32_TYPELESS/D32/R32_FLOAT`） | H |
| `+0x178 / +0x180` | 槽自己的一份 0x128 对象（8 个子项，阴影 / 渲染参数，`0x11295E0(obj, w, h)`） | H 读写 / M 语义 |

**每个视口有自己整套离屏渲染目标**，尺寸就是它的矩形尺寸；分屏两名玩家各渲染各的离屏目标，再各自合成到屏幕上（§4.4）。
`0x1198C40(system, i, const int rect[4])` 设矩形和目标尺寸后调 `0x11997A0(槽)`：没有相机时（`+0x20 == 0`）什么也不建；
矩形或尺寸与上次不同就重建目标（在游戏线程录制「建纹理」命令），并置 `system+0xAF0`（暂停中也强制渲染一帧，`0x1198F86`）。
任务结束 `0x11956C0`（场景清理，多处调用）：清空加相机队列，对 4 个槽逐一清当前相机、清相机列表（释放 shared_ptr）、个数归 0、
销毁目标（`0x11974C0`）；**矩形不清**。之后才清 Umbra 世界 `system+0x260`。

### 4.2 相机类与工厂（H）

- `xgs::game::SceneCamera` 构造 `0x118AFC0(this, desc)`：`desc+0x10..+0x4F` 世界矩阵 → `this+0x220`；`desc+0x50` = `system+0x260`
  （Umbra 世界，用来建 `+0x70` 主视角与 `+0xF0` 远景两个 Umbra 相机包装）；`desc+0x58` 视口号 → `this+0x60`；`desc+0x5C` 矩形 → `this+0x190`；
  阴影级联 `+0x170` 向量（每项 0x150，掩码 `0x40000000`）；建控制块（`_Ref_count`，new 0x18）并写 `enable_shared_from_this`
  （`this+0x10/+0x18`）和 `*desc+0x70` 指向的 shared_ptr。默认 `+0x20 = +0x24 = π/4`、近 `+0x28 = 0.1`、远 `+0x2C = 1000`。
- `GameCameraBase` 构造 `0x103740`（vtable `0x1769178`）：先调 `0x118AFC0`，`+0x38 = 1`（开阴影级联）。派生类：
  `CharacterGhostCamera`（玩家）、`DemoAnimationCamera`、`FreeViewCamera`、`TraceCamera`、`LODCaptureCamera`。
- **`TraceCamera`**（vtable `0x1769218`，0x360 字节）：构造 `0x1051F0(this, desc)` 在基类之后把 `desc+0x80/+0x88`（一个相机的
  `weak_ptr`）复制到 `this+0x350/+0x358`（弱引用计数 +1）。第 4 槽 `0x1052F0` 每步锁住被跟随的相机，抄它的
  `+0x220..+0x25F` 世界矩阵（位置沿右轴挪 `[0x1F56234]` = 0.2 m，立体用的眼距）、`+0x20/+0x24/+0x28/+0x2C`。
  **它没有 HUD、不读输入、不碰玩家**；vtbl[6]/[7]（挂上 / 摘下 `0x1041F0/0x104250`）只看 `+0x268`，TraceCamera 是 0，什么也不做。
- 工厂 `0x82F60(system, shared_ptr* out, 视口号, const float 矩阵[16] /*16 对齐*/, desc*)`：填 desc 的 `+0x10..+0x70`、new 0x360、
  `0x1051F0`、`0x1195990(system, &sp)`（加相机，见下）、`dynamic_cast` 成 `TraceCamera` 写进 `out`。
- 引擎自己的用法：调试命令 `stereo_camera`（字符串 `0x1763E28`，注册在 `0xA3C9A`）的实现 `0xACC80`：取视口 0 的相机，
  把它的 `+0x20` 翻倍，然后 `0x82F60(system, &out, 参数视口号, 单位矩阵, desc{+0x80 = 视口 0 相机的 weak_ptr})` 建一台跟随它的
  TraceCamera。**即引擎本来就支持「第二个视口跟着主相机再渲染一遍」**，这是本方案的直接依据。
- 加相机 `0x1195990(system, const shared_ptr&)`：持 `system+0x308` 临界区（`0x50BC0` = `EnterCriticalSection`，同线程可重入）
  尾插进 `system+0x4C0` 队列（强引用 +1）。`System::update 0x1198DA0` 每帧在渲染之前 `0x1198F61 → 0x1195A80` 处理队列：
  按相机 `+0x60` 的视口号 `0x119B410` 插进该槽列表、`0x1193FA0` 设为当前相机、`0x11997A0` 按矩形建目标。

### 4.3 渲染录制：`0x11978D0`（游戏线程，H）

`System::update` 在 `0x1198FA4` 调 `0x11978D0(system, dl = system+0xCE9, r8b = 1)`（插件 `firstperson.cpp RenderHook` 已链在这里）。
它对 4 个槽按下标 0..3 依次：锁当前相机（失败就跳过整个槽）→ `0x1197B50: 0x118DFF0(相机, &槽.矩形)`（按矩形宽高比、
`+0x24` 竖直视角、`+0x28/+0x2C` 近远建投影，`0x118E10A` 把 `+0x220` 交给 Umbra）→ 阴影级联查询 → 远景查询 → G-buffer 设置 →
`0x1198656: 0x11B6AA0` 主视角查询（Umbra → Commander 回调，就是热像钩住的世界开始 / 结束所在）→ 收尾：

| 调用点 | 录制 | 参数 |
|---|---|---|
| `0x1198742` | `0x112C230`（`dl` 为真）：整套后处理（`0x1131660`：泛光降采样等）并合成到屏幕 | `r8` = 槽 `+0xD0` 或 `+0xF0`，`r9` = `system+0x280`（0x48 字节，录制时整块复制；其中 `system+0x2A0` 刚写成本槽相关指针） |
| `0x1198753` | `0x112C460`（`dl` 为假）：同上的简单路径（`0x1175A50`） | `r8` = 槽 `+0xF0` |
| `0x1198777` | `0x11B6E20`（`r8b` 恒为 1） | `r8` = 同上颜色目标 |
| `0x119879F` | `0x112C5A0`（`dl` 且槽 `+0xC8`） | `r8`、`r9` = 槽两张颜色目标 |
| `0x11987BF` | `0x112A7F0`（槽模式 3） | `r8` = 槽 `+0xF0` |

循环结束 `0x119889B: 0x111B410(cmdctx)` 提交。`cmdctx` = `EDF+0x2136FF0`，上表各录制函数的 `rdx` 都是它。
上表 5 个函数都只在录制时复制参数指向的内容（TextureBase 的 shared_ptr 拷贝、0x48 字节参数），之后不再读插件给的指针，
所以**把它们推迟到循环之后用同样的参数再录一遍**是等价的（H：逐个读了 5 个函数体）。

屏幕 HUD 不在这里：`0x7058B7 → 0x11977F0` 在主循环稍后对 4 个槽的相机调 `0x118E500` 画各自的 HUD（H，`tests/thermal_native_audit.py` 已钉）。

### 4.4 渲染命令环（H）

- 录制：`0x51D00(ring, n)` 在 `ring = cmdctx+0x28A8` 里占 `n` 个 16 字节单元并返回首单元，`0x51D60(ring, n)` 发布（满 0x100 个单元
  `SetEvent` 唤醒渲染线程）；`0x111B410(cmdctx)` = 立即发布。一条命令 = 一个单元里的函数指针（+ 可选的后续单元作载荷）。
- 执行：渲染线程 `0x111B8E0(cmdctx)` 循环 `fn = 读 1 单元; if(!fn) 结束; fn(nativeCtx = cmdctx+0x140, reader = cmdctx+0x2908)`。
  `nativeCtx+8` 是 `ID3D11DeviceContext*`（`0x111D810` 录的命令 `0x1118AC0` 即 `ctx->Flush()`），与热像世界结束钩子拿到的 `native` 相同。
  这也印证 `docs/fp-render-re.md` §17.2 的实测：绘制在另一个线程，比游戏线程晚 0–3 步。
- 所以插件可以在录制流里的确定位置插一条只有函数指针的命令（与 `0x111D810` 同形），渲染线程会在前面所有命令执行完之后、
  后面的命令之前调用它。

### 4.5 Commander 的视图块（M）

Commander 的 `view` = `DeferredRenderSystem+0xE0`，由 `0x11E1BC0` 从查询描述整块复制：`view+0` 视口号、`view+4` 查询类型
（0 主视角 / 1 远景 / 2 阴影），`view+0x20` 视图矩阵、`view+0x60` 投影（`[5]` 竖直缩放）。`0x11978D0` 在 `0x1197D2A` 把循环下标
写进查询描述 `+0`（H），描述到命令再到 `view` 的复制链没有逐条核对（M），所以插件在镜片视口的世界结束处额外核对
「渲染目标尺寸 = 镜片视口的 `S×S`、投影为正方形」再用它。
审查补充（只读核对）：主视角查询的录制 `0x11B6AA0`（参数 `r8` = `0x1198656` 处的 `rbp+0x90`，即上面写了循环下标的描述）在
`0x11B6B85..0x11B6B8B` 把描述 `+0` 抄进新块 `rsp+0x40` 的 `+0`、`+4` 写 0（主视角），该块经 `0x11B41F0` 整块复制进命令环（`0x3C` 个单元，
块在载荷 `+0x20`）（H）。剩下「执行函数 `0x11B5A70` 把这一块交给 `0x11E1BC0`」这一环仍未逐条读（M）。

### 4.6 暂停

`0x1198F76..0x1198F8D`：暂停中且 `system+0xAF0` 为 0 时整帧不渲染（H）。暂停时画面停在最后一帧，镜片也一样。

## 5. 实现（方案 A）

### 5.1 原生入口（`src/scope_lens.cpp`，安装前逐字节核对 22 处，任一不符整套不装、模式 2 退回模式 1 的画面）

| 地址 | 用途 |
|---|---|
| `0x1197B50 → 0x118DFF0` | 改道：槽 0 时判定这次录制要不要镜片（「就位」），要就把镜片相机设为视口 3 的当前相机；槽 3 且是镜片相机时，把主相机的 `+0x220..+0x25F`、`+0x20`、近远原样抄过来（不要 TraceCamera 自己的 0.2 m 眼距），`+0x24 = φ` |
| `0x119863C → 0x112B230` | 改道：就位时照常录制槽 0 的 G-buffer 设定，同时用引擎自己的句柄函数（`0x1120500` 构造、`0x8F000` 赋值、`0x11207A0` 析构）复制它的 3 个纹理句柄，补录槽 0 收尾之前再录一次（槽 3 的世界会把它换成槽 3 的） |
| `0x1198742 / 0x1198753 / 0x1198777 / 0x119879F / 0x11987BF` | 改道：就位时槽 0 的这几条录制先存起来（`0x112C230` 的 0x48 字节参数块当场复制，因为槽 3 的迭代会改写 `system+0x2A0`）；槽 3 是镜片相机时一律不录（镜片视口不上屏），就位时槽 3 的第一条换成插件的「镜片合成」命令 |
| `0x119889B → 0x111B410` | 改道：先补录 G-buffer 设定、再按原顺序补录存起来的槽 0 收尾，把镜片相机从视口 3 摘下，再提交 |
| `0x82F60`、`0x1198C40`、`0x1193FA0`、`0x51D00`、`0x51D60` | 调用：建 TraceCamera、设视口 3 矩形、挂 / 摘视口 3 的当前相机、往命令环插命令 |

### 5.2 生命周期（全在游戏线程的录制 `0x11978D0` 里）

- 镜头步（§3.1）只发布「要镜片」：哪台相机、原版视角、时刻。
- 槽 0 的投影钩子：要镜片（相机就是槽 0 的当前相机、200 ms 内、主相机这一帧的 `+0x24` 比瞄准镜视角宽：`Magnification ≥ kLeast`）时
  - 还没有镜片相机：确认视口 1、2 没有当前相机（不是本机分屏）、视口 3 的相机列表为空且没有当前相机、模式为 0；
    `0x1198C40(system, 3, {0,0,S,S})`；`0x82F60` 建一台跟随视口 0 相机的 TraceCamera（描述的 vtable 与 `stereo_camera` 相同，
    `+0x80/+0x88` = 视口 0 当前相机的 weak_ptr）。工厂返回 weak_ptr，插件只留它：相机由视口 3 的列表拥有，任务结束由引擎
    `0x11956C0` 在 Umbra 世界清理之前销毁，与原生相机同一时机。这次录制不画（相机还在加相机队列里）。
  - 已有：等引擎下一次 update 的 `0x1195A80` 把它放进视口 3 的列表（个数 1、首节点就是它、`+0x28` 目标已建）；主视口尺寸变了
    （视口 3 矩形不是 `{0,0,S,S}`）就重设矩形（引擎重建目标），这次不画。
  - 就位：`0x1193FA0(视口 3, weak)` 挂上，置「就位」，发布 `S`。
- 提交钩子：补录之后 `0x1193FA0(视口 3, 空)` 摘下。**镜片相机只在录制期间是视口 3 的当前相机**，屏幕 HUD 阶段（`0x11977F0`）、
  按视口取「第 i 号玩家相机」的 55 处调用都看不到它（TraceCamera 的 vtbl[3] / vtbl[5] 本来也是 `ret 0`）。
- 弱引用过期（任务结束销毁了相机）就放掉、下次重建；`ResetInfantryScope`（任务开始）放掉弱引用并清除拒绝。

### 5.3 一帧的顺序

游戏线程录制（`0x11978D0`）：槽 0 世界（含 G-buffer 设定）→ 〔槽 0 收尾暂存〕→ 槽 3 世界（镜片视角）→ 〔槽 3 收尾不录，第一条换成镜片合成命令〕→
补录槽 0 的 G-buffer 设定 → 补录槽 0 收尾（后处理 + 上屏）→ 摘下镜片相机 → 提交 → 稍后屏幕 HUD（镜筒、分划）。
渲染线程执行：槽 0 世界结束（`InfantryScopeWorldEnd`：留住主视口世界颜色的 RTV 与投影）→ 槽 3 世界结束（留住镜片视口的颜色纹理与投影）
→ 镜片合成命令（`InfantryScopeLensCommand` → `LensCompositor::Composite`：把镜片纹理复制一份，在主视口世界颜色上按圆画进去）
→ 槽 0 后处理与上屏 → HUD。

- 镜片画在**后处理之前**的 HDR 世界颜色里，与主画面同一次色调映射 / 泛光，没有亮度跳变；没有一帧延迟。
- 判定为假（没要镜片、原版放大帧、镜片相机还没就位）时槽 0 照原样录制；槽 3 若在渲染镜片相机（只会是刚进队列那一帧）也不上屏、不插命令。
- 镜片合成只在同一帧的主视口与镜片视口都留住了目标、且镜片焦距确实大于主画面（`LensPower ≥ kLeast`）时画；画了才置 `lensAt` / `lensShown`。

### 5.4 GPU 合成（`src/scope_pip_gpu.cpp LensCompositor`）

- `CaptureMain`：主视口世界结束时的 RTV0（不得有别的 RTV、单采样、单 mip / array、全尺寸视口、可采样颜色格式），引用住。
- `CaptureLens`：镜片视口世界结束时的 RTV0 纹理（同样检查，且必须是 `S×S` 正方形）；没留住主视口时不留。
- `Composite`：D3D11.1 `SwapDeviceContextState` 隔离全部管线；`CopyResource` 镜片纹理到私有纹理；绑主视口 RTV、scissor 限在镜片外接方框，
  像素着色器圆外 `discard`，圆内 `uv = 0.5 + (p − c) / 2r` 双线性采样。深度、主画面其余像素、原生绑定都不变；结束放掉两份引用。

## 7. 需要实机确认（离线证明不了的）

日志里要看的行：`INFANTRYSCOPE lens view created: viewport 3, SxS`（建了相机）、`INFANTRYSCOPE lens view ready: viewport 3 SxS, main WxH, taa=N`
（入列、目标建好）、`INFANTRYSCOPE lens drawn: main height H, lens radius R, lens view SxS, scope fov F`（第一次画上镜片）、
`INFANTRYSCOPE the lens view cannot be used (...)` / `... cannot be drawn on this view's surface ...`（拒绝的原因）、
`INFANTRYSCOPE the lens command found no ... world colour held`（§4.5 的视口号读法不对时会出这一行）。

1. 镜片视口真的出图：`view+0 == 3` 的世界结束确实出现（§4.5 是 M），且镜片画面清晰、视角与原版开镜一致（分划对得上远处目标）。
2. **主视口后处理读到的渲染器状态**（最大的风险）：槽 0 的后处理现在在槽 3 的世界之后才录。G-buffer 设定（`0x112B230`）已重录回槽 0 的，
   但槽 3 的世界还录了别的渲染器状态：阴影级联 `0x112AA90` ×3、`0x112B550`、`0x112AD40`、（`system+0xCE8` 时）`0x112A350`。
   若后处理 `0x1131660` 读其中某项（例如雾、天空、曝光相关），开镜时整个主画面会出现错误（颜色、雾、阴影不对）。
   离线没有逐项读完后处理的执行函数。审查补充（只读核对，不完整）：后处理命令的执行 `0x1126AE0 → 0x1131660(R = 渲染器+8, native, 纹理, 参数块)`
   本体直接读的 `R` 字段是 `+0x598 / +0x698 / +0x6A8 / +0x960 / +0xB98 / +0xBB0..+0xC48`；上面几项每槽设定的执行函数本体
   （`0x1127000` 等）写的是 `native+0x698 / +0x6B8…`（另一对象），G-buffer 设定写 `R+0xF98 / +0xFB8 / +0xFD8`（已重录）；
   二者没有直接重叠。`0x1131660` 调用的子函数（`0x1134780`、`0x11325D0` 等）没有读，所以这一条仍是风险。实机若开镜时镜外画面有异常，先对照这几项。
3. 帧率：镜片视口是一整套世界渲染（含 3 级阴影、Umbra 剔除），像素约为主视口的 `(0.6·短边)² / (宽·高)`（16:9 约 20%），
   CPU 端多一次场景遍历。高倍率时视锥窄，剔除掉的更多。需要实测开镜前后的帧时间。
4. 主视口后处理里依赖深度 / 历史的效果（若有时间性抗锯齿 `+0xC8 / 0x112C5A0`、景深）在镜片区域用的是主视口的深度和运动，
   可能在转镜时拖影；`lens view ready` 日志带 `taa=<槽 0 +0xC8>` 便于对照。
5. 第一人称视角模块（`firstperson.cpp`）按视图矩阵认人：镜片视口与主视口矩阵相同，会被当作同一名玩家的视图（隐藏身体、补绘手臂一致），
   近处的枪模型若在镜片窄视角里露出来要看观感（原版开镜同一位置同一视角，应与原版放大时所见一致）。
6. 任务切换、重开、读档时视口 3 的相机随场景清理销毁，插件下次开镜重建，没有泄漏、没有崩溃（`lens view created` 每个任务第一次开镜一行）。
7. 联机房间：只影响本机画面，不涉及房间协议；本机分屏仍退回模式 1。
