# 原版载具：座位武器、挂载切换、载具内换座位（逆向笔记）

EDF.dll TimeDateStamp `0x678CCB46`，地址都是 RVA。全部是静态分析（`tools/edfre.py` + capstone），**没有进游戏实测**。
置信度：H = 指令里直接读到；M = 由代码结构推出；L = 猜测。
实现：`src/payload.cpp`（座位武器读数、原版直升机的挂载切换）、`src/seatswitch.cpp`（换座位）、`src/payload.h`（给载具 HUD 的结构）、
`tools/make_stock_stores.py`（安装器给原版直升机的请求加挂载）。2026-10-06 用户：「原版载具也补充上可切换载荷的设定」「载具内多位的情况可切换至空座」。

## 1. 座位的武器列表（已知，H）

- 座位 `+0xC8` 是持有者指针数组，`+0xD8` 是个数；持有者 `+0x10` 是武器（`docs/aim-line-re.md`）。
- 持有者是载具 `+0x638` 数组（步长 0x48，个数 `+0x648`）里的元素，所以 `(持有者 - veh[+0x638]) / 0x48` 就是它在
  `vehicle_weapon_setting` 里的行号（`payload.cpp` `HolderIndex`）。
- 设置值 `<0` 的挂点（油箱 `V_FUEL01`）加进**每个**座位的列表（`docs/stores-re.md` §2），读数里去掉它（按 SGO 文件名，`stores.h` `WeaponFile`）。

## 2. 各类载具的开火（H，除非另注）

| 类（vtable） | 开火代码 | 按键 → 持有者 |
|---|---|---|
| 506 直升机（N9 Eros、602；`0x17DB238`） | 第 57 槽 `0x61B710` | 主扳机（`veh+0x2020`）→ 0、1 两门机炮；按键位 `0x20`（`veh+0x2021`）→ 2 号（导弹 / 燃烧弹）。只读座位 0 |
| 409 直升机（`0x17DEF98`） | 第 57 槽 `0x64AF90`（`0x64B05D`） | `+0x2021` → 1 号（`0x64B071`）；`+0x2020` → 0 号（转塔机炮，带预热计时 `+0x2030`） |
| 403 坦克（`0x17D8FA0`） | `0x5FEC38` | 座位 i（0..2）的主扳机 `seat+0x2E4 ≥ 0.8` → 持有者 i |
| 404 Titan（`0x17D9458`） | `0x5FFCA8` | 座位 i 的主扳机 → 持有者 i；左扳机 `seat+0x2E0 ≥ 0.8` → 持有者 i+3（驾驶员：主炮 / 车头机枪；炮手：副炮 / 烟幕或导弹） |
| 603 防空车（`0x17DC620`） | `0x6214A4` | 主扳机 → 0、1 两门炮一起 |
| 503 摩托（`0x17DA508`） | `0x618239` | `veh+0x29A8` → 0、1 一起（这个字节由谁写没追，M：主扳机） |
| 511 摩托 | `0x61FB9E` | `+0x29A0` → 0，`+0x29C0` → 1（分开） |
| 502 深渊爬行者 | 第 5 槽 | RT → 0，按键位 `0x10` → 1，`0x20` → 2（`docs/ground-ai-re.md`） |
| 机甲（504 / 612 / 608 一类，`0x60AEC0` 读座位块） | — | 读 `0x10`、`0x40`、`0x20`、`0x80`、`0x08` 和两个扳机，各存一个字节；哪个字节开哪只手没有追（M：每只手一个键） |

结论：
- **原版里同时开火的只有成对的双联炮**（506 的左右机炮、603、503），两门是同一种炮，分开没有意义。
- 其它多武器的座位每种武器本来就各有一个按键（Titan、502、409、506 的导弹），**不需要切换**。
- 所以「可切换的挂载」只有在给座位加了**更多**武器之后才有意义：见 §4。
- 读数里的 `PayloadFire`：上表能确定的写 `primary` / `secondary`；没读过的类，座位只有一种武器时记 `primary`（M：读过的类都是这样），多种记 `other`。

## 3. 武器状态（给 HUD 读数）

| 偏移 | 是什么 | 证据 |
|---|---|---|
| `+0x1B0` | 显示名：`const wchar_t*`（随游戏语言，`name.*`） | `0x68CC19` 存 `0x551E0` 的返回值（wstring 的数据指针）（H） |
| `+0xBE8` | 当前弹数 | （H，已知） |
| `+0x248` | AmmoCount（满载） | 读参数 `0x68C55C`；装填完成 `0x695D72` 把它写回 `+0xBE8`（H） |
| `+0x20C` | ReloadTime（帧，按星级） | `0x68C9DD`（H）；`< 0` = 不装填（`0x692152`：量表的「可装填」位，H） |
| `+0xE68` | 装填剩余帧数，从 ReloadTime 倒数 | 装填完成 `0x695D6C` 重置；`0x693F3B` 递减（H） |
| `+0x22C` / `+0xE7C` | EnergyChargeRequire / 能量武器的剩余充能 | `0x68CA3D`、`0x693E5F`（H） |

原版的武器量表 `0x692100(weapon, out)`：弹数大于 0 → 已装好；否则 `+0x22C > 0` 时进度 = `1 - E7C / 22C`，不然进度 = `1 - E68 / ReloadTime`
（`0x6921A1`..`0x6921EB`，H）。插件照这个公式自己读，不调用它（它还会调 `0x6911A0`）。剩余秒数 = `E68 / 60`。

## 4. 给原版直升机加挂载（`StockHeliStores`，默认关）

- **只有 506 类**：506 第 46 槽 `0x61B770` 按 `vehicle_setup[3]` 的第 i 项调 `SetWeaponObject 0x633330(veh, 0, &项, i)`（`0x61B82D`..`0x61B839`，H），
  插件已把它的循环次数从写死的 4 改成持有者个数（`src/stores.cpp`）。409 的第 46 槽 `0x64B3C0` 是展开写死的几次调用，多出来的挂点不会有武器，所以不加。
- **安装器**（`tools/make_stock_stores.py`）：
  - 从 Root.cpk 找出所有带来 `V506_HELI` / `V506_HELI_EDF6BENEFITS` / `V602_HELI` 的请求（`Ammo_CustomParameter` 里 `[运输机, 箱子, 载具, 设定, ...]` 那一项，共 13 个）。
  - 生成 `EDF6VC_<载具>_STORES.SGO`：原版载具 + 每种挂载一行 `['body', 0]`（座位 0），排在油箱（第 4 项）之后；自带的 `vehicle_setup[3]` 同样加上。
  - 请求的副本：载具路径换成上面的文件，武器表在原版 4 项后面加上 `EDF6VC_RKT_19`、`EDF6VC_AGM_L_4`（每项的参数照抄原版导弹那一项，和战机的挂载一样），预载列表 `resource` 同步。
  - 自检：每个生成的载具挂点数 = 武器表项数，油箱在第 4 项；每个请求的武器表项数 = 它带来的载具的挂点数。
  - 原版载具文件、关卡里的直升机、武器表都不动；`Mods/WEAPON` 里已经有别的 mod 放的同名请求时跳过（不覆盖不是自己写的文件）。归属登记在账本（owner `stockstores`），
    挂载武器文件登记为「需要」（由 make_jets 写）。
- **没有插件时**：游戏只造前 4 个挂点（机炮、机炮、导弹、油箱），就是原版直升机，不会读到不存在的项。
- **插件**（`payload.cpp` `Switch`）：玩家坐座位 0、副射击的候选（2 号原版武器 + 4 号以后的挂载武器）有两个以上时：
  - 切换键（`PlayerJetSwitchKey`，默认 R；手柄 LB）按下时换到下一个还有弹的；当前的打空且不会再装填（ReloadTime < 0）时自动换下一个。
  - 拿走 `veh+0x2021`（原版第 57 槽就不再打 2 号），改扣选中武器的扳机 `+0x139`，和原版 `0x62C000` 一样先看持有者的控制块还活着。
  - 换挂载时清掉新旧两种武器的锁定（`0x68FF60`）。挂载武器的锁定音由座舱的锁定音播（`jetaudio.cpp LockTone`；它们自己的原版锁定音被 `jetsound.cpp` 静音了），原版导弹照旧自己响。
  - `helisight.cpp` 的副武器标记跟着选中的武器走（`PayloadPicked`）：地狱火按导弹画锁定框，火箭巢按火箭画直线落点。
  - 只有一种副武器的座位不碰（原版输入照常）。

## 5. 载具内换座位（`src/seatswitch.cpp`）

原版没有这个动作：只能下车再上。原版上车按钮的流程（H）：

1. `0x56D700`（人物）：按队伍遍历附近对象，访问器 `0x572610`（vtable `0x17CFCF0` 第 1 槽）对载具调第 49 槽 FindSeat，
   FindSeat 用 `0x633FE0(veh, human, seat)` 预留座位（`0x633BFE`）。
2. 访问器：`human+0x1540 = seat`（`0x57268F`），`human+0x1548/+0x1550 = 载具弱引用`（`0x56A3D0`），`+0x15B0 = 0`（8 字节）、`+0x15B8 = 0`、`+0x15BC = 1.0`（`0x572734`..`0x572745`）。
3. `0x5763E0(human)`（`0x56D799`）：联机且是本机人物时，发**消息 6**：`{载具网络 ID, 座位下标（0x62D810）, 计数 human+0x1824}`（`0x576514`..`0x576562`）；单机什么也不做。
   其他机器收到后（人物的网络消息处理 `0x5774C0` 第 6 种，`0x5775B0`）调 **RideVehicle `0x5765E0(human, &载具弱引用, 座位)`**。
4. `0x551C30(human+0x1150, {0x56C9F0, 0}, 0)`（`0x56D7CC`）：开始乘坐动作（`0x56C9F0` 是 `jmp [rax+0x278]`，人物自己的乘坐动作）。
5. 座位 `+0x2B4`（按键配置行）== 3 时 `human+0x3F0 = 1`（`0x56D7D1`）；下车 `0x56FE80` 把它清 0（`0x56FF4B`）。

RideVehicle `0x5765E0` 对已经在同一辆车里的人（别的座位）：先 `0x57C160(human, 0, 0)` → `0x56FE80`：对旧座位调 SeatKick `0x62E1A0`
（给人物发下车消息 `0x10000015`：人物处理函数 `0x572810` → `0x5701B0` 把人放到车门外地面），再清人物的载具引用；然后预留新座位、重新开始乘坐动作。
所以在其他机器上，玩家换座位走的就是这条原版路径。

**插件的做法**（`Move` / `Take`）——上车按钮的步骤，去掉走到车门边和够不够得着的检查：

1. 旧座位：`0x634940(veh, seat)` 清掉乘员（SeatKick 末尾的那一步，不发下车消息——发了就会被放到车门外），座位输入块清回构造函数的值
   （摇杆 `(0,0,0,1)`、扳机 0、按键 0）：没有人再写它，而有的类不看谁坐着就读（502 每帧拷座位 0 的块）。
2. 新座位：`0x633FE0(veh, human, seat)`。
3. `human+0x1540` 和 `+0x15B0/+0x15B8/+0x15BC` 同访问器。
4. `0x5763E0(human)`：联机时广播（其他机器走 RideVehicle），单机无操作。
5. 乘坐动作 `0x551C30(human+0x1150, {0x56C9F0, 0}, 0)`；`human+0x3F0 = (seat+0x2B4 == 3)`。

- 目标座位上是 NPC（`DummyVehicleRider`）时先把它挪到玩家腾出的座位（`crew.cpp MoveRider`：`SeatRide 0x633C10` + `0x634940`，和挤座位 Bump 同一个办法），挪不动就把玩家放回原座位。
- 兵种：照 CanRideSeat 自己的判断（`0x6346FC`）：`human+0x31C & seat+0x34 & seat+0x30` 非 0。队伍和距离不检查（人已经在车里）。
- 任何一步出错（SEH）时把玩家放回能坐的座位（新座位已预留就留在新座位，否则回原座位），绝不让人没有座位。
- 离开原版直升机的驾驶座：座位 0 空着时调第 50 槽 RideAi（`SeatPilot=1`），NPC 飞行员接手（`heli.cpp` 带着在舱门炮位的玩家在附近找敌人打），同炮舰机炮手的 `EnsurePilot`。
  地面载具不派司机。RideAi 会把每个持有者的 `weapon+0x8B6` 清 0（`docs/heli-input-re.md` §4，作用不明，L），炮舰机的 `EnsurePilot` 也一样。
- 插件的飞机：只有炮舰机的两个座位。`playerjet.cpp` 分辨「换座」和「下车」（`AboardElsewhere`）：驾驶员换到炮手座不弹射、不叫接机，交给 NPC 飞行员（`HandBack`）；
  炮手换到驾驶座不跳伞（`GunnerFrame`）。去驾驶座只在可以上车的时候（`PlayerJetBoardable`：地面上或被叫下来等你），因为接手驾驶走的是上车的同一条路径（`Board`）。
- 联机：`0x7748F0(nullptr)` 为真时默认不换（`SeatSwitchOnline=0`）。

## 6. 待游戏内确认

1. 换座位后镜头、人物姿势、座位的武器和瞄准是否都换到新座位（乘坐动作重新开始，M）；旧座位的红色瞄准线、直升机瞄准具照常切换（`crew.cpp AimLines` 每帧按座位处理）。
2. 换座时会不会闪一下「上车动画」，人物会不会在车门外出现一帧（插件不发下车消息，M）。
3. Brute 驾驶员换到舱门炮后 NPC 飞行员接手、不掉高度；按 1 回驾驶座时 NPC 挪到舱门炮位（日志 `SEAT v=… moved`、`the pilot seat empty: an NPC pilot seated`）。
4. 坦克驾驶员换到炮手座后车不再自己开（座位 0 的输入块已清零）。
5. 炮舰机空中驾驶座 → 炮手座：不弹射（日志 `PJET v=… the player moved to another seat … no ejection`），NPC 飞行员接着飞。
6. `StockHeliStores=1`：N9 Eros 的第 5、6 个挂点有武器（原版武器栏列出火箭巢和地狱火），R / LB 轮换（日志 `PAYLOAD v=… secondary: …`），副射击打选中的那种，地狱火锁定并有锁定音，火箭沿机头直飞。
7. 键位冲突：F、数字键 1~9、手柄 B 在载具里是否被游戏另作他用（原版载具代码里只有 502 读 B：和 A 一起是跳；502 只有一个座位，不受影响）。
8. 联机（`SeatSwitchOnline=1`）：其他机器上的你是否跟着换座（消息 6），NPC 的挪动只在本机（插件的 NPC 本来就是各机自己的）。
