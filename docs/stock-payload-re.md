# 原版载具：座位武器、挂载切换、载具内换座位（逆向笔记）

EDF.dll TimeDateStamp `0x678CCB46`，地址都是 RVA。全部是静态分析（`tools/edfre.py` + capstone），**没有进游戏实测**。
置信度：H = 指令里直接读到；M = 由代码结构推出；L = 猜测。
实现：`src/payload.cpp`（座位武器读数、原版载具的挂载切换、扣扳机转发）、`src/stores.cpp`（各类补造额外挂点）、`src/seatswitch.cpp`（换座位）、`src/payload.h`（给载具 HUD 的结构）、
`tools/make_stock_stores.py`（安装器给原版载具的请求加挂载）。2026-10-06 用户：「原版载具也补充上可切换载荷的设定」「载具内多位的情况可切换至空座」。

## 1. 座位的武器列表（已知，H）

- 座位 `+0xC8` 是持有者指针数组，`+0xD8` 是个数；持有者 `+0x10` 是武器（`docs/aim-line-re.md`）。
- 持有者是载具 `+0x638` 数组（步长 0x48，个数 `+0x648`）里的元素，所以 `(持有者 - veh[+0x638]) / 0x48` 就是它在
  `vehicle_weapon_setting` 里的行号（`payload.cpp` `HolderIndex`）。
- 设置值 `<0` 的挂点（油箱 `V_FUEL01`）加进**每个**座位的列表（`docs/stores-re.md` §2），读数里去掉它（按 SGO 文件名，`stores.h` `WeaponFile`）。

结论：
- **原版里同时开火的只有成对的双联炮**（506 的左右机炮、603、503），两门是同一种炮，分开没有意义。
- 其它多武器的座位每种武器本来就各有一个按键（Titan、502、409、506 的导弹），**不需要切换**。
- 所以「可切换的挂载」只有在给座位加了**更多**武器之后才有意义：见 §4。
- 读数里的 `PayloadFire`：上表能确定的写 `primary` / `secondary`；没读过的类，座位只有一种武器时记 `primary`（M：读过的类都是这样），多种记 `other`。

## 3. 武器状态（给 HUD 读数）

| 偏移 | 是什么 | 证据 |
|---|---|---|
| `+0x1B0` | 显示名：`const wchar_t*`（随游戏语言，`name.*`） | `0x68CC19` 存 `0x551E0` 的返回值（wstring 的数据指针）（H） |
| `+0xBE8` | 当前弹数 | （H，已知） |
| `+0x248` | AmmoCount（满载） | 读参数 `0x68C55C`；装填完成 `0x695D72` 把它写回 `+0xBE8`（H） |
| `+0x20C` | ReloadTime（帧，按星级） | `0x68C9DD`（H）；`< 0` = 不装填（`0x692152`：量表的「可装填」位，H） |
| `+0xE68` | 装填剩余帧数，从 ReloadTime 倒数 | 装填完成 `0x695D6C` 重置；`0x693F3B` 递减（H） |
| `+0x22C` / `+0xE7C` | EnergyChargeRequire / 能量武器的剩余充能 | `0x68CA3D`、`0x693E5F`（H） |

原版的武器量表 `0x692100(weapon, out)`：弹数大于 0 → 已装好；否则 `+0x22C > 0` 时进度 = `1 - E7C / 22C`，不然进度 = `1 - E68 / ReloadTime`
（`0x6921A1`..`0x6921EB`，H）。插件照这个公式自己读，不调用它（它还会调 `0x6911A0`）。剩余秒数 = `E68 / 60`。

## 4. 给原版载具加挂载（`StockVehicleStores`，默认开（2026-10-07 用户：「都装mod了，肯定要打开」）；旧键 `StockHeliStores=1` 仍算开）

2026-10-07 用户：「给载具应有的多种挂载增加多种挂载。例如原版坦克、aa车、直升机等」「应该有的都得有，比如导弹车」。
挂载表见 `tools/make_stock_stores.py` 的 `LOADOUTS`（README 功能 13 有中文表）。

### 4.1 各类怎么造武器（第 46 槽，H）

每个类都对 `vehicle_setup` 的武器表第 i 项调 `SetWeaponObject 0x633330(veh, 炮塔块, &项, i)`，只造自己那几个：

| 类 | 第 46 槽 | 造法 |
|---|---|---|
| 506 直升机 | `0x61B770` | 循环写死 4 次（`cmp ebx,4` `0x61B85F`）；插件把循环上限改成挂点数（`stores.cpp` 原有的补丁） |
| 403 坦克 | `0x5FEFB0` | 循环 3 次，座位 i 的炮塔块 `veh[+0x608]+0xE0+i*0x340` |
| 404 Titan | `0x6000E0` | 展开写死 6 次 |
| 603 防空车 | `0x621A50` | 展开写死 2 次 |
| 409 直升机 | `0x64B3C0` | 展开写死 3 次 |
| 503 摩托（含 613） | `0x617CF0` | 循环 3 次（`cmp edi,3` `0x617F3C`） |
| 402 / 505 / 601 | `0x5FDBC0` / `0x61B060` / `0x620B20` | 1 次 |
| Car（格雷普 401） | `0x65A910` | 按武器表循环（`0x65B3A8` 跳回 `0x65B1EA`），会自己造出全部项 |

- 第二参（炮塔块）只在该项有第 3 个元素（炮塔转速 `[速度, 加速, 减速]`）时才写（`0x6335D1`：项数 > 2 且指针非空才调 `0x5FB810`）。挂载项只有 `[武器, 参数]` 两项，所以传 0 即可。
- 武器表项是数值（Heron YG10 的导弹位是 `0.0`）时 `SetWeaponObject` 直接返回，那个挂点没有武器：**原版就有空挂点**，不会崩。
- 插件（`stores.cpp` `InstallBuilds`）在上表除 506 外的各类第 46 槽链一个钩子：原版造完后，从最后一个有武器的挂点之后开始，按同一张武器表补造。武器表按形状找：设定里项数等于挂点数（`veh+0x648`）、第 0 项是节点的那个子表（地面载具是第 2 项、直升机第 3 项）。节点读法同 `rounds.cpp`（`0x2390D0` 取子项、`0x240AF0` 取项数，载入时校验字节）。

### 4.2 开火：扣扳机函数 `0x62C000`（H）

`0x62C000(holder)`：持有者的控制块（`+0x8`）还活着（`+8` 引用计数非 0）就把武器 `+0x139` 置 1。武器自己的更新读它并清零（`0x6935B2`）。
原版全部载具的开火都调它（21 处：402 `0x5FD943`、403 `0x5FEC93`、404 `0x5FFD03`/`0x5FFD2B`、503 `0x618240`/`0x618250`（第 5 槽）、505 `0x61AD33`、
506 `0x61B72E`/`0x61B73E`（第 57 槽）、510、511、601 `0x6207F3`、603 `0x6214C3`/`0x6214D3`、409 `0x64B071`（第 57 槽）、Car `0x6265F1` 等），分布在第 5、55、57 槽，时序各不相同。
EDF6AutoTurret（`gunner.cpp`）和 `proteus.cpp` 只**调用**它。

插件（`payload.cpp` `InstallPayload`）把这 27 字节的函数整个换成跳到 `PullHook`：同样的存活检查；持有者的武器是「已选了挂载的那组原版武器」时，扳机落到选中的挂载上，否则照原样。
重定向表只属于本机玩家所坐的那辆车，由它每帧的 `PayloadFrame` 重建，超过 200 ms 没刷新即作废。

### 4.3 分组与切换

- 额外挂载按实际 `stores.inc` 目录匹配（`stores.cpp` `IsStoreWeapon`/`StoreOf`：已知前缀、弹数与 `.SGO`），不再把全部 `EDF6VC_` 文件当挂载。钻头、喀秋莎与 Proteus 的自带定制武器也是此前缀，必须保留原生槽位控制。也不按「原版造了几个」认，因为 Car 自己会造全部项。
- 座位上有副射击的原版武器（506 的 2 号、409 的 1 号、Titan 座位 i 的 i+3 号）时，挂载跟副射击一组，否则跟主射击一组（该座位上 §2 认定为主射击的原版武器，603 的左右炮一起算一个选项）。
- 切换键（`PlayerJetSwitchKey`，默认 R；手柄 LB）按下时换到下一个还有弹的；当前的打空且不会再装填（ReloadTime < 0）时自动换下一个；换挂载时清掉新旧两种武器的锁定（`0x68FF60`）。
- 一组里没有原版武器（不认识的类、或该键的原版武器位是空的）时不切换，挂载不开火。

### 4.4 安装器（`tools/make_stock_stores.py`）

- 从 Root.cpk 找出所有带来 `LOADOUTS` 里载具的请求（86 个）。每种载具生成 `EDF6VC_<载具>_STORES.SGO`：原版挂点之后每个挂载加一行，复制它旁边那个原版挂点（骨骼、座位）；载具自带的武器表（506）同样加上。
- 请求的副本：载具换成上面的文件，武器表在原版项后面加上挂载（参数：导弹 / 火箭 `[0, 0]`，属于 `BodyRecoil` 类型），预载列表同步。
- 自检：每个载具的挂点数 = 原版 + 挂载数，挂载行是被复制的原版行；每个请求的武器表项数 = 挂点数，挂载在最后且都在预载列表里；所有挂载都是 `EDF6VC_` 文件；每种载具的类都在插件会补造的类里。
- 别的 mod 已放的同名请求跳过。EDF6AutoTurret 的防空车 / 玻尔斯请求：安装器把它要写的字节交给 `build(overlay=...)`，加上挂载后还给它写（记在它自己的清单里）；`--remove` 时还被别的工具的请求引用的派生载具保留。
- 战机也用的挂载武器文件登记为「需要」（由 make_jets 写）；战机不用的（2026-10-09 起的炮弹 APFSDS / HE / AP·HE 弹链 / 近炸高爆弹和 LAHAT 炮射导弹）由本工具自己写（`own_store_files`）。炮弹（`vcobjects.Shell`）是原版同级载具武器的拷贝，只改载弹量和名字；它在请求武器表里的参数复制所挂原版主炮的 BodyRecoil 数对（导弹 / 火箭仍是 `[0, 0]`）。旧的同轴机枪已撤销。各载具的挂载按类别给出（`CATEGORIES` / `REQUIRED`），盘点与依据见 `docs/feedback-2026-10-09-loadcamp.md`。
- 挂载打出去的弹体按弹种换模型、按真实长度缩放（AIM-9X / AIM-120 / AGM-65 / AGM-114 / Hydra 70 各不相同），和插件飞机同一套文件，见 `docs/stores-re.md` §10。
- 卸载：两种卸载方式都删它们（没有插件就没人造额外挂点、也没人开火）；只删插件（选项 2）时，AutoTurret 的数据留着，安装器先让它把防空车请求按不带挂载的版本重写（`installer.uninstall_stock_stores`），再删派生载具。

## 5. 载具内换座位（`src/seatswitch.cpp`）

原版没有这个动作：只能下车再上。原版上车按钮的流程（H）：

1. `0x56D700`（人物）：按队伍遍历附近对象，访问器 `0x572610`（vtable `0x17CFCF0` 第 1 槽）对载具调第 49 槽 FindSeat，
   FindSeat 用 `0x633FE0(veh, human, seat)` 预留座位（`0x633BFE`）。
2. 访问器：`human+0x1540 = seat`（`0x57268F`），`human+0x1548/+0x1550 = 载具弱引用`（`0x56A3D0`），`+0x15B0 = 0`（8 字节）、`+0x15B8 = 0`、`+0x15BC = 1.0`（`0x572734`..`0x572745`）。
3. `0x5763E0(human)`（`0x56D799`）：联机且是本机人物时，发**消息 6**：`{载具网络 ID, 座位下标（0x62D810）, 计数 human+0x1824}`（`0x576514`..`0x576562`）；单机什么也不做。
   其他机器收到后（人物的网络消息处理 `0x5774C0` 第 6 种，`0x5775B0`）调 **RideVehicle `0x5765E0(human, &载具弱引用, 座位)`**。
4. `0x551C30(human+0x1150, {0x56C9F0, 0}, 0)`（`0x56D7CC`）：开始乘坐动作（`0x56C9F0` 是 `jmp [rax+0x278]`，人物自己的乘坐动作）。
5. 座位 `+0x2B4`（按键配置行）== 3 时 `human+0x3F0 = 1`（`0x56D7D1`）；下车 `0x56FE80` 把它清 0（`0x56FF4B`）。

RideVehicle `0x5765E0` 对已经在同一辆车里的人（别的座位）：先 `0x57C160(human, 0, 0)` → `0x56FE80`：对旧座位调 SeatKick `0x62E1A0`
（给人物发下车消息 `0x10000015`：人物处理函数 `0x572810` → `0x5701B0` 把人放到车门外地面），再清人物的载具引用；然后预留新座位、重新开始乘坐动作。
所以在其他机器上，玩家换座位走的就是这条原版路径。

**插件的做法**（`Move` / `Take`）——上车按钮的步骤，去掉走到车门边和够不够得着的检查：

1. 旧座位：`0x634940(veh, seat)` 清掉乘员（SeatKick 末尾的那一步，不发下车消息——发了就会被放到车门外），座位输入块清回构造函数的值
   （摇杆 `(0,0,0,1)`、扳机 0、按键 0）：没有人再写它，而有的类不看谁坐着就读（502 每帧拷座位 0 的块）。
2. 新座位：`0x633FE0(veh, human, seat)`。
3. `human+0x1540` 和 `+0x15B0/+0x15B8/+0x15BC` 同访问器。
4. `0x5763E0(human)`：联机时广播（其他机器走 RideVehicle），单机无操作。
5. 乘坐动作 `0x551C30(human+0x1150, {0x56C9F0, 0}, 0)`；`human+0x3F0 = (seat+0x2B4 == 3)`。

- 目标座位上是 NPC（`DummyVehicleRider`）时先把它挪到玩家腾出的座位（`crew.cpp MoveRider`：`SeatRide 0x633C10` + `0x634940`，和挤座位 Bump 同一个办法），挪不动就把玩家放回原座位。
- 兵种：照 CanRideSeat 自己的判断（`0x6346FC`）：`human+0x31C & seat+0x34 & seat+0x30` 非 0。队伍和距离不检查（人已经在车里）。
- 任何一步出错（SEH）时把玩家放回能坐的座位（新座位已预留就留在新座位，否则回原座位），绝不让人没有座位。
- 离开原版直升机的驾驶座：座位 0 空着时调第 50 槽 RideAi（`SeatPilot=1`），NPC 飞行员接手（`heli.cpp` 带着在舱门炮位的玩家在附近找敌人打），同炮舰机炮手的 `EnsurePilot`。
  地面载具不派司机。RideAi 会把每个持有者的 `weapon+0x8B6` 清 0（`docs/heli-input-re.md` §4，作用不明，L），炮舰机的 `EnsurePilot` 也一样。
- 插件的飞机：只有炮舰机的两个座位。`playerjet.cpp` 分辨「换座」和「下车」（`AboardElsewhere`）：驾驶员换到炮手座不弹射、不叫接机，交给 NPC 飞行员（`HandBack`）；
  炮手换到驾驶座不跳伞（`GunnerFrame`）。去驾驶座只在可以上车的时候（`PlayerJetBoardable`：地面上或被叫下来等你），因为接手驾驶走的是上车的同一条路径（`Board`）。
- 联机：`0x7748F0(nullptr)` 为真时看 `SeatSwitchOnline`（默认 1，可换；0 不换）。

## 6. 待游戏内确认

1. 换座位后镜头、人物姿势、座位的武器和瞄准是否都换到新座位（乘坐动作重新开始，M）；旧座位的红色瞄准线、直升机瞄准具照常切换（`crew.cpp AimLines` 每帧按座位处理）。
2. 换座时会不会闪一下「上车动画」，人物会不会在车门外出现一帧（插件不发下车消息，M）。
3. Brute 驾驶员换到舱门炮后 NPC 飞行员接手、不掉高度；按 1 回驾驶座时 NPC 挪到舱门炮位（日志 `SEAT v=… moved`、`the pilot seat empty: an NPC pilot seated`）。
4. 坦克驾驶员换到炮手座后车不再自己开（座位 0 的输入块已清零）。
5. 炮舰机空中驾驶座 → 炮手座：不弹射（日志 `PJET v=… the player moved to another seat … no ejection`），NPC 飞行员接着飞。
6. `StockVehicleStores=1`：各载具多出来的挂点有武器（日志 `STORES v=… holder N built`，需 `Debug=1`；载具 HUD 列出它们），R / LB 轮换（日志 `PAYLOAD v=… picked: …`），开火键打选中的那种、原版武器不开；坦克的导弹从炮口出；防空车的 AIM-9X / AIM-120 锁空中目标；Titan 的导弹走左扳机；摩托（开火在第 5 槽）同样能切。
7. 键位冲突：F、数字键 1~9、手柄 B 在载具里是否被游戏另作他用（原版载具代码里只有 502 读 B：和 A 一起是跳；502 只有一个座位，不受影响）。
8. 联机（`SeatSwitchOnline=1`）：其他机器上的你是否跟着换座（消息 6），NPC 的挪动只在本机（插件的 NPC 本来就是各机自己的）。

## 6. 挂载选择与火控视图分离（2026-10-08 集成审查）

- `PayloadPicked` 仍表示副触发组当前选中的原版副炮/挂载，重定向与弹药列表语义不变。
- `PayloadSightPicked(vehicle, seat)` 是独立的火控目标。默认选当前座位真实主炮；主/副扳机的新边沿切换火控，同帧两个新边沿时主炮优先。R/LB明确轮换挂载也切换到该挂载的瞄具，可先瞄准而不必先发射；随后主触发切回它真正控制的武器。若该类挂载替换的是主触发，火控跟随真实重定向，不能虚构仍在发射原主炮。
- 开镜能力、StockHudReadout.sight、炮塔镜头弹道都使用同一火控目标；StockHudReadout.selected继续独立高亮已选副挂载。同车换座、换人、换车回到新座位主炮；进入时已按住的键/扳机及地图占键不生成新边沿。
- 每次查询验证当前本机乘员、holder强引用与实时列表。可装填武器空弹时保留瞄具；永久耗尽、被移除或已过期的副挂载安全退到可用主炮，没有可用武器则无瞄具。`PullHook` 同时验证重定向目标holder强引用，不能在视图已回退后向失效旧武器写trigger。
- `payload_sight_test` 直接运行生产payload.cpp，Titan使用真实holder stride `0x48` 和 `s` / `s+3` 控制分组，覆盖40项输入、预瞄、重定向、座位/身份、装填/过期边界；它是离线内存夹具，不是实机输入或发射验证。
