# 地面支援载具生成契约

`support_spawn.h/.cpp` 只负责经过入口规划后创建真实车体；入口、真实机组上座、可行驶路线、到达和空车交付由支援协调层负责。返回非空不是“已经有司机”或“已到达”。

## 已核实资源

2026-10-08 只读本机 Root.cpk，三个资源均自带 `mission_setup`、原版模型、碰撞、真实座位和门口定位点。尺寸为 MDB bind pose 的保守外包围，包含坦克炮管；关于车体原点的半长取前后最大值。入口规划还须保留坐在露天车斗中的人的净空和车辆转弯空间。

| 枚举 | 原版 OBJECT 资源 | 原版类 | 座位（含司机） | 半宽 / 半长 / 高，米 |
|---|---|---|---|---|
| tank | V505_TANK_MISSION.SGO | Vehicle505_Tank | 1 | 1.61 / 5.60 / 2.63 |
| transport | V507_RESCUETANK_AI.SGO | Vehicle507_Rescuetank | 5 | 3.19 / 5.95 / 6.68 |
| civilianTruck | V512_KEITRUCK_BGP.SGO | Vehicle_Car | 5 | 1.04 / 2.18 / 2.65 |

装甲运兵使用现有救援装甲车的真实四个乘客位。民用轻卡使用现有四个车斗座位。没有增加座位数量，也没有钻头运兵资源、钻入动画或碰撞穿透能力。

`SupportVehicleEnvironmentAllowed` 在废土只允许民用轻卡，在地下不一律禁止地面车辆；实际入口与车辆包围的可达性必须通过。此模块不猜测当前地图是否废土，也不以任务编号代替环境识别。未知环境枚举失败关闭。

## 原生事务

使命预加载调用 `0x7A3780(manager,sgo,2,-1)`。每次先清本使命的 readiness 和车体回滚登记；校验失败不沿用前一使命状态。出错资源在本进程剩余使命保持禁用。

生成按照：验证枚举/有限坐标/朝向与预加载 → `CreateObject` (`0x11945E0`) → 校验真实 vtable/座位 → `0x62D6E0` 读取 `mission_setup` → slot 46 应用 → 按 `0x1765220` 的变体析构表释放临时 setup → `SetTeam(friend, registered=true)` → 原生 `SetLevel(1)` → `NoteLocalCopy`。独立 setup 路径与 `playerjet.cpp` 空接机的路径相同，但以失败返回和回滚为契约，不吞失败继续交付。完全不调用 `RideAi` 或 `SeatNpcRider`。

`owner` 是 `NoteLocalCopy` 的 parent；未登记 parent 时继承调用方 `SetSpawnOwner` 作用域，与 jet Launch 一致。联网的协调层还必须分配可靠实例 ID 并经原生注册接口登记各端对象；本模块不把 `NoteLocalCopy` 冒充网络对象注册。

失败后删除已返回的半初始化车体并禁止该资源继续重试。若原生构造内部在返回指针前异常，插件不能取得该半构造指针，只能关闭该资源并记日志；不能声称此类原生异常可以完全回收。回滚 API 只接受本模块记住且 weak identity 仍相同的空车；任何座位已有乘员都拒绝删除，协调层须先取消登车并处理真实乘员。最多保存 64 个本使命支援车体。

`soldiers` 表示到达后保留真实机组。`unmanned` 的业务含义固定为空车交付：仍由真实司机从场外开进来，停稳后经原生下车流程离开；不能显示为“自主无人车”，不能在交付前略过司机上座，不能用隐藏 Dummy 代替司机。

## 验证边界

`support_spawn_test` 执行生产 C++ 事务，原生服务是明确的合成回调，覆盖成功顺序、错枚举、无朝向/NaN、使命重置、setup 异常析构/回滚、错误原生类、占用车体禁止删除与环境筛选。它不执行 EDF 原生物理或游戏世界。

`python tests/support_resource_audit.py` 只读 Root.cpk 和 EDF.dll，核对生成代码的原生签名、三个类的 slot 46、真实座位/门口定位点、模型包围和无 Dummy 调用。缺少本机游戏数据时明确跳过（77）。未启动/关闭游戏、注入或写安装目录；真实模型显示、上下车姿态、碰撞、道路驾驶和多人复制仍须后续实机验收。
