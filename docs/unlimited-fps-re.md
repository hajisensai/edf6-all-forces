# 不限帧率：60 帧锁、按帧推进的时钟与渲染 / 模拟解耦方案

2026-11-10。对象是 Steam 版 EDF.dll（`0x678CCB46`）。维护者原话与来源见 `docs/feedback-2026-11-10-unlimited-fps.md`。
相关：`docs/frame-pacing-re.md`（tick 时钟 `0x11DAE60`、主循环按帧执行的点）、`docs/camera-re.md`、`docs/fp-render-re.md`、`docs/hud-re.md` §10。

证据级别：**H** = 本次或之前用 `tools/edfre.py` 只读 EDF.dll 反汇编逐条核实；**M** = 静态读到了主要路径、个别环节没逐层核实；
**L** = 只有第三方研究包（不可信数据）的说法或推断，未核实。

## 0. 结论

1. EDF6 的 60 帧锁**不是垂直同步**，是主循环的 tick 门：`0x11DAE60` 按 1/59.94 s 数「距上个边界过了几个整 tick」（n），
   n = 0 就 `Sleep(1)` 再数（本插件已把这个等待换成 `TickWait`，见 `frame-pacing-re.md`）。整个模拟按 tick 步进：
   `System::Update` 先渲染、再把场景步进 n 次（H）。
2. 只拿掉等待（社区流传的两字节补丁，就是把 `0x11A2F65` 的 `Sleep` 与 `0x11A2F74` 的 `je` NOP 掉）后，主循环会跑 n = 0 的帧：
   模拟**不会**变快（步进只按 tick），但这些帧画的是同一个状态（重复帧，看起来仍是 60 帧），并且下面 §2 那些「按帧」而不是
   「按 tick」跑的点会出错：植被风加速、滚轮与按键边沿丢失、鼠标位移丢失、输入抑制倒数加快、网络更新变频繁。
3. 把模拟改成按真实时间变步长（「所有按帧推进的时钟改按时间」）**不可行**：游戏数据本身以帧为单位——武器 SGO 的装填 / 连射 /
   弹速（米/帧，`carrier-laser-re.md`）、AI 与动作的计时、`System+0xCE4` 每 tick 加 1/60、动作重复倒数按 n 减（§2.4），
   Havok 世界按固定步长步进，联机两端按 tick 对齐。要改就得把数千处常量与所有对象的更新函数一起改，且无法证明与原版一致。
4. 正确的根因方案：**模拟留在 59.94 Hz，多出来的帧只做呈现**，在「上一步」与「这一步」两个模拟状态之间按相位插值渲染侧的数据
   （镜头、角色与载具的骨骼、粒子 / 拖尾 / 弹、植被风、着色器时间），并把 §2 那些按帧跑的点改回按 tick 节奏。显示时间比模拟晚一个
   tick（16.7 ms），换来连续的画面。这也是第三方研究包（§3）选的方向；它做了几个月，**只有镜头一项有实机遥测**，整体未验收。
5. 本 PR 是阶段 1：纯逻辑（呈现槽、渲染相位、刚体插值、输入边沿保留）+ 离线检查 + ini `FrameRateCap`（只读取，**未接入游戏**）。
   游戏侧的接入（阶段 2 起）每一步都必须实机验收，见 §5、§7。

## 1. 主循环与 System::Update（H）

```
0x11A2EDA: lea ebp,[rsi+3]                     ; ebp = 3（每帧最多补 3 个 tick）
0x11A2F4F: call 0x11DAE60 ; 0x11A2F54: mov ebx,eax ; test eax,eax ; jne 0x11A2F76
0x11A2F60: mov ecx,1 ; 0x11A2F65: call [Sleep]（插件：TickWait）
0x11A2F6B: call 0x11DAE60 ; 0x11A2F70: mov ebx,eax ; test eax,eax ; 0x11A2F74: je 0x11A2F60
0x11A2F76: cmp ebx,ebp ; cmova ebx,ebp         ; n = min(n, 3)
0x11A2F83: call 0x66D00                         ; dt = 秒表（实际帧间隔），1/dt 存为帧率显示
0x11A2FAC: [rdi+9] 置位时清掉并令 dt = 0、n = 0（原版自己的 0 tick 帧，谁置位未查）
0x11A2FCF: [rsp+0xB8] = {dt, n}
0x11A2FF3: call 0x1182A10                       ; 输入对象 [0x20B2888] 的回调（鼠标位移、滚轮取走在这里，§2.4）
0x11A3006: call [rax+8]                         ; Application::Update(0x705530)({dt, n})
0x11A305A: call 0x111CC20                       ; 等渲染线程栅栏
0x11A306B..0x11A3079: [rdi+0xC] 每帧减 1；n > 1（追帧）时置 8；0x111D890(dl = [rdi+0xC]==0)
```

`System::Update`（`0x1198DA0`，`0x705715` 调，`r12d = n`）：

```
0x1198E0A..0x1198E33: 未暂停时 System+0xCE4 += n * (1/60)，再 0x112BAA0 把它发给 XGL 着色器时间
0x1198E3E / 0x1198ED0: 非任务状态（加载等）各自按 n 循环
0x1198FA4: call 0x11978D0                       ; 渲染：0x1197B50 → 0x118DFF0（读镜头 +0x220 建视锥、交 Umbra）→ 绘制
0x1198FB0: test r12d,r12d ; je 0x1199734        ; n = 0：整段跳过
0x1198FD0..0x119972E: 每个 tick 一轮：场景步进计数 +0xCE0 += 1（插件的 GameFrame）、所有对象更新、
                      0x11995A6 call 0x118DF40（视口镜头第 4 槽步进：CharacterGhostCamera 0xF86A0 写 cam+0x220）
```

所以：**一帧的渲染在它的步进之前**，画的是上一帧最后一步之后的状态；镜头只在步进里动（H）。第三方实测「主循环与 Present 超过 60，
但不同的镜头矩阵每秒只有约 60 个」（§3）与此一致。

## 2. 耦合点：n = 0 的帧会怎样

### 2.1 按 tick 走、不受影响的（H）

| 子系统 | 位置 | 说明 |
|---|---|---|
| 全部对象更新、物理、AI、武器、弹 | `0x1198FD0..0x119972E` | 按 n 循环 |
| 视口镜头步进 | `0x11995A6 → 0x118DF40` | 在 tick 循环内（暂停时 `0x119953B` 起另走一遍，也只在跑 `System::Update` 的帧） |
| 游戏时间 `System+0xCE4` | `0x1198E0A` | += n/60；n = 0 时不动，着色器时间发同一个值（画面上就是 60 Hz 的阶梯，见 §2.3） |
| 动作重复倒数 | `0x1182C22: sub [rcx+8],r10d`（r10d = n） | 按 tick 减，重复速率不受帧率影响 |
| 本插件的逻辑 | `crew.cpp SharedFrameTick` 等 | 以 `GameFrame()`（场景步进计数 `+0xCE0`，tick 循环内 `0x1198FD0`）去重，由对象更新驱动，不会多跑 |

### 2.2 每帧都跑、n = 0 帧会多跑的（H，`Application::Update` `0x705530`）

| 位置 | 是什么 | n = 0 帧的后果 | 处理（阶段 2） |
|---|---|---|---|
| `0x705633..0x7056AE` | `SteamAPI_RunCallbacks`、前台状态 → `EOS_Platform_SetApplicationStatus`、`0x788460`（全局 `[0x20B2AC8]` 的 Update，第三方称 net::Network::Update，名未核实）、`0x12ADB30`（内调 `EOS_Platform_Tick`） | 调用频率随帧率涨；联机层（含 EDF6Coop 的钩子）的节奏变了 | 只在 n ≥ 1 的帧跑整块（跳到 `0x7056B3`），保持原节奏 |
| `0x7056BA` | `0x1230A0(MapMgr)`：`0x12341F` 处 `MapMgr+0xCC += MapMgr+0xC8`，`+0xC8` 在 `0x121555` 初始化为 `0x3C4CCCCD`（0.0125） | 植被风时间按帧加：帧率翻倍风就快一倍 | 只在 n ≥ 1 的帧调；画面上的风用 `+0xCC + 0xC8 * 相位` 插值（阶段 5） |
| `0x705963` | `Application+0x6C`（输入抑制倒数）`> 0` 时每帧 `dec` | 抑制时间随帧率缩短 | n = 0 帧不减（`[r14+4]` 就是 n） |
| `0x7058C7 → 0x77320 → 0x7CDC0` | 输入管理器每帧更新，逐个动作调 `0x1182BC0`（全 EDF.dll 154 处调用） | 见 §2.4：按键边沿丢失 | 边沿保留（`frame_rate_logic.h` `Shadow`） |
| `0x7058F7` `0x119D270`、`0x705946` `0x7B3010`、`0x705957` `0x7AF3E0`（声音）、`0x7059BE` `0x11A1CA0` | 都传 `dt`（`[r14]`） | 按时间推进的，帧率无关（**M**：传参核实了，内部没逐个看；UI 动画是否全按 dt 要实机看） | 无；实机清单 §7 |
| `0x7058B7` `0x11977F0` | HUD / 渲染派发 | 每帧画，正常 | 无 |

### 2.3 渲染侧的「时钟」（n = 0 帧画同一个值 → 仍是 60 Hz 的动画）

| 数据 | 位置 | 级别 | 插值办法 |
|---|---|---|---|
| 玩家镜头世界矩阵 | `CharacterGhostCamera`（vtable `0x1768C10`）`cam+0x220..+0x25F`，步进写、`0x118DFF0` 渲染读（`0x118E0FF` 交 Umbra） | H | 存上一步与这一步，渲染前按相位刚体插值（`InterpolateRigid`），渲染后还原 |
| 着色器时间 | `System+0xCE4` → `0x112BAA0` → XGL 状态 `+0x158`（第三方说法，`+0x158` 未核实） | M | 发 `时间 + 相位/60`，不写回 `+0xCE4` |
| 植被风 | `MapMgr+0xCC` | H | `+0xCC + +0xC8 * 相位`，在读它的渲染点替换（第三方列了 6 处读点，未核实：L） |
| 角色 / 载具骨骼 | CAS 蒙皮（第三方：`0x11009A0` / `0x1100F10`，3 个调用点）| L | 每个模型存两步的骨骼矩阵，渲染时插值；最大的一块 |
| 粒子、拖尾、带状特效、天气、弹 | 各自的更新 / 提交路径 | L | 逐类找位置历史；第三方做到静态，从未实机跑过 |

只插值镜头、不插值角色时，角色（尤其第三人称下镜头跟着的玩家）相对画面会按 tick 抖：镜头每帧都在动，角色只在 tick 帧动。
第三方的用户实测正是「镜头顺了，但跳跃等动作仍像 60 帧，并且有卡顿」（§3）。所以**镜头插值不能单独发布**，至少要和玩家角色、
载具的根变换一起上。

### 2.4 输入（H）

- **按键边沿**：`0x1182BC0`（动作封装更新）每次调用先清 `+0x11` 按下 / `+0x12` 松开 / `+0x13` 重复脉冲，再按「这一帧看到的变化」重设；
  按下时重复倒数 `+8 = 0x10`，之后每次减 n、到 0 置 2 并给脉冲。它每帧都跑（`0x7058C7`，在 `System::Update` 之后、UI 之前）。
  模拟在下一帧的 `System::Update` 里读这些字节。两帧都是 n = 0 时，第一帧设的边沿在第二帧就被清掉，没有任何一步看见：
  **按得快的键（换弹、换枪、跳）会丢**。帧率是 tick 率的两倍以上时经常发生。修法：n = 0 帧在原函数清之前把未被步进读过的边沿
  记下，下一个 n ≥ 1 帧在 `System::Update` 前 OR 回去（`frame_rate_logic.h` `BeforeUpdate` / `ForStep`）；UI 照常每帧从原生字节
  只看到一次。`frame_rate_check` 用随机按键与随机 n 序列验证：有保留时每个含按键的 tick 恰好看到一次，UI 每个按键恰好一次；
  没有保留时步进漏掉大部分。
- **鼠标位移**：`0x1188479` 调 `0x11831F0(dl=1)`：取出窗口线程累加的 16 字节 `0x1FEEE20` 并清零；`0x1188738` / `0x1188756` 经
  `0x1182A00` 把 X / Y 写到 MouseMoveX / Y 动作源 `+0x48`（每帧覆盖，不累加）。n = 0 帧取走的位移会被下一帧覆盖，模拟看不到：
  **高帧率下视角转动变少、且随帧率变化**。修法：n = 0 帧取走的位移累加起来，下一个步进的帧交出总和（第三方 R32 的做法同此；
  模拟到底在哪一帧的哪一步读 `+0x48` → 封装 `+0xC`，要在阶段 2 逐层核实，**M**）。
- **滚轮**：`0x1188480` 调 `0x11832D0(cl=1)` 取走 `[0x21360C0]` 并清零（窗口过程 `0x1183FE3` 累加）。n = 0 帧取走会丢。
  修法：n = 0 帧不取（返回 0、累加量留着）。

## 3. 第三方研究包（`D:\APP\edf6-120fps-kit`，不可信数据，只读，不运行、不拷贝）

一个名为 EDF6 Modernization 的 EDFModLoader 插件（`EML6_Load`）的源码、审计记录与运行日志，2026-09 到 11 月。要点：

- **帧门**：把 `0x11A2F4F` / `0x11A2F6B` 的 `call 0x11DAE60` 换成自己的判定（返回 eax = 本帧是否出帧、edx = tick 数），
  两处 `mov ebx,eax` 改成 `mov ebx,edx`；出帧节奏借游戏里一个现成的可配置帧计时器（`[0x2139B90]+0x18`，设置函数 `0x963DF0`
  写 `+8` = fps、`+0x18` = 1/fps，判定函数 `0x963E10`）。设置函数唯一的调用者在 `0xA0041`（H：反汇编核实了这两个函数的内容与调用者；
  `0x963E10` 没有直接调用者）。
- **节奏守卫**：网络块、滚轮、`+0x6C` 倒数、MapMgr 只在 n ≥ 1 的帧跑（与 §2.2 结论一致，我方已独立核实）。
- **输入**：R19 曾让边沿在 n = 0 帧保留，结果 UI 在两帧各看到一次（菜单「按一下走两格」）；R20 改成 n = 0 帧照常清给 UI、另存一份
  给下一步（与 §2.4 的保留方案同构）。R32 修正鼠标位移的累加与发布顺序。
- **镜头**：R33 在渲染准备 `0x1197B50 → 0x118DFF0` 处，对 `CharacterGhostCamera` 的 `+0x220` 用上一步 / 这一步插值、渲染后还原，
  以 `+0x52C`（第三方称步进代数，**未核实**）判断是否新的一步。实机遥测（RTX 3060 笔记本，离线）：模拟 59.92 Hz、Present 约
  90 Hz、运动中每秒约 90 个不同的镜头矩阵。**用户反馈：镜头顺了，但仍有卡顿，跳跃等动作仍像 60 帧。**
- **其余域**：角色骨骼（A2）、植被（F1）、着色器时间（X1）、粒子 / 拖尾 / 带状 / 天气 / 弹（V1R-D1-U1）都只到「静态检查通过」或
  「链接产物审计通过」，**没有一个跑过实机**。其文档自己写明「完整的 120 帧视觉 / 游戏未建立」。
- **被否决的**：跳过 Umbra `resolveVisibility`（加载卡死）、Umbra 重发缓存（无收益）、辅助可见性降频（黑闪、阴影成块更新）。
- **性能**：n = 0 帧并不便宜。其分析里图形工作线程栅栏约 7 ms、Umbra `processVisibility` 每帧约 3 次、每次约 3 ms；某次测得
  n = 0 帧约 9.1 ms、n ≥ 1 帧约 5.5 ms（L，单机单场景）。也就是说在中端机上，解耦后实际能到的帧率大概在 90 上下，
  「不限帧率」的上限由每帧渲染成本决定。

我方没有拷贝它的任何代码或二进制；地址都按上面的级别自己核实过才写进本文。

## 4. 方案

### 4.1 帧门（阶段 2）

- 把 `0x11A2F4F` / `0x11A2F6B` 两处 `call 0x11DAE60` 指向一个近处小桩：`sub rsp,28h; call 判定; mov rdx,rax; shr rdx,32; add rsp,28h; ret`，
  两处 `mov ebx,eax`（`8B D8`）改成 `mov ebx,edx`（`8B DA`）。判定返回低 32 位 = 出不出帧、高 32 位 = tick 数。小桩在
  `AllocateNearCode` 的页里，用 `RtlAddFunctionTable` 登记 unwind（`UWOP_ALLOC_SMALL 0x28`），异常回溯能穿过它。
- 判定（`frame_rate_logic.h`）：先看呈现槽（`Ready`），没到就返回「不出帧」——**不调** `0x11DAE60`，因为它一数就把 `last`
  往前推，数了不出帧那几个 tick 就丢了；到了才调原 `0x11DAE60` 拿 n（可以是 0）。所以 tick 照原版边沿对齐，模拟长期保持
  59.94 Hz；步进最多被推迟一个槽（`frame_rate_check` 在 61 / 120 / 144 / 240 / 1000 / 不限下各跑 30 s 假时钟：每个过去的 tick
  恰好步进一次，显示时间单调、不跳）。
- 等待：循环里的 `Sleep(1)` 已是 `TickWait`；开启后改为等到下一个槽（`WaitCounts`），不再等 tick 边界。`FrameRateCap=-1` 不等。
- 垂直同步：交换链的 SyncInterval 由游戏设置决定（`0x1118B45` 处 `Present(SyncInterval, 0)`，参数来自一个打包结构，来源未查，M）。
  开着垂直同步时帧率上限是显示器刷新率；144 Hz 显示器能到 144，60 Hz 显示器开垂直同步就没有意义。

### 4.2 节奏守卫（阶段 2，§2.2 / §2.4）

网络块、滚轮、`+0x6C` 倒数、MapMgr 只在 n ≥ 1 帧跑；按键边沿保留；鼠标位移累加。阶段 2 结束时画面仍是 60 Hz 的重复帧，
但可以实机验收「模拟节奏、输入、联机不受影响」这一层，然后再加插值。

### 4.3 插值（阶段 3 起）

相位 `RenderAlpha`：n ≥ 1 的帧为 1（渲染在步进之前，画的就是这一步），n = 0 的帧为距上个边界的 tick 比例。每个域存「上一步 /
这一步」，在渲染读它的那一刻换成插值值、渲染后还原（不写回模拟状态）。遇到断点（瞬移、切镜头、换地图、载入）不插值：
`InterpolateRigid` 对超过 `maxMove` 米 / `maxTurn` 弧度、非刚体、手性不同、NaN 一律拒绝，调用方照原样渲染。

- 阶段 3：玩家镜头 + 玩家角色 / 所乘载具的根变换（两者必须同时上，见 §2.3）。插件自己改 `cam+0x220` 的功能（地图俯视 `map.cpp`、
  第一人称 `firstperson.cpp`、敌控镜头、遥控武器站视角、炮塔镜头）都在步进里写，渲染前插值覆盖的是它们写完的结果，正常；但
  它们切换时是断点，要靠 `InterpolateRigid` 的拒绝或显式「本步是切换」标记，阶段 3 逐个核对。
- 阶段 4：所有角色 / 载具 / 敌人的骨骼。
- 阶段 5：植被风、着色器时间、粒子 / 拖尾 / 弹。

### 4.4 联机

## 6. 离线检查（阶段 1）

`cmake --build build --target frame_rate_check && build\frame_rate_check.exe`（已加入 `offline_checks` 与 ctest）：

- `FixCap`：0 关、-1 不限、1..60 当关、< -1 当关、> 1000 夹到 1000；`PresentPeriod` 向上取整，帧率永不超上限。
- 呈现槽：随机帧耗时下从不在槽前出帧、20 s 平均不超上限；廉价帧恰好在上限；长帧之后下一帧立即出、再下一帧隔一整个周期
  （不补发）；略晚的帧保持相位不漂移；QPC 64 位回绕。
- 整个循环在假时钟上 30 s：tick 只在出帧时数，步进总数 = 过去的 tick 数，模拟 59.94 Hz；显示时间（步数 - 1 + 相位）单调不退，
  且一次前进不超过一个 tick 加一个槽。
- 渲染相位：步进帧为 1、边界上为 0、过了 tick 未数时夹到 1、QPC 回绕。
- 刚体插值：2000 个随机旋转（含镜像）的四元数往返；端点精确；1/4 处的偏航与位移；镜像保持镜像；跨 ±π 走短弧；瞬移、大转角、
  手性不同、缩放、NaN、相位越界一律拒绝；第 4 列取当前。
- 按键边沿：20 万帧随机按键 / 随机 n：有保留时步进与 UI 各恰好一次，无保留时步进漏键（对照）。

## 7. 实机验证清单（阶段 2 起，逐项 A/B，`FrameRateCap=0` 对照）

1. `FrameRateCap=0`：与原版逐项一致（日志无 FRAMERATE 行以外的变化）。
2. 帧门：日志统计每 5 s 的 tick 率（应 59.9 左右）与出帧率（应接近上限或显示器刷新率）；垂直同步开 / 关各一次；菜单、载入、
   任务、暂停、过场动画、结算页都要跑到。
3. 无加速：植被随风摆动的速度、UI / HUD 动画（选单展开、伤害数字、雷达扫描）、声音、菜单按住方向键的重复速度，与 60 帧对照一致。
4. 输入：快按换弹 / 换枪 / 跳 / 翻滚 100 次不丢；鼠标同样移动量转过的角度与 60 帧一致（固定 DPI 下来回甩）；滚轮切换武器每格一次。
5. 联机：一人开、一人不开同房间打一关，敌人位置、伤害、任务进度一致；EDF6Coop 日志无异常。
6. 镜头插值（阶段 3）：快速转视角、奔跑、载具高速、地图开关、第一人称开关、敌控 / 炮塔镜头切换时无跳变、无黑闪；
   第三人称玩家角色相对画面不抖。
7. 性能：同场景帧时间分布（perfrun），n = 0 帧的成本；出帧率在中端机上实际能到多少。
8. 退出任务、返回主菜单、重开 20 次无卡死、无闪退。
