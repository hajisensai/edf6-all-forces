# 原版地面车的极速：来源、单位与运行时位置（2026-10-26）

起因：用户看到 ini 里「1 / 2 / 3 挡保持这类车最高速度的 1/4、1/2、3/4（重车 16、轻车 22、摩托 30 m/s 为基准）」后要求「按每辆车自己的真实极速分挡，不按车型类别的固定基准」。本节记录极速从哪来、在运行时对象哪个偏移、单位，以及原版 SGO 的交叉核对。静态逆向，EDF.dll TimeDateStamp `0x678CCB46`，未开游戏。核对脚本：`tests/drive_gear_native_audit.py`（ctest `drive_gear_native`）。

置信度：H = 指令级读到且多处一致；M = 推断链条完整但有一环没跟到底；L = 推测。

## 1. 齿轮表（CarBase，所有原版地面车共用）(H)

- CarBase 在 `+0x1758` 有一个齿轮向量：起始指针 `+0x1760`，行数（64 位）`+0x1770`，每行 16 字节 `{速度, 升挡速度, 降挡速度, 驱动力}`（后两项的「升 / 降挡」含义按 slot 58 的比较推断，M；速度与驱动力 H）；`+0x1778` 是空挡行，`+0x1788` 是倒挡行（同样 16 字节）。当前挡位下标在 `+0x1B24`（-1 倒挡、-2 空挡、0.. 前进挡）。`0x66DE90` / `0x67AE95` 等按这个下标取行：`-1 → +0x1788`、`-2 → +0x1778`、否则 `[+0x1760] + i*16`。
- 读入：
  - `car_base_engine_gear`（Striker、卡车、摩托等）`0x66D070` 起：`[0]` 前进挡各行、`[1][0]` 倒挡行。SGO 里每行 `[速度, 升挡比, 降挡比, 驱动力]`，升 / 降挡是相对本行速度的比例。
  - `car_base_engine_simple_gear`（坦克类）`0x66DA46` 起：`0x66DAB3` 把向量置为 1 行，行 0 速度 = `[0][0]`（`0x66DB3B`），倒挡速度 = 它的相反数（`0x66DB5E` 取反写 `+0x1788`），驱动力 = `[0][1]`，升 / 降挡比固定 1.0 / 0.025（`0x66DBFF..0x66DC1A`）。
- 设定（虚表 slot 46）把整张表按请求 / 摆放的 setup 缩放：`0x66E1A0(this, xmm1 = 速度系数, xmm2 = 力系数)` 对每行：`速度 *= xmm1`，`升挡 = 新速度 × 升挡比`、`降挡 = 新速度 × 降挡比`，`驱动力 *= xmm2`；倒挡行同样处理。
  - 调用点只有三处，都是基类 setup：TankBase `0x67FB00`（`0x67FF37`，速度系数 xmm10 = `setup[1][1]`，力 xmm9 = `setup[1][2]`）、BikeBase `0x658F10`（`0x65924C`，xmm8 / xmm7）、Car `0x65A910`（`0x65AD90`，xmm8 = `setup[1][1]` / xmm7 = `setup[1][2]`）。下标按 `0x67FB7F`（外层 1）、`0x67FC59`（元素 1）以及 Car 的 `0x65A994` / `0x65AA18` 读出。
  - 各类自己的 slot 46 都走到其中之一：402 / 403 / 404 / 505 / 507 / 510 / 601 / 603 → TankBase；503 / 511 → BikeBase；Car（Striker、408 摩托、轻卡、拖车头）/ 607 / 60X → Car setup。**507 救援车是 TankBase，402 也是 TankBase（不是 Car 系）**。
- 原版自己的「极速」取值函数 `0x66CF00`：`max(|最后一行前进挡速度|, |倒挡速度|)`（`[+0x1760] + count*16 - 16`）。它被摩托 / Car 的转速比（`0x6596A0`、`0x65B800`）、TankBase 的 setup（`0x67FFE9`，写给 `+0xE10` 指向的对象 `+0x60`）、Car 的 `0x660CB7` 等使用。原版各表最后一行速度都是最大的（SGO 里末行比例 1.0）。

结论：**每辆车的极速 = 它运行时齿轮表最后一个前进挡的速度 `[[v+0x1760] + ([v+0x1770]-1)*16]`**，已经乘过它自己的 setup[1][1]。插件 `src/drivegear.cpp` `TopOf` 就读这个值（读之前 `Readable` 检查 `+0x1760..+0x1778` 与末行；行数 0 或 > 32、值非有限或 ≤ 0 视为读不到：该车不给挡位，日志一行 `GEAR v=... its gear table (+0x1760) unreadable`）。

## 2. 单位：m/s (H)

- CarBase 每帧 `0x674074`：`0x11B1300`（Havok 刚体线速度，`src/physics.cpp` `kGetLinVel`）取车体 `[+0x1698]` 的线速度，与车头方向 `+0x1B00` 点乘得前进速度（`0x67412A`）。
- 挡位选择 slot 58 `0x66DF70` 用同一个点乘（`0x66DF7F`）直接与行的升挡速度 `[row+4]` 比较（`0x66DFFC`）、与降挡速度 `[row+8]` 比较（`0x66E027`）。升 / 降挡速度 = 行速度 × 比例，所以行速度与 Havok 线速度同单位：**m/s**（不是武器那种 m/帧）。
- 交叉：SGO 算出的值（下表）坦克 10–14 m/s（36–50 km/h）、摩托 57.2 m/s（206 km/h）、Striker 27 m/s（97 km/h），量级合理；若是 m/帧则坦克 840 m/s，不可能。

## 3. 「极速」与实际跑到的速度 (M)

- slot 60 `0x66DE90` 把油门量（截到 `±[+0x1750]`）乘当前挡位行的速度写进 `+0x1820`（`0x66DF63..0x66DF67`），即驱动的目标速度 = 油门 × 挡位速度；最高挡全油门的目标就是末行速度。`0x66EAFF` 起用 `|+0x1820| / 极速` 参与驱动 / 转向的计算（未细读）。
- 没有跟到 Havok 车辆积分本身：坡道、阻力、履带摩擦可能让车达不到这个目标（实际极速 ≤ 表值）。插件 4 挡是油门全开，不依赖能否达到；1–3 挡 25 / 50 / 75% 低于表值，达不到表值时影响最大的是 3 挡（可能接近全开）。

- 511 摩托：Root.cpk 没有以 `V511` 命名的原版对象（类在，数据未定位），运行时同样读表（M）。

## 5. 未核 / 风险

- 未实机：没在游戏里读过 `+0x1760` 的实际内容，也没核对日志 `GEAR ... its top` 的数值与上表一致。
- 「setup 只执行一次」来自 `docs/edf41-bike-re.md` §出车路径（呼叫、`CreateVehicle2`、`mission_setup` 各走一次 slot 46）；若某条路径执行两次，表会被乘两次——那时原版驱动用的也是这张表，插件读到的仍与原版一致。
- 引擎声（`vehmix.h` EngineClass::topSpeed 16 / 22 / 30）没有改，仍按类别。
- 运行时是否还有别处改写齿轮表（例如等级 / 损伤）：`0x640000..0x690000` 内对 `+0x1760` 行的写入只有读入与 `0x66E1A0`；全 .text 未扫（M）。读运行时值本身不受影响。
