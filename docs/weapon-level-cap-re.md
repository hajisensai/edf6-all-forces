# 联机武器 / 护甲等级上限：静态逆向

EDF.dll TimeDateStamp `0x678CCB46`，地址均为 RVA。只读静态分析（`tools/edfre.py` 反汇编本机 EDF.dll、`pylib/sgo.py` 读 Root.cpk 的 `DEFAULTPACKAGE/CONFIG.SGO`），未启动游戏。

用户原话（2026-10-17）：「测试场不限制武器等级」。

## 结论

- 联机的武器等级上限、护甲数上限**是数据**：当前模式（ModeList 的一项）成员 7 里，每个难度一行，第 6 个元素是武器上限，第 7 个元素是护甲上限。每台机器用**本地的** config 自己算，不是房主下发的数值。
- 测试场任务包的联机模式原来照抄原版联机剧情（`tools/make_edf5_campaign.py mode_entry` 复制 `GameMode_OnlineScenario` 的成员 7），而测试场只有一关、进度恒为 0，所以每个难度都拿到联机剧情的**最低一档**（简单 / 普通约 2 级，困难约 5 级，硬核约 35 级，炼狱约 60 级，单位为界面上的武器等级）。
- 修法（根因）：生成测试场联机模式时，把每个难度的第 6 个元素写成 EDF.dll 自己表示「无上限」的 `[-1.0, -1.0]`（原版任务包２联机模式的炼狱难度就是这样写的）。其它元素、护甲上限、其它任务包都不变；不需要 hook，不写存档。
- 单机原来就没有限制（三层证据，见 §4）。
- 之前笔记里的说法需要更正：`GS+0x6E58`（脚本 `UnlockArmorWeaponLimit` 写它）**不是上限本身**，它非 0 时把房间的「等级限制」开关锁成开、不能关；上限数值和它无关，和 `AllClearRatio` 也无关。

## 1. 上限的计算（已验证）

两个入口，参数都是 GS（`*(EDF+0x20B2890)`）：

| | 入口 | 尾跳 | 计算函数 | 读的元素 |
|---|---|---|---|---|
| 武器 | `0xD8850` | `0xD887B jmp 0xE2710` | `0xE2710(cfg=GS+0x130, 难度, 进度)` | 成员 7[难度] 的元素 6（`+0x48`） |
| 护甲 | `0xD8130` | `0xD815B jmp 0xE06B0` | `0xE06B0(...)` | 成员 7[难度] 的元素 7（`+0x54`） |

`0xD8850`：`ebx = [GS+0x4C]`（难度）→ `call 0xD7B60`（进度）→ `rcx = GS+0x130`、`edx = 难度`、`xmm2 = 进度` → `jmp 0xE2710`。

`0xE2710`（逐条读过）：

```
0xe271a mov r8,[rcx+0x18]           ; cfg+0x18 = GS+0x148：当前模式的 ModeList 节点
0xe272c lea r9,[r8+0x54] ...        ; 成员 7（每个成员 12 字节，7*12 = 0x54）
0xe2742 ...                          ; 第 [难度] 行
0xe274e cmp dword [rbx+0x48],0       ; 元素 6（6*12 = 0x48）的类型：0 = 列表
0xe2752 jne 0xe2800                  ; 不是列表 → 返回 -1
...                                  ; 是列表：按进度在元素间插值
0xe27c2 comiss xmm7,xmm1 / ja 0xe2800 ; 取到的值 < 0 → 返回 -1
0xe27ea mulss ... mulss ...          ; ×0.25 ×100（即 ×25）→ 整数等级
0xe2800 mov eax,0xffffffff           ; -1：没有上限
```

- 进度 `0xD7B60` = `GS+0x48`（任务在列表中的序号）/（任务数 − 1）；任务数 ≤ 1 时为 0。测试场只有一关，进度恒为 0。
- 数据（本机 Root.cpk `CONFIG.SGO`，`tmp` 脚本只读）：

| 模式 | 元素 6（武器，×25 级） | 元素 7（护甲） |
|---|---|---|
| 离线剧情 / 离线任务包 | 整数 0（不是列表 → -1） | 整数 0 |
| 联机剧情 | 简单 / 普通 `[0.1, 1.1]`，困难 `[0.2, 2.1]`，硬核 `[1.4, 3.1]`，炼狱 `[2.4, 3.2, 4.0, 4.0]` | `[358, 2322]` … `[8572, 22500]` |
| 联机任务包２ | 炼狱 `[-1.0, -1.0]`（原版的「无上限」写法） | `[20000, 25000]` |

## 2. 上限在哪里生效（已验证，界面条目如何调用谓词为推断）

- 生效标志 `GS+0x14FC8`（字节）：`0x7865A0` 每帧由 `Application`（`0x705530`）→ `0x788460` 调用，每个成员本地算：`0x786A4E` 处 `[会话+0x1678] > 0`（房间的武器限制开关）**且**上限 > 0 时置 1，否则置 0；同时发 `OnlineSys_WeaponCapLock` / `OnlineSys_WeaponCapUnlock`。上限为 -1 时标志为 0。
- 房间开关：武器 `GS+0x14C4C` = `[会话+0x1678]`，护甲 `GS+0x14C50` = `[会话+0x1674]`；客人在 `0x7893F4` / `0x789466` 收到。建房 `0x8FBBC0`：`GS+0x6E58 != 0` 时两个开关强制为 1；房间设置界面 `0x91D465` 只在 `GS+0x6E58 == 0` 时让开关可改。脚本 `UnlockArmorWeaponLimit`（`0x70FF30`）只在联机且原值非 0 时把 `GS+0x6E58` 写成 0。
- 选武器界面 `HUiHQWeaponSelect`（构造 `0x8B4280`）：联机时（`0x8B43D3..0x8B43F6`）才挂上谓词 `0x8BC850`：`GS+0x14FC8 && level > 0xD8850(GS)`（`0x8BC873 cmp edi,eax; jbe`，**无符号**比较，所以 -1 永远不超限）。同样的比较还有 `0x95B1E0`（`HUiHQCurrentStatus`、`0x8ACD20` 调用）、`0x744AB0` 中的 `0x74568D`（房间成员 6 把武器的超限标记）、`0x747380`。
- 出击：武器**不**降级（`0x773840` 原样写 6 把武器，`0x7738F6..0x773912`）；护甲在发送方截断（`0x773871: test ebx,ebx; js; cmp; cmovl`，上限 ≥ 0 时取 min），上限由发送方 `0x78EA9C..0x78EAC0` 用 `0xD8130` 算；接收方 `0x790600` 在 `0x7907F5` 读出记录头里的上限后丢弃。建人路径不再调用这两个上限函数。

## 3. 「当前任务包」怎么判定（已验证）

- `GS+0x148` = `&ModeList[当前模式]`（`0xE2C09` 写入），正是 `0xE2710` 取上限表时读的节点；内容号 = `[[GS+0x148] + [[GS+0x148]+8] + 0x74]`，脚本 `GetContentID`（`0x70E5D0`）就是这一句。等价读法 `modes[GS+0x38]+0x10`（`src/edf5campaign.cpp CurrentContent`，`docs/mission-list-re.md`）。
- 客人进房后脚本 `_lobby_SetModeHandler` → `ApplyModeNo` → `SetMode` 切到房间的模式（`MAINSCRIPT.AS` 第 1897–1946 行），之后同样适用。
- 插件把它导出为 `TestRangeMode()`（`src/edf5campaign.cpp`，内容号等于 ini `TestRangeContent`），测试场的「摆放」面板用它判定本关是不是测试场。

## 4. 单机没有限制（已验证）

1. 离线模式成员 7 的元素 6、7 是整数 0：两个计算函数直接返回 -1。
2. 选武器谓词只在联机时挂上（`0x8B43F2`）。
3. 即使 `GS+0x14FC8` 留着上一次联机的值，上限 -1 在无符号比较下永远不超限。

## 5. 实现（`tools/make_edf5_campaign.py`）

- `Pack(..., weapon_cap=False)` 只给测试场（`RANGE`）；`mode_entry` 生成它的**联机**模式时把成员 7 每一行的元素 6 写成 `NO_WEAPON_CAP = [-1.0, -1.0]`。离线模式、EDF5 / EDF4.1 战役的任务包、原版模式都不动。
- 校验：`tools/selftest.py edf5_campaign_range_pack`（有游戏时，用本机 CONFIG.SGO 生成后逐行核对：联机模式每个难度元素 6 为 `[-1,-1]`、其余元素与原版联机剧情相同、离线模式与原版离线剧情相同）、`range_online_mode_has_no_weapon_level_cap`（无游戏，CI 也跑）。
- 生效范围：上限由每台机器的本地 config 算，房主和客人都要用新版安装器装过（进测试场房间本来就需要双方装了同一个任务包）。没有更新的客人仍按原来的上限过滤自己的武器。
- 没有做的：`GS+0x6E58`（会进存档，且只解锁开关不解除上限）、`GS+0x14C4C/14C50`（房主设置，会同步给所有人）、`GS+0x14FC8`（4 处写入互相覆盖）、只 hook 选武器谓词（护甲截断与成员标红仍在）。护甲上限保持原样（用户只要求武器等级；如需也解除，同法把元素 7 写成整数 0）。
