# EDF6 狙击镜缩放 / 视野角逆向（静态，2026-10-08）

EDF.dll TimeDateStamp 0x678CCB46，地址都是 RVA。H = 反汇编逐条确认；M = 读法确定、语义或时序推断；L = 猜测。
方法：纯静态（`tools/edfre.py` + capstone，Root.cpk 只读解包 SGO），未启动游戏，未改任何游戏文件，**没有实机验证**。

## 一句话结论

步兵开镜**不是**插件能直接写住的一个 FOV 值：游戏每帧在玩家镜头 `CharacterGhostCamera` 的第 4 槽 `0xF86A0` 里重算
`cam+0x24 = (π/4) / zoom`（`0xF8906..0xF8916`），`zoom` 来自镜头目标（玩家人物）的 `human+0x1D0`，而 `human+0x1D0` 又由
士兵每帧 `0x59ABB0` 写成「手里各把武器 `weapon+0x784` 的最大值」（`0x59B209`）；`weapon+0x784` 是开镜开关 `0x696310`
按 SGO 的 `SecondaryFire_Parameter` 设的倍率。投影 `0x118DFF0` 读的正是 `cam+0x24`。
原版载具没有可用的缩放：只有 4 个 DLC 贝加尔塔 / Nix 武器 SGO 写了 `SecondaryFire_Type 1`（倍率 4），但载具代码从不触发副开火，
镜头也只看人物手里的武器。插件给载具加缩放，最稳的点是**钩 `CharacterGhostCamera` 第 4 槽，原函数返回后把 `cam+0x24` 再除以载具倍率**：
每次调用原函数前撤回上一帧由插件写入的 FOV（仅值仍等于自己的写值时），再对原函数结果缩放。无目标分支不会重写 FOV，不能仅停止除。投影、Umbra 视锥、HUD 的 viewProj 都跟着走（M）。

### 1.1 `+0x224` 备用镜头块

`human+0x224 = 1` 时镜头改拷 `human+0x230..` 那一块，倍率在 `human+0x290`。写它的是兵种自己的第 5 槽（`0x550C30` 突击兵、
`0x563DC0` 工程兵）和 `0x5790E9 / 0x579776`，都是兵种道具的特殊视角（工程兵的那段在 `0x56403A` 置 1，`0x564075` 视条件清 0），
与载具无关（M）。插件判断「当前倍率」时应按 `+0x224` 选 `+0x1D0` 或 `+0x290`，或者直接读 `cam+0x410`。

## 3. 载具有没有缩放

## 4. 给插件的建议：载具座位缩放

### 4.1 推荐：钩 `CharacterGhostCamera` 第 4 槽，事后再除

- 位置：vtable `0x1768C10` 第 4 项（地址 `0x1768C30`，原值 `0xF86A0`）。用和 `turretcam.cpp` 瞄准第 2 槽同样的 vtable 槽位替换（链在别的插件之上：
  保存原槽值，调用它）。
- 做法：先调原函数（游戏照常算 `cam+0x24 = π/4 / zoom`、照常跑状态 2、座位镜头、碰撞）；返回后，若这台镜头的目标是本地玩家、
  玩家在插件管的座位上且插件的缩放开着：`cam+0x24 /= 插件倍率`。
  - 识别：`*(void**)cam == base+0x1768C10`；目标 = `cam+0x360`（`dynamic_cast<SoldierBase*>` 的结果，见 camera-re §3），
    与本地玩家人物比对；座位 = 人物 `+0x1540`，`+0x1550` 有效表示在车上。
  - 和游戏自己的倍率相乘而不是覆盖：人物手里的狙击枪坐车前若还开着镜（`human+0x1D0 > 1`），叠乘也不会出错。
- 为什么最稳：
  1. 有效目标分支从头算 FOV，无目标分支 `0xF870F → 0xF891D` 跳过写入。因此插件记住该镜头缩放前后的值，
     下一次该镜头调用时先撤回自己的写值，再调用原函数；下车、死亡、关功能、任务切换即使遇到无目标分支也会恢复。
     仅在字段仍等于插件上次写值时撤回，其他镜头逻辑后来写入的值保留；不解引用已记住但本次未传入的镜头。
  2. 在状态函数之后、投影之前：状态 2 不写 `cam+0x24`；投影 `0x118DFF0` 和视锥 `0x118DD30` 都在渲染阶段读 `cam+0x24`，
     任何把镜头参数拷到别的镜头 / 快照的路径（如 `0x105425`）拷到的也是除过的值（M：游戏线程更新在渲染之前，未实机核对帧序）。
  3. 不碰人物的 `+0x1D0`：那个字段还被步兵瞄准灵敏度 `0x570780` 用，且每帧被 `0x59B209` 覆盖。
- 备选（不推荐）：代码补丁 `0xF890E divss xmm0,[rdi+0x410]` 改成跳板。效果相同，但要改 `.text`、要签名校验，且所有 `CharacterGhostCamera`（分屏的另一名玩家）都会走到。

### 4.2 不要做的

| 做法 | 问题 |
|---|---|
| 在别处（定时器、HUD 钩子里）直接写 `cam+0x24` | 下一帧 `0xF8916` 覆盖；写在镜头更新之前完全无效，写在之后只碰巧生效一帧，时序不可控 |
| 写 `human+0x1D0` | 士兵第 5 槽 `0x59B209` 每帧无条件覆盖成武器最大倍率；且会顺带把步兵瞄准灵敏度（`0x570780`）一起除掉 |
| 写座位武器的 `weapon+0x784` / `+0x780` | 镜头根本不读座位武器（§3）；`0x690060`、`0x695F10` 等也会改回 |
| 改 SGO 的 `SecondaryFire_Type` | 载具代码不触发副开火，没有效果；还要改游戏文件 |

### 4.3 灵敏度

游戏对步兵开镜时把瞄准输入除以倍率（`0x570780`）。坐车输入 `0x572DF0` 不做这一步，所以插件的炮塔镜头（`TurretCamRate`、
鼠标 / 摇杆转角速度）在缩放时应自己除以倍率，否则高倍率下一下转出画面。

### 4.4 HUD 会不会跟着走

- 插件 HUD 用的 viewProj 是 `GaugeHook` 收到的游戏参数（`docs/hud-re.md` §0，`HudDraw` → `KeepViewProj`），即游戏本帧用来画场景的
  view × projection；`ToScreen`（`src/sight.h`）只做矩阵乘法和透视除法，不假设固定 FOV。只要 `cam+0x24` 是在投影建立之前改的（§4.1），
  HUD 的世界 → 屏幕投影、`CameraRay` / `LastViewProj` 反推的视线都**自动**跟着缩放（M：未追到 viewProj 由哪台镜头的 `+0x1A0` 合成，
  但它与场景画面一致这一点已由现有 HUD 标记的对齐间接证明）。
- 例外：任何按「π/4」写死的屏幕尺寸（`src/map_cam.h kHalfFov = 0.4` 是地图镜头自己的，不受影响）。插件里若有按固定 FOV 把角度换成像素
  的代码（比如以度数画刻度、按角度算圈的像素半径），要改成从 viewProj 取，或乘上倍率。
- 画面中心不变：缩放只改 FOV，中心射线方向不变，炮塔镜头的目标点 / 落点算法不受影响。
