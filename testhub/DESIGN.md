# 测试站数据与权限边界

## 登录和分组

Worker 在读取业务数据或静态页面前验证现有的账号、签名会话或 HTTP Basic。只有登录页及其脚本、样式、公开下载页，以及原版任务排序、关卡策划、剧情大纲的只读查看（三页及其脚本、`GET /api/plan` / `/api/story` / `/api/outline` / `/api/missions`）可公开读取：只列出写了内容的组，不返回作者、评价内容和原版脚本。所有写操作仍要登录，内容写入限本组；大纲评分任何账号可对任何组写。
普通账号可以读任何列出的组，写入始终使用账号所属组，忽略客户端指定的其他组；开发者可以选择组。接口不返回账号密码或签名密钥。

## 关卡策划（MOD 关卡列表）

`story_missions` 单独存储各组的自创关卡，与 `outline`、`proposals` 和游戏任务文件无写入关联；`book` + `step` 只是指向同组大纲某一步的引用，不校验（大纲改掉那一步时页面提示重新选）。
读取、编辑、删除和移动前均按组查询目标。同组成员和开发者都可以编辑、删除、调整顺序；编辑按 `version` 比较后写入，并发修改返回 409，不覆盖。
参考地图只能引用服务器关卡目录中的键；制作状态使用固定枚举，每组最多 1000 关。

威胁模型包括跨组访问、越权改写、跨站提交、文本注入和高频写入。
所有 SQL 参数绑定；文本沿用策划页的清洗与长度限制，页面使用文本节点展示，不解析用户 HTML。
写操作沿用同源检查、JSON 内容类型检查、正文大小限制和每账号写入限额。CSP 禁止内联脚本。

排序采用相邻行之间的数值，间隔耗尽时事务重编号。并发移动可能形成同值，列表以行 ID 保持确定顺序；多人同时编排时以最后一次成功写入为准。
本功能不提供历史版本恢复；删除前页面明确确认目标关卡。数据库迁移只创建新表和索引，可重复执行，不改动已有策划或反馈。
